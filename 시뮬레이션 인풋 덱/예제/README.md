# 단일 요소 인장 — 여섯 솔버 같은 문제

물성 카드를 새로 쓰거나 남의 덱에서 옮겨 온 뒤 **가장 먼저 통과시켜야 할 시험**이다.
요소 하나를 잡아당겨 응력–변형률을 뽑고 입력한 곡선과 겹쳐 본다. 몇 초면 돌고,
경화곡선의 열 순서·변형률 종류·단위계 실수가 여기서 전부 드러난다.

여섯 덱이 **같은 재료, 같은 형상, 같은 하중, 같은 단위계**라 결과를 서로 겹쳐 볼 수 있다.

> **어느 값을 실제로 잴 수 있나** — 여기 있는 모든 물성값에 「측정 가능 / 가정」
> 표시를 붙인 문서가 따로 있습니다: [측정 가능 범위](../08-측정-가능-범위-KR.html).
> 덱에 값이 있다는 것과 그 값을 잴 수 있다는 것은 별개입니다.

## 검증에서 나온 오류 — 종류별 정리

이 덱들은 **솔버로 돌려 보지 못한 채** 문서·계산·실물 대조만으로 검증했습니다.
그 과정에서 **7개 층위에 걸쳐 70건 넘는 오류**가 나왔고, 층위를 새로 열 때마다
그 층의 오류가 한꺼번에 드러났습니다. **오류가 늘어난 것이 아니라, 그때 처음
보인 것**입니다 — 검사기는 설계된 것만 보기 때문입니다.

| 층위 | 무엇이 잡았나 | 건수 | 대표 |
| --- | --- | --- | --- |
| 필드 **정렬** | 열 파싱 | **41** | `MATS1` 한 필드 밀림, `*NODE` 를 10칸으로, `ENDCYC=5` |
| 필드 **의미** | 벤더 매뉴얼 | 5 | `FAIL` 음수, `D1` 역수, `MODULI` 기본값 |
| **해석 절차** | 벤더 매뉴얼 | 6 | SOL 106 대변형 불가, `PLSOLID`, `HASHASSM` |
| 카드 **개수·숨은 필드** | **실제 덱** | 10 | LAW42 빈 카드, LAW25 18줄, `Istrain` |
| **물리 가정** | 직접 계산 | 3 | 기질 파손 간과, 비압축 가정 |
| **모델 일관성** | 덱 간 대조 | **10** | 쉘에 BRICK 출력, 반력 누락, 엔진 제목 6개 |
| **해석 제어** | 정밀도 계산 | 2 | 이력 7점(0.18% 흔들림), 증분 0.05 |

**정렬 층위가 두 배가 된 것은 8차에서입니다.** 검사기를 `*MAT_*`·`*DEFINE_*` 밖의
제어·출력 카드까지 넓히자 27건이 한꺼번에 나왔습니다(맨 아래 8차 절).

### 정렬 — 눈으로는 안 보이는 것

고정폭 덱에서 값이 옆 필드로 넘어가도 **문법 오류가 안 납니다.** 열을 기계로
파싱해야만 보입니다.

- `MATS1` 가 한 필드 밀려 `YF` 가 비고 `HR`·`LIMIT1`·`LIMIT2` 로 값이 이동 (덱 2 + 문서 4곳)
- `PCOMP` 도 밀려 파손기준 `HILL` 이 `TREF` 자리에 — **그대로면 파손지수가 계산되지 않음** (문서 4곳)
- `PSOLID` 의 `STRESS`/`ISOP`, `MATT1` 의 NU 표 ID, `NLPARM` 의 `KMETHOD` 각 1곳
- **LS-DYNA 는 카드마다 폭이 다릅니다** — `*NODE`·`*ELEMENT_*` 는 8칸, 나머지는 10칸.
  `*NODE` 를 10칸으로 적어 1–8칸이 통째로 비어 NID 를 못 읽는 상태였음
- `1.000E+07`(9자)이 10칸 필드를 넘고, `0.4995` 가 필드를 넘음
- Radioss `LAW36` 의 `VP` 가 필드 밖(99열) — 두 덱에서 반복
- `TABLES1` 유효숫자 부족으로 탄성 기울기가 209581(E=210000이어야)

### 의미 — 읽으면 반대로 이해되는 것

- LS-DYNA `FAIL` **음수는 「파단 없음」이 아니라 사용자 서브루틴 호출**. 끄려면 `0`
- Nastran `MATHP` 의 `D1 = K/2`, Abaqus·Ansys 의 `D1 = 2/K` — **같은 기호, 역수**
- Abaqus 초탄성+점탄성은 기본이 **장기 응답**, Ansys 는 **항상 순간 응답**
- LS-DYNA `MAT_054` 의 `PRBA` 는 **부** 포아송비(0.02), 주(0.3)를 넣으면 안정성 위반
- OptiStruct `MATS1` 의 `TYPSTRN` 이 전체/소성 변형률을 고름

### 카드 개수·숨은 필드 — 실물 덱으로만 보이는 것

**문서 요약은 필드 폭·카드 개수·빈 카드를 떨어뜨립니다.** 이 층은 실제로 도는
덱을 구해 열 단위로 대조해야만 드러났습니다.

- Radioss `LAW42` 는 mu·alpha 가 **5개씩 2장** — **빈 둘째 카드가 없으면 alpha 줄이
  mu_6~mu_10 으로 먹힙니다**
- Radioss `LAW25` 는 값 카드가 **18장**(요약 페이지 기준 8장으로 썼었음)
- Radioss `/PROP/TYPE11` 의 `Istrain` 필드, 20칸인 `Ithick`, 층 앞의 `Vx/Vy/Vz` 카드
- Radioss `/PROP/SOLID` 의 빠진 두 줄, `/IMPDISP` 의 필드 순서와 빠진 둘째 줄
- `/TH/BRIC` 은 Engine 이 아니라 **Starter** 블록
- `*ELEMENT_SOLID` 는 실무 덱에서 **한 줄**(매뉴얼의 두 카드 형식이 아님)
- MSC `ANALYSIS = NLSTATICS` (문서 안에 `NLSTAT`·`NLSTATIC` 도 섞여 있음)
- Ansys `TB,RATE`·`TB,CREEP` 은 **NTEMP·NPTS 를 비움**
- 존재하지 않는 `/GLASS/OFF` 를 지어냈던 것

### 물리 가정 — 계산으로만 보이는 것

- 복합재에서 **섬유 방향 지수(0.61)만 보고 「파손 없음」**이라 했는데, 90° 층의
  기질 지수가 **1.37** 이었음 → 변형률을 1% → 0.5% 로 낮춤
- 고무를 완전 비압축으로 계산(4.7250)했으나 덱은 K/G=1000 → **4.7162**
- 반력 계산에 **탄성 체적변화**가 빠져 세 세트가 0.1~0.2% 어긋남

### 아직 못 잡는 것

실물 덱을 못 찾은 조합은 **카드 개수·숨은 필드 오류가 남아 있을 가능성이 높습니다** —
그게 실물로만 잡히는 종류인데 실물이 없기 때문입니다.

| 솔버 | 실물 대조 못 한 카드 |
| --- | --- |
| LS-DYNA | `*MAT_027` · `*MAT_054` · `*MAT_063` · `*PART_COMPOSITE` |
| Nastran | `MATHP` · `MATVP` · `MATT1`+`TABLEST` |
| Abaqus | `*CRUSHABLE FOAM` |
| Radioss | `LAW70` |

**이걸 끝내는 방법은 솔버 입력 검사 한 번뿐입니다.** 전체 해석까지 갈 필요도 없습니다.

```
OpenRadioss :  starter_linux64_gf -i <deck>_0000.rad     # _0000.out 에 카드 오류가 전부
Abaqus      :  abaqus job=<deck> datacheck
LS-DYNA     :  초기화 단계까지만 실행
Nastran     :  체크 런
```

OpenRadioss 는 무료라 **Radioss 다섯 덱은 지금 바로 검증 가능**합니다. 출력 파일을
주시면 그것으로 고치겠습니다.

## 모델

1 × 1 × 1 mm 육면체 하나. **1/8 대칭** 구속(x=0·y=0·z=0 면을 각각 그 방향으로만
고정)이라 나머지 면은 자유롭게 수축한다 — 과구속 없는 순수 단축 인장이다.
x=1 면을 **0.5 mm** 까지 당긴다(공칭변형률 0.5).

```
        8-------7          x=0 면 (1,4,5,8) : ux = 0
       /|      /|          y=0 면 (1,2,5,6) : uy = 0
      5-------6 |          z=0 면 (1,2,3,4) : uz = 0
      | 4-----|-3          x=1 면 (2,3,6,7) : ux = 0.5  ← 당기는 면
      |/      |/
      1-------2            단위: mm / N / tonne / s  →  MPa
```

여섯 덱 모두 mm·tonne·s(MPa) 계다. Radioss 는 그 톤을 `Mg`(메가그램)로 적는다 —
Radioss 의 단위 코드는 접두사 + SI 접미사라 `Mg` 가 톤의 정식 표기다.

재료는 DP600 급 강판 한 종.

```
E   = 210000 MPa      rho = 7.85e-9 tonne/mm3      nu = 0.3
진응력 – 진소성변형률:
    eps_p    sigma
    0.000    350
    0.020    455
    0.100    560
    0.400    700
    1.000    790
```

## 기대값

돌려서 이 값이 나오면 카드가 제대로 들어간 것이다.

| 양 | 값 | 나오는 자리 |
| --- | --- | --- |
| 항복 시작 변위 | u = 0.001668 mm | 하중–변위 곡선의 꺾임 |
| 최종 진응력 σ_x | **700.32 MPa** | 요소 응력 |
| 최종 등가소성변형률 | **0.40213** | PEEQ / EPEQ / effective plastic strain |
| 최종 진변형률 ε_x | 0.405465 = ln(1.5) | 대수변형률 |
| 최종 반력 (당기는 면 합) | **467.50 N** | 절점 반력 합 |
| 최종 공칭응력 | 467.50 MPa | 반력 / 원단면적 1 mm² |

검산: 소성 비압축이므로 단면이 1/1.5 로 줄어 `700.32 × 0.6667 = 467.50 N`.
진응력과 공칭응력이 1.5 배 차이 나는 것이 이 시험의 핵심이다 —
**공칭 곡선을 그대로 카드에 넣었다면 최종 응력이 700 이 아니라 470 근처로 나온다.**

명시적 두 덱(LS-DYNA·Radioss)은 0.01 초에 걸쳐 당기므로 변형률속도가 약 50/s 다.
이 재료 카드에는 속도 의존이 없어 결과는 같아야 하지만, **운동에너지가 내부에너지의
5% 를 넘으면** 준정적이 아니므로 종료시간을 늘린다. LS-DYNA 덱은 `*CONTROL_ENERGY`
로 모래시계 에너지도 함께 쓰는데, ELFORM=1 에 균일 인장이라 **거의 0 이어야 한다.**

## 곡선이 솔버마다 다르게 들어간다

같은 곡선인데 넣는 형태가 다르다. 이 덱들을 나란히 열어 비교해 볼 것.

| 솔버 | 카드 | x 축 | 열 순서 | 첫 점 |
| --- | --- | --- | --- | --- |
| LS-DYNA | `*DEFINE_CURVE` | 소성변형률 | (변형률, 응력) | (0, 350) |
| Radioss | `/FUNCT` | 소성변형률 | (변형률, 응력) | (0, 350) |
| Abaqus | `*PLASTIC` | 소성변형률 | **(응력, 변형률)** | (350, 0) |
| Ansys | `TBPT` | 소성변형률 | (변형률, 응력) | (0, 350) |
| OptiStruct | `TABLES1` | **TYPSTRN 이 고름** (여기선 전체) | (변형률, 응력) | (0, 0) |
| Nastran | `TABLES1` | **전체변형률** | (변형률, 응력) | (0, 0), 둘째가 항복 |

Nastran·OptiStruct 표의 둘째 점 `0.00167` 이 `350/210000` 인 것을 확인할 것 —
이 값이 MAT1 의 E 와 어긋나면 초기 강성이 두 번 정의된다.

```
소성 → 전체    eps = eps_p + sigma/E
전체 → 소성    eps_p = eps - sigma/E
```

## 대변형 정식이 켜져 있어야 한다

40% 진변형률까지 가는 문제라 **큰 변형률 정식이 아니면 답이 다르게 나온다.**
솔버마다 켜는 방법이 다르고, 안 켜도 오류가 아니라 조용히 다른 답이 나온다.

| 솔버 | 켜는 방법 |
| --- | --- |
| LS-DYNA · Radioss | 명시적 정식이 본래 대변형 — 따로 켤 것 없음 |
| Abaqus | `*STEP, NLGEOM=YES` |
| Ansys | `NLGEOM,ON` |
| OptiStruct | `PARAM,LGDISP,1` (문서상 MATS1 대변형 소성 지원) |
| Nastran | **`PARAM,LGDISP,1` 만으로는 부족** — 아래 |

MSC 문서는 둘을 별개의 방아쇠로 나열한다 — *"Large displacement by LGDISP
parameter … Large strain by LRGSTRN"*. LGDISP 는 큰 변위·회전이고, 큰 **변형률**은
`NLMOPTS,LRGSTRN,1` 이다. **SOL 106 에는 후자가 없다** — 그래서 이 덱은 SOL 400 이다.
그리고 SOL 400 에서도 실제로 켜지려면 「advanced」 요소여야 해서, `PSOLID` 에
같은 PID 의 `PSLDN1`(BEH=SOLID)을 덧붙였다. 안 붙이면 옛 정식으로 조용히 계산된다.

## 이 덱을 어디에 쓰나

1. **새 물성 카드의 관문.** 실모델에 넣기 전에 이 덱의 재료 블록만 갈아 끼워 돌린다.
2. **솔버를 옮길 때.** 이식한 카드가 원본과 같은 곡선을 내는지 두 솔버에서 겹쳐 본다.
3. **파서·생성기 검증.** 카드를 자동 생성하는 코드를 만들면 그 출력이 이 덱과
   같은 형태인지 대조한다.

파단 카드는 일부러 넣지 않았다 — 파단은 요소 하나로 검증되지 않는다(메시 크기에
값이 붙어 있다). 각 솔버 문서의 파단 장을 볼 것.

## 검증 상태

**이 저장소에서 솔버를 돌려 보지는 않았다** — 개발 환경에 여섯 솔버가 없다.
대신 두 가지를 반복했고, 그 과정에서 실제 오류를 계속 잡아냈다.

### 1. 열 위치를 기계로 검사했다

Nastran 계열(`.bdf`·`.fem`)은 8칸 필드로, Radioss 는 주석 헤더가 선언한 필드 경계로,
LS-DYNA 는 카드별 폭으로 파싱해 **값이 의도한 필드에 들어갔는지** 대조했다.
같은 검사를 HTML 문서 안의 카드에도 돌렸다. 이 검사로 잡은 것:

- `MATS1` 이 한 필드 밀려 `YF` 가 비고 값이 하나씩 이동해 있었다. 예제 2개 + 문서 4곳.
- `PCOMP` 도 한 필드 밀려 파손기준 `HILL` 이 `TREF` 자리에 있었다 — 그대로면 파손
  지수가 계산되지 않는다. 문서 4곳.
- `PSOLID` 의 `STRESS`/`ISOP`, `MATT1` 의 NU 표 ID, `NLPARM` 의 `KMETHOD` 도
  각각 한 필드씩 밀려 있었다.
- **LS-DYNA `*NODE` 는 다른 카드와 폭이 다르다** — 대부분 10칸인데 `*NODE` 는 NID 가
  I8, 좌표가 E16 이다. 10칸으로 적어 1–8칸이 통째로 비어 NID 를 못 읽는 상태였다.
  `*ELEMENT_SOLID` 도 8칸, `*SET_NODE_LIST` 는 10칸이다.
- **Radioss LAW36 의 `VP` 가 필드 하나 밖(99열)에 있었다** — 90열에서 끝나야 한다.
  헤더 주석의 라벨 끝열과 값의 끝열을 맞춰 보고서야 드러났다.

지금은 세 검사 모두 위반 0건이다.

### 2. 실제로 도는 덱과 나란히 놓고 봤다

문서만으로는 「형식상 유효」와 「실무에서 실제로 쓰는 형태」가 갈린다. 그래서 공개된
**진짜 덱**을 받아 카드별로 대조했다.

| 솔버 | 대조한 실물 |
| --- | --- |
| Radioss | OpenRadioss `ModelExchange` — 한 요소 솔리드 모델, LAW36 인장 모델 |
| LS-DYNA | `ansys/pydyna` 시험 덱 — LS-PrePost 가 생성한 육면체·경계·곡선 카드 |
| Nastran | `pyNastran` 모델 — 실제 SOL 400 + CHEXA 덱, SOL 106 비선형 덱 |
| Abaqus | CalculiX-Examples 의 인장시험 `Zug.inp` |
| Ansys | `ansys/pymapdl` 검증 매뉴얼 VM7 · VM24 (소성) |
| OptiStruct | Altair 공식 교재 *Introduction to Nonlinear FEA using OptiStruct* |

이 대조로 잡은 것:

- **`*ELEMENT_SOLID` 를 두 카드로 나눠 썼다.** 매뉴얼에는 그 형식도 있지만
  **실무 덱(LS-PrePost 출력)은 `eid·pid·n1~n8` 을 8칸 × 10필드 한 줄**로 쓴다.
  한 줄 형식으로 바꿨다.
- **`ANALYSIS` 철자가 `NLSTATICS` 였다.** 가이드 본문의 기능 설명 절(비선형 정적·
  크리프·점탄성)이 모두 `NLSTATICS` 를 쓰고, 실제 Patran 생성 SOL 400 덱도 그렇다.
  `NLSTATIC`·`NLSTAT` 도 문서 안에 섞여 있지만 정식은 `NLSTATICS` 다.
- **OptiStruct 에 `PARAM,HASHASSM,YES` 가 빠져 있었다.** Altair 교재가 세 곳에서
  `LGDISP` 와 한 쌍으로 쓰라고 명시한다(튜토리얼 단계로도 나온다).

대조로 **확인만 되고 고칠 것이 없었던 것**:

- Abaqus — 실제 인장시험 `.inp` 가 `*plastic` 을 **(응력, 소성변형률, 온도)** 로
  적고 첫 점이 `330, 0, 0` 이다. 열 순서와 첫 점 규약이 내 덱과 같다.
  `*STEP, NLGEOM` + `*STATIC` + 변위 제어 + `RF` 출력 구조도 같다.
- Ansys — VM7·VM24 가 `MP,EX`/`MP,PRXY` → `TB,PLAS,mat,ntemp,npts,TBOPT` →
  `TBDATA`/`TBPT` → `D,ALL,<dof>,<값>` 순서로 간다. 내 덱과 같은 형태다.
- Nastran — 실제 덱의 `PSOLID`·`CHEXA`·`GRID` 가 내 것과 같은 열에 있다. 실제
  SOL 400 덱은 `PSLDN1` 없이 `PSOLID` 만 쓰는데, 그 덱은 대변형 **변형률**을 켜지
  않기 때문이고, 가이드의 속성-물성 표는 **`PSLDN1`+`MATS1` 을 "`NLMOPTS,LRGSTRN,1`
  이 켜져 있을 때만"** 으로 규정한다 — 내 덱이 그 조합이다.
- OptiStruct — 교재가 `TYPSTRN` 규약을 내 덱 주석과 똑같이 설명한다.
  「`TYPSTRN=0` 이면 첫 점이 원점, 둘째 점이 항복점이고 **그 두 점의 기울기가
  MAT1 의 E 와 같아야 한다**」. 내 표의 둘째 점 `0.00167 = 350/210000` 이 그것이다.
  그리고 「`MATS1` 은 3D 요소와 대변위에서 지원된다」로 솔리드 의문도 해소됐다.

### 앞선 회차에서 문서 대조로 잡았던 것

- **Radioss** — `/PROP/SOLID` 의 빠진 두 줄, `/IMPDISP` 의 필드 순서와 빠진 둘째 줄,
  Engine 에 잘못 둔 `/TH/BRIC`(Starter 블록이다), 지어낸 `/GLASS/OFF`.
  `/TH/NODE` 의 `DEF` 는 변위·속도만 주므로 반력용 `REACX` 를 덧붙였다.
- **LS-DYNA** — `FAIL` 은 `0.0`이 「파단 고려 안 함」이고 **음수는 사용자 서브루틴
  호출**이다. 요소는 `ELFORM=2`→`1`(LSTC 권고).
- **Nastran** — SOL 106 은 대변형 **변형률**이 없어 SOL 400 으로 바꿨고,
  `NLMOPTS,LRGSTRN,1` + `PSLDN1`(`C8 SOLID L`)을 넣었다. `NLPARM` 을 쓰면
  `KMETHOD=FNT` 여야 한다.
- **Abaqus** — `C3D8` 은 Abaqus/Standard 가 일정 체적변형률을 쓰므로 소성에 안전하다.
- **Ansys** — `/UNITS,MPA` = mm·Mg·s, `SOLID185 KEYOPT(2)=2` 가 전단·체적 잠김을
  함께 다룸, `TBPT` 첫 인자 생략 시 `DEFI`.

### 아직 실행으로만 걸러질 것

- 각 솔버의 수렴 설정(증분 수, 반복 한계)은 형식만 맞췄고 튜닝하지 않았다.
  발산하면 `NINC`/`NSUBST`/증분 크기를 먼저 조인다.
- LS-DYNA 명시적 덱의 준정적 여부 — glstat 의 운동에너지/내부에너지 비를 본다.
- Radioss `/PROP/SOLID` 의 `Ismstr=4` 는 문서상 대변형(진변형률·Cauchy 응력)이 맞고
  LAW36 과 호환되지만(10·12 는 LAW36 비호환), 레퍼런스 덱은 2를 썼다.

돌려 본 결과가 기대값과 다르면 이 README 를 고쳐 두면 다음 사람이 산다.

# 고무 — 초탄성 (2번째 물성 세트)

`rubber-1elem-*` 여섯 벌. **형상·경계·단위계는 소성 덱과 같고 재료와 하중만 다릅니다** —
1mm 육면체를 x 로 **1.0mm** 당겨 신장비 λ=2 (공칭변형률 100%)를 만듭니다.

재료는 2항 Mooney–Rivlin 하나.

```
C10 = 0.6 MPa   C01 = 0.15 MPa   rho = 1.10e-9 tonne/mm3
G0  = 2(C10+C01) = 1.5 MPa       K = 1500 MPa  (K/G = 1000, nu = 0.4995)
```

## 기대값

비압축 Mooney–Rivlin 의 단축 인장 해석해가 있어 손으로 검산됩니다.

```
sigma_true = 2(L^2 - 1/L)(C10 + C01/L)          L = 신장비
L=2 :  2 x (4 - 0.5) x (0.6 + 0.075) = 4.725 MPa
```

| 양 | 값 |
| --- | --- |
| 최종 진응력 σ_x | **4.7162 MPa** |
| 최종 공칭응력 (= σ/λ) | **2.3625 MPa** |
| 당기는 면 반력 | **2.3606 N** (단면이 1/2 로 줄어 4.725 × 0.5) |

## 이 세트가 드러내는 것 — 같은 기호가 다른 뜻

**체적항 `D1` 이 솔버마다 역수 관계입니다.**

| 솔버 | 체적 상수 | K=1500 일 때 값 |
| --- | --- | --- |
| Abaqus | `D1 = 2/K` | 1.3333e-3 |
| Ansys | `d = 2/K` | 1.3333e-3 |
| **Nastran MATHP** | **`D1 = K/2`** | **750** |
| OptiStruct MATHE | `K` 를 직접 | 1500 |
| LS-DYNA MAT_027 | 포아송비 `PR` | 0.4995 |
| Radioss LAW42 | 포아송비 `nu` | 0.4995 |

MSC QRG 가 MATHP 의 D1 기본값을 `1000*(A10+A01)` 로 정의하는데, 그것이 곧 K/G=1000 이라
이 덱의 750 과 일치합니다 — 규약이 역수라는 것의 교차 확인입니다.

**점탄성을 얹으면 초탄성 상수의 의미가 갈립니다.**

| 솔버 | `*VISCOELASTIC`/PRONY 와 함께일 때 초탄성 상수는 |
| --- | --- |
| Abaqus | **기본이 장기(LONG TERM)** — 완전 완화된 응답 |
| Ansys | **항상 순간(t=0)** — 문서가 장기 지정 방법이 없다고 명시 |

같은 숫자가 정반대를 뜻합니다. 그래서 Abaqus 덱에 `MODULI=INSTANTANEOUS` 를 **명시**해
뒀습니다. Prony 블록 자체는 두 덱에 주석으로 넣어 두었고, 기본 덱은 **초탄성만** 켭니다 —
그래야 여섯 솔버가 같은 문제를 풀고 4.725 MPa 로 비교됩니다.

## 요소가 달라지는 자리

거의 비압축이라 소성 덱의 요소를 그대로 쓰면 **체적 잠김**이 생깁니다.

| 솔버 | 소성 덱 | 고무 덱 |
| --- | --- | --- |
| Abaqus | `C3D8` | **`C3D8H`** (혼합 정식) |
| Ansys | `SOLID185` KEYOPT(2)=2 | `SOLID185` + **KEYOPT(6)=1** (mixed u-P) |
| LS-DYNA | `ELFORM=1` | **`ELFORM=2`** (선택적 축소적분) |
| Radioss | `Icpre=0` | **`Icpre=1`** |
| OptiStruct | `PSOLID` | **`PLSOLID`** (초탄성 전용 속성) |
| Nastran | `PSOLID`+`PSLDN1` | 동일 |

`PLSOLID` 는 Altair 교재의 "MATHE materials are referenced by PLSOLID property,
which is a property dedicated exclusively for nonlinear hyperelastic materials"
에서 왔습니다 — `PSOLID` 로 두면 초탄성 재료가 붙지 않습니다.

## 이 세트의 검증 상태

- 카드 형식은 **정본 매뉴얼**에서 읽었습니다 — LS-DYNA `*MAT_027`(Keyword Manual
  Vol. II), MSC `MATHP`·`MATHE`(Quick Reference Guide), Abaqus·Ansys 는 공식 문서.
- 열 검사(ASCII·8칸·10칸·필드 경계) 전부 통과. 이 검사로 `*MAT_027` 첫 줄에서
  `0.4995` 가 필드 밖으로 밀린 것을 잡았습니다.
- **가장 덜 확실한 둘**:
  - **Radioss `/MAT/LAW42`** — OpenRadioss 공개 예제에 초탄성 모델이 없어 실물 대조를
    못 했습니다. 필드 순서는 레퍼런스 페이지 기준입니다.
  - **OptiStruct `MATHE` 1행 4번째 칸** — Altair 페이지가 JS 렌더라 필드표를 읽지
    못해 MSC 의 `MATHE`(= K) 배치를 따랐습니다. `NU` 일 가능성이 남아 있습니다.

# 복합재 — 준등방 적층판 (3번째 물성 세트)

`laminate-1elem-*` 여섯 벌. 이 세트만 **쉘 1개**이고, 나머지 둘은 솔리드입니다.

```
1 x 1 mm 쉘 1개,  4층 [0/45/-45/90] x 0.125 mm = 두께 0.5 mm
층 물성: E1=135000  E2=9000  nu12=0.3  G12=5000  G13=5000  G23=3500 MPa
         rho=1.57e-9,  Xt=2200 Xc=1400 Yt=60 Yc=200 S=90 MPa
경계: uz 와 회전 3개 전부 고정 (막 거동만),  x=0 변 ux=0,  y=0 변 uy=0
하중: x=1 변을 ux = 0.005 mm  ->  eps_x = 0.5%, 가로 수축은 자유
```

## 기대값 — 고전 적층판 이론으로 손검산됩니다

[0/45/-45/90] 등두께는 **면내 준등방**이라 A 행렬이 등방처럼 됩니다
(계산으로 A16=A26=0, A11=A22 확인).

| 양 | 값 |
| --- | --- |
| 유효 막 탄성계수 E_eff | **52090.3 MPa** |
| 유효 포아송비 | 0.30686 |
| 적층 평균 σ_x | **260.45 MPa** |
| 당기는 변 반력 (폭 1mm) | **130.226 N** |
| ε_y (자유 수축) | −0.001534 |
| 0° 층 σ₁ | 674.9 MPa |
| 최대 파손지수 | **0.69** (90° 층 기질) — 파손 안 함 |

0.5% 변형이라 **선형 탄성**입니다 — 여섯 솔버가 정확히 같은 값을 내야 하고,
파손기준은 카드에 선언만 되고 발동하지 않습니다.

## 이 세트가 드러내는 것

**층 각도의 기준 좌표계를 안 정하면 조용히 틀립니다.** 여섯 덱 모두 명시했습니다 —
Abaqus `*ORIENTATION`, Ansys `ESYS`, LS-DYNA `AOPT`+`MANGLE`,
Nastran/OptiStruct `CQUAD4` 의 `THETA`, Radioss `Iorth`. 안 정하면 요소의 첫 변이
기준이 되어 곡면에서 층 방향이 요소마다 달라집니다.

**LS-DYNA `MAT_054` 의 `PRBA` 는 부 포아송비입니다.**

```
nu_ba = nu_ab * E_b/E_a = 0.3 * 9000/135000 = 0.02
```

주 포아송비 0.3 을 넣으면 nu_ab = 4.5 가 되어 안정성 조건을 깨고 LS-DYNA 가
막습니다 — 다행히 그쪽이 나은 경우고, **나쁜 경우는 그대로 돌아가는 덱**입니다.
Ansys 의 `PRXY`(주) 와 `NUXY`(부) 구분도 같은 함정이고, 등방 재료에서는 둘이
같아서 복합재로 넘어오는 순간에만 드러납니다.

**허용값과 파손기준은 둘 다 있어야 합니다.** `MAT8` 에 Xt/Xc/Yt/Yc/S 를 넣고
`PCOMP` 의 `FT`(다섯째 데이터 필드)도 지정해야 파손지수가 나옵니다. 하나만
있으면 **오류 없이 지수가 안 나오고**, 결과에 없는 것을 「안전」으로 읽게 됩니다.

## 층 구성을 어디에 적는가

| 솔버 | 층 구성 카드 |
| --- | --- |
| Abaqus | `*SHELL SECTION, COMPOSITE` (두께, 적분점, 재료, 각도) |

| Nastran · OptiStruct | `PCOMP` (MIDi, Ti, THETAi, SOUTi 를 두 층씩) |

## 검증 상태

- `MAT8`·`PCOMP`·`MAT_054`·`*PART_COMPOSITE` 은 **정본 매뉴얼**(MSC QRG,
  LS-DYNA Keyword Manual Vol. I·II)에서 필드 순서를 직접 읽었습니다.
- 열 검사 전부 통과. 이 검사로 Radioss `/PROP/TYPE11` 의 `Ithick`·`Iplas` 가
  필드 밖으로 나간 것을 잡았습니다.
- 기대값은 CLT 로 독립 계산했고 준등방 조건(A16=A26=0)도 수치로 확인했습니다.
- **가장 덜 확실한 것**: Radioss `/MAT/LAW25`·`/PROP/TYPE11`. Altair 필드표가
  기계로 읽히지 않고 OpenRadioss 공개 예제에 복합재가 없어 실물 대조를 못 했습니다.
  덱 머리말에도 같은 경고를 적어 뒀습니다.

# 폼과 크리프 — 솔버가 갈리는 물성 (4·5번째 세트)

이 둘은 앞의 셋과 다릅니다. **여섯 솔버가 같은 물리를 제공하지 않아서**, 억지로
여섯 벌을 만드는 대신 **할 수 있는 솔버에만** 덱을 두었습니다. 그 사실 자체가
이 세트의 결론입니다.

| 물성 | LS-DYNA | Radioss | Abaqus | Ansys | Nastran | OptiStruct |
| --- | --- | --- | --- | --- | --- | --- |
| 크러셔블 폼 | ✓ | ✓ | ✓ | 명시적 전용 | ✗ | ✗ |
| 크리프 | 사실상 ✗ | 사실상 ✗ | ✓ | ✓ | ✓ | ✓ |

- Ansys 의 크러셔블 폼은 `TB,CFOAM` 인데 **explicit dynamics 요소 전용**입니다.
  암시적 Mechanical 에는 회복형 초탄성 폼(`TB,HYPER,,,FOAM`)만 있습니다 —
  압착되고 안 돌아오는 폼과는 다른 물리입니다.
- Nastran·OptiStruct 도 마찬가지로 `MATHE` 의 Ogden Foam(회복형)만 있습니다.
- 반대로 크리프는 1000초를 적분해야 하는데, 명시적 솔버의 시간증분은 마이크로초
  단위라 현실적이지 않습니다.

## 폼 — `foam-1elem-*` (LS-DYNA · Radioss · Abaqus)

1mm 육면체를 x 로 **−0.3mm 압축**(30%). 폼 압괴 곡선:

```
변형률   0.00  0.05  0.10  0.30  0.50  0.70
응력MPa  0.35  0.38  0.42  0.55  0.90  3.00      E0 = 50 MPa,  PR = 0,  60 kg/m3
```

| 양 | 값 |
| --- | --- |
| 30% 압축에서 σ_x | **0.55 MPa** |
| 누르는 면 반력 | **0.55 N** (PR=0 이라 단면이 안 변해 공칭 = 진값) |

세 덱의 곡선이 **숫자까지 같은지 스크립트로 대조**했습니다. 다만 가로축 규약이
갈립니다:

| 솔버 | 카드 | 곡선의 가로축 |
| --- | --- | --- |
| LS-DYNA | `*MAT_063` | **전체 체적변형률** γ = 1−V |
| Radioss | `/MAT/LAW70` | **공학 변형률** (압축을 양수로) |
| Abaqus | `*CRUSHABLE FOAM HARDENING` | **소성 체적변형률** |

Abaqus 만 소성변형률이라 첫 점이 (0.35, 0) 이고, 전체변형률로 환산하면 0.007
에서 시작합니다 — 소성 세트에서 겪은 것과 같은 규약 차이입니다. 30% 지점에서는
셋 다 0.55 MPa 로 만납니다.

그리고 **`*MAT_063` 은 제하가 완전 탄성**입니다(매뉴얼 명시). 이력이 필요하면
`*MAT_083`(FU_CHANG) 이나 `*MAT_057` 로 가야 합니다. Radioss LAW70 은 제하
함수를 따로 받을 수 있는데, 여기서는 비교를 위해 `NuL = 0` 으로 껐습니다.

## 크리프 — `creep-1elem-*` (Abaqus · Ansys · Nastran · OptiStruct)

1mm 육면체에 **일정 하중 100 N**(= 100 MPa)을 걸고 **1000초 유지**.
Norton 2차 크리프라 손검산됩니다.

```
eps_dot_cr = A * sigma^n      A = 1e-15,  n = 5
100 MPa 에서 :  1e-15 * 100^5 = 1e-5 /s
```

| 양 | 값 |
| --- | --- |
| 1000초 크리프변형률 | **0.01000** (1%) |
| 탄성변형률 | 0.00047619 |
| 최종 ux | **0.0104762 mm** |

**대변형을 일부러 껐습니다.** 소변형이면 단면이 안 줄어 응력이 정확히 100 MPa
로 유지되어 닫힌 해가 됩니다. 대변형을 켜면 진응력이 올라가고, n=5 라 단면 1%
변화가 속도를 5% 움직입니다.

같은 법칙을 넣는 자리가 넷 다 다릅니다:

| 솔버 | 카드 | Norton 으로 만드는 법 |
| --- | --- | --- |
| Abaqus | `*CREEP, LAW=STRAIN` | A, n, **m=0** (m 은 변형률 지수) |
| Ansys | `TB,CREEP` TBOPT=**2** | C1, C2, **C3=0**(시간), **C4=0**(온도) |
| Nastran | `MATVP` | A, IT3D=0, M=5, **N=P=Q=0** |
| OptiStruct | `MATVP` | 동일 |

Ansys 의 `C4` 는 `exp(-C4/T)` 의 활성화항이라 **T 가 절대온도**여야 합니다 —
섭씨로 세운 모델은 조용히 틀립니다. 여기서는 0 으로 껐습니다.

**MSC 문서가 명시하는 두 가지**를 Nastran 덱에 반영했습니다.

1. *"Creep analysis requires an initial static solution at t = 0, which can be
   obtained by specifying a subcase that requests an NLPARM entry with DT = 0.0."*
   → SUBCASE 1 이 `NLPARM ... DT=0.0` 입니다.
2. *"In SOL 400, MATVP is only supported for elements with property extensions"*
   → `PSOLID` 에 `PSLDN1` 을 붙였습니다. 안 붙이면 크리프 데이터가 안 쓰입니다.
   대변형 소성이 `PSLDN1` 을 요구한 것과 같은 구조입니다.

## 검증 상태

- `*MAT_063`·`MATVP` 는 **정본**(LS-DYNA Vol. II, MSC QRG)에서 필드 순서를
  읽었고, `MATVP` 는 QRG 의 예제(`MATVP 10 .00375 0 1.5 1.1 1.0 1.0`)로 교차
  확인했습니다. Abaqus `*CRUSHABLE FOAM`·`*CREEP`, Ansys `TB,CREEP` TBOPT=2 는
  공식 문서 확인.
- 열 검사 전부 통과. 이 검사로 Radioss `/MAT/LAW70` 의 `RHO_I` 가 한 칸 넘어간
  것을 잡았습니다.
- 하중 합계(네 덱 모두 100 N)와 기대값을 스크립트로 재계산했습니다.
- **가장 덜 확실한 것**: OptiStruct `MATVP` 의 필드 배치(MSC 를 따랐다고 가정),
  그리고 Radioss `/MAT/LAW70` 의 파라미터 줄 묶음.

# 속도 의존과 온도 의존 소성 (6·7번째 세트)

소성 세트와 **같은 재료·같은 형상**을 쓰고 조건만 바꿉니다. 이 둘도 폼·크리프처럼
솔버가 갈립니다.

| | LS-DYNA | Radioss | Abaqus | Ansys | Nastran | OptiStruct |
| --- | --- | --- | --- | --- | --- | --- |
| 속도 의존 소성 | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ |
| 온도 의존 소성 | 별도 카드 필요 | 별도 카드 필요 | ✓ | ✓ | ✓ | ✓ |

`MATS1` 에는 속도 항이 없습니다(속도 의존은 `MATVP` 점소성으로 가야 하는데 그건
다른 구성식입니다). 반대로 온도 의존 소성은 명시적 두 솔버에서 `*MAT_024`·`LAW36`
로는 안 되고 열-구조 연성이 붙은 다른 카드로 가야 해서, 여기서는 암시적 넷만 뒀습니다.

## 속도 — `rate-1elem-*` (LS-DYNA · Radioss · Abaqus · Ansys)

**변형률속도를 일정하게 만드는 것이 이 덱의 핵심**입니다. 등속으로 당기면 길이가
늘면서 진변형률속도가 떨어져 답이 흐려집니다. 그래서 지수 이력을 씁니다.

```
u(t) = exp(100 t) - 1        t = 0 .. 0.00405465 s   ->  u = 0 .. 0.5 mm
진변형률속도가 구간 내내 정확히 100 /s
```

| 양 | 값 |
| --- | --- |
| 속도 배율 (100/s) | **1.10** |
| 진응력 σ_x | **770.30 MPa** (준정적 700.32 의 1.10배) |
| 반력 | **514.29 N** |

### 같은 물리를 네 솔버가 두 방식으로 적습니다

| 솔버 | 카드 | 방식 |
| --- | --- | --- |
| LS-DYNA | `*MAT_024` 의 `C`, `P` | 정적 곡선 × **해석식** Cowper–Symonds |
| Abaqus | `*RATE DEPENDENT, TYPE=POWER LAW` (D, n) | 동일 |
| Ansys | `TB,RATE` PERZYNA (m, γ) | 동일 |
| Radioss | `/MAT/LAW36` 의 속도별 함수 | **속도마다 곡선 하나** (표) |

```
sigma = sigma_static * [ 1 + (eps_dot / C)^(1/P) ]      C=1.0e7,  P=5
Ansys 는 같은 식을 m = 1/P = 0.2, gamma = C 로 적는다  <- m 과 1/m 을 뒤집는 것이 고전적 실수
```

Radioss LAW36 에는 해석식 배율이 없어 **0.001/s 곡선과 그것의 1.10배 곡선**을
넣었습니다. 100/s 에서는 넷이 일치하고, **그 밖에서는 갈립니다** — 덱을 이식할 때
기억할 지점입니다.

그리고 흔히 쓰는 연강 값 `C=40, P=5` 는 100/s 에서 배율 **2.66** 을 냅니다. 훨씬
낮은 속도대의 피팅이라 그대로 옮겨 쓰면 크게 과대예측합니다.

## 온도 — `temp-1elem-*` (Abaqus · Ansys · Nastran · OptiStruct)

균일 200℃ 에서 같은 0.5mm 인장.

```
 20 C : E = 210000,  곡선 350 / 455 / 560 / 700 / 790
200 C : E = 198000,  곡선 300 / 390 / 480 / 600 / 677
```

| 양 | 값 |
| --- | --- |
| 진응력 σ_x (200℃) | **600.31 MPa** |
| 반력 | **400.69 N** |
| 참고: 20℃ 였다면 | 700.32 MPa / 467.50 N |

**열팽창을 일부러 안 넣었습니다.** `*EXPANSION`/`ALPX` 가 있으면 TREF 에서 200℃
로 가는 열변형이 기계적 변형에 얹혀 연화 효과만 떼어 보는 검산이 흐려집니다.

### 온도를 넣는 자리가 두 갈래입니다

| 솔버 | 방식 |
| --- | --- |
| Abaqus | 기존 데이터 줄에 **온도 열을 덧붙임** — 별도 카드 없음 |
| Ansys | `MP` 계열은 `MPTEMP`/`MPDATA`, `TB` 계열은 `TBTEMP` 블록 |
| Nastran · OptiStruct | **별도 카드**: `MATT1`(탄성) + `TABLEST`(응력–변형률 곡선) |

Nastran 계열은 **둘 다 필요합니다.** `MATT1` 만 넣으면 탄성계수만 온도를 따라가고
**항복 곡선은 20℃ 값에 머뭅니다** — 오류 없이 조용히 틀립니다. 이 덱은
`TABLEST 500` 이 20℃→`TABLES1 501`, 200℃→`TABLES1 502` 로 곡선 전체를 바꿉니다.

Ansys 는 `TB,PLASTIC` 의 `NTEMP` 가 뒤따르는 `TBTEMP` 블록 수와 맞아야 합니다 —
2 라고 선언하고 3 개를 쓰면 나머지가 조용히 버려집니다.

## 검증 상태

- 카드 형식은 정본/공식 문서 확인. 이번에 새로 확인한 것: Abaqus/Standard 는
  **정적 스텝에서 속도 의존 항복이 살아 있는 몇 안 되는 시간 의존 응답**이고,
  Ansys `TB,RATE` PERZYNA 도 정적 해석에서 시간 증분으로 동작합니다(단 소성 모델이
  아래에 깔려 있어야 합니다).
- 열 검사로 잡은 것: Radioss `LAW36` 의 `VP` 가 또 필드 밖(99열), `fct_ID2` 헤더
  한 칸 어긋남, 그리고 **LS-DYNA `*MAT_024` 둘째 줄에서 `1.000E+07`(9자)이 10칸
  필드를 넘은 것**.
- 곡선과 변위 이력이 LS-DYNA/Radioss 사이에서 숫자까지 같은지, Radioss 의 100/s
  곡선이 정확히 정적×1.10 인지 스크립트로 대조했습니다.

# 실제 사례와 사용법 대조 (마지막 검증 라운드)

앞선 세트들은 **카드 형식을 정본 매뉴얼로** 확인했지만, **실무 덱이 실제로 그렇게
쓰는지**는 첫 세트(소성)에서만 대조했습니다. 나머지 여섯 세트를 같은 방식으로
다시 봤습니다.

## 대조한 실물

| 출처 | 무엇 |
| --- | --- |
| `ansys/pymapdl` 검증 매뉴얼 **260개** | VM56(초탄성) · VM133(크리프) · VM155(속도) · VM134·VM104(온도) |
| `pyNastran` `flat_plate_pcomp_test` | 실제 PCOMP + MAT8 적층 덱 |
| CalculiX-Examples `NonLinear/Creep` | 실제 Abaqus 형식 크리프 덱 |

## 이 대조로 고친 것

- **Ansys 는 `TB,RATE`·`TB,CREEP` 에서 NTEMP·NPTS 를 비웁니다.** 실제 용법은
  `TB,RATE,1,,,PERZYNA` 와 `TB,CREEP,1,,,3` 입니다. 제가 `TB,RATE,1,1,2,PERZYNA`,
  `TB,CREEP,1,,4,2` 로 점 개수를 채워 넣었던 것을 실제 형태로 바꿨습니다.
  (점 개수가 의미 있는 것은 `MISO`·`HYPER` 처럼 항 수가 가변인 모델뿐입니다 —
  VM56 이 `TB,HYPER,1,2,2,MOONEY` 로 NPTS=2 를 쓰는 것과 대비됩니다.)
- Ansys 초탄성 요소 설정에 **VM56 의 대안**(mixed u-P 대신 축소적분)을 주석으로
  달아 뒀습니다. 둘 다 체적 잠김을 피하는 정식입니다.

## 대조로 확인만 되고 고칠 게 없던 것

- **Perzyna 상수 순서** — Ansys 문서 예제 `TBDATA,1,0.1,2` 가 (m, γ) 순서임을
  확인했습니다. 제 `TBDATA,1,0.2,1.0e7` 이 맞습니다.
- **초탄성 상수 개수** — VM56 의 `TB,HYPER,…,MOONEY` + `TBDATA,1,C10,C01,d`
  세 상수가 제 것과 같습니다. 문헌의 실제 고무 값도 C01/C10 ≈ 0.25 로,
  제 (0.6, 0.15) 와 같은 비율입니다.
- **Ansys 크리프 절차** — VM133 이 `RATE,OFF` 로 하중을 걸고 `RATE,ON` 으로
  유지하는 2단계 구조입니다. 제 덱과 같습니다.
- **Ansys 온도** — VM134 의 `TB,PLAS`+`TBTEMP` 블록, VM104 의
  `MPTEMP`/`MPDATA` 가 제 덱과 같은 형태입니다.
- **Nastran PCOMP** — 실제 덱이 `PCOMP PID (Z0) (NSM) SB FT` 다음에 층을 두 개씩
  적습니다. 제 것과 같습니다. (실제 덱은 `SOUT` 을 비우고 저는 `YES` 를 씁니다 —
  둘 다 유효하고, YES 라야 층별 응력이 나옵니다.)
- **조밀 배치가 실무 관행임이 확인됐습니다.** 실제 MAT8 줄이
  `MAT8   102   1.5+76000000.      .38000000.` 처럼 값이 서로 붙어 있습니다.
  제가 TABLES1 을 8칸에 꽉 채워 붙여 쓴 것과 같은 형태입니다.
- **Abaqus 크리프** — 실제 덱이 `*Creep` 에 상수 3개(A, n, m)를 주고 `*VISCO,
  CETOL=` 로 유지합니다. 제 `*CREEP, LAW=STRAIN` + `*VISCO` 와 같은 구조입니다.
  (실제 덱은 하중과 크리프를 한 스텝에 넣고, 저는 정적 스텝을 앞에 둡니다.)
- Abaqus `*AMPLITUDE` 값이 `u(t)/0.5` 와 1e-6 이내로 맞는지 스크립트로 재검산.

## 실물을 못 찾은 것 (남은 한계)

공개된 실제 덱을 찾지 못해 **매뉴얼 형식 확인에만 의존하는** 조합입니다.

- Abaqus `*HYPERELASTIC` · `*SHELL SECTION, COMPOSITE` · `*CRUSHABLE FOAM`
- LS-DYNA `*MAT_027` · `*MAT_054` · `*MAT_063` · `*PART_COMPOSITE`

- Nastran `MATHP` · `MATVP` · `MATT1`+`TABLEST`

# 실물 QA 덱 대조 — 2차 (Radioss·복합재)

`OpenRadioss/OpenRadioss` 본체의 **qa-tests 에 Starter 덱 81개**가 있는 것을 찾았습니다.
1차에서 본 ModelExchange 예제집에는 없던 LAW42(Ogden)·LAW25(복합재)·FOAM·LAW44
시험 덱이 여기 있습니다. 이걸로 대조하니 **구조 오류 셋과 물리 오류 하나**가 나왔습니다.

## 구조 오류 — 실물을 보고서야 드러난 것

**1. `/MAT/LAW42` 는 mu·alpha 가 각각 5개씩 2장입니다.** 실제 덱:

```
#               Mu_1                Mu_2                Mu_3                Mu_4                Mu_5
               827.6                  55                   0                   0                   0
# blank card                      <- 이 빈 카드가 반드시 있어야 한다
                                  
#            alpha_1             alpha_2 ...
```

제 덱은 mu 를 2개만 한 줄 쓰고 곧바로 alpha 줄을 뒀습니다. **빈 둘째 카드가 없어
alpha 줄이 mu_6~mu_10 으로 먹힙니다.** 실제 구조로 다시 썼습니다.
(상수 자체는 맞았습니다 — μ1=2·C10, μ2=−2·C01 로 W = C10(I1−3)+C01(I2−3) 를 재현합니다.)

**2. `/MAT/LAW25` 는 값 카드가 18장입니다.** 제 덱은 8장이었습니다. 요약 페이지의
줄 나열만 보고 만든 것이 화근이었고, 실제 CRASURV 덱은 방향별 항복·손상 파라미터가
줄줄이 이어집니다. 실제 헤더에 값을 자동 정렬해 18장으로 다시 썼습니다.

**3. `/PROP/TYPE11` 에 제가 모르던 필드와 카드가 있었습니다.**
- `N` 과 `Thick` 사이에 **`Istrain`** 필드가 있습니다 (제 값이 두 필드에 걸쳐 있었습니다).
- `Ithick` 은 10칸이 아니라 **20칸**입니다.
- 층 목록 앞에 **`Vx Vy Vz Skew_ID Iorth Ipos` 카드**가 하나 더 있습니다 — 이게 없으면
  첫 층 줄이 그 카드로 먹힙니다.

## 물리 오류 — 파손지수를 섬유 방향만 봤다

복합재 세트를 1% 변형으로 잡고 "0° 층 지수 0.61, 파손 없음" 이라고 적었는데,
**90° 층의 횡방향 응력이 82.2 MPa 로 Yt=60 MPa 를 넘습니다 (지수 1.37).**
기질이 먼저 깨지므로 선형 CLT 값과 맞을 수가 없었습니다.

층별로 섬유·기질·전단 지수를 전부 계산해 **0.5% 변형**으로 낮췄습니다.

| | 1% (이전) | 0.5% (수정) |
| --- | --- | --- |
| 최대 파손지수 | 1.37 (90° 기질) — **파손** | 0.69 (90° 기질) — 안전 |
| 적층 σ_x | 520.90 MPa | **260.45 MPa** |
| 반력 | 260.45 N | **130.23 N** |

## 남은 한계

이번에도 실물을 못 찾은 것: Abaqus `*HYPERELASTIC`·`*SHELL SECTION, COMPOSITE`·
`*CRUSHABLE FOAM`, LS-DYNA `*MAT_027`·`*MAT_054`·`*MAT_063`·`*PART_COMPOSITE`,
Nastran `MATHP`·`MATVP`·`MATT1`+`TABLEST`.

Radioss 는 이제 **LAW36·LAW42·LAW25·PROP/SOLID·PROP/TYPE11·BCS·IMPDISP·TH 전부
실제 QA 덱과 대조**했습니다. 남은 것은 LAW70(폼)뿐입니다 — QA 덱의 폼 시험은
LAW33(`/MAT/FOAM_PLAS`)이라 직접 비교가 안 됩니다.

# 계산 가정 재점검 — 정확값으로 교체

카드 형식만 보다가 **제 기대값 계산의 가정**을 다시 봤더니 오차가 있었습니다.

## 고무를 완전 비압축으로 계산했다

해석해 σ = 2(λ²−1/λ)(C10+C01/λ) = **4.7250 MPa** 는 **완전 비압축** 값입니다.
그런데 덱은 여섯 다 **K/G = 1000**(ν=0.4995)으로 두었습니다. 압축성 Mooney–Rivlin
을 그대로 풀면(측면 자유, σ₂=σ₃=0):

```
lambda2 = lambda3 = 0.7074772   (완전 비압축이면 0.7071068)
J       = 1.001048             (부피가 0.1% 는다)
sigma_1 = 4.7162 MPa           (비압축 해석해보다 0.19% 낮다)
단면    = 0.500524 mm^2  ->  반력 2.3606 N
```

**4.7250 → 4.7162**, **2.3625 → 2.3606** 으로 고쳤고, 두 값의 관계를 덱 머리말에도
적어 뒀습니다.

## 소성 계열 반력도 탄성 체적변화만큼 어긋났다

단면을 `A = 1/λ` 로 잡았는데(소성 비압축), **탄성 부분은 압축성**입니다.
단축 응력 상태의 탄성 체적변형률 `(1−2ν)σ/E` 만큼 부피가 늘어납니다.

| 세트 | J | 정확한 단면 | 반력 (이전 → 수정) |
| --- | --- | --- | --- |
| 소성 (준정적) | 1.001335 | 0.667557 | 466.88 → **467.50 N** |
| 속도 100/s | 1.001468 | 0.667646 | 513.53 → **514.29 N** |
| 온도 200℃ | 1.001213 | 0.667476 | 400.21 → **400.69 N** |

0.1~0.2% 수준이라 실무에서는 무시할 만하지만, **기대값을 다섯 자리로 적어 두고
그 자리가 틀린 것**은 검증 덱으로서 문제라 고쳤습니다.

## 영향 없던 것 (확인함)

- **폼**: PR = 0 이라 단면이 아예 안 변합니다. A = 1.0, 반력 0.55 N 그대로.
- **크리프**: `NLGEOM` 을 껐으므로 소변형이고, 반력은 건 하중 100 N 그대로.
- **복합재**: 선형 막 거동이라 두께 불변, 130.226 N 그대로.

## 이번 라운드에 실물로 확인한 Abaqus 형식 사용법

CalculiX 시험 스위트 **620개**를 받아 내용으로 검색했습니다.

- `*HYPERELASTIC,NEO HOOKE` → `C10, D1`,  `*HYPERELASTIC,OGDEN,N=1` → `mu1, alpha1, D1`
  → **Mooney–Rivlin 은 `C10, C01, D1`** 순서. 제 덱과 같습니다.
- `*SHELL SECTION,ELSET=...,COMPOSITE` 의 층 줄이 `두께, 적분점, 재료[, 각도]` 순서.
  제 `0.125, 3, CFRP, 0.0, PLY0` 과 같습니다.
- `*ORIENTATION,NAME=OR` + `0.,0.,1.,1.,0.,0.` (a·b 벡터 6개 한 줄). 제 덱은 여기에
  회전 줄(`3, 0.0`)을 더 붙였는데, Abaqus 에서 선택적으로 허용되는 둘째 데이터 줄입니다.
- 실제 덱들은 `*SOLID SECTION` 에 **데이터 줄을 아예 안 씁니다**. 제 `,` 줄도 유효하지만
  (Abaqus/CAE 가 그렇게 씁니다) 실무 덱은 생략하는 쪽이 흔합니다.

# 해석 제어 층위 — 설정이 답에 도달할 수 있는가

형식·정렬·카드개수·물리가정·경계하중·출력 다음 층입니다. 여기서도 두 건 나왔습니다.

## 1. 속도 덱의 지수 이력이 너무 성겼다

속도 세트의 핵심은 **진변형률속도를 정확히 100/s 로 유지하는 것**인데, 곡선은
구간선형이라 구간 안에서 속도가 흔들립니다. 7점으로 끊었던 것을 재 봤더니:

| 이력 점 수 | 변형률속도 편차 | 응력 편차 |
| --- | --- | --- |
| 7점 (이전) | ±5.17% | **0.18%** |
| 10점 | ±2.06% | 0.074% |
| **21점 (채택)** | ±1.02% | **0.037%** |
| 41점 | ±0.51% | 0.018% |

기대값을 `770.30` 처럼 다섯 자리로 적어 놓고 **이력 자체가 0.18% 를 흔들고 있었던**
셈입니다. 네 덱 모두 21점 등간격으로 바꿨고, 네 이력이 숫자까지 같은지 대조했습니다
(Abaqus `*AMPLITUDE` 는 정규화값이라 7자리로 올려 왕복 오차를 없앴습니다).

## 2. Abaqus 최대 증분이 컸다

`dp600`·`rubber`·`temp` 가 최대 증분 `0.05`(전체의 5%)였습니다. 40% 로그변형률 /
λ=2 까지 가는 문제에서 증분당 2% 변형률이라, 대변형 갱신과 경화곡선 꺾임을
지나는 정확도가 기대값의 자릿수에 못 미칩니다. **`0.02`(50증분 이상)로 조이고**
초기 증분도 `0.002` 로 낮춰 항복점을 첫 증분에 건너뛰지 않게 했습니다
(`INC` 한계도 200 → 500).

## 확인만 되고 이상 없던 것

**명시적 세 덱은 전부 준정적입니다.** 운동에너지/내부에너지를 계산했습니다.

| 덱 | 속도 | KE/IE | 시간증분 | 사이클 |
| --- | --- | --- | --- | --- |
| 소성 | 50 mm/s | 4.4e-8 | 1.9e-7 s | 51,700 |
| 고무 | 100 mm/s | 4.0e-6 | 8.6e-7 s | 11,700 |
| 폼 | 30 mm/s | 2.0e-7 | 1.1e-6 s | 9,100 |
| 적층 | 5 mm/s | 3.0e-8 | 1.1e-7 s | 9,300 |
| 속도 | ~123 mm/s | 2.5e-7 | 1.9e-7 s | 21,000 |

모두 1e-5 이하라 관성 영향이 없습니다. (속도 덱의 속도 의존성은 관성이 아니라
구성식에서 오므로 이 판정과 무관합니다.)

그 밖에 확인한 것:

- Radioss `/DT/NODA/CST/0` + `Tscal=0.9, Tmin=0.0` 이 실제 OpenRadioss 덱과 같습니다.
- Ansys `NSUBST` 가 속도 덱에서는 `*DO` 루프 안에 있어 grep 에 안 잡혔을 뿐,
  20개 하중단계마다 20~200 substep 으로 들어 있습니다. 적층은 선형이라 불필요.
- Nastran/OptiStruct `NINC` 는 소성·고무·온도 50, 크리프 100(×10초=1000초) 으로
  모두 충분합니다.
- Abaqus 크리프의 `*VISCO, CETOL=1.E-5` 는 허용 응력오차 1 MPa / E 에 해당하는
  값이라 적정합니다.

# 속도 의존 폼 — 드롭타워 데이터를 그대로 받는 덱 (8번째 세트)

`foamdyn-1elem-*` 는 기존 `foam-1elem-*` 와 **같은 시험편·같은 정적 곡선**을 쓰되,
고속 압축 시험기(드롭타워)가 실제로 내놓는 두 가지 — **속도 의존성**과
**되돌아올 때의 이력 손실** — 를 받을 자리를 만든 것입니다.

## 왜 기존 폼 덱으로는 안 되나

`foam-1elem-*` 가 쓰는 `*MAT_063` / `*CRUSHABLE FOAM` 은

- 속도에 무관하고,
- **완전히 탄성적으로 되돌아옵니다** (제하 이력이 없습니다).

드롭타워가 재는 것이 정확히 그 둘이라, 데이터를 받아 놓고도 카드가 대부분을
버립니다. EPS·EPP 같은 완충재에서는 흡수 에너지가 곧 성능이므로 치명적입니다.

## 파일과 카드

| 파일 | 솔버 | 카드 | 속도 | 이력 |
| --- | --- | --- | --- | --- |
| `foamdyn-1elem-lsdyna.k` | LS-DYNA | `*MAT_FU_CHANG_FOAM` (083) | `TBID` 표 | `HU=0.70` ○ |
| `foamdyn-1elem-radioss_0000/0001.rad` | Radioss | `/MAT/LAW70` | `NL=2` 곡선 | `Hys=0.7` ○ |
| `foamdyn-1elem-abaqus.inp` | Abaqus/Standard | `*CRUSHABLE FOAM` + `*RATE DEPENDENT` | 항복비 표 | **✗** |

**Abaqus/Standard 만 이력을 못 냅니다.** 여기 crushable foam 은 소성 모델이라
제하가 탄성입니다. 드롭타워 곡선의 되돌이 고리를 재현하려면 `*LOW DENSITY FOAM`
이 필요한데 그건 **Explicit 전용**입니다. 이 한계를 덱 머리말에 적어 두었습니다.

## 시험 데이터가 그대로 들어가는 자리

세 솔버 다 **"속도 하나에 곡선 하나"** 구조입니다 — 낙하 높이를 바꿔 가며 얻은
곡선을 그대로 쌓으면 됩니다.

```
LS-DYNA   *DEFINE_TABLE 300 -> 값 0.001, 50.0 -> *DEFINE_CURVE 301, 302
Radioss   /MAT/LAW70  NL=2  -> fct_IDL 301 @0.001, 302 @50
Abaqus    *RATE DEPENDENT, TYPE=YIELD RATIO -> (1.00, 0.0) (1.40, 50.0)
```

LS-DYNA 매뉴얼이 `*MAT_083` 을 두고 Hirth/Du Bois/Weimar 개선판이
*"load curves generated by drop tower test to be directly input"* 을 허용한다고
적고 있습니다 — 이 카드는 애초에 그 시험을 위해 만들어진 것입니다.

LS-DYNA·Radioss 곡선은 **공칭응력 vs 공칭변형률, 압축을 양수로** 넣는 규약이
같아 숫자가 한 줄씩 정확히 일치합니다(기계로 대조했습니다). Abaqus 만 소성
체적변형률 축이라 값이 다릅니다.

## 하중 이력과 기대값

1 mm 정육면체 1/8 대칭, x 면을 **0.003 초에 −0.3 mm 까지 압축한 뒤 다시
0.003 초에 걸쳐 되돌립니다**(총 0.006 초, 공칭 100 /s).

| 시점 | 값 |
| --- | --- |
| t = 0.003 s (최대) | σx ≈ **−0.77 MPa**, 반력 ≈ **0.77 N** |
| 근거 | 정적 0.55 MPa × 속도비 1.40, PR=0 이라 단면 불변 |

100 /s 는 표의 위끝(50 /s)보다 빠릅니다. **세 솔버 모두 표 밖에서 외삽하지 않고
끝값을 물리므로** 답이 50 /s 곡선으로 확정됩니다 — 기대값을 손으로 검산할 수
있게 하려고 일부러 그렇게 잡았습니다.

되돌아오는 구간은 숫자로 못 박지 않았습니다. `HU`/`Hys` 가 흡수 에너지를
바꾸는데, 그 값이야말로 **시험으로 정해야 할 것**이기 때문입니다. 0.70 은
자리를 잡아 둔 값입니다.

# 8차 검증 — 정렬 검사기를 제목 줄까지 덮게 고치니 32건이 더 나왔다

앞 회차까지 "0건"이었던 것은 검사기가 **`*DATABASE_*` 옵션 카드를 보고 있지
않았기** 때문입니다. 이번에 LS-DYNA 전 카드로 넓히자 한꺼번에 드러났습니다.

## 1. `1.0E-05` 가 11칸을 먹고 있었다 (LS-DYNA 6덱 × 4~5줄)

```
    1.0E-05         0         0         1     <- 앞 공백 4칸 + 7자 = 11칸
   1.0E-05         0         0         1      <- 고침
```

10칸 격자에서 `DT` 는 `    1.0E-0` = **1.0 초**로, `BINARY` 는 `5` 로 읽힙니다.
둘 다 **문법상 멀쩡한 값**이라 오류가 안 납니다. 출력이 사실상 안 나오고,
`BINARY=5` 는 존재하는 옵션이라 조용히 다른 동작을 합니다.

## 2. `*CONTROL_TERMINATION` 이 더 나빴다 (`rate` 덱)

```
 0.00405465         0       0.0  ...    <- 11칸
0.00405465         0       0.0  ...     <- 고침
```

`ENDTIM` 이 `0.0040546` 으로 잘리는 것은 사소하지만, 밀려난 `5` 가 **`ENDCYC` 로
들어가 5 사이클 만에 정상 종료**합니다. 결과 파일은 만들어지고 오류도 없습니다.
**이 층위의 오류가 왜 위험한지를 가장 잘 보여주는 사례**입니다.

## 3. Radioss 엔진 파일 여섯 개가 전부 남의 제목을 달고 있었다

```
# DP600 single-element uniaxial tension  --  ...   <- foam·rubber·laminate·rate 에도
```

`sed` 로 복제해 만들면서 머리말만 안 고친 것입니다. 솔버에는 영향이 없지만
**"복사-수정이 결함을 나른다"** 는 앞 회차의 진단이 그대로 재현됐습니다.

## 4. 엔진 파일 값이 20칸 격자보다 두 칸 왼쪽이었다

읽히기는 하지만(필드 안이므로) 주석 헤더가 실제 경계와 어긋나 **검사기가 거짓
경보를 내는 원인**이었습니다. 헤더와 값을 모두 20칸 격자에 맞췄습니다.

## 5. `creep-1elem-ansys.dat` 만 반력 출력이 없었다

앞 회차에서 5개를 채웠는데 이것 하나가 남아 있었습니다. `FSUM` 을 추가했습니다
(x=0 면에서 −100 N).

## 이번 라운드의 교훈

앞선 일곱 층위와 **같은 종류(정렬)** 인데 새로 나왔습니다. 검사기가
`*MAT_*`·`*DEFINE_*`·`*NODE` 만 보고 **제어·출력 카드를 안 보고 있었기**
때문입니다.

> 검사기가 "0건"이라고 말할 때 그것이 뜻하는 것은
> **"내가 보도록 만들어진 곳에는 없다"** 뿐입니다.

현재 검사 범위: LS-DYNA 는 `$`·`*` 로 시작하지 않는 **모든 줄**, 제목 줄만
제외합니다. Nastran 계열은 BEGIN BULK 이후 전 줄, Radioss 는 주석 헤더가 있는
전 블록입니다.
