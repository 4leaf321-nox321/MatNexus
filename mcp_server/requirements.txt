# MCP 서버 전용. **백엔드 venv 와 섞지 않는다** — SDK 가 언제든 프레임워크를
# 올릴 수 있고(ReportArchive 는 그것으로 FastAPI 와 충돌했다), 그때 앱이 인질이
# 되면 안 된다. 실측(2026-09-06): mcp 2.1.1 은 starlette 1.6.0 · pydantic 2.13.5 로
# 우리 백엔드와 충돌하지 않는다 — 그래도 분리는 유지한다.
#
# **전이 의존성까지 `==` 로 고정한다**(2026-11-15 전반 점검 — 백엔드 requirements 와 같은 방식).
# 전에는 `mcp>=2.1.0,<3` · `httpx>=0.27.0` 범위라 패키징(`package_deploy.ps1` 의 `pip wheel`)
# 때마다 그날의 최신 판이 풀렸다 — 같은 날 색인의 mcp 는 2.3.0 인데 개발 venv 는 2.1.1 이었다.
# 그런데 운영 서버는 이 파일의 해시가 같으면 venv 를 그대로 쓴다(`venv_sync.ps1`). 파일은 그대로인
# 채 패키지만 새로 나가면 **언제 처음 깔았느냐에 따라 서버마다 SDK 판이 달랐다.** 판을 바꾸는 일이
# 이 파일을 고치는 일이어야 해시가 갈리고 모든 서버가 같은 판으로 다시 깐다.
#
# 판은 개발 venv(`mcp_server/.venv`)의 것이다 — 그 판으로 `MCPServer.run(transport=
# 'streamable-http', host=, port=, transport_security=)` 가 돌고 도구 129개가 등록된다.
#
# 올리는 법: `.venv` 에서 `pip install -U mcp httpx` → `probe.py` 로 진짜 클라이언트 한 바퀴
# (README §6) → `pip freeze` 에서 `pip` 를 뺀 목록으로 아래를 바꾼다(`pywin32` 의 조건은 남긴다).
