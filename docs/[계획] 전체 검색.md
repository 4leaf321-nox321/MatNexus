# [계획] 전체 검색 — 한 칸에 치면 무엇이든

날짜: 2026-09-08
관련: [[계획] 온톨로지](%5B%EA%B3%84%ED%9A%8D%5D%20%EC%98%A8%ED%86%A8%EB%A1%9C%EC%A7%80.md) ·
[ADR 0028](adr/0028-온톨로지는-표를-안-바꾸고-얹는다.md)

## 무엇이 문제였나

검색 칸이 화면마다 따로 있었다. 그래서 「SECC180」 이 재료인지 시료인지 시험
이름인지 **아는 사람만** 찾을 수 있었다 — 모르면 화면 넷을 돌아야 했다.

ReportArchive 의 검색을 참고했다. 거기는 셋을 한다:

    키워드    pg_trgm 부분일치
    의미      질의 임베딩 → pgvector HNSW KNN
    융합      위 둘을 RRF(reciprocal rank fusion)로 합산

임베딩은 사내 호스트의 **Ollama**(bge-m3, 1024차원)를 부르고, 개발·시험은 mock
(텍스트 해시 → 결정적 단위벡터)으로 Ollama 없이 파이프라인 전체를 돌린다.

## 1·2단계 — 일치·포함·비슷 (v1.206.0, 완료)

    GET /api/search?q=&mode=exact|contains|similar&kind=

- **대상은 온톨로지 레지스트리가 정한다.** `relations.KINDS` 가 종류마다 「어느 표,
  어느 열이 이름인가」 를 이미 들고 있어서, 종류를 더하면 검색에 저절로 들어온다.
- **권한은 `graph.visible_ids` 를 그대로 쓴다.** 규칙이 둘이 되면 「검색에는 뜨는데
  열면 404」 가 생긴다.
- `similar` 는 `pg_trgm`. 재료·시료·시편·시험 이름에는 GIN 색인이 이미 있다
  (`154c0d5508af`: 5만 건 118ms → 4.6ms).
- 실측(개발 DB, 13종 전부): 18~56ms. 첫 호출만 215ms(콜드).

**경계 하나를 시험이 적어 뒀다**: 부서를 잠가도 기준정보 낱말은 남는다. 재료
등급이 기준정보에 자동 등록되고 그 표는 전 부서가 같은 것을 보기 때문이다 —
검색이 만든 구멍이 아니라 기준정보 화면에서 이미 보이던 것이고, 가려야 한다면
고칠 자리는 자동 등록이지 검색이 아니다.

## 3단계 — 의미 검색 (Ollama, 예정)

사용자 확인: **사내에 Ollama 를 둘 수 있다.** RA 와 같은 구조로 간다.

### 무엇을 임베딩할 것인가 — 여기가 RA 와 갈린다

RA 는 보고서 본문을 청크로 쪼개 임베딩한다. **우리 데이터는 대부분 산문이
아니다.** `SECC180_MDOI_1.0` 에 임베딩을 걸면 뜻 없는 유사도가 나온다 — 그 이름은
트라이그램이 훨씬 정확하다.

의미 검색이 값을 내는 것은 **산문이 있는 것들**이다:

    물성 핸드북(guide_documents·sections)   가장 확실하다. 문장으로 쓰여 있다
    문헌 물성 정의 설명(271개)              「무른 금속의 항복」 같은 물음에 답한다
    시험·재료의 notes                       사람이 자유롭게 적은 자리
    공지·VOC                                 문장이다

**이름 열에는 임베딩을 걸지 않는다.** 걸면 「비슷한 뜻」 이라는 이름으로 엉뚱한
재료가 상위에 서고, 그것이 왜 떴는지 아무도 설명하지 못한다.

### 붙일 것

1. **pgvector 확장 + `search_chunks` 표** — `(kind, entity_id, text, embedding vector(1024))`,
   HNSW 색인. 온톨로지 종류를 그대로 쓰므로 권한 게이팅이 1단계와 같아진다.
2. **`app/shared/embeddings.py`** — `ollama` · `mock` 두 백엔드. **시험은 mock 으로
   돈다** — CI 에 Ollama 를 두지 않는다(RA 와 같은 판단).
3. **채우는 일은 워커가 한다.** 핸드백 절이 저장될 때 큐에 넣는다 — 저장 요청을
   임베딩 왕복만큼 느리게 만들지 않는다.
4. **`mode=similar` 를 강화한다.** 새 모드를 더하지 않는다 — 사람에게 「비슷」 은
   이미 하나의 뜻이고, 그 안에서 트라이그램과 의미를 RRF 로 합치면 된다. 모드가
   넷이 되면 무엇을 고를지가 새 문제가 된다.
5. **MCP 도구** — `search_all(q, mode)`. AI 가 길을 찾는 첫 손잡이가 된다.

### 정해야 할 것

- 모델·차원(bge-m3 1024 가 기본값). 한국어를 다루므로 다국어 모델이어야 한다.
- Ollama 가 어느 기계에서 도는가(운영 서버? 별도?). 배포 문서에 들어가야 한다.
- 재색인 정책 — 모델을 바꾸면 전부 다시 만들어야 한다. 그때 표를 비우는 스크립트가
  필요하다.

## 안 하기로 한 것

- **상단에서 결과를 미리 떨구는 드롭다운.** 열세 종류를 좁은 목록에 우겨넣으면
  무엇을 찾았는지 안 보인다. Enter 로 화면에 넘긴다(RA 와 같다).
- **저장된 검색.** RA 에는 있는데, 우리는 아직 검색이 없어서 무엇을 자주 찾는지
  모른다. 쓰이는 것을 보고 만든다.
