# 서버 이전 — 다른 컴퓨터로 옮기기

옛 서버의 데이터를 새 컴퓨터로 통째로 옮긴다. **DB 만 옮기면 안 된다.**

| 무엇 | 어디에 있나 | 빠뜨리면 |
| --- | --- | --- |
| DB | PostgreSQL | — |
| 파일스토어 | `<AppPath>_data\filestore` | 「DB 에는 있는데 파일이 없는」 행 — 화면은 멀쩡하고 **그 곡선을 열 때만** 터진다 |
| `.env` | `<AppPath>\backend\.env` | **전원 재로그인** — JWT 비밀키가 바뀌어 살아 있던 세션이 전부 끊긴다 |

DB 에는 곡선의 **경로와 해시**가, 파일스토어에는 그 **내용**이 있다. 시점이 어긋나면
둘이 안 맞는다 — 그래서 `backup.ps1` 이 같은 시각에 셋을 함께 받는다.

---

## 1. 옛 서버 — 받는다

```powershell
cd C:\Server\tools\MatNexus
.\backup.ps1 -AppPath 'C:\Server\MatNexus' -BackupRoot 'D:\move'
```

`D:\move\` 안에 이렇게 생긴다. **폴더 하나를 통째로** 새 컴퓨터에 복사한다:

```
D:\move\db\db-<yyyyMMdd-HHmmss>.dump     DB 덤프 (pg_dump 커스텀 포맷)
D:\move\filestore\                        시험 원본·Parquet·처리 결과
D:\move\env\.env                          접속 정보 · JWT 비밀키
D:\move\LAST_BACKUP.txt                   무엇을 언제 받았나
```

> **`<타임스탬프>\` 폴더는 없다.** 2026-09-05 에 세대 정책으로 바뀌면서 배치가
> 위처럼 바뀌었다 — 옛 문서를 보고 타임스탬프 폴더를 찾고 있다면 그것 때문이다.

앱을 세우고 받을 필요는 없지만, **옮기는 날에는 세우고 받는 편이 낫다.** 받는 도중에
새 시험이 올라오면 그것만 새 서버에 안 간다.

## 2. 새 서버 — 준비

먼저 [배포.md](../%EB%B0%B0%ED%8F%AC.md) 의 「0. 사람이 미리 준비할 것」 을 끝낸다
(PostgreSQL · Python · 폴더). 그다음 설치한다 — **빈 상태로 한 번 깔고, 그 위에
데이터를 되돌리는 순서다.**

```powershell
cd C:\Server\tools\MatNexus
.\install.ps1 -AppPath 'C:\Server\MatNexus' -DbPassword '<postgres 비밀번호>' `
              -AdminEmail '<옛 서버와 같은 관리자 아이디>'
```

**관리자 아이디를 옛 서버와 맞춘다.** 다르면 복구한 DB 안의 계정과 새로 만든 계정이
따로 놀아, 로그인은 되는데 아무 권한이 없는 상태가 된다.

## 3. 리허설 — **건너뛰지 않는다**

```powershell
.\restore.ps1 -BackupRoot 'D:\move' -DbName matnexus_check
```

다른 이름의 DB 로 되돌려 보고, **DB 가 가리키는 파일이 실제로 다 있는지 세어 준다.**
여기서 「없는 파일」 이 나오면 4번 전에 안다 — 옮기고 나서 알면 옛 서버를 이미
내렸을 수 있다.

## 4. 진짜 복구 — DB + 파일스토어

```powershell
.\restore.ps1 -BackupRoot 'D:\move' -DbName matnexus -AppPath 'C:\Server\MatNexus' -Force
```

`-AppPath` 를 주면 파일스토어도 `<AppPath>_data\filestore` 로 넣는다. **지우고 넣지
않는다** — 백업에 없는 파일이 지금 있을 수 있어서다.

`-Force` 는 이미 있는 `matnexus` 를 덮는다는 뜻이다. 2번의 설치가 빈 DB 를 만들어
뒀으므로 여기서 필요하다. 무엇을 지우는지 먼저 적고 진행한다.

## 5. `.env` 를 손으로 옮긴다 — **여기가 가장 잘 빠진다**

```powershell
Copy-Item 'D:\move\env\.env' 'C:\Server\MatNexus\backend\.env' -Force
```

**복구 스크립트가 이걸 안 한다.** 백업의 `.env` 는 DB 접속 정보를 읽는 데만 쓴다 —
새 서버의 주소·포트가 다를 수 있어 자동으로 덮지 않는다.

옮긴 뒤 새 서버에 맞게 손볼 것: `DATABASE_URL`(비밀번호가 다르면), `PORT`,
`BACKUP_DIR`, `CORS_ORIGINS`. **`JWT_SECRET` 은 반드시 옛 것을 그대로 둔다** —
바꾸면 전원 재로그인이다.

## 6. 마이그레이션과 씨앗

```powershell
cd C:\Server\MatNexus\backend
& 'C:\Server\MatNexus_venvs\backend\Scripts\python.exe' -m alembic upgrade head
& 'C:\Server\MatNexus_venvs\backend\Scripts\python.exe' scripts\import_guides.py
& 'C:\Server\MatNexus_venvs\backend\Scripts\python.exe' scripts\import_materialtwin.py --apply
```

옛 서버가 최신 릴리스였다면 마이그레이션은 「할 것 없음」 으로 끝난다. 씨앗 둘은
멱등이라 이미 있으면 전량 「동일」 이다.

## 7. 리허설 DB 정리

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -U postgres -c "DROP DATABASE matnexus_check;"
```

## 8. 기동과 확인

```powershell
cd C:\Server\MatNexus
.\run_server.ps1     # 창 1
.\run_worker.ps1     # 창 2
.\run_mcp.ps1        # 창 3 (AI 연결을 쓸 때만)
```

**눈으로 확인할 것 넷** — 하나라도 어긋나면 옛 서버를 아직 내리지 않는다.

- 로그인이 **옛 비밀번호로** 된다(JWT 비밀키와 계정이 함께 왔다는 뜻)
- 재료 목록의 건수가 옛 서버와 같다
- **곡선이 그려지는 시험을 하나 연다** — 파일스토어가 제대로 왔는지는 이걸로만 안다
- 홈 화면에 운영 경고가 없다

## 새 서버에서 다시 해야 하는 것들

데이터가 아니라 **기계에 붙는 설정**이라 백업에 안 담긴다.

| 무엇 | 어떻게 |
| --- | --- |
| 백업 작업 스케줄러 | `backup.ps1` 머리글의 `Register-ScheduledTask` 예시를 새 서버에서 한 번 |
| pgvector (의미 검색) | [의미 검색 설치](%EC%9D%98%EB%AF%B8%20%EA%B2%80%EC%83%89%20%EC%84%A4%EC%B9%98.md) — **복구보다 먼저**여야 한다 ↓ |
| Ollama (의미 검색) | 같은 문서. 순서는 상관없다 |
| 방화벽 · 포트 개방 | 8010(앱), 8012(MCP 를 쓸 때) |
| MCP 클라이언트 등록 | 사람마다 토큰을 새로 발급(주소가 바뀌었다) |

### pgvector 를 쓰고 있었다면 — **순서가 있다**

옛 서버에서 의미 검색을 켰다면 그 DB 의 덤프에 `CREATE EXTENSION vector` 가 들어
있다. **새 서버에 pgvector 가 없으면 복구가 그 줄에서 실패한다.**

    ① pgvector 설치 (의미 검색 설치 문서의 0~2)
    ② 그다음 3번 리허설 · 4번 복구

Ollama 는 복구와 무관하니 나중에 해도 된다. 안 켤 생각이면 복구가 실패한 뒤
`DROP EXTENSION vector CASCADE` 로 그 DB 에서 확장을 떼는 길도 있지만, 색인이
사라지므로 다시 켤 때 재색인해야 한다.

## 걸리면

**복구가 「이미 있는 DB」 라며 멈춘다**
일부러 그렇게 만들었다 — 살아 있는 DB 를 실수로 덮으면 되돌릴 데가 없다. 덮으려면
`-Force` 를 준다. 리허설(3번)에는 절대 `-Force` 를 쓰지 않는다.

**로그인은 되는데 아무것도 안 보인다**
관리자 아이디가 옛 서버와 다르게 설치됐다. 새로 만든 계정으로 들어간 것이라 부서
소속이 없다 — 부서 관리 화면에서 그 계정을 옛 부서에 넣거나, 옛 아이디로 다시
로그인한다.

**전원이 다시 로그인해야 한다**
`.env` 의 `JWT_SECRET` 이 새로 생성된 것이다(5번을 건너뛰었을 때). 옛 `.env` 를
넣고 서버를 다시 띄우면 원래대로 돌아온다.

**시험은 보이는데 곡선이 안 열린다**
파일스토어가 안 왔거나 다른 곳에 들어갔다. `<AppPath>_data\filestore` 를 확인하고,
`restore.ps1` 을 `-AppPath` 와 함께 다시 돌린다(리허설 3번이 이걸 미리 잡는다).

**`-KeepDays` 같은 인자가 없다고 한다**
`backup.ps1` 의 세대 인자는 `-KeepDaily`(기본 7) · `-KeepWeekly`(기본 4)다.

## 왜 이 순서인가

- **설치 → 복구**다. 빈 앱을 먼저 세워야 폴더 배치·가상환경·스크립트가 제자리에
  생기고, 그 위에 데이터만 얹으면 된다. 반대로 하면 복구한 DB 를 가리킬 앱이 없다.
- **리허설이 복구보다 먼저**다. 되돌아오는지는 되돌려 봐야 안다 — 받아만 두고 복구해
  본 적 없는 백업은 백업이 아니다.
- **`.env` 는 자동으로 안 덮는다.** 새 서버의 주소·비밀번호가 다를 수 있어서다.
  그래서 사람이 한 줄 복사하고, 그 사실을 여기 크게 적어 둔다.
