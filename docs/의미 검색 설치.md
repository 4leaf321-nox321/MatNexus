# 의미 검색 설치 — 윈도우 서버, 한 번만

「비슷」 검색에 **뜻이 가까운 것**까지 얹는 절차. 제목에 없는 낱말로 핸드북 절을
찾는 일이 된다.

    지금(설치 전)   「물림부」 로 찾으면 0건 — 제목이 「시편 준비」 라서
    설치 후         그 절이 나온다 — 낱말이 하나도 안 겹쳐도

**안 해도 된다.** 검색의 「일치·포함·비슷(오타 허용)」 은 배포만으로 이미 돈다.
이 문서는 그 위에 얹는 선택 부품이고, 안 깔면 화면이 「뜻 검색 꺼짐」 이라고
표시할 뿐 나머지는 그대로 작동한다.

**배포와 별개다.** 평소처럼 `deploy.ps1` 로 배포하고, 이건 마음 내킬 때 한 번만
하면 된다. 부품이 없다고 배포가 실패하지 않는다.

---

## 0. 먼저 확인 — 운영 서버의 PostgreSQL 판

```powershell
Get-ChildItem 'C:\Program Files\PostgreSQL' -Directory | Select-Object Name
```

**`17` 이면 그대로 진행한다.** 다른 판이면 그 판으로 다시 빌드해야 한다 —
[3-B](#3-b-판이-다르거나-처음-빌드할-때) 를 본다. DLL 은 PostgreSQL 메이저 판에
묶여서 17용은 16에서 안 뜬다.

## 1. 산출물 폴더를 서버로 복사

```
보낼 것 :  <저장소>\build\pgvector\pg17\      38개 파일, 5MB
           (vector.dll · vector.control · vector--*.sql 35개 · build-info.json)
받을 곳 :  서버의 아무 데나. 예: C:\Temp\pgvector-pg17\
```

**릴리스 zip 에는 안 들어 있다.** 기계와 PostgreSQL 판마다 다른 바이너리라 저장소에
안 넣기 때문이다 — 그래서 이 폴더만은 사람이 나른다. 네트워크 공유든 USB든 상관없다.

## 2. pgvector 설치 — 서버, **관리자** PowerShell

```powershell
cd C:\Server\tools\MatNexus
.\install_pgvector.ps1 -FromDir 'C:\Temp\pgvector-pg17'
```

`-FromDir` 은 **1에서 복사해 둔 그 경로**다.

무엇을 하나: PostgreSQL 설치 폴더에 파일 3종을 넣는다. **재시작 불필요**하고
**DB 데이터도 안 건드린다**(확장 파일을 놓기만 한다).

```
[HH:MM:SS] PostgreSQL: C:\Program Files\PostgreSQL\17
[HH:MM:SS] 산출물: pgvector v0.8.0 / PostgreSQL 17 / …
[HH:MM:SS] 파일을 넣습니다.
[HH:MM:SS]   C:\Program Files\PostgreSQL\17\lib\vector.dll
```

> `install_pgvector.ps1` 이 없으면 릴리스 zip 을 푼 `unpacked\` 에서 꺼내
> `C:\Server\tools\MatNexus\` 로 복사한다(v1.206.0 부터 zip 에 들어간다).

## 3. 임베딩 엔진 설치 — 같은 창

```powershell
.\setup_ollama.ps1
```

설치 → **시작 시 자동 실행 등록**(작업 스케줄러, SYSTEM) → 모델(bge-m3, 1GB 남짓)
→ 임베딩을 한 번 재 보고 **`.env` 에 넣을 네 줄을 화면에 찍어 준다**:

```
    EMBEDDING_BACKEND=ollama
    OLLAMA_BASE_URL=http://127.0.0.1:11434
    EMBEDDING_MODEL=bge-m3
    EMBEDDING_DIM=1024
```

**트레이 앱으로 두지 않는 이유**: Ollama 의 윈도우 설치본은 로그인한 사람의 트레이에
뜬다. 서버는 아무도 로그인해 있지 않으므로 그대로 두면 재부팅한 다음 날 「의미
검색만 안 되네」 로 드러난다.

## 4. 켜기

```powershell
# ① 위 네 줄을 C:\Server\MatNexus\backend\.env 에 붙여넣는다

# ② 표를 만든다 (다음 배포가 알아서도 하지만, 지금 하면 바로 켜진다)
cd C:\Server\MatNexus\backend
& 'C:\Server\MatNexus_venvs\backend\Scripts\python.exe' scripts\ensure_semantic_schema.py

# ③ 워커 창(run_worker.ps1)을 닫았다 다시 띄운다
```

**확인**: 검색 화면에서 「비슷」 을 눌렀을 때 옆의 **`· 뜻 검색 꺼짐(글자만 봅니다)`
표시가 사라지면** 켜진 것이다.

색인은 워커가 채운다(하루 한 번 자동). 바로 채우려면 위 ② 명령을 다시 돌린 뒤
서버 화면의 작업 큐에서 `search.reindex` 가 도는지 본다.

## 3-B. 판이 다르거나 처음 빌드할 때

pgvector 는 소스 확장이고 윈도우용 공식 바이너리가 없다. **빌드는 개발 PC 에서
한 번**, 서버는 복사만 한다 — 운영 서버에 Visual Studio 를 깔 이유가 없다.

```powershell
# 개발 PC (Visual Studio Build Tools 의 「C++를 사용한 데스크톱 개발」 필요)
cd <저장소>\scripts\deploy
.\build_pgvector.ps1                                            # 서버 판이 17일 때
.\build_pgvector.ps1 -PgRoot 'C:\Program Files\PostgreSQL\16'   # 16이면
```

산출물이 `<저장소>\build\pgvector\pg<판>\` 에 생긴다. 그 폴더를 가지고 1번으로 간다.

**PostgreSQL 의 서버 개발 파일이 필요하다**(`lib\postgres.lib`). 설치 프로그램의
Development 구성 요소인데, 기본 설치에 대개 들어 있다. 없으면 빌드 스크립트가
먼저 그렇게 말한다.

## 걸리면

**「모듈을 로드할 수 없음」 이 나온다**
판이 안 맞는 것이다(17용을 16에 넣는 등). 설치 스크립트가 `build-info.json` 으로
먼저 막지만, 손으로 파일만 복사했다면 이 오류가 난다. 그 판으로 다시 빌드한다.

**`setup_ollama.ps1` 이 90초 안에 응답이 없다고 한다**
작업 스케줄러에서 `MatNexus-Ollama` 의 마지막 실행 결과를 본다. 수동으로
`ollama serve` 를 한 번 띄워 보면 원인이 보인다.

**모델은 받았다는데 서비스가 없다고 한다**
사람 계정으로 `ollama pull` 을 돌리면 그 사람 프로필에 받는다. 설치 스크립트가
`OLLAMA_MODELS` 를 기계 전역(`C:\ProgramData\MatNexus\ollama-models`)으로 박아
두므로, **새 PowerShell 창**을 열어 다시 확인한다(환경변수는 새 세션부터 보인다).

**설치는 했는데 「뜻 검색 꺼짐」 이 그대로다**
셋 중 하나가 빠졌다 — `.env` 의 `EMBEDDING_BACKEND=ollama`, 표(`4-②`), 워커 재시작.
표 상태는 `ensure_semantic_schema.py` 가 찍어 준다.

**빌드가 링크에서 죽는다** (`_guard_check_icall_$fo$`)
새 Windows SDK 와 옛 링커가 안 맞는 것이다. 빌드 스크립트가 자동으로 옛 SDK 로
물러서므로 보통은 안 보인다. 그래도 나면 Visual Studio Build Tools 2022 를 깐다.

## 되돌리려면

```powershell
# 확장 끄기 (그 DB 에서만)
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' <주소> -c 'DROP EXTENSION vector CASCADE'

# 파일 지우기 — 관리자
Remove-Item 'C:\Program Files\PostgreSQL\17\lib\vector.dll'
Remove-Item 'C:\Program Files\PostgreSQL\17\share\extension\vector*'

# 엔진만 끄려면 .env 에서 EMBEDDING_BACKEND=off
```

`CASCADE` 는 `search_chunks` 표를 함께 지운다 — 그 표에는 색인뿐이라 원본은 안 없어진다.

## 백업·서버 이전에 미치는 영향

확장을 켠 DB 의 덤프에는 `CREATE EXTENSION vector` 가 들어간다. 그래서 **복원 대상
기계에도 pgvector 가 먼저 설치돼 있어야** 한다 — 서버를 옮길 때 순서는
「pgvector 설치 → 복원」이다. 같은 기계에서 도는 복구 리허설은 영향이 없다.

## 왜 이렇게 나눠 놨나

- **표를 마이그레이션이 안 만든다.** `vector` 열은 확장이 있어야 만들어지므로,
  마이그레이션에 넣으면 확장을 아직 안 넣은 서버에서 `alembic upgrade` 가 통째로
  실패한다. 검색의 곁가지 때문에 릴리스가 못 나가는 것은 균형이 안 맞는다.
- **배포가 이 설치를 안 부른다.** 매 배포가 1GB 모델을 받게 하면 배포가 몇 분씩
  길어지고, 인터넷이 잠깐 막힌 날 배포가 실패한다.
- **엔진이 죽어도 검색은 산다.** 「비슷」 은 트라이그램만으로 계속 돌고, 화면이
  꺼져 있다고 말한다 — 안 말하면 사람이 「왜 이건 안 나오지」 를 데이터 탓으로 돌린다.

설계 근거는 [[계획] 전체 검색](%5B%EA%B3%84%ED%9A%8D%5D%20%EC%A0%84%EC%B2%B4%20%EA%B2%80%EC%83%89.md)
에 있다.
