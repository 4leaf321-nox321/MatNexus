# 65 참조 지도

66에서 무언가를 만들기 직전에 **65의 어디를 열어볼지** 알려주는 색인.

65는 `cae-material-platform` (`github.com/pikachu444/cae-material-platform`).
로컬 최신 사본은 `f:\data\0_Program\65_MaterialCenter\cae-material-platform_ver0821`
(기준 `fa75a136`, 2026-08-21, 493커밋).

---

## 이 문서를 읽는 법

65는 **엔지니어링 파이프라인이 깊고 제품 껍데기가 얇습니다.** 66은 반대로 시작했습니다 —
`matcore` 레지스트리, `auth`/`accounts`/`workspaces`, CI, `AppError`, 생성 타입이 이미 있습니다.

그래서 65에서 가져올 것은 **코드가 아니라 대부분 "도메인 지식과 계약"** 입니다.
파일을 통째로 복사할 일은 거의 없고, **무엇을 어떤 순서로 물어야 하는가**를 읽어오는 쪽입니다.

세 종류로 표시했습니다.

| 표시 | 뜻 |
|---|---|
| 🟢 **캘 것** | 66에 없고, 만들 때 반드시 먼저 볼 것 |
| 🟡 **참고** | 66에 이미 있음. 경계 조건·예외 처리만 대조 |
| 🔴 **가져오지 말 것** | 65의 알려진 실패. 반복하면 손해 |

## 2. 단위 — `matcore/units.py` 넓힐 때

**가져올 개념 둘**

**① 3중 보존.** 값 하나에 다섯 칸을 씁니다.

```

original_unit_string "MPa"          원본 단위 텍스트 (버리면 영원히 못 되살림)
```

## 3. 곡선 메타데이터 계약 — 차트를 만들 때

🟢 **65에서 가장 잘 만든 계약 중 하나**입니다. 66의 `shared/curvedata.py`를 넓힐 때 참조하세요.

```
contracts/  (curve metadata contract 1.0.0)
apps/web/src/curve-contract.ts          프론트가 이것을 어떻게 소비하는지
```

핵심은 **서버가 표시 방법까지 내려준다**는 것입니다.

```
채널마다:  axis_role(independent/dependent/auxiliary) · quantity_semantics
          original_unit · normalized_unit · display_unit
          display_scale · display_offset      ← 프론트는 곱하기만 한다
편차:      standard_deviation · standard_error · confidence_bound
          prediction_bound · tolerance_bound · quantile
          median_absolute_deviation · interquartile_range
          range_bound · coefficient_of_variation
          + method_id · method_version · ddof · confidence_level · coverage
```

**단위 변환 로직이 클라이언트로 새지 않습니다.** 프론트의 `displayCurveValue()`가

몰라도 됩니다.

편차 종류를 10가지로 나눈 것도 그대로 쓸 만합니다 — "표준편차"와 "신뢰구간"과 "예측구간"은

## 6. 불변성과 계보 — 저장 구조 정할 때

66의 ADR 0007(원본과 처리결과 저장 구조)과 CLAUDE.md의 *"불변과 가변을 섞지 않는다"* 가 이미
같은 방향입니다. 65는 **훨씬 강하게** 갔습니다.

### 🟡 참고할 것 — 리비전 커널

```
65: backend/src/cmp/shared/domain/revisions.py      245줄
```

모든 자원이 **안정 정체성 + 불변 리비전** 쌍입니다.

```
<name>            id · current_revision_id · created_at/by
<name>_revision   revision_no · based_on_revision_id
                  schema_id · schema_version
                  content_hash CHAR(64)          ← SHA-256
                  request_id · trace_id           ← 어느 요청이 만들었는지
```

**볼 가치가 있는 건 `canonical_json_bytes()`** 입니다. 해시가 재현되려면 직렬화가 결정적이어야
하는데, 규칙이 명시돼 있습니다 — 키 정렬, 공백 제거, **비유한 수 거부**, UUID·datetime·Decimal은
**도메인 코덱이 명시적으로 매핑**(암묵 변환 금지).

66이 곡선·처리결과·모델 파라미터·카드를 불변으로 둔다면, **해시를 뜰 때 이 함정을 그대로
만납니다.** Decimal을 float로 바꾸는 순간 해시가 달라집니다.

다만 **65처럼 전면 리비전화할 필요는 없습니다.** 66의 "라벨 하나 바꿨다고 리비전이 찍히면
안 된다"가 더 나은 판단입니다. 65는 그 구분이 없어 리비전이 폭증했습니다.

## 7. AI 검색 — 나중에 붙일 때

🟢 **65에 없습니다.** 다만 65의 자료 구조가 이 문제를 쉽게 만들어 줍니다.

66이 검색·임베딩을 붙일 때, **스키마별 추출기를 만들지 마세요.** 타입을 아니까 추측 없이
텍스트를 만들 수 있습니다.

```
number 값   → "인장강도 350 MPa"     (quantity_semantics + 정규화값)
discrete    → 속성 라벨 + 값
curve       → 채널명 · 범위 · 점 수
정의        → 라벨 · 도움말 텍스트
```

청크에 **위치 메타를 달아** 두면 검색 스니펫·점프·RAG 인용이 같은 토대를 씁니다.

> 참고 구현 — ReportArchive `backend/app/widgets/text_extraction.py`
> (`~/projects/ReportArchive`, WSL). content JSON을 재귀로 훑어 사람이 읽는 문자열만 모으고,
> `_SKIP_KEYS`로 노이즈를 거릅니다. 다만 그쪽은 **추측**해야 하고 66은 타입을 압니다.

순서는 **추출 계층 → 키워드 검색(pg_trgm) → 임베딩(pgvector)**.

한국어는 stock PostgreSQL에 형태소 분석기가 없어 ReportArchive가 **trigram**을 택했습니다
(`'보고서'`가 `'보고서를'`에 걸리도록). 형태소 분석기 도입 없이 해결한 실전 사례입니다.

## 8. 가져오지 말 것 🔴

### 익명 409

65 API 어댑터 34개가 전부 같은 패턴입니다.

```python
except Exception as error:
    raise _translate(context, error) from error
```

그리고 `_translate`의 마지막 분기가 **알려지지 않은 모든 예외를 409 + 로그 없음**으로 바꿉니다.
`ValueError`는 422 "입력이 잘못됐습니다"로 갑니다 — **코드 버그가 사용자 잘못처럼 보입니다.**

```
except Exception   332 (08-12) → 346 (08-20)   계속 늘고 있음
그중 로깅 없음      273
```

테스트 84,139줄이 통과하는데도 실제로 쓰면 정체불명의 409가 나오고 로그가 없는 이유입니다.

**66은 이미 막았습니다** — CLAUDE.md의 *"오류 본문을 라우트에서 직접 만들지 않는다.
`AppError` 계열을 raise 한다 — 응답을 만드는 경로가 곧 로그를 남기는 경로여야 한다."*
이 규칙이 왜 필요한지 궁금하면 65가 살아 있는 반례입니다.

| Plan 목록·상세 | 있음 | 없음 |
| 승격 경로 | `…/tabulated-plasticity-models` | `…/promotions` |
| 진단 | `diagnostics-preview` | `diagnostics` |
| Holdout | 5 ops | 없음 |

66의 `@register(...)` 레지스트리가 이 문제의 답입니다. **65에서 계산식만 읽어오고 슬라이스
구조는 절대 따라가지 마세요.**

### 전역 CSS

65 프론트: 전역 클래스 1,043개를 화면 파일 29개가 공유. 커스텀 CSS 20,092줄
(`styles.css` 8,140 + `design/layout.css` 8,641 + 기타). 한 화면 수정이 다른 화면으로 파급됩니다.

65도 `#249`로 재정비 중이지만(FE-00~FE-09, 현재 FE-06), `styles.css`는 **아직 한 줄도 안 줄었고**
`layout.css`는 오히려 +1,034줄 늘었습니다. 스코프 CSS를 위에 얹기만 하고 전역에서 빼내지
못한 상태입니다.

### 스크린샷 1,666장 + 픽셀 회귀 0건

65는 다섯 뷰포트(1366/1440/1920/2560/3840) 캡처를 승인 게이트로 요구합니다. Playwright로
자동 캡처는 하는데 **`toHaveScreenshot`/`toMatchSnapshot` 사용이 0건**입니다.

즉 사람이 1,666장을 눈으로 봐야 하고, 실제로는 아무도 다 보지 않습니다. **"확인했다는 증거"가
아니라 "확인할 기회가 있었다는 알리바이"** 가 됩니다.

66은 픽셀 회귀를 **자동 비교로** 넣으세요. 달라진 것만 실패로 뜨면 2~3장만 보면 됩니다.
스코프 격리된 CSS가 전제입니다 — 안 그러면 오탐이 계속 납니다.
