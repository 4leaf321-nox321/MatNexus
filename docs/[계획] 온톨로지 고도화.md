# [계획] 온톨로지 고도화 — 이 안의 자료를 어떻게 더 읽히게 하나

2026-09-16. **MatNexus 에 이미 들어 있는 자료**(재료·시험·물성값·문헌·장비·의뢰)의
온톨로지를 어떻게 고도화할지의 계획이다. 대 본 것은 둘 — 「그룹의 모든 자료를 온톨로지화
한다」 는 물음에 대한 조언(Core → Domain → Instance → Evidence → Document 의 5층, 관계
20~40개, 그래프+RAG 두 축)과, 온톨로지가 더 진하게 구성된 **StandardPlatform(SP)** 의
설계. SP 는 **참조**다 — 별도 시스템이고 잇지 않는다. 그쪽에서 값을 치른 판단만 빌린다.

지금까지 한 것은 [[계획] 온톨로지](%5B계획%5D%20온톨로지.md)·ADR 0028 에 있다(마디 17 ·
관계 19 · 물성 사전 · 값 검색 · 트래버설 · MCP). 이 문서는 그 다음이다.

> 한 줄 결론: **도메인 층은 이미 진하다. 빠진 것은 「값이 어느 문서 어디에서 왔나」 를 담는
> 근거(Evidence) 층이고, 그것을 기르는 거버넌스(후보 → 승인, 품질을 세는 것)다.** 새 표를
> 갈아엎지 않고, 마디에 근거를 **잎으로 매단다.**

---

## 0. 결정된 것 (2026-09-16)

| 물음 | 결정 |
| --- | --- |
| SP 와 하나로 갈까 | **아니다.** SP 는 별도 시스템, 참조만 한다. 이 계획에 SP 연동은 없다 |
| 범위 | **MatNexus 안의 자료.** 과제·회의록·PPT 같은 업무 문서 일반은 이 계획 밖 |
| 추출기(문서에서 값을 뽑는 AI) | **서버 밖에서 돈다.** 사내 승인 모델이 있지만 이 서버에서는 못 부른다. 사람 + 사내 AI 가 밖에서 만든 **묶음**을 붙여넣기·파일로 올리고, 서버는 검증·미리보기·적용만 한다(부서 정보 가져오기와 같은 모양). 서버 안 AI 는 Ollama 임베딩(찾기)까지 |
| 근거 강제 | **막지 않고 센다.** 홈 「남은 일」 에 「근거 없는 값 N」 |

## 1. 문서가 MatNexus 자료를 보강하는 자리 — 있나?

있다. 다만 **회의록이 아니라 「시험이 주지 않는 값」 이 들어오는 문서**다. 실측(개발 DB):

| 자리 | 지금 | 근거는 |
| --- | --- | --- |
| 카탈로그 문헌값 | **42,209건**, 출처 3,013(논문 1,272 · 데이터시트 1,165 · DB 314 · 책 77 …) — MaterialTwin 이관 | 출처(어느 논문)는 있고 **어느 페이지·표**인지는 없다 |
| 선언 물성(ADR 0016) | 시험으로 못 얻는 값을 데이터시트에서 옮겨 적음 | `source_ref` 글자 한 줄 |
| 문헌 모델 파라미터(ADR 0029) | `material_parameter_sets.source_ref/source_detail` | 글자 |
| 앞으로 — 외주 시험 성적서 | 측정 의뢰(v1.234)가 외부 기관에 나가면 결과가 **PDF 성적서**로 온다 | 아직 자리 없음 |
| 앞으로 — 교정 성적서 | `equipment_calibrations` 4건 | 자리 없음 |

즉 MatNexus 의 문서는 조언이 말한 「모든 자료」 가 아니라 **값을 실어 오는 문서** 넷이다
(논문·데이터시트·성적서·교정서). 회의록·PPT·설계변경서는 여기 것이 아니다. 그래서 문서
파이프라인은 SP 처럼 크지 않고, **「값 + 어느 문서 몇 페이지」 를 한 번에 넣는 길** 하나면
된다(§2-D).

## 2. 더할 것

### A. 근거(Evidence) 층 ★ 핵심

조언의 그림을 MatNexus 말로 옮기면 — 측정값은 이미 사슬이 있고, 문서에서 온 값은 끊겨 있다:

    SECC (material)
      ─ has_card ─▶ 카드 · 블록 「인장」                    ← 있다
      ─ adopted ──▶ 처리 결과 (채택)                        ← 있다
      ─ processed_from ─▶ 시험 #132 ─ tested ─▶ 시편         ← 있다
      ─ 시험 파일 해시 → filestore                          ← 있다
    항복강도 = 280 MPa @ 23 °C                               ← 값·조건 있다
    선언 물성 「밀도 7.85」 → source_ref "포스코 카탈로그 2024"  ← 글자뿐
    문헌값 「E = 210 GPa」 → catalog_sources #1187           ← 논문은 알고 페이지는 모른다

만들 것:

| 무엇 | 모양 |
| --- | --- |
| `documents` | 문서 파일(PDF·xlsx·pptx·docx). `sha256` · `kind`(datasheet · paper · test_report · calibration · other) · 제목 · 부서 소유 · 올린 사람. **장비 원본과 같은 파일스토어, 다른 표** — 장비 파일은 시험 하나에 매달리고 문서는 여러 마디에 매달린다. `catalog_sources` 는 그대로 두고 `document_id` 로 잇는다(논문 PDF 가 있으면) |
| `evidence` | `(kind, entity_id)` — 레지스트리의 마디 어디든 — `document_id` · `locator`(JSONB: `page` / `sheet`·`cell` / `table`·`row` / `bbox`) · `quote`(발췌) · `extractor`(사람 · 모델 이름 · 스크립트) · `confidence` · `extracted_at` · `note`. **관계에도 붙는다**(`kind='edge'`) — 「같은 물성이다(`same_as`)」 의 근거 |
| 값 옆에 「근거 N」 | 선언 물성·문헌값·모델 파라미터 화면. 누르면 문서와 위치. 없으면 「근거 없음」 을 **회색으로 말한다** |
| `search_chunks` 에 `locator` | 문서 조각(`kind='document'`)이 페이지·시트를 안다 → 의미 검색 결과가 **곧 근거 후보**. 「이 값 어디 있더라」 를 조각이 답한다 |
| MCP `get_evidence(kind, id)` · `get_source(document_id, locator)` | `related` 가 찾고 `get_evidence` 가 원본으로 내려간다. 조언 §9 의 도구 둘 |
| 구조 시험 | 마디마다 근거를 붙일 수 있는지 · 끊어진 `document_id` 가 없는지(다형 참조라 FK 가 없다 — 기준정보 어긋남 검사와 같은 자리) |

**하지 않을 것**: 문서 본문을 마디로 넣는 것([계획] 온톨로지 §1-④). 근거는 **마디에 매달린
잎**이지 마디가 아니다. 그래프는 크기가 그대로다.

### B. 계산의 계보 — 근거의 다른 얼굴

ADR 0030 으로 계산식이 행이다. 그런데 **계산된 값이 어느 식과 어느 입력에서 나왔는지**는
관계로 안 잡혀 있다. 둘을 더한다:

    computed_by   카드 블록 값 → 계산식        (식 실행 기록이 있으면 fk, 없으면 근거 표에)
    input_of      카드 블록 값 → 계산식 실행

「이 값 어디서 왔어」 에 측정이면 시험으로, 계산이면 식과 입력으로, 문헌이면 페이지로 —
세 갈래가 **같은 도구(`get_evidence`)** 로 답한다.

### C. 관계 레지스트리 — 19 → 30 안쪽에서 멈춘다

조언 §7(초기 20~40)과 실측(19)이 맞는다. 후보와 판정:

| 후보 | 판정 | 근거 |
| --- | --- | --- |
| `computed_by` · `input_of` | **넣는다** | §B |
| `evidenced_by`(마디→문서) | **관계가 아니라 근거 표**(§A) | 관계로 두면 마디마다 잎이 수십 개 뻗어 그래프가 문서로 뒤덮인다 — 사람·부서 FK 를 뺀 것과 같은 판단 |
| `ran_with`(처리 결과→레시피) | **넣는다** | 「이 레시피로 돌린 결과들」 을 AI 가 물었다([§8-①]). FK 가 있어 값이 싸다 |
| `requested_by`(시험→측정 의뢰 항목) | **넣는다** | `test_runs.commission_item_id`(v1.234). 「이 의뢰에서 나온 값」 이 곧 질문 |
| `calibrated`(장비→교정) | 보류 | 장비 6 · 교정 4 — 자료가 먼저. 교정 성적서가 `documents` 로 들어오면 그때 |
| `member_of`(재료→구성체) | 보류 | ADR 0026 은 초안, 표가 없다 |
| 사람·부서·감사 FK | 계속 뺀다 | — |

`entity_edges`(5단계)는 **여전히 안 만든다** — 넣는 것 전부 FK 나 연결 표가 있다.

### D. 문서 → 값 묶음 — 서버 밖에서 만들고, 서버는 검증·미리보기·적용

추출 AI 가 서버에 없으니 길은 이것뿐이고, 그래서 오히려 단순하다. SP 의 `preview → apply`
(미리 본 지문과 같을 때만 적용, 전부 아니면 무)와 부서 정보 붙여넣기(v1.241)의 모양을 합친다.

    [밖]  사람이 데이터시트·논문·성적서를 사내 AI 에 보이고
          정해진 형식(CSV/JSON)으로 받아 낸다:
            재료 · 물성 · 값 · 단위 · 조건 · 문서 · 페이지/표 · 발췌 · 확신도
    [안]  재료 상세 > 「문서에서 값 넣기」 — 붙여넣기 칸 + 문서 PDF 올리기
          → 미리보기: 이름 해소(물성 사전) · 단위 환산 · 조건 정규화 · 재료 매칭 결과를 줄마다
            (「항복응력 → yield_stress 로 읽음」 「단위 없음 — 거절」 「재료 못 찾음」)
          → 적용: 값은 `status=proposed` 로, 근거 행과 문서가 함께 들어간다
          → 승인(부서 관리자)하면 카드·검색에 보인다

| 규칙 | 왜 |
| --- | --- |
| **단위 없는 값은 받지 않는다** | 값 검색과 같은 원칙 — 짐작해 넣으면 조용히 틀린다 |
| 이름 해소 실패는 **거절이 아니라 후보**(§E) | 「UTS」 가 사전에 없으면 그 줄은 미해결로 남고, 나머지는 들어간다 — 부서 가져오기와 같은 판단 |
| 승인 전엔 검색·카드에 안 보인다 | 보이면 그 순간 정본이 된다 |
| 형식은 하나 | 사내 AI 지시문(붙여 넣을 프롬프트)을 **가이드 문서로 서버가 쥔다** — SP 의 「사내 AI 지시문」 과 같은 발상. 사람마다 다른 형식으로 받아 오면 파서가 늘어난다 |

이것이 **MatNexus 의 문서 파이프라인 전부**다. 회의록·PPT 는 없다.

### E. 거버넌스 — 후보를 쌓고 사람이 확정한다

| 길 | 지금 | 더할 것 |
| --- | --- | --- |
| 이름 해소 실패(`resolve_property` 빈손 · 묶음의 미해결 · 의미 검색이 빈손일 때 친 말) | 아무 데도 안 남는다 | `alias_candidates`(term · property · material 공용)에 쌓는다. 관리자가 승인하면 `term_aliases` / 물성 사전 별칭으로. 홈 「남은 일」 에 「해소 못 한 이름 N」 |
| 문서에서 온 값 | 없음 | §D 의 `proposed` 상태 |
| 관계 종류 추가 | 코드 PR | 그대로 — **관계 종류는 사람이 코드로**(조언 §5 「Core 는 거의 수동」) |
| 근거 없는 값 | 조용히 있다 | 품질 보고(§F)에 센다. **막지 않는다** — 막으면 사람이 가짜 근거를 적는다 |
| 모델링 규약 | 없음 | MCP 가이드에 「무엇을 마디로 · 속성으로 · 관계로」 「관계는 30개까지」 「사람·부서 FK 는 온톨로지가 아니다」 「단위 없는 값은 값이 아니다」 — `get_guide(topic="modeling")`. SP 가 서버가 규약을 쥐게 한 것과 같은 판단 |

### F. 품질을 센다 — 홈 「남은 일」

[§8-④] 의 숫자(값이 안 붙은 출처 102 · 값 없는 문헌 재료 3 · 시험 찌꺼기 재료 2 · 같은 값 묶음 5)
를 지금은 사람이 SQL 로 센다. `ontology/quality.py` 가 **매번 세고**, 시스템·부서 관리자의
홈에 올린다(SP 의 `register_maintenance` 판단 — 못 고치는 사람에게 띄우면 못 지우는 숫자다).
여기에 §A 의 「근거 없는 선언 물성·문헌값 N」, §E 의 「해소 못 한 이름 N」 이 더 선다.
**세지 않는 숫자는 줄지 않는다.**

### G. 조건을 질의가 안다

값 검색은 이름·단위·범위를 안다. **조건(온도·변형률속도·주파수)** 은 `shared/conditions.py`
가 정규화해 블록에 두지만 질의 도구에는 없다. `find_by_property(..., conditions=
{"temperature": {"near": 80, "unit": "degC"}})` — 「80 °C 에서의 항복강도」 를 AI 가 찾는다.
조건은 마디가 아니라 **값의 한정자**다.

### H. 평가 — 「AI 가 찾나」 를 숫자로

[§8-③] 그대로, 이번엔 **먼저** 한다. 물음 30개(순회 · 조회 · 값 · 근거 · 조건) + 답에 반드시
있어야 할 것 + 도구 자취 채점(호출 수 · 지도 봤나 · 빈손 호출 · 기대 사실 포함). CI 에는 안
넣고 릴리스 전 추세로. 이것이 없으면 아래 단계마다 「나아졌나」 를 10분씩 transcript 로 읽는다.

### I. MCP — 도구 수를 줄이지 말고 들머리를 좁힌다

57도구는 도메인이 진한 값이다. 다만 조언 §9 와 SP 의 실측(도구가 길수록 엉뚱한 것을 고른다)
을 받아 **온톨로지 도구 8개를 가이드 첫 줄에**:

    get_ontology · search_all · resolve_property · find_by_property
    related · find_path · get_evidence · get_source

나머지는 그 아래 층(레시피가 가리킨다). 도구를 합치는 것은 §H 가 「같은 물음에 호출 수가
준다」 를 보인 뒤에.

## 4. SP 에서 빌린 판단 — 코드가 아니라 결정

| SP 의 것 | 여기서 |
| --- | --- |
| 원 표를 복제하지 않고 투영한다(`system` 타입) | 재료·시험을 일반 객체(JSONB)로 옮기지 않는다. 마디는 그대로, 근거만 잎으로 |
| `preview` 지문과 같을 때만 `apply`, 전부 아니면 무 | §D 묶음 |
| 파이프라인의 `_source` · `_confidence` · `unresolved` | §A 근거 표에 **저장한다**(SP 는 떼어 버린다 — 그쪽 계획서도 「출처를 담을 자리」 가 열린 질문) |
| 품질 보고 → 홈 「남은 일」, 못 고치는 사람에게는 안 띄움 | §F |
| 별칭 · 합치기 · 동의어 사전은 그룹이 키우는 자산 | §E 후보 큐 |
| 규약을 서버가 쥔다(`get_guide(topic="modeling")`), 사내 AI 지시문을 문서로 | §E · §D |
| 타입마다 도구를 만들지 않는다 | §I — 도구를 늘리지 않고 들머리를 좁힌다 |
| 그래프 그림의 상한(fanout · 「+N」) | (뒤) 관계도 때 |

빌리지 않는 것: 메타모델(타입·속성을 데이터로) — 이 안의 자료는 표가 제 형태를 이미 갖고
있다. 웹훅 · 지켜보기 · 코드표 승격 · 데이터 소스 동기화 — 온톨로지가 아니거나 기준정보가
이미 그 일이다.

## 5. 하지 않을 것

- 표를 일반 객체로 옮기지 않는다. 있는 것(유일제약·리비전·권한·소프트삭제)을 전부 잃는다.
- 서버 안에서 LLM 으로 값을 뽑지 않는다 — 부를 모델이 없고, 있어도 타입·관계 종류는 사람이 만든다.
- 관계 종류 30개를 넘기지 않는다. 넘길 것 같으면 근거 표나 속성으로 내린다.
- 근거 없는 값을 막지 않는다 — 센다.
- 문서 본문을 마디로 넣지 않는다. 마디는 작고 안정적이고 권한이 안 붙는 것.
- RDF/OWL/그래프 엔진 — 방아쇠([계획] 온톨로지 §1-③)가 안 당겨졌다.
