# MatNexus → Standard Platform: 물성 목록 연동

물성 목록의 정본은 MatNexus 다([ADR 0054](adr/0054-물성-목록의-정본은-MatNexus-다-분류를-여기서-세우고-SP-가-읽어-간다.md)).
Standard Platform(SP)은 **데이터 소스 셋**으로 밤마다 읽어 간다 — SP 「외부 시스템 ↔ Standard Platform 연동
지침서」 §3 의 방향(그쪽이 만들 것 ① — SP 가 읽어 갈 API)이고, MatNexus 가 그 「그쪽」 이다.

| 무엇 | 어디 |
| --- | --- |
| 물성 분야 | `GET /api/catalog/feed/fields` |
| 물성군 | `GET /api/catalog/feed/groups` |
| 물성(문헌 + 사내) | `GET /api/catalog/feed/properties` |
| 토큰 | MatNexus 「내 정보 → 액세스 토큰」 에서 **읽기 전용**으로 발급 |
| 분류를 고치는 곳 | MatNexus 「물성 분류」 화면(자료 관리자) — **SP 에서 고치지 않는다** |

## 1. SP 데이터 소스 설정

셋 다 같고 `path` 만 다르다.

| 칸 | 값 |
| --- | --- |
| 종류 | `rest` |
| base_url | `https://<MatNexus 주소>/api` |
| path | `catalog/feed/fields` · `catalog/feed/groups` · `catalog/feed/properties` |
| rows_path | `items` |
| paging | `page` (`page_param=page` · `size_param=page_size` — 기본값 그대로) |
| page_size | `500` — **1000 까지**. 넘게 달라면 깎지 않고 422 로 거절한다(깎아 주면 SP 가 끝으로 읽는다) |
| 인증 | `bearer` — 읽기 전용 토큰(`mnx_pat_…`) |
| 바깥 식별자 열 | `key` |

정렬은 늘 `key` 차례다. 같은 요청은 같은 답이다.

## 2. 열

**열 이름은 바꾸지 않는다. 늘리는 것은 자유다**(지침 §3.2). 시각은 UTC `Z`(§12-A ⑧). 여럿인 값은 `;` 로
잇는다 — SP 가 여러 값을 가르는 글자다.

### 물성 분야 (`fields`)

| 열 | 뜻 |
| --- | --- |
| `key` | 안 바뀌는 식별자. 씨앗 열둘은 키 앞머리(`mechanical` …), MatNexus 에서 만든 것은 `pf-0001` 꼴이거나 만든 사람이 준 것 |
| `name` | 이름 — 고쳐질 수 있다 |
| `description` | 설명 |
| `sort_order` | 화면 차례 |
| `group_count` · `property_count` | 쓰는 중인 물성군 수 · 든 물성 수 |
| `status` · `is_active` | `active` · `deprecated`(폐기) / 참 · 거짓 |
| `deleted` | 폐기했으면 참 — **SP 가 실제로 읽는 칸**(아래 「폐기는 `deleted` 로 간다」) |
| `updated_at` | 마지막으로 바뀐 때 |

### 물성군 (`groups`)

| 열 | 뜻 |
| --- | --- |
| `key` | 안 바뀌는 식별자(`pg-0001` 꼴이거나 준 것). **다른 분야로 옮겨도 그대로다** |
| `name` · `description` · `sort_order` | |
| `field_key` · `field_name` | 든 분야 — SP 의 「물성 분야」 와 잇는 열 |
| `property_count` | 든 물성 수 |
| `status` · `is_active` · `deleted` | 분야가 폐기됐으면 군도 `deprecated` · 거짓 · 참 |
| `updated_at` | 군이나 그 분야가 마지막으로 바뀐 때 |

### 물성 (`properties`)

| 열 | 뜻 |
| --- | --- |
| `key` | 허브 키 — 안 바뀐다. 문헌은 `domain.name`, MatNexus 에서 만든 것은 `local.` 으로 시작한다 |
| `name` · `symbol` | 이름 · 기호 |
| `unit` | 원본 표기 그대로(`kg/m^3`). 환산하지 않는다 |
| `value_type` | `numeric` · `vector` · `categorical` · `boolean` |
| `description` | 정의문 — 이 물성이 무엇인가(ADR 0050) |
| `test_standard` | 대표 시험 규격 |
| `condition_axes` | 조건 없이는 무의미해지는 축(`temperature_k;frequency_hz`) |
| `origin` | `literature`(문헌) · `local`(사내) |
| `domain` | 키 앞머리 — **분류가 아니다**(분류는 아래 넷) |
| `group_key` · `group_name` · `field_key` · `field_name` | 든 물성군 · 분야. 아직 군에 안 들었으면 비었다 |
| `aliases` | 다른 이름들(`;`) — SP 의 별칭 칸에 잇는다 |
| `status` · `is_active` · `deleted` | `active` · `deprecated` / 폐기된 키는 거짓 · 참 |
| `superseded_by` · `deprecation_note` | 폐기된 키면 대신 쓸 키와 사유 |
| `updated_at` | 정의 · 소속 · 군 · 분야 · 별칭 중 가장 늦게 바뀐 때 |

## 3. 칸 대응 (SP 화면에서)

| MatNexus 열 | SP 칸(데이터 소스 대화상자) | 비고 |
| --- | --- | --- |
| `key` | ① 「바깥 식별자 열」 | SP 는 적용한 뒤 `source:<slug>` 별칭으로 기억한다 |
| `name` | ② 「이름 열」 | |
| `description` | ④ 「설명 열」 | |
| `aliases` | ④ 「다른 이름(별칭) 열」 | 물성만 |
| `field_key` | ③ 속성 — 「물성 분야」 를 가리키는 객체 참조 속성 | 물성군 소스. 관계(선)로 잇고 있으면 아래 |
| `group_key` | ③ 속성 — 「물성군」 을 가리키는 객체 참조 속성 | 물성 소스. 관계(선)로 잇고 있으면 아래 |
| 나머지 | ③ 속성 `properties.<칸>` | 필요한 것만 — 모르는 열은 무시된다(§12-A ⑦) |

**객체 참조 속성이 아니라 관계(선)로 잇고 있으면** 같은 주소로 소스를 하나 더 만들어 「무엇을 가져오나」 를
「선(관계)」 으로 두고, 「관계 종류」 · 「출발점 열」(`key`) · 「도착점 열」(`group_key` 또는 `field_key`)을 고른다.
「넣을 타입」 은 관계의 출발 타입이다. 관계가 「하나만」(N : 1)이면 물성이 다른 군으로 옮겨질 때 그 실행이 오류로
선다 — 끊고 다시 잇는 순서를 SP 가 안 세운다.

### 폐기는 `deleted` 로 간다

SP 의 데이터 소스는 **`status` 를 칸 대응에 올리지 못한다**(대상이 key · 이름 · 설명 · 별칭 · 속성뿐이다). 대신
`deleted: true` 인 행을 「사라진 것」 으로 보고 그 객체를 사용 중지로 바꾼다 — 그래서 폐기한 분야 · 군 · 키는
`deleted: true` 로 나간다. 그 행의 다른 칸은 SP 가 읽지 않는다. 「외부에서 삭제된 행은 「사용 중지」 로 표시」 는
**켤 필요가 없다** — 이 목록은 행을 빼지 않는다.

## 4. 첫 적재

1. **(운영 SP 에 분류가 이미 있으면) MatNexus 로 먼저 밀어 넣는다.** SP 의 타입 목록(`/o/<타입>`) 오른쪽 위
   「내보내기」 로 물성 분야 · 물성군 · 물성을 CSV 로 받는다(관계로 잇고 있으면 「관계 CSV」 도). 엑셀에서
   `분야 | 물성군 | 물성 | (분야 키) | 물성군 키` 로 엮어 MatNexus 「물성 분류 → 밀어 넣기」 에 붙인다.
   - **분야 키는 비운다.** 기본 분야(기계 · 열 …)는 키가 키 앞머리라, 다른 키를 주면 이름이 겹쳐 걸린다. SP 의 분야
     이름이 기본 분야 이름과 다르면 MatNexus 에서 기본 분야 이름을 SP 의 이름으로 먼저 고친다.
   - 물성군 키에 SP 의 키를 실으면 두 시스템의 물성군 키가 같아진다(선택).
   - 미리 보기의 「새로 생기는 분야」 는 이름이 기존 분야와 한 글자라도 다른 것이다 — 고친 뒤 넣는다. 「키 앞머리와
     다른 분야로 가는 물성」 은 이름이 같아도 뜻이 다른 것일 수 있다(「항복응력」 은 유변학 물성이다).
2. **SP 는 첫 연동에서 이미 있는 객체를 이름으로 찾는다** — 그 타입 안에서 이름 · 별칭이 **하나에만** 맞아야
   하고, 둘 이상이면 그 행이 오류다(오류가 하나라도 있으면 그 실행은 아무것도 안 넣는다). 그래서 MatNexus 의 분야 ·
   물성군 · 물성 이름이 SP 와 같아야 하고, SP 쪽에 이름이 겹친 객체가 없어야 한다. 한 번 적용되면 우리 키를
   별칭(`source:<slug>`)으로 기억해 그 뒤로는 키로 찾는다.
3. **「우리 식별자(key)로도 쓴다」 는 끈다** — 이름으로 찾은 SP 객체의 키를 **우리 키로 바꾼다.** 두 시스템의 키가
   같을 때(예: 물성군 키를 SP 키로 밀어 넣었을 때)만 켠다.
4. **분야 → 물성군 → 물성 차례로** 소스를 만들고 차례로 손으로 「동기화」 한다 — 앞의 것이 있어야 참조가 풀린다.
5. 전량 한 번 → **건수 · 표본 대조** → 주기 켜기(지침 §12-A ⑤). 대조할 건수: `total` 이 그대로 답이다.

### SP 쪽에서 걸리는 것 (SP 코드로 확인, 2026-10-03 — 고치지 않고 적어 둔다)

- **「몇 분마다」 를 0 보다 크게 두면 타이머가 계획과 적용을 한 번에 한다** — 사람이 계획을 안 본다. 새 소스는
  만들자마자 기한이 찬 것으로 보여 5분 안에 적용된다. 첫 수동 실행을 확인할 때까지 0 으로 둔다. 시각을 정하는
  칸은 없다(1440 = 하루 한 번, 마지막 실행부터 센다).
- **새 소스에서 「미리 보기」 를 먼저 누르면** 소스가 저장된 채 대화상자는 「생성」 으로 남아, 이어서 「저장」 을
  누르면 「이미 있는 데이터 소스입니다」 가 난다. 칸을 다 채우고 「저장」 → 목록에서 「수정」 → 「미리 보기」 순서로 한다.
- 「선(관계)」 으로 두면 「저장」 이 바깥 식별자 열 · 이름 열을 요구하는데 그 칸이 안 보인다 — 「객체」 일 때 아무
  값이나 채운 뒤 「선(관계)」 으로 바꾼다.
- 쪽 크기 칸이 화면에 없고 500 으로 고정이다. MatNexus 는 1000 까지 받으므로 그대로 둔다.

| 점검 | 결과 |
| --- | --- |
| 인증 없이 부르면 막히나 | 401 |
| 읽기 전용 토큰으로 쓰면 막히나 | 403 `MNX-AUTH-0104` |
| 첫 쪽이 오나 | 분야 12 · 물성 271 |
| 행 자리가 늘 같은가 | `items` |

| 쪽을 다 넘기면 빠지거나 겹치나 | 100씩 3쪽 — 271 · 겹침 없음 |
| 마지막 쪽이 덜 차나 | 71 |
| 폐기한 것이 행으로 남나 | `status: deprecated` · `is_active: false` |

## 6. §12-B 양식 — 연동 전 교환할 것

지침의 양식은 SP 가 공개하고 다른 시스템이 받는 방향으로 적혀 있다. 여기는 거꾸로 **MatNexus 가 공개하고 SP 가
받는다** — 칸 이름을 그 방향으로 읽는다. **빈칸으로 남은 항목은 연동을 켜지 않는 사유다.**

**① 대상**

| MatNexus 공개 목록 | SP 수신 타입 | 식별자 대응 | 첫 적재 예정일 |
| --- | --- | --- | --- |
| `catalog/feed/fields` | 물성 분야 | MatNexus `key` ↔ SP 별칭 `source:<슬러그>` | |
| `catalog/feed/groups` | 물성군 | MatNexus `key` ↔ SP 별칭 `source:<슬러그>` | |
| `catalog/feed/properties` | 물성 | MatNexus `key`(허브 키) ↔ SP 별칭 `source:<슬러그>` | |

**② 시각과 실행**

| 것 | 값 |
| --- | --- |
| 야간 수신 시각 | (SP 가 정한다 — MatNexus 쪽 제약 없음) |
| 수동 실행 경로 | SP 데이터 소스 화면의 수동 실행 |
| 웹훅 | 미사용 |
| 재시도 | (SP 정책) |

**③ 코드값 (고를 값)**

| 목록 · 열 | 지금의 값 | 늘릴 때 알리는 사람 · 방법 | 유예 |
| --- | --- | --- | --- |
| 셋 다 · `status` | `active` · `deprecated` | MatNexus 플랫폼 개발자 → SP 담당 | |
| `properties` · `origin` | `literature` · `local` | 〃 | |
| `properties` · `value_type` | `numeric` · `vector` · `categorical` · `boolean` | 〃 | |
| `properties` · `domain` | `mechanical` · `thermal` · `physical` · `chemical` · `optical` · `electrical` · `interface` · `structure` · `rheological` · `magnetic` · `surface` · `acoustic` | 〃 | |

**④ 연락과 만료**

| 것 | 값 |
| --- | --- |
| 공개 측(MatNexus) 담당 | |
| 수신 측(SP) 담당 | |
| 토큰 만료일 | (읽기 전용 토큰을 발급할 때 정한다 — 만료 2주 전 재발급) |
| 열 변경 통보 | 열을 늘릴 때(이름은 안 바꾼다) — 공개 측 담당이 수신 측 담당에게 |
