# [계획] MCP 서버 — AI 가 MatNexus 를 직접 묻는다

2026-09-06. MaterialTwin 이식 5단계의 남은 항목. **참고 구현이 둘 있고 서로
반대편을 배운다** — 실측 조사해 필요한 쪽을 각각 가져왔다(아래 비교).

    MaterialTwin (MT)     물성 도메인 — **무엇을 도구로 낼까**에 답한다
    ReportArchive (RA)    운영 1년 — **어떻게 안전하게 굴릴까**에 답한다

## 왜 만드나

MatNexus 안에는 사람이 화면으로 캐기 어려운 것이 쌓여 있다 — 문헌 물성
42,209건, 측정법 750건, 시험 250여 건과 그 처리·카드. 화면은 "무엇을 볼지 아는
사람"에게 맞춰져 있고, **"SUS304 쓸 만한가", "이 BOM 으로 덱 뽑아 줘", "이 물성
어떻게 재?" 같은 질문은 화면 여러 장을 오가야** 답이 나온다.

MCP 는 그 질문을 AI 에게 맡긴다. MaterialTwin 도 MCP 서버를 갖고 있었지만
**무인증 단일 사용자 전제**라 그대로는 못 쓴다 — 우리는 계정·부서·권한이 있다.

## 두 구현 비교 — 무엇을 어디서 가져오나

| | MaterialTwin | ReportArchive | 우리 |
| --- | --- | --- | --- |
| 도메인 | **물성**(같다) | 보고서 | — |
| 인증 | **없음** — 단일 사용자 전제 | PAT 를 백엔드로 전달 | **RA** (D2) |
| 구조 | 웹앱에 `/mcp` 마운트 + stdio 겸용 | 별도 프로세스·별도 venv | **RA** (D1) |
| 데이터 접근 | DB 직접(`SessionLocal`) | REST 프록시 | **RA** (D6) |
| 도구 수 | 30(조회 22·쓰기 8) | 70 | 14로 시작 (D4) |
| 위험 도구 | 삭제를 **환경변수로 미노출** | 게시·삭제에 확인 토큰·조건 가드 | **양쪽** (D3) |
| 안내 | MCP **리소스**(`materialtwin://guide`) | 서버가 파일을 매 호출 읽음 | **양쪽** (D5·D7) |
| 값 응답 | **tier·출처·조건·불확도가 필수 필드** | (도메인이 달라 해당 없음) | **MT** (D8) |
| 그림 | PNG 반환(matplotlib) | 없음 | **안 함** (아래) |
| 프롬프트 | 워크플로 2종 | 없음 | **MT** (D7) |

**왜 이렇게 갈리나**: MT 는 무인증 단일 사용자라 「앱에 마운트 + DB 직접」 이
가장 짧은 길이었다. 우리는 계정·부서·권한이 있어 그 길을 가면 **권한 판정을 MCP
안에 다시 구현**하게 된다 — 규칙이 두 벌이 되는 순간 갈라진다. 그래서 뼈대는 RA,
**도구 설계와 응답 모양은 MT** 를 따른다.

**그림(PNG)은 안 한다.** MT 는 `plot_curve`·`plot_ashby` 로 이미지를 냈지만 우리
백엔드에는 matplotlib 이 없다(그래프는 프론트가 그린다). 도입하면 의존성이 늘고
서버가 그림을 그리는 새 책임이 생긴다 — 대신 **점 배열을 반환**하고 화면 링크를
함께 준다.

### MT 에서 배운 것 — 도구 설계

- **값에는 근거가 붙어 나간다.** `get_material_properties` 는 값마다
  `unit·conditions·uncertainty·method·quality_tier·source(title·doi·kind)` 를
  전부 싣는다. 우리 최대 위험(AI 가 tier4·합성값을 실측처럼 옮기는 것)에 대한
  답이 여기 있다 → D8.
- **화면과 MCP 가 같은 것을 말해야 한다.** MT 안내에 *"`valid=false` 는 웹에서
  제외한 이상치이므로 대표 물성으로 쓰지 말 것"* 이 박혀 있다 — 웹이 거른 값을
  LLM 이 유효 물성으로 오인한 실측이 있었다는 뜻이다. 우리 대응 목록: 채택 안 된
  처리 결과 · `draft` 카드 · tier4 · **합성 곡선** · 미확정 덱.
- **도구 설명에 함정을 적는다.** MT 의 `get_material_properties` 설명은
  *"물성이 많은 재료(최대 512건, 40만 자)는 반드시 `domain` 으로 좁혀 호출한다 —
  `property_key` 인자는 없으며 넣어도 무시된다"* 까지 적는다. RA 는 반대로 설명
  길이를 줄여 토큰을 아꼈다. **절충**: 자주 오용되는 도구만 길게 쓴다.
- **응답 크기를 도구가 스스로 막는다.** 상한(`limit≤200`)·다운샘플(LTTB)·
  도메인 필터. 우리도 곡선·목록에 같은 장치를 둔다.

## 참고한 실측 — ReportArchive 가 겪은 것

| 그쪽이 겪은 일 | 우리가 받을 판단 |
| --- | --- |
| `mcp` SDK 가 starlette·pydantic 을 올려 **FastAPI 와 같은 venv 불가** | 별도 프로세스·별도 venv (아래 D1) |
| 안내를 클라이언트 스킬에 뒀더니 **복사 안 한 사람에게 개선이 전달 안 됨** | 안내 본문을 **서버가 들고** 매 호출 읽는다 (D5) |
| 도구 46개 설명이 **매 요청 10,000 토큰 상주** | 도구 수를 절제한다 — 20개 안쪽으로 시작 (D4) |
| 로그인 세션 JWT 는 12시간이라 **하루 두 번 등록이 깨짐** | PAT 로만 붙인다 (D2) |
| 만능 토큰을 두면 권한 체계가 둘로 갈림 | **사용자 토큰을 그대로 전달** — 만능 토큰 금지 (D2) |
| MCP 경로로 게시·삭제가 조용히 일어남 | 위험한 방향은 **아예 도구를 안 내거나** 사람 확인을 요구 (D3) |

**그쪽에서 본 주의할 점 둘**(우리는 안 따른다):
- 비-localhost 바인딩에서 `MCP_ALLOWED_HOSTS` 가 비면 **DNS rebinding 보호를 끈다**.
  우리는 기본을 127.0.0.1 로 두고, 밖에 열 때 허용 Host 를 **필수**로 받는다.
- 개발자 로컬 설정(`~/.claude.json`)에 **PAT 평문이 저장**된다. 이건 MCP 클라이언트
  공통 성질이라 막을 수 없다 — 대신 **토큰 수명을 짧게, 폐기를 쉽게** 하고 그
  사실을 발급 화면에 적는다.

## 우리 전제 — 그쪽보다 유리한 것 둘

1. **PAT 가 이미 있다.** `PersonalAccessToken` 모델 + `POST /api/auth/tokens`
   발급·목록·폐기가 v0.x 부터 있었다(구조결정 9 — 장비 파이프라인용으로 만든
   것). ReportArchive 가 새로 만들어야 했던 조각을 우리는 안 만든다.
2. **의존성이 최신이다.** 우리는 `fastapi 0.141.1 · starlette 1.6.0 ·
   pydantic 2.13.4` 로, 그쪽이 충돌했던 조합(FastAPI 0.115)보다 위다. 같은 venv
   가 될 수도 있다 — **설치해 보고 정한다**(D1 의 확인 항목).

## 설계 결정

### D1. 별도 프로세스·별도 venv

의존성이 맞더라도 별도로 둔다. 이유는 셋:

- **재시작이 독립이어야 한다.** MCP 를 고쳐 올리는 일이 API·화면을 끊으면 안 된다.
- **죽어도 앱은 산다.** 배포 스크립트에서 MCP 실패는 **비치명적**으로 다룬다.
- SDK 가 언제든 다시 프레임워크를 올릴 수 있다 — 그때 앱이 인질이 되지 않는다.

`mcp_server/` 를 저장소 최상위에 둔다(backend 안이 아니다 — 백엔드 venv 와 섞이지
않게). 파일은 넷: `server.py` · `guide/GUIDE.md` · `requirements.txt` · `README.md`.

### D2. 인증 — 사용자 토큰을 그대로 나른다

**MCP 서버는 토큰을 검증하지 않는다.** 헤더를 백엔드로 넘기고, 판정은 지금 있는
권한 코드가 한다 — 권한 규칙이 두 곳에 생기면 갈라지는 날이 온다.

    Authorization: Bearer mnx_pat_...  사용자의 PAT (사람마다 자기 것)
    X-Workspace-Slug: <부서>         어느 부서로 볼 것인가
    X-Client: mcp                   서버가 붙인다 — 감사 표식이지 보안 경계가 아니다

**만능 토큰을 두지 않는다.** 서버가 자기 자격으로 백엔드를 부르면 그 순간 모든
사용자가 같은 권한을 갖는다.

실측 확인: 접두어는 이미 `mnx_pat_` 이고(`auth/security.py`), 해시만 저장하며
표시용 prefix 도 있다 — **PAT 쪽은 손댈 것이 없다.** 남은 것은 백엔드가
`X-Client` 를 받아 감사 로그에 남기는 자리 하나다.

### D3. 읽기가 본론이다 — 쓰기는 좁게

MatNexus 에서 AI 에게 시킬 값진 일은 **찾고 견주는 것**이다. 쓰기는 사람이 화면에서
하는 편이 낫고, 잘못 쓰면 되돌리기 비싼 것이 많다.

**아예 안 내는 도구**: 카드 확정(`published`) · 삭제(재료·시험·카드) · 부서·계정
변경 · 기준정보 편집 · 처리 레시피 실행. 화면에서 사람이 한다.

**내되 초안까지만**: 선언 물성 채우기(문헌 채택) · 선언 카드 만들기(항상 `draft`) ·
BOM 덱 만들기(**텍스트만 반환** — 파일을 서버에 안 쓴다).

### D4. 도구는 20개 안쪽으로 시작

도구 설명은 매 요청 상주 비용이다(그쪽 실측: 46개 = 약 10,000 토큰). 처음부터 다
내지 않고, **질문 다섯 개**에 답하는 데 필요한 것만 낸다:

1. *"이 재료 뭐가 있어?"* → `search_materials` · `get_material`
2. *"SUS304 항복강도 얼마야?"* → `search_catalog` · `get_catalog_material`
3. *"이거 어떻게 재?"* → `how_to_measure`
4. *"이 재료 시험 결과 어때?"* → `list_test_runs` · `get_test_run` · `list_cards` · `get_card`
5. *"이 BOM 으로 덱 뽑아 줘"* → `match_bom` · `build_bom_deck`

여기에 안내(`get_guide`) · 단위계(`list_unit_systems`) · 쓰기 셋
(`adopt_catalog_values` · `create_declared_card` · `set_declared_properties`)을
더해 **15개**로 시작한다.

### D5. 안내는 서버가 들고 있는다

`guide/GUIDE.md` 를 매 호출 읽어 `get_guide(topic)` 로 낸다. 클라이언트 스킬에
복사해 두면 **고쳐도 옛 사본을 쓰는 사람에게는 전달되지 않는다**(그쪽 실측).

여기 적을 것: 단위 규약(전부 SI, 화면 표시는 별개) · tier 의 뜻(4는 추정) ·
「합성」 표지의 뜻 · 선언 물성의 층(재료/시료) · 덱을 만들기 전에 확인할 것.

### D6. 얇은 프록시 — DB 를 직접 안 읽는다

`httpx` 로 `http://127.0.0.1:8010/api` 를 부른다. MT 는 DB 를 직접 읽었지만 그쪽은
권한이 없었다 — 우리가 그러면 **부서 가시성·전역 재료·편집 권한 판정을 MCP 안에
다시 구현**하게 된다. 로직이 두 벌이 되면 갈라진다. 필요한 계산이 있으면
**백엔드에 엔드포인트를 만든다.**

### D7. 리소스와 프롬프트도 낸다 (MT 에서)

RA 는 도구만 냈지만 MT 는 MCP 표준의 **리소스**(`materialtwin://guide`,
`://taxonomy`)와 **프롬프트**(`find_material`, `register_test_data`)를 함께 낸다.
리소스는 도구 목록에 상주 비용을 안 얹으면서 안내를 제공하고, 프롬프트는
「무엇부터 물어야 하나」 를 알려 준다.

우리 것: 리소스 `matnexus://guide`(단위·tier·표지 규약) · `matnexus://taxonomy`
(재료 분류와 현재 분포). 프롬프트 `pick_material`(요구조건 → 후보 → 비교 → 카드)
· `build_deck`(BOM → 매칭 → 덱).

### D8. 값에는 근거가 붙어 나간다 — 필수 필드

이 서버에서 가장 위험한 실패는 **AI 가 추정값을 실측처럼 옮기는 것**이다. 그래서
값을 내는 모든 도구는 다음을 **선택이 아니라 필수로** 싣는다:

    unit          정본 SI (화면 표시 단위와 다르다)
    quality_tier  문헌 값일 때 — 4 는 추정·가정이다
    source        어디서 왔나 (제목·DOI·출처 종류)
    origin        measured | declared:<출처> | **synthetic** | catalog
    caveat        「합성 곡선」·「초안 카드」·「미채택 결과」 같은 표지

`origin` 과 `caveat` 는 우리가 더한 것이다 — MT 에는 합성 곡선·카드 수명주기가
없었다.

### D9. 단위 — 조회는 SI, 덱은 골라서 (2026-09-06 사용자 지적)

두 자리를 나눈다:

- **조회는 SI 로 낸다.** MCP 가 환산하면 환산 규칙이 화면·백엔드·MCP 세 벌이
  된다 — 갈라지는 날 AI 가 1000배 틀린 숫자를 말한다. 대신 **단위를 값과 함께
  싣고**(재료 기본 칸처럼 SI 가 아닌 것이 있다) 안내가 「어느 단위로 말하는지
  반드시 밝혀라」 를 못 박는다.
- **덱은 단위계를 고른다.** 솔버 덱은 단위를 선언하지 않아 계가 섞이면 조용히
  1000배 틀린다. `list_unit_systems()` 로 고를 수 있는 계(내장 SI·mm_n_tonne +
  부서가 만든 계)를 보이고, 덱 도구는 `units` 인자를 받는다. **안 고르면 SI 로
  나가고, 어느 계로 뽑았는지 사람에게 말한다.**

## 단계

> **네 단계 다 끝났다 (2026-09-08).** 지금 도구는 41개다 — 처음 세운 계획에는
> 없던 값 질의·온톨로지·처리·정의 짓기가 뒤에 붙었다. 아래는 처음 계획 그대로
> 두고, 실제로 겪은 것과 늘어난 것은 「진행 기록」 에 적는다.

### 1단계 — 뼈대 (0.5일)

`mcp_server/` 생성 · PAT 헤더 전달 · `get_guide` · `search_materials` ·
`get_material` · `list_unit_systems`. 로컬에서 Claude Code 에 등록해 실제로
물어본다.

**확인 항목**: `mcp` SDK 를 우리 백엔드 venv 에 설치했을 때 의존성이 깨지는지
(깨지면 D1 의 근거가 하나 더 생긴다 — 어느 쪽이든 별도 venv 로 간다).

### 2단계 — 조회 도구 (1일)

문헌 카탈로그 · 측정법 · 시험 · 카드. 값에 **출처와 tier 가 함께 나가게** 한다 —
AI 가 숫자만 옮기면 근거가 사라진다.

### 3단계 — 덱과 제한적 쓰기 (1일)

BOM 매칭·덱(텍스트 반환) · 문헌 채택 · 선언 카드(초안). 쓰기 도구는 **무엇이
바뀌는지 먼저 말하고**(dry-run 기본) 사람이 확인하게 한다.

### 4단계 — 배포 (0.5일)

`run_mcp.ps1`(창 셋째 — 우리 배포는 systemd 가 아니라 `run_server.ps1` ·
`run_worker.ps1` 두 창이다) · `deploy.ps1` 에 설치 단계 추가(**실패는 비치명적**) ·
`배포.md` 와 운영 핸드북에 등록 절차.

클라이언트 등록:

    claude mcp add --transport http matnexus http://<서버>:8012/mcp \
      --header "Authorization: Bearer <내 PAT>" --header "X-Workspace-Slug: <부서>"

포트는 **8012**(백엔드 8010, 워커가 쓰는 자리를 피한다).

## 위험과 주의

- **PAT 평문이 클라이언트 설정에 남는다.** 막을 수 없는 성질이라 수명을 짧게
  (기본 90일 → 우리는 30일 검토) 하고 폐기를 쉽게 한다. 발급 화면에 그 사실을 적는다.
- **밖에 열 때는 허용 Host 를 필수로.** 기본 바인딩은 127.0.0.1.
- **AI 가 tier4 를 실측처럼 옮기는 것**이 이 기능의 가장 큰 위험이다. 모든 값 응답에
  tier·출처·「합성」 표지를 **필수 필드로** 싣고, 안내에 못 박는다.
- **도구가 늘면 토큰이 는다.** 새 도구를 더할 때마다 설명 길이를 재고, 안 쓰는
  도구는 뺀다.

## 이번에 안 하는 것

- **OAuth·SSO** — PAT 로 충분하다. 사내망이고, 토큰 발급 화면이 이미 있다.
- **쓰기 확대**(확정·게시·삭제) — 사람이 화면에서 한다.
- **MaterialTwin MCP 코드 이식** — 무인증 전제라 구조가 안 맞는다. 도구 이름과
  응답 모양만 참고한다.

  `adopt_parameter_set`): 문헌 물성에 **같은 이름의 다른 변수**가 섞여 있었다

  **처리와 인박스**(`run_processing` · `run_batch_processing` · `save_recipe` ·
  `list_inbox` · `assign_inbox_item`): 파일을 대화로 나르지 않고 장비 PC 가 올려
  둔 것에 **어디에 붙일지만** 정한다. 배치는 성공보다 **실패를 사유별로 묶는
  것**이 값이다 — 50건에서 「12건은 점이 성겨서, 3건은 채널 이름이 달라서」.
  자동 재시도는 옵션이고 흔적을 남긴다(사용자 요청), 그리고 **넓힐 수 있는 것은
  구간뿐**이다 — 신뢰 문턱(`MIN_TRUSTWORTHY_POINTS` · R²)은 레시피 옵션이 아니라
  코드 상수라 AI 가 손댈 수 없다. 그것이 이 자동화가 안전한 이유다.

  **정의 짓기**(`inspect_device_file` · `check_format_profile` ·
  `save_format_profile` · `scan_deck_format` · `render_card_deck` ·
  `draft_test_type`): AI 가 규약 자체를 만드는 자리라 검증을 가장 세게 걸었다.
  「돌아는 갔다」 로는 부족하다 — 이 파서는 **모든 열을 채널로 만들기** 때문에
  이름을 안 정해 줘도 파싱은 성공하고, 그 뒤 처리 단계가 `force` 를 못 찾는다.
  그래서 `test_type` 을 주면 **시험법 계약의 필수 채널과 대조**하고, `expect` 로
  사람이 아는 답(장비 화면의 최대하중)과 기계가 대조한다.

  **시험 정의는 초안까지만 한다**(사용자 판단). 프로파일은 표본에 대 보면 되고
  덱은 렌더해 보면 되는데, 시험법은 **검증할 방법이 없다** — 만들어서 시험을
  붙여 봐야 안다. 되돌리기도 어렵다(이미 붙은 시험의 뜻이 바뀐다). 그래서

  조용히 덮는다 — `render_card_deck` 이 MID 를 함께 돌려주고 안내가 「사람에게
  말해라」 라고 못 박는다.
