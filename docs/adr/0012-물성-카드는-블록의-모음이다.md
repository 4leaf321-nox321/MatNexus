# ADR 0012 — 물성 카드는 블록의 모음이다

- 상태: 채택 (2026-08-23)
- 관련: D7(정의는 데이터, 계산은 플러그인), ADR 0009(피팅과 솔버 카드),
  ADR 0010(Expand→Backfill→Contract), 개발계획 §6 Phase 5
- 코드: `matcore/cards/`(`BlockSpec`·`register_block`·`card_kwargs`),
  `matcore/cards/{mechanical,viscoelastic}.py`, `matcore/export/__init__.py`
  (`missing_for`·`available_formats`), `app/modules/fitting/{models,schemas,routes}.py`,
  `frontend/src/modules/fitting/CardBlocks.tsx`,
  마이그레이션 `b6e2f7c918da`

## 배경

`abaqus_viscoelastic` 형식은 v1.14.0 에 등록됐다. 그런데 **그것을 부를 수 있는
카드가 없었다.**

```
matcore/export/__init__.py:498   "abaqus_viscoelastic": Format(...)
app/modules/fitting/*.py          prony·viscoelastic 참조 0건
```

DMA 파일 → 마스터커브 → Prony 적합까지는 도는데(v1.11.0~v1.16.0), 그 계수를 담을
`PropertyCard` 를 만들 길이 없어서 **한 번도 불릴 수 없는 렌더러**였다. 만들어 둔
것이 닿을 수 없는 상태는 가장 나쁜 종류의 미완성이다 — 있는 줄 알았던 것이 없는
자리이고, v1.18.0 에서 `Plugin.inputs` 가 선언만 있고 읽는 코드가 없던 것과 같은
패턴이다.

막힌 이유를 파고들다 **진짜 원인은 다른 데 있다**는 것이 드러났다.

### 레지스트리가 한 층 깊은 곳에 있었다

경화식은 이미 데이터였다. `matcore.fitting.FAMILIES` 에 하나 더하면 `GET
/fitting/families` 가 그것을 내고 화면의 목록이 따라온다 — Ghosh 를 붙이는 데
마이그레이션도 스키마도 화면도 필요 없다.

그런데 **물성의 갈래**는 코드였다.

```
app/modules/fitting/models.py     elastic · hardening · table   ← 컬럼 이름
app/modules/fitting/schemas.py    elastic · hardening           ← 응답 필드
app/modules/fitting/routes.py     셋을 이름으로 읽고 쓴다
matcore/export/__init__.py        Card 필드가 물성 종류마다 하나씩
frontend/.../FittingPanel.tsx     셋을 이름으로 그린다
```

점탄성을 더하려면 네 번째 컬럼이, 초탄성이면 다섯 번째가 필요하다. 매번
마이그레이션·스키마·화면이 딸려 온다.

**폴리머 점탄성 슬라이스에서 D7 이 못 미친 45%(저장·API·화면)의 정체가 이것이다.**
개발계획 §6 Phase 5 가 "구현 2,456줄/18파일, 한 자릿수가 아니라 2~4배" 라고 적고
남은 비용의 정체까지 짚어 뒀는데, 그 비용이 나오는 **구조적 자리**가 여기였다.

아이러니가 하나 있다. `elastic`·`hardening`·`table` 은 **셋 다 이미 JSONB 였다.**
안은 형식이 없는데 바깥의 컬럼 이름만 굳어 있었다 — JSONB 를 쓰는 이유를 절반
버린 모양이다.

### 재 본 세 길

| | 지금(점탄성) | 그다음 물성 1종마다 |
|---|---|---|
| A. 컬럼 하나 더 | ~300줄 · 마이그레이션 1 | ~300줄 · **마이그레이션 1** |
| B. 별도 카드 종류 | ~840줄 · 마이그레이션 1 | ~840줄 · 마이그레이션 1 |
| C. 블록 레지스트리 | ~880줄 · 마이그레이션 1 | **~120줄 · 마이그레이션 0** |

B 는 어느 시점에서도 이득이 없다 — 재고 나니 근거가 사라졌다. A 와 C 의 본전은
**물성 3종째**이고, 로드맵에 적힌 것만 세어도(고무 Ogden, 스칼라 분포 적합,
LS-DYNA) 넘는다.

## 결정

**카드는 블록의 모음이다.** `PropertyCard` 가 `blocks` JSONB 한 칸을 갖고, 무엇이
들어갈 수 있는지는 `matcore.cards` 레지스트리가 안다.

```python
@register_block(BlockSpec(
    key="viscoelastic", label="점탄성", help="...",
    produces=(Produced("equilibrium_pa", "평형 탄성률", "Pa", "..."), ...),
    rows=(Produced("relaxation_time_s", "완화시간 τᵢ", "s"), ...),
    to_card=lambda payload: {"prony": ..., "prony_reference_temperature": ...},
))
```

payload 의 모양은 블록이 무엇이든 같다. 그래야 화면이 **선언만으로** 그린다.

```
{"values": {키: 값}, "rows": [{열: 값}], "notes": [문장]}
```

곁들여 정한 규약 둘:

- **값의 출처는 `<키>_source` 에 둔다.** 7850 이 실측인지 관례값인지 덱만 봐서는
  모르고 화면에서도 모른다. 규칙으로 정해 두면 새 블록이 저절로 따라온다.
- **행이 `si_unit` 을 들면 그것이 이긴다.** 경화식 파라미터는 식마다 단위가 다르다
  — Voce 의 `b` 는 무차원이고 `q` 는 Pa 다. 열 선언 하나로는 못 적는다.

### 한 자리는 한 블록이 채운다

`card_kwargs` 가 자리 겹침을 **거절한다.** Abaqus 는 `*VISCOELASTIC` 이 있을 때
`*ELASTIC` 을 순간 탄성률로 읽는데, 평형 탄성률이 실리면 재료가 통째로 무르게
계산된다. 그런데 **덱은 멀쩡히 돌고 결과도 그럴듯하다** — 나중에 알 수 없는
종류의 틀림이라 만드는 자리에서 막는다.

그래서 점탄성 카드는 E₀ 를 **탄성 블록에** 출처 `prony` 로 넣는다.

### 모르는 블록에 소리를 낸다

카드에 실린 블록이 지금 레지스트리에 없다는 것은 그 물성을 만든 코드가 사라졌거나
이름이 바뀌었다는 뜻이다. 조용히 넘기면 **덱에 그 물성만 빠진 채로 나가고 덱은
멀쩡히 돈다.** 목록에서는 카드 하나가 목록 전체를 죽이지 않게 붙잡되,
`PropertyCardOut.problem` 에 담아 그 카드를 짚는다.

### DMA 적합은 기존 묶음에 든다

Prony 는 시험 1건에 매달려 있고 경화 카드는 재료+시험종류+방향의 대표 곡선에서
나온다. 그래서 "별도 카드 종류가 필요한가" 를 물었는데, **이 코드가 이미 답을 한
번 냈다.** `_representative` 의 독스트링이다.

> 여러 개의 평균이 낫다. … 그렇다고 **막지는 않는다.** 막으면 사람은 시스템 밖에서
> 계산해 카드 없이 덱을 만든다 — 그러면 근거가 아무 데도 안 남는다. 대신 표본
> 수를 카드에 박고, 1건이면 그 사실을 근거에 문장으로 남긴다.

시편 1건짜리 카드는 이미 허용하기로 한 것이다. Prony 가 1건이라는 사실은 **새로운
종류의 문제가 아니라 이미 있는 답의 적용 대상**이다. 재료·방향은 체인(적합 →
마스터커브 → 시험 → 시편 → 시료 → 재료)에서 따라간다.

## 대안

- **A. 컬럼 하나 더** — 지금 제일 싸고(300줄), 물성 3종째부터 계속 손해다. 무엇보다
  같은 값을 매번 다시 낸다.
- **B. 별도 카드 종류** — 카드 종류를 둘로 늘리는 값이 840줄인데, 늘려서 얻는 것이
  "Prony 는 시험 1건짜리다" 라는 사실의 표현뿐이다. 그 사실은 `source.sample_count`
  와 덱 주석으로 이미 표현된다.
- **화면 자동 렌더링을 미룬다** — 저장 구조만 먼저 바꾸고 화면은 Ogden 의 실제
  모양을 보고 만드는 안. "쓰이는 모양을 모르고 만들지 않는다"(번들 ZIP 을 미룬
  근거)와 맞지만, **그 규율보다 구조가 낫다고 판단했다.** 화면이 블록 이름을 계속
  알고 있으면 45% 중 화면 몫이 그대로 남는다.

## 결과

**막다른 길이 뚫렸다.** DMA 파일 → 마스터커브 → Prony → 카드 → Abaqus 덱이 한
줄기로 돈다(`tests/api/test_viscoelastic_api.py::Test점탄성카드`).

곁들여 나온 것 둘:

- **`Format.requires` 를 읽는 곳이 생겼다.** 독스트링에 *"화면이 미리 알려 줄 수
  있어야 한다"* 고 처음부터 적혀 있었는데 읽는 코드가 없었다. 이제 서버가
  `available_formats` 로 판정한다 — 전에는 화면이 한국어 이름(`탄성계수`)을 카드
  필드에 **손으로 이어 붙였고**, 새 물성이 붙으면 그 표에도 줄을 더해야 했다.
- **`points` 가 `requires` 에 없었다.** 표가 빈 카드는 검사를 지나 `render` 안에서
  터졌다 — 화면이 "이 형식은 아직 못 낸다" 를 미리 말할 수 없었다. 점탄성 카드가
  생기면서 실제로 걸리는 자리가 됐다.

**아직 안 잰 것:** 이 구조에서 새 물성 1종이 정말 `BlockSpec` 하나로 끝나는지는
**고무 Ogden 에서 재야 확정된다.** 점탄성은 이 구조를 만들면서 함께 넣은 것이라
공정한 측정이 아니다. Phase 5 의 수용 기준은 그때 다시 쓴다.

**되돌리기의 대가:** `downgrade` 는 옛 컬럼 셋을 복원하지만 **점탄성 블록은 갈 곳이
없다** — 옛 스키마에 그 컬럼이 없다. 되돌리면 점탄성 카드는 값을 잃는다. 조용히
버리지 않고 마이그레이션에 적어 뒀다.

**모듈 경계 예외 하나:** 프론트 `viscoelastic → fitting`. 카드를 만드는 버튼이 Prony
결과 옆에 있어야 한다 — 계수를 보고 나서 "이걸로 카드" 가 이어지는 자리다. 반대로
뒤집으면(fitting 이 점탄성을 앎) 경화 카드 화면이 DMA 를 알아야 하고, 새 물성마다
그 목록이 는다 — 그것이 바로 여기서 걷어낸 결합이다.
