# 0053. 채택 화면은 자르기 전 공칭 곡선을 함께 그린다 — 옛 결과는 다시 돌린 참고로

날짜: 2026-10-03
상태: 채택
관련: [ADR 0007](0007-원본과-처리결과-저장-구조.md)(처리 결과는 불변, 다시 계산하지 않는다)

## 배경

운영에서 받은 지적(2026-10-03): 「데이터 처리 한 다음 채택 화면에서 s-s curve 가 뒤에 잘린 부분만
보인다. 앞쪽 데이터부터 볼 수 있나 — E 값 부분은 어떻게든 포함해야 할 것 같다.」

원인은 하나였다. 진응력 · 진소성변형률 단계(`tensile.true_plastic`)는 항복강도 앞의 점을 **모든 열에서**
버린다 — 소성 곡선은 항복점부터라는 판단(2026-09-11, 토우 구간이 섞이면 Voce 항복이 304 → 225 MPa 로
내려앉았다)이고 되돌리면 안 된다. 그런데 결과 파일에는 그 단계가 끝난 곡선만 남아서, 공칭 축으로 봐도
곡선이 항복점에서 시작했다. 채택은 「이 곡선을 이 시험의 물성으로 삼는다」 는 결정인데, 그 직전에
「E 를 제대로 잡았나」 를 볼 곡선이 없었다.

## 결정

1. **저장할 때 자르기 전 공칭 곡선을 결과 파일에 함께 싣는다.** 앞을 잃지 않은 마지막 단계
   (`processing.front_intact_stage` — 공칭 변형률의 가장 작은 값이 아직 남아 있는 단계)의 곡선을 600점으로
   줄여 Parquet 스키마 메타데이터(`extra:context`)에 JSON 으로 둔다. 앞을 잃지 않았으면 `null` 을 적는다 —
   「필요 없다」 와 「이 칸 전의 파일이라 없다」 를 가르려고.
2. **곡선 API 가 공칭 축일 때 앞쪽 곡선 · 보조선 · 항복점을 함께 준다.** 탄성 직선은 탄성계수 단계가 맞춘
   σ = Eε + 절편, 오프셋 선은 항복강도 단계가 교점을 찾은 σ = E(ε - 오프셋) 그대로(그 단계에 들어간 E),
   항복점은 그 교점이다. 그 값을 잰 단계가 공칭 축에서 쟀을 때만 긋는다.
3. **이 칸 전에 저장한 결과는 그 결과의 단계를 지금 원본에 다시 돌려 참고로 그린다.** 화면은 점선으로
   그리고 「다시 계산한 참고 곡선」 이라고 적는다. 저장된 결과의 첫 점이 다시 계산한 곡선 위에 있는지
   견주어 1% 넘게 어긋나면 그렇다고 말한다. 다시 돌리다 멈추면 거기까지 된 단계를 쓰고, 그것도 없으면
   이유를 단다 — 조용히 빼지 않는다.

## 대안

- **진응력 단계가 앞을 안 버리게 되돌린다** — 2026-09-11 에 고친 결함(덱 첫 점이 (0, 0 MPa), Voce 항복이
  내려앉음)이 돌아온다. 버렸다.
- **앞쪽 행을 결과 열에 NaN 으로 채워 남긴다** — 행 수가 거짓말을 하고, 결과 열을 읽는 모든 자리(카드 표 ·
  적합 · 덱)가 NaN 을 걸러야 한다. 버렸다.
- **DB 에 칸을 더한다** — 마이그레이션이 들고, 결과 파일과 DB 가 따로 지워질 수 있다. 결과 파일은 이미
  불변이고 자기 단위도 메타데이터로 든다 — 같은 자리에 둔다.
- **옛 결과는 「다시 처리하면 보입니다」 로만 안내한다** — 운영에 쌓인 결과를 사람이 하나씩 다시 처리해야
  E 를 볼 수 있다. 사용자가 다시 돌린 참고를 골랐다.

## 결과

- ADR 0007 의 「다시 계산하지 않는다」 에 예외가 하나 생겼다 — **값이 아니라 그림, 그것도 옛 결과의 앞쪽만.**
  결과의 값 · 결과 곡선 · 보조선은 여전히 저장된 것에서 나온다. 다시 돌린 그림은 점선 · 「참고」 · 어긋남
  경고로 저장된 것과 갈린다.
- 개발 DB 실측(2026-10-03): 진소성 결과 중 행 100개 넘는 58건 모두 앞쪽 곡선을 다시 그렸고, 2026-08-26 에
  만든 2건은 지금 계산과 첫 점이 3~4% 어긋나 경고가 붙었다 — 그 사이 처리 방식이 바뀐 결과다.
- 결과를 열 때마다 옛 결과는 단계를 다시 돈다. 넘파이 계산이라 한 건에 수십 ms 이고, 다시 처리하면 저장된
  곡선으로 바뀐다.
