# 0054. 물성 목록의 정본은 MatNexus 다 — 분야 ⊃ 물성군 ⊃ 물성을 여기서 세우고 SP 가 읽어 간다

날짜: 2026-10-03
상태: 채택
관련: [ADR 0027](0027-물성-카탈로그를-들인다.md)(문헌 카탈로그) · [ADR 0050](0050-물성의-정의문은-허브-키가-들고-조회가-돌려준다.md)(정의문) ·
Standard Platform 「외부 시스템 ↔ Standard Platform 연동 지침서」 §3 · §12

## 배경

운영 Standard Platform(SP)의 코어 온톨로지에 **물성 · 물성군 · 물성 분야** 세 타입이 있다. 이름은 MatNexus
데이터를 바탕으로 온톨로지화해서 만든 것이다. 그런데 MatNexus 에는 그 가운데 층이 없었다 — 문헌 물성 정의는
키 앞머리(`mechanical.` …)로 열두 갈래로만 나뉘어, 기계 104종이 한 줄로 늘어섰다.

방향을 정해야 했다. 사용자의 말(2026-10-03): 「물성은 오히려 이쪽이 정본이라 이쪽에서 저쪽으로 넘겨야 할 수도
있다」 · 「개발 서버에서 (운영 SP 를) 받기 어려운 게 문제다」 · 「MatNexus → SP 물성 목록 내보내기에 초점」 ·
「물성 = 문헌 + 사내」 · 「물성군을 만드는 기능을 만들어서 이 안에 — 분야 · 군 · 물성 순서로 포함 관계. 그
데이터가 있으니 밀어 넣을 수 있게」.

물성의 값 · 정의문 · 별칭 · 폐기 · 사내 물성(`local.`)이 전부 여기서 생긴다. 목록의 정본이 SP 면 물성 하나
만들 때마다 SP 를 먼저 고쳐야 하고, 개발 서버는 운영 SP 에 닿지 못해 그 길을 시험할 수도 없다.

## 결정

1. **분류 세 층을 MatNexus 에 둔다** — `property_fields`(분야) · `property_groups`(물성군) ·
   `property_group_members`(물성 → 군). 포함 관계다: 물성은 한 군에만(소속 표의 기본 키가 물성 키), 군은 한
   분야에만. 이관물(`catalog_definitions`) 옆에 따로 두고 물성 키에 외래키를 안 건다 — 별칭 · 연결과 같은 판단.
2. **키 앞머리는 분류가 아니다.** `mechanical.` 은 식별자의 일부일 뿐이다. 씨앗 분야 열둘의 키를 키 앞머리와
   같게 두고(이름은 화면 라벨 「기계」 · 「열」 …) 배포가 없는 것만 만든다(`refresh_builtins`). 밀어 넣은 분류가
   다르게 묶었으면 그대로 따른다.
3. **지우지 않고 폐기한다. 키는 안 바뀐다.** 바깥이 키로 잇는다 — 지우면 그쪽에서 행이 말없이 사라진다(지침
   §3.2 · §12-A ⑨). 비우지 않은 군 · 분야는 폐기를 막는다. 이름 · 설명은 고친다.
4. **고치기 · 밀어 넣기는 자료 관리자다** — 정의문 고치기와 같은 판정(ADR 0035 D4). 분류는 바깥과 AI 가 읽는
   전사 자산이라 **사람이 해도 감사에 남긴다**(`property_taxonomy.*`).
5. **밀어 넣기는 표 → 미리 보기 → 넣기.** 한 줄이 분야 › 물성군 › 물성(+ 선택: 분야 키 · 물성군 키 · 설명).
   없는 분야 · 군은 만들고, 물성은 **만들지 않는다** — 키 · 이름 · 별칭이 정확히 하나에 맞아야 한다. **오류가 한
   줄이라도 있으면 하나도 안 넣는다.** 이름이 맞아도 키 앞머리와 다른 씨앗 분야로 가면 미리 보기에 세운다
   (`cross_domain`) — 막지는 않는다.
6. **바깥(SP)이 읽는 목록** — `GET /api/catalog/feed/{fields,groups,properties}`, 지침 §3.1 의 모양
   (`{items, total, page, page_size}`). 행은 평평하고 키 차례로 늘 같은 순서다. 행마다 `updated_at`(UTC `Z`) ·
   `status`(active · deprecated) · `is_active` · **`deleted`**. 여럿인 값(별칭 · 조건 축)은 SP 가 가르는 글자 `;`
   로 잇는다. **`deleted` 가 SP 가 실제로 읽는 칸이다** — SP 의 데이터 소스는 `deleted: true` 인 행을 「사라진 것」
   으로 보고 그 객체를 사용 중지로 바꾸며, `status` · `is_active` 는 칸 대응의 대상이 아니다. 이 칸이 없으면 여기서
   폐기한 것이 SP 에서는 영영 「사용」 으로 남는다(SP 코드를 읽고 찾았다).
   `page_size` 는 1000 까지이고 **넘게 달라면 깎지 않고 거절한다** — SP 는 「받은 행이 page_size 보다 적으면
   끝」 으로 읽어서, 깎아 주면 거기서 멈추고 나머지를 영영 안 받는다.
7. **읽기 전용 토큰** — `personal_access_tokens.read_only`. 인증 자리(`shared/auth.current_user`)가 GET · HEAD ·
   OPTIONS 밖을 막는다. 지침이 「토큰은 읽기 전용으로 준다」 를 요구하는데, 토큰은 만든 사람의 권한 그대로라
   읽으라고 준 토큰으로 자료를 고치고 새 토큰까지 만들 수 있었다.
8. **방향은 MatNexus → SP 다.** SP 는 데이터 소스로 밤마다 읽고(지침 §12-A ①), 받은 타입은 SP 화면에서
   읽기 전용이다(②). 운영 SP 에 이미 있는 분류는 **사람이 한 번 표로 밀어 넣는다** — 자동 수신이 아니다.

## 대안

- **SP 코어를 받아 기준정보로 쓴다(SP → MatNexus)** — 물성의 정본이 거꾸로 서고, 개발 서버가 운영 SP 에
  닿지 못해 시험할 수 없다. 조직 · 장비 · PLM 처럼 SP 가 정본인 것은 나중에 이 방향으로 받는다. 물성은 버렸다.
- **SP 묶음 밀어 넣기(`POST /api/bundles/import`, 지침 §5)** — MatNexus 가 SP 의 `ontology:write` 토큰을 들고
  순서 · 재시도 · 실패 알림을 떠안는다. 데이터 소스는 주기 · 칸 대응 · 미리 보기 · 다시 찾기를 SP 가 한다.
  지금은 버렸다.
- **분야를 키 앞머리로 못 박는다(표 없이)** — SP 의 분야 이름이 다르거나 갈래가 늘면 밀어 넣기가 막힌다. 표로
  두되 씨앗을 키 앞머리로 했다.
- **소속을 `catalog_definitions` 칸으로** — 이관물이다. 별칭 · 연결과 같은 까닭으로 옆에 둔다.
- **분류를 지식 그래프 마디로** — 분류는 물성의 칸이다. 기준정보 축을 재료의 칸으로 둔 판단과 같다
  (`tests/architecture/test_relations.py`).
- **이름이 비슷하면 골라 준다** — 「항복응력」 은 유변학 물성이다. 기계 › 강도에 적은 「항복응력」 이 이름으로
  정확히 맞아 페이스트가 흐르는 응력이 금속 강도 군에 들어간다 — 개발 DB 점검에서 실제로 그렇게 풀렸다. 정확히
  맞는 것만 받고, 그래도 다른 분야로 가면 세운다.

## 결과

- 개발 DB: 분야 12(씨앗) · 물성군 0 · 물성 271(문헌 271 + 사내 0). 운영 SP 의 분류를 표로 받아 밀어 넣으면
  선다.
- **SP 는 첫 연동에서 이미 있는 객체를 이름으로 찾는다**(그 타입 안에서 이름 · 별칭이 하나에만 맞아야 한다 — 둘
  이상이면 그 행이 오류다). 그 뒤로는 우리 키를 별칭(`source:<소스>`)으로 기억해 그것으로 찾는다. 그래서 분야 ·
  물성군 · 물성의 **이름이 SP 와 같아야** 첫 연동이 잇는다. SP 의 「우리 식별자(key)로도 쓴다」 는 이름으로 찾은
  객체의 키를 **우리 키로 바꾸므로**, 두 시스템의 키가 같을 때만 켠다.
- SP 쪽 할 일: 데이터 소스 셋(`rest` · `rows_path=items` · `paging=page`) · 칸 대응 · 읽기 전용 토큰 — 설정 값과
  §12-B 양식은 [연동-SP-물성-목록.md](../연동-SP-물성-목록.md).
- MCP 도구 둘: `get_property_classification`(읽기) · `classify_properties`(밀어 넣기, 미리보기 기본).
- 화면의 키 앞머리 라벨(`catalog/api.ts` 의 `DOMAIN_LABELS`)과 분야 이름은 따로 산다. 키 앞머리로 거르는 화면은
  식별자의 갈래를 거르는 것이라 분류 이름을 따르지 않는다 — 씨앗 이름만 같은 말로 시작한다.
- 남은 것: WSL SP 에 데이터 소스를 걸어 미리 보기까지 리허설, 운영 SP 의 분류 표를 받아 밀어 넣기.
