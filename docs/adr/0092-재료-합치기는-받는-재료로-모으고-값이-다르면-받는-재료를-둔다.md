# 0092. 재료 합치기는 받는 재료로 모으고, 값이 다르면 받는 재료를 둔다

날짜: 2026-11-17
상태: 채택
관련: [ADR 0079](0079-시료-이동은-받을-재료를-고르되-분류가-같고-시료째다.md)(시료 이동 — 그때 합치기는 범위
밖) · [ADR 0035](0035-보기는-모두에게-고치기는-사람에게.md)(고칠 권한)

## 배경

VOC 59(재료를 잘못 등록함)에서 시료 이동을 만들고 합치기는 미뤘다. 같은 재료를 두 번 등록했을 때(「DP590」
과 「DP 590」) 시료를 다 옮긴 뒤 빈 재료를 휴지통에 넣는 것이 우회였는데, 재료에 **직접** 붙은 것 — 선언
물성 · 밀도 · 푸아송비 · 문헌 연결 · 계수 묶음 · 적용 부품 · 카드 · 묶음 기록 · 저장한 대표 곡선 — 은 따라오지
않아 빈 재료와 함께 휴지통으로 갔다. 정할 것은 하나였다: 두 재료에 같은 칸이 있는데 값이 다르면 어느 쪽을
남기나. 사용자 결정: **받는 재료 우선**, 다른 값은 미리보기에 목록으로 보인다.

## 결정

1. **미리보기 → 실행**(`POST /materials/{id}/merge-plan` · `/merge`, `materials/merge.py`). 같은 계산으로 계획을
   만들고, 막히는 까닭(`blocked`)이 하나라도 있으면 합치지 않는다 — 반만 옮긴 재료는 휴지통에 넣을 수 없다.
2. **옮기는 것(행)**: 시료 전부(휴지통의 것도 — 되살리면 받는 재료로 돌아오게. 시편 · 시험 · 처리 결과 ·
   채택이 따라가고 이름은 받은 재료 기준으로 다시 계산) · 카드(코멘트 「재료 합치기 — …」) · 묶음 기록 ·
   저장한 대표 곡선 · 계수 묶음 · 문헌 연결 · 워크벤치에 담긴 줄 · BOM 이름 매칭. 시료 이동과 달리 카드 ·
   기록도 옮긴다 — 같은 재료의 것이고, 옛 재료는 휴지통으로 간다.
3. **채우는 것(값)**: 받는 재료가 비어 있는 칸만 — 밀도 · 푸아송비(근거 `column_evidence` 와 함께) · 별칭 ·
   메모 · 받는 재료에 없는 선언 물성 항목(항목 이름으로 견줌) · 입력 단위 · 적용 부품(`parts.copy_all`).
4. **값이 다르면 받는 재료 우선** — `kept` 에 두 값을 함께 적는다(「푸아송비: 받는 재료 0.3 유지(합칠 재료
   0.29)」). 스펙 두께 · Details 는 이름을 정하는 칸이라 가져오지 않고 다르면 알린다. 한 재료에 하나뿐인
   자리(문헌 연결 · 같은 계수 묶음)가 받는 재료에 이미 있으면 옛 재료에 남기고 `left` 로 알린다.
5. **분류가 같아야 한다**(Family · Category · Grade, 시료 이동과 같은 규칙). Grade 를 잘못 적었으면 재료의
   분류를 먼저 고친다. 두 재료와 옛 재료의 시료 · 시편을 모두 고칠 수 있어야 한다.
6. 옛 재료는 **휴지통**(지우기와 같은 길 — 기준정보 사용 수 · 적용 부품 사용 수를 되돌린다). 감사는 받는
   재료에 `materials.merged`, 옛 재료에 `material.deleted`(사유: 재료 합치기). 화면은 재료 상세 머리의 「다른
   재료와 합치기」, MCP `merge_materials`(기본 미리보기, 도구 131개).

## 대안

- **보내는 재료 우선 · 칸마다 사람이 고름** — 칸마다 고르면 정확하지만 창이 커지고, 대개 받는 재료가 바르게
  적힌 쪽이다. 다른 값을 보여 주고 받는 재료에서 고치게 했다.
- **값을 옮기고 옛 재료에서 지운다** — 되살리기가 뜻을 잃는다. 값(칸 · 선언 물성 · 부품)은 복사하고 옛
  재료에 그대로 둔다. 행(시료 · 카드 등)은 하나만 있어야 하므로 옮긴다.
- **분류가 달라도 합친다** — 다른 재료의 시험을 조용히 만드는 길이 된다(ADR 0079 와 같은 판단).

## 결과

- 코드: `app/modules/materials/merge.py` · `routes.py` · `schemas.py` · `parts.row_key`, `shared/audit.py`
  (`MATERIALS_MERGED`), 화면 `MaterialMergeDialog` · `MaterialDetailPage`, MCP `merge_materials` · 프로브.
- 시험: API 다섯(미리보기는 안 씀 · 합치면 모임과 받는 재료 우선 · 분류 · 같은 재료 · 권한), 화면 둘.
  사보타주 넷(받는 재료 우선 · 카드 · 분류 · 빈 시료) 모두 물었다.
- 남긴 것: 묶음 기록은 옮기되 다시 묶지 않는다(구성원 시험은 이제 받는 재료에 있으니 그대로 쓸 수 있다).
  선언 물성은 항목 이름으로만 견준다 — 같은 항목의 온도점이 다르면 받는 재료의 줄을 두고 알린다.
