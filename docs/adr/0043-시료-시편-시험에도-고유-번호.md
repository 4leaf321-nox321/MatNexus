# 0043. 시료 · 시편 · 시험에도 고유 번호 — S · P · T

날짜: 2026-09-30
상태: 채택
관련: [ADR 0004](0004-재료-계층과-식별자-정책.md)(이름은 계층에서 계산한다) ·
[ADR 0042](0042-다른-두께에-넣은-시편은-고른-것만-옮긴다.md)(옮기면 이름이 바뀐다)

## 배경

이름은 계층을 밑줄로 엮는다 — `SECC_MDOI_1.0__01__MD_01__TEN_01`. 길어서 말 · 메신저로 전하기
어렵고, 재료 개명이나 다른 두께로 옮기기(ADR 0042)에 따라 **바뀐다.** 재료에는 2026-09-05 부터
안 바뀌는 번호(`M-000082`)가 있었지만 시료 · 시편 · 시험에는 없었고, 재료 번호도 상세 제목 옆에
흐린 글씨로만 있어서 「번호가 화면에 안 나온다」 는 말을 들었다.

요청(2026-09-30): 「모든 재료, 시료, 시편, 시험 데이터에 고유 id 가 있는 게 좋겠다. 명칭만으로는
`_` 로 엮여 있어 의사전달이 어렵다.」

## 결정

1. **머리글자는 재료 `M` · 시료 `S` · 시편 `P`(Piece) · 시험 `T`**, 숫자 여섯 자리
   (`T-000203`). 사용자가 셋 중에서 골랐다 — 시료와 시편이 둘 다 S 로 시작해서 시편을 P 로 뒀다.
2. **재료 번호와 같은 방식이다.** DB 시퀀스가 매기고(server default — 만드는 코드가 몰라도
   붙는다), 종류마다 따로 1부터, 한 번 붙으면 안 바뀌고, 지워도 재사용하지 않는다. 기존 행은 등록
   순으로 매기고 **등록 시각이 같으면 이름순**이다 — 한 트랜잭션으로 넣은 묶음(이관 · 일괄 등록)은
   시각이 같아서 id(무작위)로 가르면 `__MD_01` · `__MD_02` 의 번호가 뒤섞인다. 지운 행도 번호를
   받는다(옛 문서가 가리킬 수 있다).
   시퀀스에 maxvalue 999999 를 둔다(`lpad` 는 넘치면 조용히 자른다).
3. **사람이 치는 꼴을 맞춘다** — `T-000203` · `T-203` · `t203` 은 같은 번호다
   (`app/shared/codes.py`). 정확 일치라 유니크 색인을 탄다.
4. **어느 목록에서든 어느 번호로든 찾는다.** 사람은 손에 든 라벨의 번호를 친다.
   - 시험 목록에 시편 번호 → 그 시편의 시험, 재료 · 시료 번호 → 그 아래 시험
   - 시편 목록에 시험 번호 → 그 시험의 시편, 시료 · 재료 번호 → 그 아래 시편
   - 재료 목록에 시료 · 시편 · 시험 번호 → 그것이 든 재료
   - 전체 검색은 번호 꼴이면 그 종류에서 번호가 같은 것을 맨 위에 두고(「번호 T-000203」 으로
     걸렸다고 말한다), 결과마다 번호를 싣는다
5. **보이는 자리** — 목록(재료 · 시편 · 시험)은 첫 열 「번호」(정렬 가능), 상세 제목(재료 ·
   시험)은 누르면 복사되는 번호 칩, 재료의 시료 · 시편 탭은 시료 카드와 시편 표에, 전체 검색
   결과에. 데이터 내보내기(CSV)의 시료 · 시편 · 시험 표에 `code` 열, MCP 응답에 `code`.

## 대안

- **계층 번호(`M-82-01-P03`)** — 버렸다. 이름과 같은 문제(길고, 옮기면 바뀐다)를 되풀이한다.
  번호는 어디에 속했는지를 말하지 않는 것이 요점이다 — 그것은 이름과 화면이 말한다.
- **UUID 앞부분(`b6672132`)** — 버렸다. 말로 못 부르고, 종류가 안 보인다.
- **전 종류 하나의 번호 줄** — 버렸다. 종류가 머리글자로 드러나는 편이 전하기 쉽고, 재료 번호가
  이미 종류별이다.

## 결과 (2026-09-30)

- 개발 DB 백필: 시료 134 · 시편 269 · 시험 261, 모두 유일. 다른 두께로 옮겨도 번호는 그대로다
  (시험 `tests/api/test_codes.py`).
- 사보타주 4곳(자릿수 맞추기 · 시편 목록의 시료 번호 · 시험 목록의 번호 가지 · 전체 검색의 번호
  가지) 모두 물었다.
