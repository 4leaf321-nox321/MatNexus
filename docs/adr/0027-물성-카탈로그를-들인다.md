# 0027. 물성 카탈로그를 들인다 — 별도 모듈, 무손실, 파일이 유일한 문

날짜: 2026-09-05
상태: 채택
관련: [[계획] MaterialTwin 이식](../%5B계획%5D%20MaterialTwin%20이식.md)

## 결정

MaterialTwin 의 물성 카탈로그(재료 2,663 · 물성값 42,209 · 출처 3,013 · 물성 정의
271)를 MatNexus 에 들인다. 세 가지를 못 박는다.

1. **별도 모듈이다.** `app/modules/catalog` 에 새 표 4개
   (`catalog_materials`·`catalog_sources`·`catalog_definitions`·`catalog_values`)로
   받고, 기존 표(materials·기준정보 등)는 한 줄도 바꾸지 않는다.
2. **무손실이다.** 원본 컬럼 전부가 대상 컬럼에 1:1 로 간다. `attributes`·
   `conditions` 같은 JSON 은 **그대로**(정정 이력 `*_before_correction`, 판정
   `verdict_*`, 부재 판정 `core_*` 포함) 나른다. 이관기는 원본 표의 컬럼 목록을
   전수 대조해서 **모르는 컬럼이 있으면 진행을 거부**한다 — 미래 스냅샷의 새
   컬럼이 조용히 버려지는 일을 구조로 막는다.
3. **materialtwin.db 파일이 유일한 문이다.** 카탈로그 데이터는 어느 환경(개발·
   운영)에서든 「이관 스크립트 + 원본 .db 파일」로만 들어간다. 개발 DB 를 운영으로
   복사하는 경로는 없다 — 개발 DB 에는 테스트 임시 데이터가 섞여 있고, 그것이
   운영에 갈 길 자체를 만들지 않는다.

## 배경

- 카탈로그 재료는 문헌·데이터시트상의 등급/제품이고, MatNexus 재료는 사내에 실물
  lot 이 있는 것이다. 수명주기(등록·시험·카드·삭제)가 달라 한 표에 섞으면 양쪽
  규칙이 서로를 깬다. 연결이 필요해지면 사내 재료 쪽에 선택 링크 컬럼 하나로
  잇는다(이번에는 안 만든다).
- 원본의 품질 체계(tier 1~4, `assumption` 표지, method 의 `digitized` 분리)는 값의
  일부다 — 등급을 지우면 "그 제품 실측"과 "계산 추정"이 구별을 잃는다. **tier4 도
  똑같이 쓴다**(2026-09-06 사용자 결정) — 추정·가정값도 필요해서 모은 데이터다.
  구별은 배지·출처 표기로만 하고, 채택·내보내기 어느 경로에서도 기본 제외하지
  않는다. 판단은 등급을 보는 사람이 한다.
- 물성 정의 271종의 단위는 원본 taxonomy 를 정본으로 **그대로** 둔다. matcore
  단위표에 없는 단위(HV·ShoreA 등)가 있어 억지로 꿰면 값이 상한다 — matcore
  차원과의 매핑은 필요해질 때 별도 표로 한다. 기준정보 `property_item` 축과도
  같은 이유로 매핑 표로 잇는다(통합하지 않는다).

## 멱등의 열쇠

각 표에 원본 id 를 `mt_id`(유니크)로 보존한다. 재실행하면 `mt_id` 로 대응행을
찾아 갱신하고, 없던 것만 넣고, **지우지 않는다**. 이관기는 드라이런이 기본이고
`--apply` 라야 쓴다 — 원본 파이프라인의 규율을 그대로 가져온 것이다.

## 운영 반영 절차

**`deploy.ps1` 이 자동으로 한다**(2026-09-06 고침, 아래 참조). 사람이 할 일은
없고, 새 스냅샷을 들일 때만 손으로 돌린다.

## 고침 (2026-09-06): 원본을 패키지에 동봉한다

처음에는 사람이 운영 서버에 `materialtwin.db`(84MB)를 반입해 손으로 돌리는
절차였다. **그것이 실제로는 「아무도 안 하는 절차」다** — 핸드북 씨앗이 같은
모양이었고, 운영 가이드가 통째로 빈 채로 있었다(실측 2026-08-31: 씨앗 파일은
서버에 이미 가 있었는데 넣는 명령을 아무도 안 돌렸다).

그래서 이관이 읽는 여섯 표만 깎아 `backend/seeds/catalog/materialtwin.db.gz`
(5.4MB)로 저장소에 두고, `deploy.ps1` 이 배포 끝에 `--apply` 로 돌린다. 실패해도
배포는 세우지 않는다 — 문헌 물성이 비는 것은 불편이지 장애다.

**「파일이 유일한 문」 은 그대로다.** 그 규칙이 금지하는 것은 개발 DB 를 운영으로
덤프하는 것이고, 얼어붙은 원본을 패키지에 실어 같은 스크립트로 넣는 것은 오히려
재현성을 더한다 — 어느 환경이든 같은 파일에서 같은 결과다. 잃은 것은 「사람이
드라이런으로 수를 확인한다」 는 한 단계인데, 이관기가 스키마 대조로 거부하고
검산 실패 시 rollback 하므로 그 확인은 자동으로 남아 있다.

씨앗은 `make_catalog_seed.py` 가 깎고, 그 표 목록은 이관기의 `EXPECTED_COLUMNS`
를 그대로 따른다 — 손으로 적으면 이관이 표를 하나 더 읽게 된 날 씨앗만 옛것으로
남는다. CI 가 씨앗과 이관기를 대조한다(`test_catalog_seed.py`).

## 대안과 기각 이유

- **기존 materials 에 합친다** — 기각. 수명주기·유일 제약(record_name)·소유(부서)
  전부가 카탈로그와 안 맞고, 테스트 데이터와 섞인다.
- **선언 물성(JSONB)에 얹는다** — 기각. 42,209건을 재료별 JSON 배열에 넣으면
  검색·출처 FK·등급 필터가 전부 불가능해진다.
- **개발 DB 에서 채워서 운영으로 덤프** — 기각. 개발 DB 의 임시 데이터가 함께
  간다. 파일→스크립트 단방향만 둔다.

## 결과

재현 가능한 카탈로그: 운영이든 새 환경이든 같은 파일에서 같은 결과. 원본이
갱신되면(새 스냅샷) 같은 스크립트로 재이관 — 컬럼이 늘었으면 이관기가 거부하며
알려 주고, 그때 매핑을 늘린다.
