# 0063. SP 코어 온톨로지는 받기와 잇기를 가른다 — 받은 원본은 그대로, 잇기는 운영에서 AI 로

## 배경

Standard Platform(SP)에는 코어 온톨로지가 있다 — 업무 공통(부서 · 사람 · 기관 · 설비 · 장비 · 소프트웨어 ·
기술 분야 · 업무 · 문서)과 PLM 기준정보(프로젝트 · 시험 주체 · 과제 · 개발모델), 그리고 운영 SP 에만 있는
물성 · 물성군 · 물성 분야. SP 는 바깥 시스템이 이것을 읽어 가는 창구(`/api/core`, `core:read` 토큰)를 둔다.

사용자(2026-10-21): SP 의 코어를 받아 MatNexus 기준정보에 이어야 한다. 다만 **물성 · 물성군은 확실히
겹치는데 다른 것은 애매하다** — 기관이 제조사인지 거래처인지, 부서가 사업부인지 시험실인지, SP 장비가 기준정보의
「장비」 인지 한 대씩 적는 「보유 장비」 인지. 그리고 **잇는 일은 개발 서버가 아니라 운영에서 AI(MCP)로** 하는
편이 맞다 — 개발 DB 에는 운영의 기준정보 값이 없고, 개발 서버는 운영 SP 에 닿지 못한다.

MatNexus 의 구조를 SP 온톨로지 모양(범용 객체 · 속성 · 관계)으로 바꾸는 것은 따로 따져 버렸다(같은 날 대화) —
곡선 · 처리 결과 · 채택 · 권한 · 휴지통 · 단위가 정해진 표와 DB 제약에 서 있어 사실상 다시 짓는 일이고, SP 연동
지침서도 「내부를 바꾸라」 가 아니라 「읽어 갈 창구를 내라 / 창구에서 읽어 가라」 다.

## 결정

1. **받기와 잇기를 가른다.**
   - 받기: 운영 MatNexus 가 운영 SP 의 코어 API 를 하루 한 번(워커 `sp_core.pull`) · 자료 관리자가 부를 때 읽어
     **받은 원본**(`sp_core_types` · `sp_core_objects` · `sp_core_relations`)에 그대로 쌓는다. 기존 표는 건드리지
     않는다. 설정은 `SP_CORE_URL`(…`/api/core`) · `SP_CORE_TOKEN`(`core:read`) — 비면 받지 않는다.
   - 잇기: SP 객체 ↔ MatNexus 대상(기준정보 값 · 물성 · 물성군 · 물성 분야)을 `sp_core_links` 에 **기록한다.**
2. **받기는 지침서 §4.2 의 받는 쪽 규칙을 그대로 지킨다.** `as_of` 는 SP 가 준 것을 끝까지 받은 뒤에만 저장
   (쪽마다 커밋하되 시계는 끝에서) · 지운 것은 표시만(되살아나면 살린다) · `renamed_from` · `previous_keys` 로
   옛 행을 찾아 키를 옮기고 **받은 선 · 연결도 함께** · 사라진 객체를 끝점으로 하는 선은 이쪽이 끊는다 ·
   일주일에 한 번 처음부터 받아 부재 대조 · 404 두 코드를 가른다(공개 해제는 멈추고 알림, 커서는 다시) · 선이
   `reset` 이면 처음부터. 실패는 예외 대신 실행 기록(`sp_core_runs`)에 남긴다 — 밤에 도는 일이라 남는 것이 그것뿐이다.
3. **잇기는 사람이 확인한 것만.** 대조(`match`)는 key 가 같거나 이름 · 별칭의 비교키가 **하나에만** 맞는 것을
   후보로, 둘 이상은 「애매함」 으로 따로 낸다. 비슷한 이름은 후보가 아니다. 후보도 저절로 잇지 않는다 — AI 가
   미리보기를 사람에게 보이고 확인받은 뒤 잇는다(ADR 0061 의 모양). 오류가 한 줄이라도 있으면 하나도 안 잇는다.
   잇기 · 끊기 · 받기 부르기는 자료 관리자이고 **사람이 해도 감사에 남긴다**(분류와 같은 전사 자산).
4. **연결은 지금 아무 값도 바꾸지 않는다.** SP 정본으로 잠그기 · SP 이름으로 덮기 · SP 에만 있는 것을 새 값으로
   만들기는 연결이 쌓이고 어느 축이 어느 타입인지 굳은 뒤 따로 정한다.
5. **화면을 두지 않는다**(`BACKEND_ONLY` 의 `sp_core`). 잇는 일은 MCP 도구 여섯(`sp_core_status` ·
   `find_sp_core_objects` · `match_sp_core` · `link_sp_core` · `unlink_sp_core` · `sync_sp_core`)으로 한다. 도구
   설명 예산을 56,500 → 58,500 으로 올렸다(사용자 결정, `tests/architecture/test_mcp_tools.py`).
6. **물성 목록의 방향(ADR 0054)은 그대로다** — 물성은 MatNexus 가 정본이고 SP 가 읽어 간다. SP 의 물성 · 물성군을
   받아 두는 것은 **대조용**이다(MatNexus 키와 같은지, SP 쪽에만 있는 것이 무엇인지).

## 대안

- **SP 타입을 기준정보 축에 코드로 못 박고 받자마자 값으로 넣는다** — 대응이 애매한 지금 개발 서버에서 정하면
  운영 데이터를 못 본 채 정하게 되고, 틀리면 기준정보 값이 SP 이름으로 덮인다(되돌리기 어렵다). 버렸다.
- **받은 객체를 기준정보 값으로 바로 쓴다(값을 SP 객체로 갈아 끼운다)** — 재료 · 시편 · 시험이 기준정보 값을
  외래키로 가리킨다(ADR 0010). SP 키가 바뀌면 그 참조를 옮겨야 하고, SP 가 없는 설치는 기준정보가 비게 된다.
  연결 표로 옆에 걸었다 — 키가 바뀌면 연결의 `sp_key` 만 옮긴다.
- **웹훅으로 받는다**(지침서 §4.5) — 본문에 값이 없고 「바뀌었다」 신호뿐이라 결국 코어 API 를 다시 읽는다. 주기
  동기화가 지침서의 권장이다. 나중에 즉시성이 필요하면 웹훅을 「지금 받기」 의 방아쇠로만 더한다.
- **SP 의 연동 키트(`sp_core_pull.py` · SQLite)를 그대로 돌린다** — 받은 것이 MatNexus DB 밖에 남아 대조 ·
  연결 · 감사와 이어지지 않는다.
- **연결에 받은 원본의 외래키를 건다** — SP 키가 바뀌면 행이 옮겨지는데 외래키는 id 라 문제는 없지만, 받은 원본을
  다시 받는(재적재) 날 행이 갈리면 연결이 끊긴다. `(sp_type, sp_key)` 로 들고 키를 옮기는 자리를 한 곳에 둔다.

## 결과

- 코드: `app/modules/sp_core/`(client · sync · links · routes · jobs), `app/shared/link_targets.py`(잇는 대상
  목록 — 기준정보 · 문헌 물성을 함께 보는 일이라 공용), 마이그레이션 `c8e2a7d4f1b6`(표 다섯), 설정 둘, 감사 행위
  셋(`sp_core.linked` · `sp_core.unlinked` · `sp_core.sync_requested`).
- 시험: `tests/api/test_sp_core.py` — SP 를 흉내 낸 창구로 쪽 넘기기 · 중간 실패(as_of 안 옮김) · 증분(since) ·
  삭제 · 병합 · 되살림 · 키 변경(선 · 연결 함께) · 부재 대조 · 커서 오류 · 공개 해제 · 선 reset · 틀린 토큰, 그리고
  대조(키 · 이름 · 별칭 · 애매함) · 잇기(미리보기 · 하나라도 틀리면 안 잇음 · 감사) · 끊기 · 권한.
- **남은 것**: 운영 SP 의 실제 공개 타입 · 칸을 보고(첫 받기 뒤 `sp_core_status`) 어느 짝을 견줄지 사람과 정하기,
  연결의 효과(잠금 · 덮어쓰기 · 새 값 만들기) 결정, 개발 SP(WSL 8041)로 실제 받기 리허설(토큰이 필요하다).
