# 0049. 선언 물성은 자료 관리자 승인으로 한 단계 오른다 — 승인은 값에 묶인다

날짜: 2026-10-02
상태: 채택
관련: [ADR 0016](0016-시험이-주지-않는-물성은-선언한다.md)(선언 물성) · [ADR 0035](0035-보기는-모두에게-고치기는-사람에게.md)(검토의 뜻이 있는
일은 자료 관리자) · [ADR 0012](0012-물성-카드는-블록의-모음이다.md)(카드는 근거를 든 스냅샷) · `shared/tiers`(품질 등급 1~4)

## 배경

요청(2026-10-02): 「선언 물성으로 선언한 것도 관리자 승인 같은 것을 통해 높은 등급의 물성이 되도록
하면 좋겠다.」

선언 물성의 등급은 출처 하나로 정해졌다 — 데이터시트 · 밀시트 1 · 규격 2 · 문헌 3 · 추정 4. 문헌이
3 인 까닭은 「어느 문헌인지 · 그 문헌의 등급을 모른다 — 보수적으로」 였다. 그래서 자료 관리자가
「ASM Handbook Vol.1 p.120」 을 직접 펴 보고 맞다고 한 값과, 누가 옮겨 적었는지 모르는 값이 같은
3 이었다. 그 차이가 남을 자리가 없었다.

걸리는 원칙이 하나 있었다 — **등급은 사람이 매기지 않는다**(`shared/tiers`). 매기게 두면 근거와
등급이 두 벌이 되고 갈린다(표본을 하나 더 채택했는데 등급은 그대로인 채로).

## 결정

1. **승인은 등급이 아니라 근거다.** 자료 관리자가 근거 문서와 대조해 「승인」 하면 줄에 「누가 ·
   언제 · 무엇을 확인했나」 가 붙고, 등급은 여전히 출처와 그 사실에서 산출한다. 사람이 등급 숫자를
   고르는 길은 없다.
2. **한 단계 오르되 2 위로는 안 간다.** 문헌 3 → 2 · 추정 4 → 3. 규격 2 · 데이터시트 · 밀시트 1 은
   그대로다. 1 은 「그 제품 문서에 인쇄된 실측」 이다 — 승인은 근거를 확인한 것이지 실측을 만들지
   않는다. 승인으로 1 이 되면 등급 1 이 「잰 값」 이라는 뜻을 잃는다.
3. **승인은 값에 묶인다.** 줄에 승인과 함께 그때 값의 지문(값 · 조건 · SI 단위 · 척도 · 출처 · 근거
   문서, 유효숫자 9자리)을 남기고, 읽을 때마다 지문이 지금 값과 같은지 본다. 하나라도 바뀌면 승인은
   없는 것이 된다. 비고와 표시 단위는 지문에 안 든다 — 비고를 다듬거나 MPa 를 GPa 로 바꿔 보이는 것은
   값을 바꾸는 일이 아니다. 유효숫자 9자리는 화면이 값을 12자리 · 조건을 10자리로 되보내므로,
   고치지 않고 다시 저장한 것만으로 풀리지 않게 하려는 것이다.
4. **고치는 길(PATCH)로는 승인이 안 들어온다.** 지문은 누구나 셈할 수 있어, 받은 줄의 승인을
   받아 주면 아무나 승인을 적어 넣는다. 세 겹으로 버린다 — 입력 스키마(모르는 칸) · `check`(줄을 새로
   지음) · `carry`(마지막 문으로 명시적으로 뗌). 그런 뒤 **저장돼 있던** 승인 중 지문이 그대로인 것만
   옮긴다(`shared/declared_approval.carry`). 승인은 승인 길로만 생긴다. 사보타주에서 드러났다 — 처음엔
   앞의 두 겹에만 기대고 있어 `check` 를 뚫어도 시험이 안 물었다(스키마가 우연히 막고 있었다).
5. **자료 관리자 · 시스템 관리자만**(`permissions.require_steward`). 카드 확정 · 핸드북 승인과 같은
   「검토의 뜻이 있는 일」 이다. 값을 고칠 수 있는 등록자 · 편집 부서도 스스로 승인하지 못한다.
   **리뷰 큐는 두지 않는다** — 카드 확정(D8)과 같다. 상태만 두고 절차는 운영이 보인 뒤에 만든다.
6. **흔적.** 승인 · 거둠 · 풀림(값을 고쳐 승인을 잃음)이 감사에 남는다(`declared.approved` ·
   `declared.unapproved` · `declared.approval_lapsed`). 풀림은 값을 고친 사람의 이름으로 남는다 —
   「이 값은 왜 등급이 내려갔나」 의 답이다. 고치는 것 자체는 막지 않는다(고칠 권한은 ADR 0035 그대로).
7. **어디로 가든 승인을 안다.**
   - 응답: 선언 줄마다 `quality_tier`(서버가 센 것) · `tier_if_approved` · `approval`(지금 값에 유효한
     것만). 화면이 출처 → 등급 표나 「한 단계, 2 까지」 를 따로 들지 않는다.
   - 카드: 칸의 출처 표지가 `declared:<출처>+approved` 가 된다 — 카드는 만들 때의 승인을 든다
     (근거를 든 스냅샷, ADR 0012). 덱 각주 등급 · 근거 말(「사람이 적은 값 (문헌 · 자료 관리자 승인)」)이
     그것을 읽는다. 승인 전에 만든 카드는 옛 등급 그대로다.
   - 물성 지도 · 값으로 찾기(최소 등급 거르기) · 데이터 내보내기 CSV(`quality_tier` · `approved_at`).
     CSV 는 **승인한 사람 이름을 안 싣는다** — 이 묶음은 사람을 일부러 뺀다.
   - MCP: 읽기에 `quality_tier` · `approval`, 승인 도구는 **두지 않는다**(「사람이 원문을 펴 봤다」 는
     기록이라 AI 가 대신할 수 없다). 값 쓰기 · 문헌 반영 미리보기가 승인된 값을 덮어쓰면 알린다.

## 대안

- **자료 관리자가 등급 숫자를 고른다.** 사람이 매기는 등급이 된다 — 근거와 등급이 두 벌이 되고,
  승인 뒤 값을 고쳐도 숫자는 그대로 남는다. 기각.
- **승인을 1 까지 연다.** 「사내 공인값」 으로 쓰고 싶은 마음은 이해되지만, 1 은 문헌 쪽에서도 「그
  제품을 실제로 잰 값」 이다. 승인된 핸드북 값이 1 이 되면 같은 척도 안에서 1 의 뜻이 둘이 된다.
  기각 — 사내 공인값이 필요하면 확정 카드가 그 자리다(ADR 0035 D3).
- **승인을 별도 표에 둔다.** 이력이 남고 위조 걱정이 적지만, 선언 물성이 JSON 한 칸이라 마이그레이션 ·
  조인이 따라오고, 재료를 다른 두께로 복사할 때 승인을 따로 옮겨야 한다. 줄에 두고 지문으로 묶으면
  값이 그대로인 한 어디로 복사돼도 유효하고, 바뀌면 저절로 풀린다. 이력은 감사가 든다. 기각.
- **승인 요청 · 리뷰 큐.** 카드 확정과 같은 판단으로 지금은 안 둔다(결정 5).
- **등록자 본인 승인 금지(네 눈 원칙)를 자료 관리자에게도.** 자료 관리자가 직접 적은 값도 스스로
  승인할 수 있다 — 카드 확정 · 핸드북 승인과 같다. 자료 관리자가 한 사람인 부서에서 막히기 때문이다.
  운영에서 문제가 되면 연다.

## 결과

- 재료 상세 물성 요약 줄에 「등급 N」 · 「승인」 표시, 편집 창 아래 「승인」 칸(자료 관리자에게만 단추,
  고치는 중에는 잠김 — 저장된 값을 승인한다). 밀시트 창도 같다.
- 엔드포인트 넷: `POST /materials/{id}/declared/approve` · `/unapprove`, `POST /samples/{id}/declared/approve`
  · `/unapprove`(본문 `{item, note}`). 오류 `MNX-MATERIALS-0044`(권한) · `0045`(없는 항목) · `0046`(이미
  승인 / 승인 안 됨).
- 마이그레이션 없음 — 승인은 선언 물성 JSON 줄 안에 산다.
- 시험: `tests/api/test_declared_approval.py`(등급 규칙 · 지문 · 승인 · 권한 · 되보내기 · 풀림 · 위조 ·
  시료 · 카드 · 근거 말 · CSV), `tests/unit/test_mcp_declared_points.py`(덮어쓰기 경고), 화면 시험(편집 창 ·
  요약 · 카드 출처 말). 사보타주 아홉(권한 판정 · 풀림 기록 · 읽을 때 지문 · 위조 두 갈래 · 2 상한 · 카드
  등급 · 비고 지문 · CSV 등급)을 시험이 전부 물었다.
- 점검(개발 서버): 승인 → 등급 3 → 2 · 거듭 승인 409 · 물성 지도 등급 2 · 거두면 3. MCP 프로브 101건 중
  100(남은 1은 자료에 따른 거절). AI 세션은 「네가 승인해 줘」 를 승인 도구가 없고 원문을 안 본 승인은 거짓
  기록이라며 거절하고, 규격 값은 이미 상한이라 안 오른다고 답했다.
- **열린 것**: 승인을 기다리는 값을 모아 보는 자리(지금은 재료마다 본다) · 승인 요청 알림 · 승인한
  사람이 바뀐 값을 다시 볼 수 있게 「풀린 승인」 목록.

## 덧붙임 (2026-10-04)

- **나중에 더한 칸은 있을 때만 지문에 든다**(`_EVIDENCE_IF_PRESENT`). 선팽창계수 표의 할선 기준 온도
  θ₀(`secant_reference_k`)를 더하면서 정했다(사용자 결정). 늘 넣으면 그 칸이 없는 옛 줄도 몸통에 `null` 이
  생겨 지문이 바뀌고, **배포하는 순간 운영의 승인이 전부 풀린다.** 시험이 θ₀ 를 들이기 전 판의 지문을
  글자로 박아 두었다(`test_declared_approval.Test할선_기준_온도`). 앞으로 칸을 더할 때도 이 목록에 둔다.
- 「승인을 기다리는 값을 모아 보는 자리」 는 닫았다 — 「승인 대기 값」 화면(`GET /materials/declared-review`).
  큐는 여전히 아니다(결정 5).
