# 0093. 덱은 소성 없이 나간 줄을 빠짐없이 알리고, 받는 덱의 탄성 값을 지킬 수 있으며, 출처를 덱 글자가 든다

날짜: 2026-11-17
상태: 채택
관련: [ADR 0036](0036-나가는-숫자의-기본-단위계는-mm-N-tonne.md)(덱 단위계) · [ADR 0094](0094-문헌-범위의-끝은-대표값-뒤로-서고-끝만-있으면-그렇다고-말한다.md)(같은
연결에서 드러난 대표값 결함)

## 배경

외부 시스템(HWAX)을 MCP 로 붙이며 세 가지가 드러났다.

1. **항복값이 없으면 말없이 *MAT_ELASTIC.** `build_deck` 에 재료 id 를 주면 서버가 카드마다
   `소성 → 점탄성 → 탄성` 차례로 되는 첫 형식을 골랐다(`_pick_card_deck`). 소성 표가 없는 카드는 탄성 형식으로
   나갔고 응답에는 어느 형식이었는지가 없었다. 문헌 줄은 「곡선 합성」 을 안 켜면 항복이 있어도 늘 탄성이었다.
   MCP 는 백엔드의 `notes` 도 버렸다. 확정 카드를 먼저 대 보므로, 확정 카드가 탄성뿐이면 초안의 소성 표를 두고
   탄성으로 나갔다.
2. **받는 덱의 ro · e · pr 이 바뀐다.** 받는 쪽은 MID 로 재료를 통째로 바꿔 넣는다. 곡선만 바꾸려던 사람의
   모델 밀도 · 탄성계수 · 푸아송비가 MatNexus 값으로 바뀌었다. MatNexus 는 받는 쪽 덱을 몰랐다.
3. **덱 값의 출처를 거꾸로 못 찾는다.** MID 는 카드 UUID 를 줄인 해시라 거꾸로 셀 수 없다. 덱 머리에는 카드
   번호만 있고 재료 · 시험 id 가 없었다. MCP `render_card_deck` 의 `mid` 는 받은 인자를 되돌려 null 이었다.

사용자 결정(2026-11-17): 대체의 기본은 지금처럼 탄성 + 반드시 보고, 받는 덱의 값은 MatNexus 가 받은 덱을 읽어
지킨다(A안).

## 결정

1. **대체 판정은 하나**(`matcore/export/fallback.py`). `elastic` — 구조 형식인데 소성 표가 없다(서버가 탄성
   형식을 골랐거나, 형식이 소성 표를 선택으로 받는데 재료에 없다). `yield_from_uts` — 항복 없이 인장강도를
   평탄부로 지은 합성 표(`synth.YIELD_FROM_UTS_MODEL`). 사람이 탄성 형식을 직접 고른 줄(`format` ·
   `lit_format`)은 대체가 아니다. 점탄성 · 초탄성 · 열 형식도 아니다.
2. **`on_missing_yield`**(`elastic` 기본 · `reject`). `elastic` 이면 대체한 줄을 `fallbacks` 에 빠짐없이 적는다.
   `reject` 면 그 줄은 `skipped` 로 가고, 같은 재료의 다른 카드에 소성 표가 있으면 그 카드를 고른다 — 덱에 탄성
   재료가 0건이다. 화면 BOM 덱은 「소성 없이 나간 부품」 상자로 보인다.
3. **`keep_deck_values` + `base_deck`**(LS-DYNA). 받은 덱에서 MID 마다 ro · e · pr 을 읽어(`dyna_base.read`) 같은
   MID 의 탄성 블록에 SI 로 되돌려 넣는다(`dyna_base.keep`). 첫 카드가 `MID RO E PR` 인 키워드만 읽는다 —
   `*MAT_GENERAL_VISCOELASTIC` 의 셋째 칸은 BULK 라 짐작하면 체적탄성률이 탄성계수가 된다. 지킨 값의 출처 줄은
   덱 머리에서 「받은 덱의 값으로 둠」 으로 바꾸고, 온도별 탄성 표는 뺀다. 못 읽은 재료 · 없는 MID 는 알린다.
   MCP 는 덱 파일(`base_deck_path`)에서 재료 카드만 뽑아 보낸다(차 한 대 덱은 수백 MB).
4. **출처는 덱 글자가 든다 — 전역 MID 는 관리하지 않는다**(`solver_id_from` 의 결정). 카드 덱 머리에
   「근거: 재료 M-… · 시험 T-…」, 문헌 줄에 「문헌 카탈로그: 이름 · id」. 그 글자에서 거꾸로 읽는다
   (`POST /fitting/decks/lineage`, `fitting/lineage.py`). 카드 하나는 `GET /fitting/cards/{id}/lineage`(재료 ·
   근거 시험과 채택 결과 · 그 밖의 근거 · 값마다 출처 · `default_mid`). BOM 응답의 `rows` 가 줄마다 고른 카드 ·
   재료 · 근거 시험이다. MCP `card_lineage`(도구 132개), `render_card_deck` 은 실제로 쓴 `mid` 와 계보 요약.
5. 곁가지(같은 자리): DMA E′ 카드의 시험 목록에 선형 구간을 못 내 뺀 시편까지 들어 있었다 — 값을 낸 시편만
   적는다(계보가 쓰지 않은 시험을 근거로 읽는다).

## 대안

- **기본을 `reject` 로** — 화면 BOM 덱까지 달라진다. 탄성으로라도 받고 싶은 부품(유리 · 세라믹 · 단순 구조)이
  있고, 문제는 대체 자체가 아니라 **말없이** 한 것이었다.
- **받는 쪽이 합친다(B안)** — MatNexus 는 값만 구조로 준다. 덱 칸 차례를 아는 쪽이 MatNexus 라 두 벌이 되고,
  받는 플랫폼마다 같은 함정(BULK 를 E 로)을 다시 밟는다.
- **덱 MID 를 전역으로 관리(내보내기 기록)** — 「어느 덱에 어느 번호를 썼나」 를 관리해야 하고, 받는 쪽이 번호를
  바꾸면 기록이 틀린다. 덱 글자가 출처를 드는 편이 덱과 함께 다닌다.
