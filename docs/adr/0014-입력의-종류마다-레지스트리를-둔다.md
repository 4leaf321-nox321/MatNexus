# ADR 0014 — 입력의 종류마다 레지스트리를 둔다

- 상태: 채택 (v1.55.0)
- 관련: [ADR 0009](0009-경화식은-고르지-않고-견준다.md) ·
  [ADR 0012](0012-물성-카드는-블록의-모음이다.md) ·
  [ADR 0013](0013-물성은-폴더로-붙는다.md)

## 배경

스칼라 분포 적합(정규·로그정규·와이블을 반복 시편 특징값에 맞춘다)을 붙이면서
물음이 하나 있었다. 계획서에 이렇게 적혀 있었다:

> **구조 시험이기도 하다.** 지금 `Family` 는 곡선의 x/y 를 받는데 분포는 **스칼라
> 여러 개**를 받는다 — 확장이 곡선 아닌 입력을 다룰 수 있는지가 여기서 드러난다.

D7("정의는 데이터, 계산은 플러그인")을 세 번 쟀는데 전부 **곡선**이었다. 토우
보정 146줄, 폴리머 점탄성 2,456줄, 고무 초탄성 775줄 — 모두 `(x, y)` 를 받아
`(x, y)` 나 파라미터를 낸다. 분포는 x 가 없다. 값 n 개가 전부다.

## 결정

**`matcore.fitting.Family` 를 넓히지 않고 `matcore.distributions.Distribution`
을 따로 만든다.**

넓히는 길도 있었다. `Family.x_column` 을 선택으로 만들고 `evaluate` 가 x 를 안
받는 경우를 허용하면 한 레지스트리로 끝난다. 그러면 등록 창구가 하나가 되고,
ADR 0013 이 "남은 것" 으로 적어 둔 *"`fitting`·`processing`·`parsers` 의 등록
창구가 아직 따로다"* 에도 어긋나지 않는다.

그런데 그렇게 하면 **Voce 와 Weibull 이 한 목록에서 RMSE 로 줄 선다.**

## 근거

### 나란히 설 수 있는 것만 나란히 세운다

ADR 0009 가 세운 규칙이 이것이다 — 후보를 견주는 화면은 **같은 물음의 답들**만
모아야 한다. 그래서 `Family.applies_to` 가 있다. 금속 경화식과 고무 초탄성을
한 표에 넣으면 RMSE 가 작은 쪽이 이기는데, 그 비교에는 뜻이 없다.

분포는 그보다 한 겹 더 다르다. 경화식과 초탄성은 적어도 **같은 종류의 입력**
(곡선)을 받고 같은 종류의 오차(잔차)를 낸다. 분포는 입력도 다르고 견주는 척도도
다르다 — RMSE 가 아니라 AICc 와 Anderson-Darling 이다. 한 레지스트리에 넣으면
`applies_to` 같은 가드가 하나 더 필요해지고, **가드로 갈라야 하는 것은 애초에
갈라져 있어야 한다.**

### `Optional[x]` 는 두 물음을 한 자리에 앉히는 것이다

`x` 를 선택으로 만들면 `Family` 를 읽는 모든 코드가 "x 가 있나" 를 물어야 한다.
`prepare`·`tangent`·`jacobian`·`stability` 가 전부 `(파라미터, x)` 서명이다.
곡선이 없는 식을 그 자리에 넣으면 그 넷이 다 의미를 잃고, **의미를 잃은 필드는
`None` 으로 채워지며, `None` 이 늘어난 dataclass 는 두 dataclass 다.**

## 결과

### 값

    폴리머 점탄성   2,456줄 / 18파일   마이그레이션 187줄
    고무 초탄성       775줄 /  8파일   마이그레이션 0
    스칼라 분포     1,185줄 /  7파일   마이그레이션 0

**초탄성보다 늘었다.** 파일은 줄었는데 줄이 는 것이 답이다 — 초탄성은 있는
레지스트리에 식 넷을 얹은 것이고, 분포는 **레지스트리 자체를 만든 것**이다
(`matcore/distributions` 616줄). 화면도 얹을 자리가 없어 새로 그렸다(268줄).

D7 의 경계가 한 겹 더 드러났다.

    기존 물성 안의 새 계산     146줄     `@register` 가 덮는다
    기존 레지스트리의 새 식     775줄     `Family` 가 덮는다
    **새 입력 종류**          1,185줄   **덮는 것이 없다 — 레지스트리를 만든다**

### 패턴은 옮겨졌다

`Distribution` 은 `Family` 와 같은 모양이다 — key·label·파라미터 이름·계산
함수들·describe. 그래서 **네 번째 분포를 더하는 값이 12줄**이다(단위 시험의
`Test레지스트리` 가 지수분포로 실증한다).

구조가 재사용되지 않은 것이 아니라, **입력의 종류마다 레지스트리가 하나씩**
필요한 것이다. 그리고 종류는 많지 않다 — 곡선, 스칼라 묶음, 그리고 아직 안 온
것 몇 개다.

### 대가

- **등록 창구가 하나 더 늘었다.** ADR 0013 이 적어 둔 `GET /extensions` 통합이
  그만큼 더 벌어졌다. 지금은 `/families`·`/blocks`·`/formats`·
  `/processing/plugins` 에 분포가 붙는다
- 두 레지스트리가 **비슷하지만 같지 않다.** `Family.evaluate(p, x)` 와
  `Distribution.logpdf(p, x)` 는 서명이 같은데 뜻이 다르다. 읽는 사람이 헷갈릴
  자리이고, 그래서 양쪽 docstring 에 서로를 가리켜 뒀다

### 실측으로 드러난 것 하나

**정규분포로 흩뜨린 표본에서 정규가 1등이 안 된다.**

    초기값 CV 3%  n=60    lognormal 0.0   normal 0.61   weibull 13.64
              n=200   lognormal 0.0   normal 1.90   weibull 42.44
        CV 15% n=60    lognormal 0.0   normal 1.78   weibull  8.17
        CV 30% n=120   normal    0.0   lognormal 0.06  weibull  1.48

재료 시험의 CV 는 3~5% 다. 그 좁은 폭에서 로그정규는 정규와 **수치적으로 거의
같은 곡선**이고, n 을 200으로 늘려도 안 갈린다. 시편을 더 만들어도 답이 안 나온다.

그래서 이 모듈이 내는 답은 *"어느 분포다"* 가 아니라 **"이 중 무엇으로 봐도
하위 5% 는 이만큼이다"** 여야 한다. ΔAICc 가 2 미만인 후보를 안내로 짚는 것이
장식이 아닌 이유다 — 우리 데이터에서는 그것이 **기본 상태**다.

시험 하나를 그 실측에 맞춰 고쳤다. 처음에 `test_정규_표본에서_정규가_1등이다`
로 썼다가 `test_정규_표본에서는_1등을_고를_수_없다` 가 됐다.
