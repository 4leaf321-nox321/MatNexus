# 0030. 계산식은 데이터다 — 식 한 줄이 적합식·스칼라 단계·열 단계가 된다

날짜: 2026-09-13
상태: 채택 (구현 중)
관련: [ADR 0006](0006-장비-파일-정의는-데이터다.md) · [ADR 0023](0023-솔버-덱도-파일로-정의한다.md) ·
[ADR 0007](0007-처리는-레시피와-결과로-나눈다.md) · [ADR 0009](0009-피팅과-솔버-카드.md) ·
[[계획] 계산 확장](../%5B계획%5D%20계산%20확장.md)

## 배경

입력(장비 파일 정의)과 출력(솔버 덱)은 배포 없이 는다. 계산은 파이썬 폴더라 **물성
개발자 + 배포**가 필요하다(1단계에서 창구 다섯을 전부 열어 두고 계약서를 생성했다 —
그래도 개발자 몫이다).

그런데 부서가 실제로 더하고 싶은 계산의 대부분은 **닫힌 식 한 줄**이다:

    경화식     σ = A + B·εⁿ           σ = K·(ε₀ + ε)ⁿ − p
    유변식     η = η∞ + (η₀ − η∞) / (1 + (λγ̇)ᵐ)
    파생 값    항복비 = 항복강도 / 인장강도
    환산 열    진응력 = 공칭응력 · (1 + 공칭변형률)

이런 것을 넣으려고 파이썬을 쓰고 배포를 기다리는 것은 형식 프로파일을 코드에
박아 두던 시절(ADR 0006 이전)과 같은 상태다.

## 결정

### D1. 식은 하나의 장치이고, 등록 자리는 셋이다

평가기(문법·안전·단위) 하나를 두고, 같은 식을 **세 자리 중 하나**에 등록한다. 사람이
자리를 고른다 — 자리마다 받는 것과 내는 것이 다르기 때문이다.

| 자리 | 식의 모양 | 받는 것 | 내는 것 | 등록되는 레지스트리 |
| --- | --- | --- | --- | --- |
| **적합식** | `y = f(x; p₁…pₙ)` | 채택 결과의 곡선 (x, y) | 파라미터 → 카드 블록 | `fitting.Family` |
| **스칼라 단계** | `v = g(@a, @b, …)` | 앞 단계가 낸 스칼라 | 스칼라 하나 | `registry(kind="processing")` |
| **열 단계** | `새열 = h(열₁, 열₂, …)` **점마다** | 프레임의 열 | 새 열 하나 | `registry(kind="processing")` |

**처리 자리에서도 쓰이지만 처리의 전부는 아니다.** F-D → S-S 의 뼈대(정렬·구간
탐색·회귀·교점·자르기)는 점마다의 식이 아니라 **알고리즘**이라 이 길로 안 된다 —
그것은 지금처럼 내장·파이썬 폴더다. 식이 덮는 것은 그 사이의 **환산·조합**과
**경화식 적합**이다. 안 되는 것은 화면이 그 말을 한다.

### D2. 안전한 평가기 — `eval` 이 아니다

`ast` 로 읽어 **허용 노드만** 받는다: 수·이름·사칙·거듭제곱·단항 부호·괄호·허용 함수
호출(`exp log log10 sqrt abs tanh sinh cosh sin cos pow min max where clip`). 속성 접근·
첨자·람다·비교 연산·이름 바인딩은 거절한다. 이름은 선언한 변수·파라미터·상수(`pi e`)만.
numpy 로 벡터 평가한다 — 점마다 도는 열 단계와 곡선을 통째로 맞추는 적합식이 같은
평가기를 쓴다. 미분은 수치로(`tangent` 는 비운다).

식 길이(1,000자)와 노드 수(300)에 상한을 둔다 — 루프가 없으니 실행 시간은 유계다.

### D3. 저장은 표 하나, 등록은 기동·변경 때

새 표 `formulas`: `key · kind(family|scalar_step|column_step) · label · expression ·
variables(JSON: 이름·단위·역할) · parameters(JSON: 이름·단위·초기값·범위) · axes(x·y 열,
적합식) · block(적합식) · applies_to · requires_channels · version · enabled · created_by`.

서버·워커가 **기동할 때** 표를 읽어 레지스트리에 넣고, 저장·수정·삭제 API 가 그 자리에서
다시 넣는다(`formulas.sync`). 워커는 다른 프로세스라 — 작업이 모르는 플러그인 id 를
만나면 한 번 다시 읽고 다시 찾는다(폴링 없음).

**키에 `formula.` 접두어를 붙인다.** 파이썬 확장·내장과 같은 레지스트리에 서되 겹치지
않는다 — 레지스트리는 중복 key 를 거절하므로 접두어가 곧 이름공간이다(`local.` 물성 키와
같은 판단).

### D4. 판(version)이 있고, 저장된 것은 안 바뀐다

식을 고치면 `version` 이 오르고 레지스트리의 항목이 새 판으로 바뀐다. **이미 저장된
레시피·처리 결과·카드는 옛 판 그대로다** — 처리 결과는 `plugin_version` 을 들고
있고(ADR 0007), 카드는 값을 들고 있다. 옛 판으로 다시 돌릴 수는 없다(식 본문의 이력을
두지 않는다) — 그 대신 식을 "고치는" 대신 새 키로 만들고 옛 것을 끄는 길을 화면이
먼저 권한다.

**삭제는 참조가 없을 때만.** 저장된 레시피가 그 단계를 쓰거나 카드가 그 식을 인용하면
지우지 못하고 `enabled=false` 로 끈다 — 물성 키 폐기와 같은 규칙. 끈 식은 목록에서
빠지되 옛 결과는 그대로 읽힌다.

### D5. 단위는 선언하고 검사한다

변수·파라미터·결과에 SI 단위를 적는다(ParamSpec·Produced 와 같은 어휘). 열 단계의
입력 열은 프레임에 그 이름이 **있어야 하고**, 적합식의 축은 계약서의 열 어휘에서 고른다.
단위 **환산은 하지 않는다** — 프레임과 결과는 SI 이고 식도 SI 로 적는다. 결과 단위를
사람이 적는 것이 유일한 자유도이고, 그것이 틀리면 화면·덱이 틀린 단위로 보인다 — 그래서
저장 전 미리보기가 실제 곡선 한 벌로 결과를 보여 준다.

### D6. 저장 전에 돌려 본다

화면은 저장 전에 **실제 채택 결과 하나**를 골라 식을 돌려 보인다 — 적합식이면 파라미터와
R², 열 단계면 새 열의 앞 몇 점, 스칼라 단계면 값. 식이 문법은 맞는데 뜻이 틀린 것(축을
바꿔 적음, 단위가 천 배)은 여기서 드러난다. 미리보기 없이 저장할 수는 있지만 화면이
권하지 않는다.

## 대안

- **파이썬 폴더만 유지** — 부서는 개발자를 기다린다. 형식 프로파일에서 이미 버린 길이다.
- **파이썬 코드를 화면에서 받는다** — 임의 코드 실행이다. 폐쇄망이라도 안 된다.
- **적합식만 데이터로** — 항복비 같은 파생 값은 여전히 파이썬이 된다. 같은 평가기로
  세 자리를 덮는 비용이 작아 셋 다 한다.
- **식의 이력을 전부 남긴다** — 옛 판으로 되돌리기가 되지만 표·화면이 배로 커진다. 지금은
  "새 키로 만들고 옛 것을 끈다" 로 충분하다.

## 결과

- 부서 엔지니어가 화면에서 경화식·유변식·파생 값·환산 열을 더한다. 배포 없음.
- 개발자 몫으로 남는 것: 알고리즘(정렬·탐색·회귀·교점), 묶음, 적분·미분방정식·다중
  곡선 동시 적합(Prony·Anand·초탄성 다중 모드). 계약서에 그렇게 적힌다.
- 기존 계산·레시피·카드·결과는 한 줄도 안 바뀐다. 새 표 하나, 새 화면 하나.
- 사보타주 등급: **높음** — 식 평가는 조용히 틀리는 자리다. 답을 아는 곡선으로 되돌아오는지,
  허용 밖 노드가 거절되는지, 판이 오를 때 옛 결과가 그대로인지를 시험이 못 박는다.
