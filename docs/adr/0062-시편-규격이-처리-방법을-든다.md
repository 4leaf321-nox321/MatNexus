# 0062. 시편 규격이 처리 방법을 든다

날짜: 2026-10-16
상태: 채택
관련: [ADR 0010](0010-기준정보를-외래키로.md)(기준정보) · `app/modules/vocabulary/standards.py` ·
`vocabulary_terms.processing_defaults` · `GET /processing/defaults` · `matcore/processing`(`@?`) ·
확장 `flexural` · `compression`

## 배경

굽힘 · 압축 처리(2026-10-16)를 만들고 나서 사용자가 물었다 — 「처리 로직은 무엇을 보고 고르나?」. 답은
**시험 종류뿐**이었다. 처리 화면은 시험 종류로 기본 순서를 깔고(굽힘이면 굽힘 응력-변형률 → 탄성률(현) →
강도), 시편 규격은 치수 숫자(`@specimen_span` …)만 보탰다. 그래서:

- **4점 시편이 3점 식으로 계산됐다.** 기본 순서에 하중 스팬이 비어 있어, 시편 규격에 하중 스팬이 있어도
  3점으로 돌았다 — 응력과 E 가 오류 없이 틀렸다.
- **규격마다 다른 방법이 안 따라왔다.** D790 은 탄성률을 접선으로, ISO 178 은 현(0.05 ~ 0.25%)으로,
  D7264 · D3410 은 현(0.1 ~ 0.3%)으로 잰다. 기본(현 0.05 ~ 0.25%)으로 돌리면 몇 % 다른 값이 남는다.
  ISO 7743 · ISO 3386-1 은 4번째 하중 구간을 쓴다.

처리 단계는 일부러 규격 이름을 모른다 — 확장은 DB 를 모르고, 같은 계산을 규격마다 복사하면 계산이
규격 수만큼 갈린다.

## 결정

1. **규격 값이 처리 기본값을 든다** — `vocabulary_terms.processing_defaults`(처리 단계 → 옵션 → 값).
   카탈로그(`standards.py` 의 `processing`)가 가져오기 때 함께 심고, 관리자가 규격 치수 창에서 고친다.
   저장할 때 단계 · 옵션 · 선택지를 레지스트리와 대조한다(MNX-VOCABULARY-0031) — 없는 것을 적으면 처리
   화면이 둘 자리가 없어 조용히 버리기 때문이다.
2. **처리 화면이 시편의 규격을 보고 기본 순서를 그 값으로 채우고, 그렇다고 말한다**(「시편 규격 ASTM D790
   기준으로 채웠습니다 — 방법 = 접선」). 사람이 바꿔도 되고, 결과에는 실제로 돌린 옵션이 남는다. 레시피를
   불러오면 레시피가 정한다. AI 는 `list_processing_inputs` 의 `standard_defaults` 로 같은 값을 본다.
3. **「있으면 쓰는」 참조 `@?` 를 둔다.** 없으면 오류 대신 비운다. 굽힘의 하중 스팬 기본이
   `@?specimen_load_span` 이다 — 시편에 있으면 4점, 없으면 3점. 4점 규격(D6272 · C1161 · 사내 4점)은 처리
   기본값으로 `@specimen_load_span` 을 걸어 **없으면 멈추게** 하고, 3점 전용 규격(ISO 178 · D790 · 사내 3점)은
   비움(`null`)으로 고정한다 — 분류가 하중 스팬 칸을 주므로 잘못 적힌 값이 4점으로 돌지 않게.

## 대안

- **레시피를 규격에 묶는다.** 부서가 자기 방식을 저장하기엔 좋지만, 처음에는 레시피가 하나도 없어 규격
  22종마다 레시피를 심어야 하고, 레시피는 단계 전부를 들어 기본 순서가 바뀌면 22벌을 고쳐야 한다. 규격은
  **다른 것만** 들면 된다.
- **코드에 규격 → 방법 표를 둔다.** 규격 값의 이름은 사람이 바꿀 수 있고(같은 규격을 부서가 이름을 바꿔
  한 벌 더 만든다), 관리자가 배포 없이 고칠 수 없다.
- **처리 단계가 규격 이름을 받는다.** 확장이 규격 목록을 알게 되고, 새 규격마다 확장을 고쳐야 한다.

## 결과

- 규격을 고르면 방법이 따라온다. 화면 · AI · API 가 같은 값을 본다.
- 이미 가져온 규격(인장 · DMA)에는 처리 기본값이 없다 — 지금 그대로 돈다. 필요하면 관리자가 적는다.
- 일괄 처리는 한 레시피를 여러 시험에 건다 — 규격별 기본값은 시험마다 다시 채우지 않는다(`@?` 는 시험마다
  풀린다). 규격이 섞인 묶음은 규격별로 나눠 건다.
