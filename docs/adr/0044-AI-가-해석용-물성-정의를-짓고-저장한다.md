# 0044. AI 가 해석용 물성 정의를 짓고, 실제 카드에 그려 보고, 저장한다

날짜: 2026-09-30
상태: 채택
관련: [ADR 0023](0023-솔버-덱도-파일로-정의한다.md)(덱을 파일 정의로) ·
[ADR 0033](0033-카드-항목란을-화면에서-정의한다.md)(카드 항목란) ·
[ADR 0038](0038-정의-문법을-넓혀-기본-형식을-정의로-옮긴다.md)(정의 문법)

## 배경

사용자가 eCAE 전용 물성을 선언 물성으로 적어 두고, 그 값을 싣는 해석용 물성 정의를 MCP 로
AI 에게 짓게 했더니 잘 안 됐다(2026-09-30). 흐름을 대조해 보니 MCP 로는 끝까지 갈 수 없었다.

    예제 덱 → 초안            scan_deck_format  — 초안만. 카드로 이름을 맞춰 주는 인자는 빠져 있었다
    초안 → 정의               없음 — 초안은 화면 폼 모양(`lines`)이라 AI 가 문법으로 옮기다 막혔다
    정의를 카드에 그려 보기     없음 — 백엔드에는 있었다(`/export-profiles/preview`)
    정의 저장                 없음 — 백엔드에는 있었다
    선언 물성 카드에 항목란 싣기  없음 — 카드 만들기 도구가 `block_keys` 를 안 넘겼다

마지막이 가장 컸다. 화면에서 만든 항목란(eCAE 같은)은 값이 있어도 **사람이 골라야** 카드에
실리는데, MCP 가 고를 길을 안 줬다 — 카드에는 탄성 · 열물성만 실리고, 정의는 가리킬 값이 없었다.
AI 용 안내(GUIDE)는 「scan_deck_format → render_card_deck 로 눈으로 확인」 이라고 했지만,
`render_card_deck` 은 **저장된** 정의만 그린다 — 안내대로는 초안을 확인할 수 없었다.

## 결정

1. **AI 가 해석용 물성 정의를 저장한다** — 사용자 결정(2026-09-30). `save_export_profile` 은
   기본이 미리보기(dry_run)이고, 같은 key 가 있으면 `overwrite=True` 가 있어야 고친다. 저장하면
   변경 이력에 「AI 가 해석용 물성 정의 저장」(`export_profile.saved_by_client`)으로 남는다 —
   전에는 사람이 저장해도 AI 가 저장해도 흔적이 없었다.
2. **정의를 저장 없이 실제 카드에 그려 본다** — `preview_export_profile`. 그려졌으면 `error`
   칸을 빼서 돌려준다(이 도구들은 `error` 가 있으면 실패로 읽는 관례다 — 점검에서 그려진 덱이
   실패로 세어졌다).
3. **초안에 바로 쓸 정의를 싣는다** — 예제 덱 초안(`scan`)이 `definition` 을 함께 준다. 줄 폼 →
   정의의 규칙은 화면(`deckLines.ts` 의 `fromScan` → `toDefinitionLine`)과 같고, **두 벌이라
   서버 시험이 화면 시험과 같은 경우를 문다**(빈 칸 `{"const": ""}` · 빈 구분자 · 칸 폭 · 맞춤).
   `scan_deck_format` 에 `card_id` 를 열어 카드 값과 같은 숫자에 이름을 제안하게 했다.
4. **문법은 정본을 그대로 낸다** — `GET /fitting/export-profiles/grammar` 가 `matcore/export/
   template.py` 의 문법 설명을 그대로 준다(`export_definition_grammar`). 따로 적으면 문법을
   넓힐 때 한쪽만 고쳐진다. 기존 정의는 `list_export_profiles(include_definitions=True)` 로
   본보기가 된다.
5. **선언 물성 카드에 항목란을 골라 싣는다** — `create_declared_card(block_keys=…)`, 미리보기가
   고를 수 있는 항목란(`fillable`)과 그 칸에 닿는 값을 보여 준다. 없는 것을 고르면 무엇을
   고를 수 있는지와 함께 거절한다.
6. **빈 칸을 그리면 무엇이 비었는지 말한다** — 전에는 「'블록.값' 으로 적어야 합니다: 」 로
   끝났다(화면도 같은 문구를 본다).

**사람에게 남긴 것** — 카드 항목란 만들기(시스템 관리자)와 선언 물성 항목 ↔ 물성 키 연결(물성
매핑). 둘 다 전 부서에 한꺼번에 먹고, 틀리면 숫자가 그럴듯한 채로 다른 물성 자리에 실린다.
AI 에게 열지는 사용자가 판단 중이다(2026-09-30 질문). → 같은 날 열었다 — 사람 확인 대신 서버
검사를 두고([ADR 0045](0045-사내-물성-들이기를-AI-에게-연다.md)).

## 대안

- **초안 → 정의 변환을 MCP 서버에 둔다** — 버렸다. 세 벌(화면 · MCP · 서버)이 된다.
- **화면의 변환을 걷고 서버 `definition` 만 쓰게 한다** — 이번에는 안 했다. 화면 편집기의 시험이
  촘촘해서 흔들 값이 없었다. 대신 쌍둥이를 서로 가리키게 적고 서버 시험을 붙였다.
- **저장은 사람만** — 처음 제안이었고, 사용자가 AI 저장을 허락했다. 장비 파일 정의
  (`save_format_profile`)가 이미 같은 모양이다(미리보기 기본 · 감사).

## 결과 (2026-09-30)

- MCP 프로브 95건 중 94건 성공(남은 1건은 문헌값 부족 — 자료에 따른 거절). 도구 86개.
- 실제 AI 세션(`claude -p`)에 「이 LS-DYNA 예제 덱 모양으로 정의를 만들어 이 카드로 보여 달라,
  저장은 말고」 를 시켰다: 기존 정의 목록 → 항목란 → 카드 → 초안(카드 지정) → 문법 → 미리보기
  순으로 부르고 **저장하지 않았다.** 저장하면 무엇이 남는지 설명하고, SI 로 뽑으면 10칸 고정폭을
  넘친다는 위험을 먼저 물었다. 재료 번호 자리(`{id}`)를 칸에 넣는 법을 찾느라 미리보기를 다섯 번
  불렀다 — 문법 설명에서 `prefix` 의 자리표가 눈에 덜 띈다.
- 초안의 이름 제안은 **카드의 SI 값과 덱 숫자가 같을 때만** 붙는다. mm · MPa 덱에서는 대개 비고,
  그 칸은 AI(사람)가 채운다.

**열린 것**: 초안의 이름 제안을 단위계를 가로질러(SI · mm-N-tonne) 맞추는 것 · 문법 설명에 재료
번호 자리표 예를 보태는 것.
