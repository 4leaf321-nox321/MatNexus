# 0047. 기본 형식의 정의판은 배포가 꺼진 채 넣는다 — 손대지 않은 것만 씨앗을 따른다

날짜: 2026-10-01
상태: 채택
관련: [ADR 0037](0037-물성-모델마다-솔버-덱을-따로-낸다.md)(사용 중단) ·
[ADR 0038](0038-정의-문법을-넓혀-기본-형식을-정의로-옮긴다.md)(정의판) ·
[ADR 0046](0046-가이드-씨앗은-사람이-안-고친-절만-따라간다.md)(가이드 씨앗 — 같은 규칙)

## 배경

기본 형식(코드판 50 + 중립 JSON)은 코드라 화면에서 못 고친다. 틀린 것이 드러나면 시스템
관리자가 「사용 중단」 으로 내리고(ADR 0037), 같은 내용을 정의로 다시 적은 **정의판**(ADR 0038,
`seeds/export-profiles/기본-형식-정의.json` 50벌)을 켜서 화면에서 고쳐 쓰는 것이 설계였다.

그런데 정의판을 DB 에 넣는 길이 **개발 서버의 손작업뿐**이었다(2026-09-28 에 넣은 50벌). 배포는
코드판만 날랐다 — 코드판은 배포와 함께 가니 「옮길 것이 없다」 고 여겼고, ADR 0038 이 적은 「DB
씨앗이 되면 운영 서버마다 들여와야 한다」 는 코드판을 지울 때의 이야기로만 읽었다. 그래서 운영에서
사용 중단을 걸면 형식이 메뉴에서 빠지기만 하고 대신 쓸 것이 없었다.

드러난 계기(2026-09-30): Abaqus 점탄성 코드판에 `MODULI=INSTANTANEOUS` 가 빠진 것을 찾았다.
v1.263.0 으로 고쳐 냈지만, 배포 전까지 운영에서 쓸 대안이 없었다. 사용자의 물음 「운영에 보낼 때
왜 이걸 포함해서 안 보내는 거야?」 — 빠뜨린 것이었다.

## 결정

1. **배포가 넣는다** — `scripts/import_export_profiles.py`(`deploy.ps1`, 핸드북 씨앗 다음).
   `--check` 는 넣지 않고 판정만 보인다. 실패해도 배포는 계속한다.
2. **꺼진 채로만.** 켜면 카드의 내보내기 메뉴에 코드판과 같은 형식이 하나씩 더 선다. 씨앗 파일이
   켜짐을 말해도 따르지 않는다. 등록자는 비운다 — 자료 관리자 · 시스템 관리자만 고친다.
3. **아무도 손대지 않은 것만 새 씨앗을 따른다.** 판정은 새 칸 `export_profiles.seed_digest` —
   씨앗이 마지막으로 쓴 이름 · 설명 · 정의의 sha256 이다.

       없다                                꺼진 채 만든다
       씨앗과 같다                          그대로(지문이 없으면 적어 둔다 — 손으로 들여온 같은 판)
       지문 그대로 · 꺼짐                    새 씨앗대로 바꾼다
       고쳤다 · 켰다 · 지문 없는 다른 판       안 덮는다 — 이름을 적는다
       지웠다                              되살리지 않는다

   **켠 것을 안 덮는 이유**: 사용 중단한 코드판 대신 켜 둔 판이면 지금 누군가 그것으로 덱을 내고
   있다. 배포 한 번에 바뀌면 받는 사람은 이유를 모른다. **지문 없는 다른 판을 안 덮는 이유**: 손으로
   들여와 고쳤는지 씨앗의 옛 판인지 가를 수 없다 — 사람이 「불러오기」 의 「덮어쓰기」 로 정한다.
4. **깨진 씨앗은 안 넣는다** — 넣기 전에 정의로 읽어 본다. 넣으면 형식 목록이 그 줄을 로그만 남기고
   건너뛰어, 켜려는 순간에야 안다.

## 대안

- **`updated_at` 으로 가른다.** 켜고 끄기에도 움직이고, 개발 DB 의 50벌은 이미 두 번에 걸쳐 저장돼
  있었다 — 시각으로는 「손댔나」 를 못 가른다. 기각.
- **없는 것만 넣는다(가이드의 옛 규칙).** 이번 `MODULI` 같은 수정이 운영 정의판에 영영 안 간다 —
  ADR 0046 이 가이드에서 막은 구멍을 여기서 다시 판다. 기각.
- **지문을 정의 JSON 안에 둔다.** 정의는 사람이 편집기로 고치는 자리라 지워지거나 딸려 복사된다.
  마이그레이션 하나(칸 하나)가 더 싸다. 기각.
- **코드판을 지우고 정의판만 둔다.** ADR 0038 이 미뤘다. 코드판의 키워드 확인 · 물리적 타당성 검사를
  정의가 대신하지 못한다. 그대로 미룬다.

## 결과

- 운영 서버에 첫 배포 때 정의판 50벌이 꺼진 채 들어간다. 「해석용 물성 정의」 목록에 「… · 정의」
  50줄이 「꺼짐」 배지로 선다(안내 씨앗이 알린다).
- **추가(2026-10-02)**: 이 설계가 전제한 「정의판을 켠다」 가 **화면에 없었다** — 저장(PUT)이 켜짐을 통째로
  받을 뿐이었고, 그나마 안 보내면 켜짐으로 덮어써 MCP 의 고치기 한 번에 꺼 둔 정의판이 켜질 수 있었다.
  켜고 끄기 전용 길(`POST /fitting/export-profiles/{key}/active`, 고칠 수 있는 사람만 · 감사)을 두고, 저장은
  켜짐을 안 보내면 그대로 둔다. 응답이 짝(`twin_of`)과 그 코드판의 사용 중단 여부(`twin_held`)를 실어,
  화면이 「기본 제공 형식」 의 내린 줄에서 바로 「정의판 켜기」 를 세우고, 코드판이 살아 있는데 켜면
  메뉴에 두 줄이 선다고 묻는다. 목록의 배지는 「중단」 → 「꺼짐」(코드판의 「사용 중단」 과 갈랐다).
- 코드판을 고치면 정의판 씨앗도 함께 고쳐야 한다 — `tests/unit/test_export_twins.py` 가 둘이 글자까지
  같은지 묶으므로 한쪽만 고치면 CI 가 멈춘다. 배포가 손대지 않은 운영 정의판까지 가져간다.
- 개발 DB 의 50벌은 씨앗과 같아 그대로 받아들여졌다(지문 50, 켜진 것 0).
- 시험: `tests/unit/test_export_profile_seeds.py` — 판정 다섯(켠 것 · 고친 것 · 꺼진 채 넣기 · 지운 것 ·
  들여온 옛 판)을 하나씩 망가뜨려 시험이 무는 것을 봤다.
