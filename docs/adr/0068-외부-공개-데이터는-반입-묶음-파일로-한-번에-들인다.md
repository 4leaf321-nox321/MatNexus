# 0068. 외부 공개 데이터는 반입 묶음 파일로 한 번에 들인다 — 외부 키 · 라이선스 · 산점

날짜: 2026-10-23
상태: 채택
관련: [0027](0027-물성-카탈로그를-들인다.md) · [0067](0067-문헌-곡선은-점을-낱값으로-두고-묶음-머리로-잇는다.md) ·
요청: `75_MaterialCollector/docs/[개발지시] MatNexus 문헌물성 외부데이터 반입.md`

## 배경

MaterialCollector 가 라이선스를 확인한 공개 데이터(문헌 피로 S-N · ε-N, 고무 · 실리콘 곡선과 초탄성
계수)를 문헌 카탈로그에 넣으려 한다. 지금 길로 넣으면 셋이 터진다(코드로 확인).

- **중복**: `contribute.create_value` · `create_series` 는 늘 새 줄이다. MCP 쓰기가 시간 초과된 뒤 다시
  부르면 두 번 들어간다.
- **묶음이 없다**: 무엇을 언제 넣었는지 묶어서 볼 수도, 되돌릴 수도 없다.
- **라이선스를 적을 수 없다**: `catalog_sources.license` 칸은 있는데 입력(`CatalogSourceIn`)에 없다.

그 밖에 MCP 의 문헌 값 요약에 값 id 가 없고, 문헌 재료 찾기는 이름만 보며, 재료 만들기에 미리보기 ·
속성 칸이 없고, 곡선 한 벌은 「같은 x 는 한 번」 이라 S-N 점(같은 수명 10⁷ 의 런아웃 여럿)을 못 받는다.

## 결정

1. **묶음 파일 하나를 서버가 한 번에 받는다**(`POST /catalog/batches/import`, 자료 관리자). 요청서의
   초안은 MCP 로 낱개 도구를 1,100번쯤 부르는 흐름이었는데 받지 않았다 — ADR 0027 은 「문헌 데이터는 파일
   + 스크립트로만」 이고, AI 가 운영 PAT 로 수백 번 쓰다 끊기면 반쯤 들어간 채 남으며 사람이 그 전부를
   검토할 수 없다. 수집기 자신의 계획(§5.2)도 원래 묶음 파일이었다.
   - 기본은 미리보기(`dry_run=true`) — 들였을 때의 결과(만들 것 · 이미 있는 것 · 문제)만 돌려준다.
   - 적용은 **전부 되거나 전부 안 된다** — 문제가 하나라도 있으면 아무것도 적지 않고 보고서를 422 의
     `details` 로 준다. 항목마다 savepoint 안에서 값 하나 · 한 벌을 넣을 때와 **같은 검사**를 지난다.
   - MCP `import_catalog_batch(path)` 는 이 컴퓨터의 묶음 파일을 읽어 그 길을 한 번 부른다(파일 내용을 모델
     문맥에 싣지 않는다). `get_catalog_batch` 로 확인한다. 지우기 도구는 두지 않는다(ADR 0061).
2. **외부 키로 멱등이다.** 재료 · 출처 · 값 · 벌이 `batch_id` · `external_key`(`{묶음 키}:{항목 키}`,
   표마다 유일) · `external_hash`(키를 뺀 항목을 정렬한 JSON 의 sha256)를 든다. 같은 키 · 같은 내용이면
   그대로 두고(`existing`), 내용이 다르면 문제로 낸다 — 조용히 덮어쓰지 않는다. 벌의 점은 벌이 키를
   가진다. 같은 DOI · 제목의 **있던 출처**에 붙으면 그 출처는 묶음의 것이 아니다(여러 값이 나눠 쓴다).
   `existing_id` 로 이미 있는 문헌 재료에 붙일 수 있고, 그 재료는 묶음을 지워도 남는다.
3. **묶음 지우기는 자료 관리자**(`DELETE /catalog/batches/{key}`, 기본 미리보기). 벌 → 값 → 남은 값이 없는
   출처 · 재료. 사내 재료 · 시료가 받아 간 값(선언 물성의 근거 `value_ids`, ADR 0055)이 있거나 묶음 재료가
   사내 재료와 이어져 있으면 막는다. 묶음 줄은 남기고 `retired_at` 을 찍는다.
4. **출처는 라이선스와 귀속 문구를 든다**(`license` 입력을 열고 `attribution` 칸을 더했다). SPDX 의
   `NC` 토막이 있으면 거절한다 — 사내에서 쓰는 카탈로그다. 같은 출처를 다시 쓰면 빈 칸만 채우고, 라이선스가
   이미 다르게 적혀 있으면 거절한다. 이관해 온 출처는 원본이 정본이라 채우지 않는다.
5. **산점 한 벌**(`kind="scatter"`): 곡선과 같은 모양이되 같은 x 를 받고, 줄마다 조건(`row_conditions` —
   `runout` · `specimen` · `failure_mode` 만)을 둔다. 점(`catalog_values.scatter_point`)은 그 물성의
   **대표값 후보에서 빠진다** — S-N 점 하나가 「피로강도」 대표로 서면 안 된다. 값 검색 · 물성 지도에는
   남는다. 산점만 있는 물성에는 대표를 세우지 않는다.
6. **새 정의 키는 씨앗으로 배포한다**(`seeds/catalog/local-definitions.json`, `refresh_builtins`) —
   `local.mechanical.compressive_stress_at_strain`(고무 압축 곡선) · `local.mechanical.fatigue_strain_amplitude`
   (ε-N). 개발 서버에서 손으로 만든 정의는 운영에 없다(ADR 0047 의 교훈).
7. 읽기 보강: MCP 문헌 값에 `id` · `series_id`, 재료에 벌 머리 · 묶음 키. 문헌 재료 찾기가 이름 · 등급 ·
   코드 · 제조사 · 규격명(`attributes.designation`)을 본다. 재료 만들기 미리보기(`/catalog/materials/preview`,
   비슷한 재료 10)와 정해진 속성 칸(`designation` · `product_form` · `condition` · `thickness_mm` · `formula` ·
   `external_ids` · `composition`).

## 묶음 파일의 모양

```json
{
  "batch":     {"key": "materialcollector/fatigue-literature/2026-10-23", "title": "…", "manifest_sha256": "…"},
  "sources":   [{"key": "src-1", "kind": "journal", "title": "…", "doi": "…", "license": "CC-BY-4.0", "attribution": "…"}],
  "materials": [{"key": "mat-1", "name": "…", "category": "metal", "attributes": {"designation": "EN 1.4301"}},
                {"key": "mat-2", "existing_id": "<문헌 재료 uuid>"}],
  "values":    [{"key": "v-1", "material": "mat-1", "source": "src-1", "property_key": "…", "value_num": 650, "unit": "MPa", "quality_tier": 2, "method": "measured"}],
  "series":    [{"key": "s-1", "material": "mat-1", "source": "src-1", "kind": "scatter", "x_key": "cycles",
                 "columns": [{"property_key": "mechanical.fatigue_strength", "unit": "MPa"}],
                 "rows": [[1.2e5, 400], [1e7, 250]], "row_conditions": [{}, {"runout": true}], "quality_tier": 3, "method": "digitized"}]
}
```

절차: 개발 서버에 미리보기 → 문제를 수집기에서 고침 → 적용 → 같은 파일로 다시 들여 전부 `existing`
인지 확인 → 같은 릴리스가 운영에 배포되면 운영에서 같은 파일로 되풀이.

## 대안

- **요청서 초안 그대로 — MCP 낱개 쓰기 + 외부 키**: 위 1 의 이유로 기각. 낱개 넣기 도구는 사람이 한두 건
  넣을 때의 길로 남는다.
- **배포 패키지에 묶음을 실어 `deploy.ps1` 이 넣기**(ADR 0027 의 MaterialTwin 방식): 수집기 자료가 나올
  때마다 MatNexus 릴리스가 따라 나가야 한다. 나중에 묶음이 안정되면 고려한다.
- **묶음을 먼저 만들고(`POST /catalog/batches`) 넣기**(요청서): 파일 하나로 들이면 묶음 키도 파일 안에
  있어 오타로 묶음이 갈릴 일이 없다 — 따로 두지 않았다.

## 하지 않은 것 · 나중

- **문헌 피로 → 덱**(`sn_curve` · `*MAT_ADD_FATIGUE`): 필요하지만 중심 코드(`shared/litdeck.py`)가 확장
  (`extensions/fatigue`)의 블록 · 적합을 직접 부르면 확장 경계 위반이다. 확장이 「문헌 값 → 블록」 을
  등록하는 길을 먼저 설계한다(확장 계약 변경, 물성 개발자 경로).
- **재료 단위**: 요청서는 「논문 × 재료 × 상태마다 새 문헌 재료」 를 기본으로 했는데, 사내 재료는 문헌 재료
  하나에만 이어져 BOM 덱이 그중 한 편만 쓴다. 산점이 대표값에서 빠지므로 기존 재료에 출처별 한 벌로 붙이는
  안(`existing_id`)과 견줘 묶음마다 정한다.
- DFT 키 · 단위(eV/atom · Å · C/m²), 값 여러 개 한 번에(낱개 길), 방법 `fitted`, 조건 칸 경고, 반입 묶음 화면.
