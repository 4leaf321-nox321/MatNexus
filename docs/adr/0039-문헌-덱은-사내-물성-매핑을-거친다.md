# 0039. 문헌 덱은 사내 물성 매핑을 거친다

날짜: 2026-09-28
상태: 채택
관련: [ADR 0038](0038-정의-문법을-넓혀-기본-형식을-정의로-옮긴다.md)(정의판 — 이 결정이 문헌 덱까지
넓힌다) · [ADR 0037](0037-물성-모델마다-솔버-덱을-따로-낸다.md)(사용 중단 · 솔버별 형식) ·
[ADR 0027](0027-물성-카탈로그를-들인다.md)(문헌 카탈로그)

## 배경

문헌 재료로 덱을 내는 길이 둘이다 — 카탈로그의 **문헌 덱**(부품표 붙여넣기 → 문헌 재료만)과
워크벤치의 **BOM 덱**(사내 카드 우선 + 모자란 부품은 문헌 값). 둘 다 `shared/litdeck` 을 지난다.

ADR 0038 로 기본 형식 50개가 정의로 옮겨졌는데, 이 길은 정의를 못 받았다. 이유가 셋이었다.

    형식이 박혀 있었다       dyna_elastic · dyna_thermal 둘을 화면과 서버에 따로 적어 두고
                           key 로 코드판을 바로 불렀다 — 정의도, 다른 솔버도 못 탔다
    옮기는 표가 따로 있었다   문헌 키 → 블록 칸(DECK_SLOTS, 다섯 줄). 사내 물성 매핑과 같은
                           일을 하는 두 번째 표라 어긋났다 — 선팽창계수는 매핑에 이어져
                           있는데 그 표에 없어서, 문헌에 값이 있어도 덱에 안 실렸다
    합치기가 LS-DYNA 뿐이었다 *KEYWORD/*END 를 떼는 규칙 하나 — 다른 솔버는 이어 붙이기만

문헌 값을 정의가 읽게 하는 길은 둘이었다. (가) 정의 문법에 「문헌 키」 자리를 더한다, (나) 문헌
값을 선언 물성의 모양으로 옮겨 **선언 물성 카드의 조립기**에 태운다. 사용자 질문이 방향을
정했다 — 「문헌에서 가져올 때 직접 갖고 오는 것보다 사내 물성 매핑을 거치는 게 용어가 안
헷갈리지 않을까」, 「그래야 이중 개발을 안 하는 거지?」.

## 결정

**(나)를 고른다. 문헌 값은 「사내 재료에 반영했다면 적혔을」 선언 물성으로 옮겨진 뒤, 선언
물성 카드와 같은 조립기로 블록이 되고, 카드 내보내기와 같은 형식 목록으로 적힌다.**

    문헌 재료 → 가상 사내 재료(저장 안 함) → 선언 카드 조립기 → 형식(코드판·정의판) → 솔버 규약으로 합치기
                shared/literature_material   shared/declared_card    shared/deckmap          litdeck.combine_family

1. **번역은 「사내 재료에 반영」 과 같은 규칙이다**(`literature_material`). 매핑 화면에서
   `same_as` 로 이은 것(폐기된 키 제외) · 재료 기본 칸(밀도·포아송비) · 물성마다 대표값 하나 ·
   출처 낱말. 안 이어진 값은 덱에 없고, 덱 머리 각주에 이름이 선다 — 「매핑에서 이으면
   실립니다」. 덱 각주는 사내 항목 이름으로 적는다(「선팽창계수(CTE)」).
2. **조립기는 하나다**(`shared/declared_card`, 워크벤치 라우트에서 옮겼다). 온도별 표, 사내
   항목 연결로 빈 칸 채우기, 합성 소성 표까지 선언 카드와 같다. 합성 곡선의 입력은 항복·
   인장이 모순이면 **등급 합이 가장 좋은 정합 짝**으로 바꾼다(전의 판단을 번역 쪽으로 옮겼다).
3. **형식은 판정한다**(`litdeck.takes_literature`). 카드 내보내기와 같은 목록(코드판 + 해석용
   물성 정의, 사용 중단 제외)에서 **요구하는 블록을 문헌이 다 채울 수 있는 것**. 곡선을
   요구하는 형식은 「곡선 합성」 을 켤 때만, 여러 재료를 못 합치는 JSON 은 뺀다. 화면은 그
   목록을 받는다(`GET /catalog/deck/formats`).
4. **합치기는 솔버 규약으로**(`combine_family`). 솔버는 정의가 적은 `solver` → key 앞부분
   (코드판 규약) → 확장자 차례로 안다 — 화면에서 만든 정의의 key 는 `deck_1a2b3c4d` 다.
5. **BOM 덱의 문헌 줄은 그 파일의 솔버로 싣는다.** 문헌 형식을 안 주면 그 솔버의 구조(선형)
   형식이 기본이고, 합성 곡선 줄은 카드 형식이 곡선 형식이면 그것, 아니면 그 솔버의 곡선
   기본이다. 어느 형식이었는지를 응답에 싣는다(`literature_format`).

## 결과 (2026-09-28)

- 문헌 덱이 **LS-DYNA · Abaqus · ANSYS · Nastran · OptiStruct · Radioss** 의 선형·열 형식을
  낸다(코드판 12개). 정의판을 켜면 목록에 서고, 코드판과 **합친 파일까지** 같은 글자다.
- 문헌 값을 덱으로 옮기는 코드 표가 없어졌다. 선팽창계수가 실린다.
- **Radioss 합치기의 조용한 결함을 잡았다.** 재료마다 `/END` 가 남아 있었는데 Starter 는 첫
  `/END` 에서 읽기를 멈춘다. OpenRadioss 로 두 재료를 합친 파일을 돌리니 둘째 재료를 가리키는
  부품이 「MATERIAL ID DOES NOT EXIST」 였다 — 파일은 오류 없이 나왔었다. 이제 `/UNIT`·`/END`
  를 파일에 하나만 두고, 같은 모델로 Starter 오류 0 · 두 재료 모두 읽힘을 확인했다.
- 시험: `tests/api/test_literature_deck.py`(형식 판정 · Abaqus · Radioss · 매핑 · 정합 짝 ·
  정의판) · `test_bom_deck.py`(다른 솔버의 문헌 줄 · Radioss 카드 + 문헌). 사보타주 5건 —
  옛 Radioss 합치기 · 매핑 건너뛰기 · 정합 짝 안 고르기 · JSON 안 빼기 · 확장자 무시 — 전부 문다.

## 대가

- **매핑이 비면 문헌 덱도 빈다.** 전에는 코드 표가 늘 있었다. 운영은 배포가 기본 연결을 깐다
  (`scripts/refresh_builtins.py`, 마이그레이션 888bca60a86b). 시험 DB 는 그것이 없어 덱 시험이
  먼저 깐다(`test_catalog.link_builtin`).
- 매핑을 바꾸면 문헌 덱이 바뀐다 — 그것이 의도다(한 곳에서 고친다). 다만 연결을 지운 사람은
  덱에서 빠지는 것까지 생각하지 않을 수 있어, 빠진 이름을 덱 각주가 말한다.
- 합치기 규약(`combine_family`)은 아직 코드다. 솔버 다섯의 머리·끝 규칙이 전부라 정의로
  옮기지 않았다 — 새 솔버를 정의로 붙이면 합칠 때 「이어 붙이기」 로 간다.

## 버린 대안

- **정의 문법에 문헌 키 자리를 더한다** — 형식마다 문헌 키와 선언 물성 이름을 두 벌로 적게
  된다. 문헌과 사내가 같은 물성을 다른 이름으로 부르는 것을 형식 작성자가 풀어야 하고, 매핑과
  또 어긋난다(이번 결함의 반복).
- **반영(저장)한 뒤 카드로 낸다** — 부품표 수십 줄마다 사내 재료가 생긴다. 덱 한 번 내려고
  자료가 늘면 안 된다. 번역은 같고 저장만 안 한다.
