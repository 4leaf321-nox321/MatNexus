# 0056. HWAX 포털 위임은 SSO 가 아니라, 공유 비밀로 내주는 읽기 전용 토큰이다

- 상태: 수용
- 날짜: 2026-10-03
- 관련: TestScope ADR 0010(같은 결정) · [0054](0054-물성-목록의-정본은-MatNexus-다-분류를-여기서-세우고-SP-가-읽어-간다.md)(읽기 전용 토큰) · [0051](0051-사용-현황은-행이-아니라-수로-센다.md)(MCP 호출 집계)

## 결정

HWAX 포털의 MCP 게이트웨이가 MatNexus 도구를 **그 사람 명의로** 부를 수 있게, 표준 위임 창구
`POST /api/auth/sso`(+ `/verify` · `/revoke`)를 연다. 계약은 포털 요청서(HWAXPortal
`docs/sso-delegation/ra-request.md`) 그대로이고, Report Archive · TestScope 가 같은 계약으로 먼저 붙었다.

> **게이트웨이가 공유 비밀로 「이 사람」 을 말하면, MatNexus 에 이미 있고 승인된 그 사람의 개인
> 토큰(`mnx_pat_`, 읽기 전용, 2일)을 내준다.** 계정은 만들지 않는다.

「TestScope 처럼 — SSO 연동은 안 한다」(2026-10-03 사용자). 넷을 못 박는다.

1. **SSO 가 아니다.** 포털에 로그인했다고 MatNexus 에 들어오지 않는다. 브라우저 길은 종전대로
   MatNexus 로그인뿐이고, 이 창구는 이미 있는 계정에 토큰을 내줄 뿐이다.
2. **계정을 만들지 않는다.** MatNexus 는 가입 신청 → 관리자 승인의 절차가 있다. 없는 사람 · 승인
   대기 · 정지는 **403** 이다. 404 는 「창구 꺼짐」 전용이다 — 게이트웨이가 404 를 그렇게 읽으므로,
   사람 하나의 거절을 404 로 내면 창구 전체가 꺼진 줄 안다(RA 가 겪고 고친 자리).
3. **읽기 전용이다.** 토큰은 ADR 0054 의 `read_only` 다. 포털에서 들어오는 쓰기는 우리가 프롬프트를
   못 보는 통로다. 쓰기 도구는 미리보기(`dry_run`)까지만 돌고, 실제로 쓰려면 MatNexus 에서 발급한
   토큰으로 직접 붙는다. **단 MCP 호출 집계(`POST /api/usage/mcp-calls`)는 읽기 전용 토큰으로도
   된다** — 자료를 안 바꾸고, 막으면 포털 경유 호출이 사용 현황에서 조용히 빠진다.
4. **직전 토큰은 폐기하고 새로 낸다** — 지우지 않는다. 「언제 누가 받아 갔나」 가 내 계정의 토큰
   목록과 감사(`pat.issued_for_gateway`)에 남는다.

함께 둔 것 — **연결 주소는 서버가 준다**(`GET /api/auth/mcp-connection`, Report Archive 의
`/api/me/mcp-connection` 과 같은 판단). 화면의 「AI 도구에 등록하기」 가 `MCP_PUBLIC_URL` 을 쓰고,
`HWAX_PORTAL_URL` 이 있으면 포털 게이트웨이로 붙는 길과 위임이 켜졌는지를 함께 보인다. 그리고 MCP
스킬(`mcp_server/skill/matnexus/SKILL.md`)이 두 연결의 도구 이름(`mcp__matnexus__*` · 게이트웨이의
`mcp__hwax__<도구>` · 겹칠 때 `mcp__hwax__matnexus_<도구>`)을 모두 허용한다.

## 배경

포털은 하위 서비스를 두 방식으로 붙인다(포털 `docs/sso-delegation/context-notes.md` D-15 · D-16).
① 토큰 등록 — 사람이 그 서비스에서 토큰을 발급해 포털 「외부 연결」 에 붙여 넣는다. ② 사람별 위임
(ste 방식) — 게이트웨이가 공유 비밀로 그 서비스의 `/api/auth/sso` 에서 그 사람 토큰을 그때그때
받는다. ①은 사람이 토큰을 눈으로 옮기고, 만료되면 다시 하고, **쓰기 범위를 켠 토큰을 붙여 넣어도
막을 길이 없다.** ②는 서비스 쪽에 창구 하나만 있으면 된다.

MatNexus 쪽은 ②의 창구를 이번에 갖췄다. **포털 · 게이트웨이에는 아직 MatNexus 가 없다** — 포털 코드는
서비스마다 따로 있다(`connections.py` 의 `SERVICES`, 설정 `<서비스>_SSO_SECRET`, 권한표
`access.yaml`). 포털 쪽에 필요한 것은 [연동-HWAX-포털.md](../연동-HWAX-포털.md) 에 요청서로 적었다.
다른 저장소는 여기서 고치지 않는다.

## ②의 위험과, 그래서 좁힌 것

②의 위험은 **누구의 토큰을 만들지를 포털이 정한다**는 것이다. 비밀이 새면 그 값을 가진 쪽이 관리자를
골라 그 사람 토큰을 받는다. 권한 분리 자체는 그대로 돈다(토큰은 그 사람을 못 넘는다) — 어느 권한을
쓸지를 남이 고르게 되는 것이 문제다. 그래서 셋으로 좁혔다.

- **읽기 전용 고정** — 쓰기는 이 길로 아예 안 나간다.
- **계정 생성 없음** — 포털 쪽 실수 · 탈취로 MatNexus 에 없는 사람이 생기지 않는다.
- **`HEAX_SSO_ALLOWED_IPS`** — 게이트웨이 박스에서만 부르게 묶는다(운영에서는 꼭 채운다).

남는 위험: 비밀을 가진 쪽은 MatNexus 에 있는 아무 활성 계정(관리자 포함)의 **읽기** 토큰을 받을 수
있다. 관리자만 보는 읽기도 있다(계정 목록 · 접근 로그). 더 좁히려면 OAuth 식 동의(사람이 「허용」 을
누름)로 가야 하고, 그것은 양쪽에 화면을 새로 만드는 일이라 고르지 않았다.

## 대안 — 그때 안 고른 것

- **SSO(jwt-handoff)** — 포털 로그인으로 MatNexus 에 들어오게 하는 것. 사용자가 원하지 않았다.
- **JIT 로 계정 만들기**(RA 는 한다). 승인 절차를 우회한다. 뺐다.
- **쓰기 허용**. 포털 경유 쓰기는 누가 무엇을 시켰는지 우리 쪽에서 안 보인다. 감사에 `mcp` 로 남지만
  그 프롬프트는 없다. 읽기로 시작하고 필요해지면 다시 본다.
- **토큰 행을 지우기**(RA). 폐기(`revoked_at`)로 남겨야 「언제 누가 받아 갔나」 가 보인다.

## 결과

- `backend/app/modules/auth/gateway_token.py` — 창구 셋. `routes.py` 가 얇게 건다. 오류 코드
  `MNX-AUTH-0200`~`0206`(꺼짐 · IP · 비밀 · 이메일 없음 · 형식 · 계정 없음 · 계정 못 씀).
- 설정 `HEAX_SSO_SECRET`(비면 창구 없음 · 404) · `HEAX_SSO_ALLOWED_IPS` · `MCP_PUBLIC_URL` ·
  `HWAX_PORTAL_URL`. 감사 `pat.issued_for_gateway`.
- 읽기 전용 토큰의 예외 하나 — `POST /api/usage/mcp-calls`(`shared/auth._READ_ONLY_WRITES`).
- 켜는 순서는 **MatNexus 먼저** — 포털 쪽에 비밀이 생기는 순간 위임 전용이 된다(운영 핸드북
  「HWAX 포털에서 붙게 하려면」).
- 시험 `tests/api/test_gateway_token.py`(계약 모양 · 읽기 전용 · 집계 예외 · 403/404 가름 · 계정 안 만듦
  · 폐기 · 감사 · 연결 주소) · `tests/architecture/test_mcp_skill.py`(스킬이 두 연결의 이름을 다 허용).
  사보타주 넷(비밀 확인 · 읽기 전용 · 승인 대기 통과 · 집계 예외)을 시험이 전부 물었다.
