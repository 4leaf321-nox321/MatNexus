# 0058. 워크벤치는 업무 단위다 — 업무가 전용 화면을 가질 수 있다

날짜: 2026-10-04
상태: 채택
관련: [ADR 0024](0024-워크벤치는-가로지르는-일에만-둔다.md)(워크벤치는 가로지르는 일에만 — 이 결정이
그 「얼개」 를 고친다) · [ADR 0025](0025-바구니는-서버에-산다.md)(바구니는 서버에) ·
[ADR 0007](0007-원본과-처리결과-저장-구조.md)(채택) · [ADR 0035](0035-보기는-모두에게-고치기는-사람에게.md)(고치기는 사람에게) ·
[ADR 0053](0053-채택-화면은-자르기-전-곡선을-함께-그린다.md)(채택 화면의 앞쪽 곡선)

## 배경

워크벤치(2026-09-01)는 여섯 **사례**로 시작했다 — 「오늘 들어온 것 처리하기」 · 「DMA 한 벌로 점탄성
계수 내기」 · 「해석에 쓸 물성 준비」 · 「BOM 혼합 덱」 · 「새 장비 파일 연결」 · 「확정 전 근거 검토」.
단계는 다른 화면으로 데려가고(`where`), 담긴 것의 사실로 「끝났나」 를 말했다.

한 달 뒤 점검(2026-10-04)에서 드러난 것:

- **사례가 기능을 못 따라왔다.** 그사이 기능이 서른여 개 늘었는데(내보내기 창 · 선언 물성 승인 ·
  묶음 카드 · 처리 결과의 앞쪽 곡선 …) 워크벤치에는 하나도 안 붙었다. 사례 하나가 「DMA 로 Prony」
  처럼 좁아서, 새 기능마다 사례를 새로 지어야 했기 때문이다. 개발 DB 에 작업 10 · 담긴 것 3.
- **판정이 틀린 자리가 있었다.** 카드 각주를 전부 「경고」 로 세어 카드 42장이 다 경고 카드였고,
  사용 중지 카드를 「초안」 으로 셌고, 표로 입력한 시험을 「안 읽힘」 으로 셌다.
- **화면을 오가는 값이 컸다.** 「채택」 단계는 시험 목록으로 데려갔고, 사람은 시험마다 결과 탭을
  열어 채택했다. 스무 건이면 스무 번 — 그사이 한 건이 튀어도 다른 시험과 견줘야 보이는데, 견줄
  자리가 없었다.

요청(2026-10-04): *「dma 한 벌로 점탄성 계수 내기 같은 기준이 아니라, 물성 카드 하나 만들기 · BOM
기준으로 여러 카드를 한 덱에 · 시험 데이터 한번에 처리하기 · 계산된 시험 데이터 한번에 채택하기
처럼 업무 단위로. 전용 UI 를 만들어도 된다 — 예를 들어 한번에 채택하기는 여러 시험의 처리 전/후를
견주는 화면. 비슷한 기능은 묶어서, 기능이 늘어도 체계적으로 확인할 수 있게.」*

## 결정

**1. 워크벤치의 단위는 업무다.** 사례가 아니라 「하는 일」 의 이름으로 짓고, 비슷한 업무는 묶음으로
세운다. 지금 묶음 넷 · 업무 여덟(`frontend/src/modules/workbench/workflows.ts`).

| 묶음 | 업무 | 형태 |
|---|---|---|
| 시험 데이터 | 한번에 등록하기 · **한번에 처리하기** · **한번에 채택하기** | 안내 · 전용 · 전용 |
| 물성 카드 | **카드 하나 만들기** · 확정 전 검토하기 | 전용 · 안내 |
| 해석 덱 | **부품표(BOM)로 한 덱에** · 한 묶음으로 내보내기 | 전용 · 안내 |
| 장비 · 형식 | 새 장비 파일 연결 | 안내 |

**2. 업무가 전용 화면을 가질 수 있다 — 단, 그 화면은 도메인 모듈의 것이다.** ADR 0024 는 *「시나리오
마다 화면을 만들면 화면이 또 는다」* 며 바구니 하나로 미는 얼개를 골랐다. 그 판단의 뿌리는 「같은
일을 하는 자리가 둘이 되면 안 된다」 였고, 그것은 그대로 지킨다. 바뀌는 것은 **끼우는 것**이다:

- 단계가 `view` 를 가지면 도메인 화면을 그 자리에 세운다(`workbench/views.tsx`). 화면은 시험 ·
  처리 · 카드 모듈에 살고 시험 id · 재료 id 만 받는다 — 워크벤치를 모른다.
- 새 화면이 필요하면 **도메인 모듈에** 만든다. 채택 검토대(`processing/AdoptionBoard.tsx`)가 처리
  모듈에 사는 것이 그 예다. 시험 목록의 일괄 처리 창과 워크벤치의 「한번에 처리하기」 는 같은
  본문(`processing/BatchPanel.tsx`)을 세운다.
- 프론트 경계 예외는 `fitting` · `processing` · `tests` 셋이고 사유가 적혀 있다
  (`src/test/boundaries.test.ts`). **늦게 읽는 import(`lazy`)도 센다** — `from` 만 보던 동안에는
  동적 import 로 바꾸는 순간 검사를 조용히 빠져나갔다.

**3. 채택 검토대.** 여러 시험의 결과를 한 화면에서 견준다 — 시험마다 결과 하나를 고르고(기본은
지금 채택, 없으면 옛 원본이 아닌 최근), **같은 재료 · 시험 종류 · 방향끼리**(반복 시편끼리)
**중앙값과의 차이**를 세어 문턱(기본 10%)을 넘은 것을 칠하고 위로 올리고, 그 묶음의 곡선을 겹친다.
처음에는 시험 종류로만 묶었는데, 개발 DB 의 채택 전 47건(재료 여섯)을 열어 보니 206 GPa 강판이 수지
시험들의 중앙값에 대어 「+5405%」 로 섰고 47건 중 41건이 「먼 것」 이었다 — 칠한 것이 아무것도 가리키지
않았다. 묶음을 고친 뒤 2건이 남았고, 그것은 항복강도가 173.5 MPa 대 1.757 MPa 로 갈린 시편 셋이었다. 한 건 자세히는 결과 탭의 그
그림(ADR 0053)이다. 서버는 셋을 **한 요청씩** 준다: `POST /processing/overview`(결과 목록 · 지금
채택 · 고칠 수 있나), `POST /processing/results/curves`(겹쳐 그릴 곡선), `POST /processing/adopt-many`
(건별 채택 · `null` 이면 거둔다).

**4. 되돌릴 수 없는 일은 여전히 사람이 누른다**(ADR 0024). 채택 검토대는 누르기 전에 새로 채택 ·
바꿈 · 문턱 넘은 것 · 고칠 수 없는 것을 세어 묻고, 누른 뒤 「되돌리기」 로 이전 채택으로 돌려놓는다
(채택은 결과를 지우지 않으므로 되돌릴 수 있다). 한 건 채택과 **같은 규칙**을 지난다 — 고칠 수 있는
사람만(`MNX-PROCESSING-0017`), 이름이 긴 값을 든 옛 결과는 못 하고(`-0018`), 고른 결과가 그 시험의
것인지 본다(`-0019`). 남의 시험을 채택하면 등록자마다 한 줄로 남는다(배치와 같다).

**5. 옛 이름은 별칭으로 남긴다.** 서버는 `workflow_key` 문자열만 든다(ADR 0025). 이름을 바꾸면
그 이름으로 적힌 작업이 「모르는 워크플로」 로 선다 — 그래서 `LEGACY_KEYS`(업무)와 `formerly`(단계)
로 지금 것에 잇는다. DB 는 안 바꾼다.

**6. 업무 사이를 잇는다.** 업무가 `next` 를 가지면 마지막 단계에 「이 작업을 끝내고 ○○ 로 이어
하기」 가 선다 — 담은 것을 그대로 새 작업에 넘긴다(등록 → 처리). 다시 고르게 하면 고른 것이 버려진다.

## 대안

- **사례를 그대로 두고 더하기.** 「인장 스무 건 채택」 · 「열팽창 카드」 처럼 사례를 계속 더한다.
  한 달 동안 아무것도 안 더해진 것이 답이었다 — 사례가 좁으면 더할 이유가 매번 약하다.
- **전용 화면을 워크벤치 모듈에 만들기.** 빠르지만 채택 규칙 · 미리보기 · 되돌리기가 두 벌이 된다.
  워크벤치 경계 시험(`test_workbench_only_assembles`)이 막는 그 방향이다.
- **채택 검토대를 시험 목록에 붙이기.** 시험 목록은 이미 열이 많고, 곡선을 겹치려면 폭이 모자란다.
  그리고 「채택할 것을 모으고 → 견주고 → 누르는」 흐름은 바구니(어제 고른 것을 오늘 이어 한다)와
  맞물린다.

## 결과

- 홈이 묶음별로 선다. 업무 카드에 「전용 화면」 / 「안내」 배지 · 빈도 · 단계 미리보기.
- 판정 바로잡음: 카드는 경고만 센다(`shared/card_notes.py` — 각주에 등급이 없어 문구 표지로
  가른다), 사용 중지 · 코멘트를 따로 센다, 표로 입력한 시험을 따로 센다. 화면이 읽는 사실 이름
  (`FACTS_READ`)과 서버의 `FACT_KEYS` 를 양쪽 시험이 대 본다.
- 시험 상세가 `?tab=` 을 받는다 — 채택 검토대의 「이 시험 열기」 가 결과 탭으로 간다.
- 시험 상태 이름표가 `shared/run_status.py` 한 벌이 됐다 — 워크벤치가 따로 적었다가 「읽힘」 과
  「완료」 로 갈렸다.
- 함께 잡은 것: 남의 자료 고침을 한 줄로 묶는 감사(`record_edit_by_other`)가 커밋 직후 첫 기록만
  다른 열쇠를 가져 줄이 갈렸다 — 트랜잭션이 아직 안 열린 순간이었다. 배치는 끝에서 결과를 다시
  읽어 우연히 안 걸렸다. 열쇠를 잡기 전에 트랜잭션을 연다.

## 지켜야 유지되는 것

ADR 0024 의 넷(판정을 새로 쓰지 않는다 · 시험이 지킨다 · 경계 예외를 사유와 함께 · 문구도
도메인에서)에 하나를 더한다:

    전용 화면은 도메인의 것   워크벤치 파일에 도메인 API 주소가 서면 `test_workbench_only_assembles`
                            가 건다. 새 업무의 화면이 어느 모듈의 것인지부터 정한다
