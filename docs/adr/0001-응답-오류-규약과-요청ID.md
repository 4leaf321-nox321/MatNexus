# ADR 0001 — 응답·오류 규약과 요청 ID

- 상태: 채택 (2026-08-14)
- 관련: 개발계획 §3-13(예외를 로그로 전파), §9.3(로그), D13(OpenAPI→타입 생성)

## 배경

65는 `except Exception` 322회/60파일이 불투명한 409로 치환돼 원인이 로그에 남지
않았다(비교표 C-1: *"최저비용·최고효과. 이것 없이 폐쇄망 배포는 위험"*). 반면
구조화 오류 코드(`CMP-CATALOG-0001`)는 RA가 배워야 할 자산으로 평가됐다.

D9로 콘솔 실행을 택했고 운영 서버에 원격 디버깅이 없다. 사용자가 본 화면과 서버
로그를 잇는 수단이 없으면 "그 화면에서 안 돼요"를 재현할 방법이 없다.

## 결정

**1. 성공 응답에는 엔벨로프를 씌우지 않는다.** 리소스를 그대로 돌려준다.
D13이 OpenAPI에서 프론트 타입을 생성하므로, 모든 타입이 `{data: T}` 로 한 겹
감싸이면 생성된 타입이 그만큼 불편해진다. RA는 성공에도 표준 엔벨로프를 쓰지만
RA에는 타입 생성이 없다.

**2. 오류에만 엔벨로프를 쓴다.**

```json
{ "error": { "code": "MNX-TESTS-0001", "message": "...",
             "request_id": "8ec4e65b569d", "details": {} } }
```

코드 형식은 `MNX-<MODULE>-<NNNN>`. 사용자가 화면에서 코드를 읽어 전달하면 그
문자열로 코드를 검색할 수 있다.

**3. 오류 본문은 핸들러만 만든다.** 라우트에서 `JSONResponse`로 직접 오류를
만들지 않고 `AppError` 계열을 raise 한다. 응답을 만드는 경로가 곧 로그를 남기는
경로여야 65의 실패가 재발하지 않는다. 4xx는 WARNING, 5xx는 스택 트레이스와 함께
ERROR로 남긴다.

**4. 요청 ID는 순수 ASGI 미들웨어로 심는다.** BaseHTTPMiddleware가 아니다.

실측: Starlette의 `BaseHTTPMiddleware`는 downstream을 별도 태스크로 실행해서
`dispatch`에서 설정한 ContextVar가 엔드포인트와 예외 핸들러에 전파되지 않는다.
응답 헤더에는 id가 붙는데 로그와 오류 본문에는 `-` 가 찍혔다. 순수 ASGI
미들웨어는 같은 컨텍스트에서 downstream을 호출하므로 전파된다(sync 엔드포인트도
anyio가 contextvars를 스레드풀로 복사한다).

**5. 접근 로그를 따로 만들지 않는다.** uvicorn의 `uvicorn.access` 를 우리
핸들러로 흘리면 `_RequestIdFilter` 가 요청 id를 붙여 주고 클라이언트 주소까지
함께 남는다. 미들웨어에서 한 줄 더 찍으면 같은 요청이 두 줄이 될 뿐이다.

```
16:52:36 INFO [97a3964c548e] uvicorn.access: 127.0.0.1:62180 - "GET /api/health" 200
```

참고로 uvicorn은 `access_log=False` 설정이 아니라 `uvicorn.access` 로거의
`hasHandlers()` 로 발행 여부를 정한다 — 루트에 핸들러가 있으면 그 설정과 무관하게
켜진다.

## 대안

- **성공에도 엔벨로프(RA 방식)**: 일관성은 높지만 생성 타입이 불편해진다. 오류만
  감싸는 쪽이 D13과 맞는다.
- **요청 ID 없이 타임스탬프로 로그 추적**: 동시 사용자가 여럿이면 구분되지 않는다.
- **접근 로그 자체 구현**: uvicorn 줄을 끄고 우리 줄만 남기려 했으나, 위의
  `hasHandlers()` 동작 때문에 끄는 쪽이 오히려 복잡하고 정보도 적었다.

## 결과

- `app/shared/errors.py` — `AppError`/`NotFound`/`Conflict`/`Forbidden` + 핸들러 3종
- `app/shared/request_context.py` — 순수 ASGI `RequestIdMiddleware`
- `app/logging_setup.py` — 파일 로테이션 + 요청 id 필터 + uvicorn 로거 연결
- 프론트 `shared/api/client.ts` 의 `ApiError` 가 code·request_id를 그대로 노출
