# 0045. 사내 물성 들이기를 AI 에게 연다 — 항목 · 연결 · 항목란 · 값

날짜: 2026-09-30
상태: 채택
관련: [ADR 0044](0044-AI-가-해석용-물성-정의를-짓고-저장한다.md)(AI 가 해석용 정의를 저장) ·
[ADR 0033](0033-카드-항목란을-화면에서-정의한다.md)(카드 항목란) ·
[ADR 0035](0035-보기는-모두에게-고치기는-사람에게.md)(권한)

## 배경

ADR 0044 로 AI 가 해석용 정의를 짓고 저장하게 됐지만, 해석 프로그램 전용 물성(eCAE 등)이
**카드에 올라오기까지의 네 걸음**은 화면에만 있었다.

    사내 물성 항목   재료에 적을 때 고르는 이름 · 차원           누구나(열린 축) — 속성은 관리자
    물성 연결       항목 ↔ 물성 키                            시스템 관리자
    카드 항목란     카드가 담는 칸 — 칸마다 물성 키             시스템 관리자
    선언 값 적기    재료에 값                                  고칠 수 있는 사람(문헌 채택 도구만 있었다)

ADR 0044 를 쓰며 「항목란과 연결은 사람에게 남긴다」 고 적었고, 두 가지가 틀리면 어떻게 되는지
설명한 뒤 판단을 물었다. 사용자(2026-09-30): 「사내 물성 추가가 필요하다고 하면 그것도 AI 에서 할
수 있도록 해 줘.」

## 결정

1. **MCP 도구 다섯** — `list_property_items` · `add_property_item` · `link_property_item` ·
   `save_card_block` · `set_declared_values`. 전부 **미리보기가 기본**이고, 권한은 화면과 같다
   (연결 · 항목란은 시스템 관리자 토큰 — 서버가 막는다). `add_catalog_property`(물성 키)도 같은
   줄에 서도록 미리보기를 기본으로 바꿨다 — 실제 AI 세션이 「이것만 미리보기가 없어 부르면 바로
   만들어진다」 고 짚었다.
2. **사람 확인 대신 서버 검사를 둔다** — 가장 위험한 두 가지를 서버가 막는다.
   - **항목란 칸의 물성 키가 실재하고, 칸 단위와 차원이 같아야 한다**(MNX-CARDBLOCK-0009 · 0010).
     전에는 칸 단위가 단위표에 있는지만 봤다 — 칸은 `1` 인데 키가 `Pa` 면 단위계를 바꿔 내보낼 때
     환산이 조용히 어긋난다. 사람이 만들든 AI 가 만들든 같은 검사다.
   - **물성 연결은 차원이 다르면 거절한다** — 전부터 있던 검사(`catalog/links`)를 그대로 쓴다.
     미리보기가 서버의 연결 후보(이름 · 별칭 · 기호가 정확히 같고 차원이 맞는 짝)인지 알려
     주고(`server_suggested`), 후보가 아닌 짝은 근거를 설명하고 사용자 확인을 받으라고 안내한다.
3. **사내 물성 항목은 만들 때 차원 · 기호 · 붙는 곳을 함께 받는다** — 전에는 만들 때 숫자 속성만
   받아서, 차원은 관리자가 따로 붙여야 했다(안 붙이면 무차원으로 취급된다).
4. **세 걸음이 감사에 「AI 경유」 로 남는다** — 기준정보 값 추가(`vocabulary.term_created_by_client`)
   · 물성 연결(`property_link.created_by_client`) · 카드 항목란 저장(`card_block.saved_by_client`).
   전에는 사람이 하든 AI 가 하든 흔적이 없었다. 화면에서 한 것은 전처럼 안 남는다.

## 대안

- **연결은 서버 후보만 허용** — 버렸다. 새로 들이는 전용 물성은 이름이 달라 후보에 안 서는 경우가
  대부분이다(실제 세션: 「정적 마찰계수」 ↔ 공용 「마찰계수」). 대신 후보 여부를 알리고 확인을 받게
  한다. 차원이 다른 연결은 여전히 서버가 막는다.
- **항목란은 계속 사람만** — 버렸다. 사람 확인이 막으려던 것(단위 오기)을 서버 검사가 막는다.

## 결과 (2026-09-30)

- `tests/api/test_inhouse_property.py` — eCAE 마찰계수를 `X-Client: mcp` 로 물성 키부터 만들어
  항목 · 연결 · 항목란 · 선언 값 · 카드(항목란 골라 싣기)를 거쳐 정의로 그리면 `0.150` 이 나온다.
  세 걸음이 감사에 남는다. 사보타주 2곳(차원 검사 · 연결 감사) 모두 물었다.
- MCP 프로브 101건 중 100건 성공(남은 1건은 문헌값 부족). 도구 91개.
- 실제 AI 세션에 「eCAE 용 정적 마찰계수를 재료에 넣고 카드까지, 필요하면 사내 물성 추가도, 오늘은
  저장 말고 계획만」 을 시켰다: 있는 것부터 찾아(카탈로그에 무차원 「마찰계수」 키가 있음) 항목 →
  연결 → 항목란 → 값 → 카드를 **미리보기로만** 순서대로 돌리고, 연결이 서버 후보가 아님을 짚고
  정 · 동 마찰계수를 키에서 나눌지와 0.15 의 근거를 물었다.
