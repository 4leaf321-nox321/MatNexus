# 0067. 문헌 곡선은 점을 낱값으로 두고 묶음 머리로 잇는다

날짜: 2026-10-22
상태: 채택
관련: [0027](0027-물성-카탈로그를-들인다.md) · [0029](0029-문헌-모델-파라미터는-재료에-두고-카드가-인용한다.md)

## 배경

문헌 카탈로그의 값은 **한 줄에 숫자 하나**다(원본 MaterialTwin 도 같았다 — `property_value` 에 곡선
칸이 없고, 곡선 파일은 시험 쪽 `raw_curve_ref` 에만 있었다). 그래서:

- 온도별 영률 여섯 점이 한 곡선이라는 사실이 어디에도 없었다. 「재료 · 키 · 출처 · 나머지 조건이 같으면
  한 곡선」 이라 추정할 수밖에 없었다.
- 응력-변형률 곡선 같은 점열은 넣을 길이 없었다(정의 `mechanical.tensile_stress_at_strain` 은 있었다).
- MCP 로 넣으려면 값 하나씩 — 20점 곡선이면 미리보기까지 40번 불러야 했다.
- 재료 상세는 값 하나가 한 줄이라, 값이 366건인 재료(SAC-Q)는 같은 물성 이름이 수십 줄 섰다.

사용자 요청: 문헌 물성에 곡선 등 이어진 값을 넣는 구조, 그리고 웹 화면에서 체계적으로 보이게.

## 결정

사용자가 고른 세 가지(2026-10-22):

1. **점은 지금처럼 문헌 값 한 줄씩이고, 한 벌의 머리(`catalog_series`)가 잇는다**
   (`catalog_values.series_id`). 값 검색 · 물성 지도 · 사내 재료 반영 · 덱은 고치지 않고 그 점을
   낱값처럼 읽는다.
   - `curve`: 축 `x_key` 는 **정의의 조건축**(`condition_axes`) 가운데 하나여야 한다 — 같은 온도를
     `temperature_c` · `temperature_k` 둘로 적으면 지도 · 검색에서 한 축으로 안 모인다. 축 값은
     `x_unit` 으로 받아 키의 단위로 바꾼다(°C → K). 물성 열은 여럿(DMA 의 E′ · E″ · tan δ)이고, 열마다
     값 하나와 같은 단위 환산을 거친다. 같은 x 는 한 번, 점 2개 이상.
   - `parameter_set`: 식 하나의 계수. 점의 조건에 `model` · `term` · `set_id`(=이 벌)를 적어 기존 계수
     묶음 읽기(`catalog.parameters`)가 그대로 묶는다. 무차원 키(Anand 상수)의 항은 **환산하지 않고**
     `unit_of_term` 으로 남긴다(ADR 0029 D2). 두 키에 걸친 벌(Prony 의 상대 탄성률 · 완화시간)은 항마다
     키를 적는다.
   - 출처 · 등급 · 방법 · 공통 조건은 벌 전체가 하나다. 지우기는 벌째(넣은 사람 · 자료 관리자), 감사에
     남는다. 벌의 점은 낱개로 안 지운다.
2. **이관해 온 값은 그대로 두고 화면에서만 잇는다.** 같은 물성 · 출처 · 방법의 값 가운데 수 조건 하나만
   다른 것이 3개 이상이면 그 축을 따라 선으로 그린다(`catalogShape.autoCurves`). 「조건별 값을 이어
   그림(자동)」 이라 이름을 달리 붙인다 — 저장된 곡선처럼 보이면 숨은 조건으로 갈렸어야 할 값을 한 선으로
   믿는다. 한 값은 한 선에만, 점이 많은 축부터.
3. **재료 상세는 요약 + 탭.** 「물성 요약」(물성 하나에 한 줄 — 대표값 · 등급 · 값 수 · 조건 범위, 펼치면
   후보) · 「곡선 · 표」 · 「계수 묶음」 · 「출처」 · 「전체 값」(지금 표 + 거르개). 탭은 주소에 남는다.

넣는 길: `POST /catalog/materials/{id}/series`(+`/preview` — 넣는 코드를 돌리고 되돌린다) ·
`DELETE /catalog/series/{id}`, MCP `add_catalog_series` · `delete_catalog_series`, 화면 「곡선 입력」
(엑셀에서 복사한 칸을 붙여넣기). 물성 지도는 한 벌을 물성마다 20점까지 양 끝을 남기고 솎는다(온도별
탄성률 표와 같은 규칙) — 응력-변형률 수백 점이 지도를 덮지 않게.

## 대안

- **곡선을 통째로 한 칸(JSON)에** — 저장은 단순하지만 값 검색 · 물성 지도 · 사내 반영 · 덱에 점이 안
  나타나 따로 이어 붙여야 한다. 기각(사용자).
- **이관할 때 기존 값도 묶음으로 저장** — 계수 묶음(`set_id`, 1,713벌)은 확실하지만 온도 곡선은 추정이라
  노화 조건 같은 숨은 축이 있으면 잘못 묶인 것이 **저장된다**. 기각(사용자) — 추정은 화면에만 둔다.
- **축을 아무 조건 칸이나** — 정의의 조건축 밖을 받으면 같은 뜻의 축이 이름 둘로 갈린다.
