# 0046. 가이드 씨앗은 사람이 안 고친 절만 따라간다 · 「앱 사용」 문서 종류

날짜: 2026-09-30
상태: 채택
관련: [ADR 0022](0022-핸드북은-누구나-초안-검토자가-승인.md)(누구나 초안, 검토자가 승인)

## 배경

요청(2026-09-30): 「플랫폼 안의 가이드 내용이 낡은 것 같다. 전체 개발된 내용을 반영해 업데이트해
달라.」 살펴보니 두 가지였다.

- **내용** — 핸드북 21편 가운데 앱을 서술하는 문서는 「지금 이 앱이 다루는 물성」 하나뿐인데, 그것이
  해석 프로그램 두 개(Abaqus · OpenRadioss) 시절 판이었다. 지금은 여섯이다. 나머지 20편은 규격 ·
  물리 내용이라 낡을 것이 없었다. **앱을 어떻게 쓰는지 설명하는 문서는 한 편도 없었고**, 「용어」
  종류는 비어 있었다.
- **전달** — 원문(`규격/*.html`)을 고쳐 씨앗을 다시 만들어도 **운영에 안 간다.** 배포가 도는
  `import_guides.py` 기본 모드가 「있는 절은 무엇이든 안 덮는다」 였다. 운영 편집을 지키려던 규칙인데,
  사람이 한 번도 안 고친 절까지 처음 들어간 판에 묶어 두었다. 개발 DB 로 확인하니 사람이 고친 절은
  0 이었다 — 지킬 것이 없는데 갱신만 막고 있었다.

## 결정

1. **기본 모드는 「사람이 안 고친 절」 만 새 씨앗으로 바꾼다.** 판정은 리비전으로 한다 — 씨앗이 넣은
   리비전은 쓴 사람이 비어 있고, 화면에서 낸 리비전은 반드시 쓴 사람이 있다. 마지막 승인 리비전이
   씨앗의 것이고 절 본문이 그 리비전과 같으면 씨앗이 주인이다. 바꿀 때 리비전을 하나 더 남긴다
   (「씨앗에서 갱신」) — 앞 판은 이력에 있다.
2. **안 바꾸는 절** — 사람이 고쳐 승인했다 · 검토 대기 초안이 있다 · 삭제됐다 · 리비전 없이 본문이
   달라졌다. 이름을 적어 알린다. 대기 초안을 막는 이유: 그 초안은 옛 본문 위에 쓴 것이라 승인되는
   순간 씨앗 갱신을 말없이 되돌린다. 검토자가 초안을 처리하면 다음 배포가 가져간다.
3. **`--replace` 는 그대로** — 사람이 고친 절까지 덮는다. 사람이 `--replace` 로 씨앗을 고른 절은
   다시 씨앗의 것이 되어 다음 배포부터 따라간다. `--check` 는 다른 절을 「씨앗대로 바뀔 절」 과
   「사람이 고친 절」 로 갈라 보인다.
4. **문서 종류 `platform`(「앱 사용」 — 이 앱에서 무엇을 어떻게 하나)을 더하고 맨 앞에 둔다.** 앱의
   흐름을 설명하는 「플랫폼 사용 안내」 와, 비어 있던 「용어」 에 앱의 말 풀이를 넣는다.
5. **계산 문서의 앱 서술은 「이 앱에서는」 안내 상자에만 둔다.** 인장 → 소성 · DMA → Prony 같은
   문서를 읽는 사람이 가장 알고 싶은 것이 「이 단계를 앱이 해 주나」 라서 그 절 끝에 둔다. 도메인
   본문에 섞지 않는 이유: 이번처럼 낡았을 때 찾을 수가 없다. 앱이 바뀌면 「이 앱에서는」 으로 찾는다 —
   그것과 「앱 사용」 두 편, 「지금 이 앱이 다루는 물성」 이 앱 서술의 전부다. 시편 규격 · 시험 방법
   문서는 규격 내용뿐이라 상자를 안 넣었다 — 앱이 계산까지 하는 판재 성형의 r값 절 하나만 넣었다.

## 대안

- **배포에서 `--replace` 를 돈다.** 갱신은 되지만 운영 편집이 릴리스마다 사라진다 — ADR 0022 가
  막으려던 바로 그것. 기각.
- **본문을 견주어 「씨앗 옛 판과 같으면」 바꾼다.** 옛 씨앗 판을 저장소가 기억해야 한다(해시 목록).
  리비전의 쓴 사람이 이미 그 정보를 들고 있다. 기각.
- **사람이 손으로 `--check` → `--replace --only` 를 돈다.** 이번에는 되지만 다음 원문 갱신 때 또
  잊힌다 — 2026-08-31 에 가이드가 통째로 비어 있던 것도 「넣는 명령을 아무도 안 돌렸다」 였다. 기각.

## 결과

- 원문을 고치면 다음 배포에 운영 가이드가 따라온다. 사람이 고친 절은 배포 로그에 이름이 남는다.
- 리비전 이력에 「씨앗에서 갱신」 판이 쌓인다. 안 바뀐 절에는 안 쌓는다(배포마다 도는 모드다).
- 시험: `tests/unit/test_guide_seeds.py` — 씨앗만 있던 절은 따라가고, 사람이 승인한 절 · 대기
  초안이 있는 절 · 리비전 없이 바뀐 절은 안 덮는다(세 판정을 하나씩 망가뜨려 시험이 무는 것을 봤다).
