# ADR 0023 — 솔버 덱도 파일로 정의한다

- 상태: **완료** (2026-08-30 — 다섯 단계 전부)
- 관련: ADR 0006(형식 프로파일은 데이터다) · ADR 0013(확장 창구 넷) · [개발계획 §11](../개발계획.md)

## 배경

CAE 카드를 솔버 덱으로 내보내는 코드는 `matcore/export/__init__.py` 에 있다. 지금
여섯 벌이다 — Abaqus(탄성·점탄성·초탄성) · OpenRadioss(구조·열) · 중립 JSON.

새 솔버를 붙이려면 **파이썬 함수를 짜고 배포해야 한다.** `@register_renderer` 로
확장 폴더에서 붙일 수는 있지만 그것도 코드다.

**이것은 「장비 파일 정의」 가 이미 푼 문제와 같은 모양이다.** 장비 파일을 읽는
규칙도 처음에는 코드였는데, 새 장비마다 배포가 필요해서 데이터로 옮겼다
(ADR 0006). 지금은 관리 화면에서 만들고, **운영 서버에서 실제 파일로** 만든다 —
현장 파일이 개발자에게 갈 필요가 없다.

내보내는 쪽은 그 반대 방향인데 아직 코드에 있다.

실측이 그것을 가리킨다(개발계획 §11, 2026-08-27):

    matcore.fitting.register_family    ✅ Ghosh 가 씀 — 96줄, 3파일
    matcore.cards.register_block       ❌ 한 번도 안 불림
    matcore.export.register_renderer   ❌ 한 번도 안 불림

**한 번도 안 불렸다는 것은 창구가 좁다는 뜻일 수도 있고, 그 자리에 확장할 일이
아직 없었다는 뜻일 수도 있다.** 이 결정은 앞쪽을 가정한다 — 근거는 아래 「왜
지금인가」 다.

## 결정

**덱 렌더러를 파일 정의(템플릿)로 만들 수 있게 한다.** 코드 렌더러는 그대로 둔다.

    장비 파일 정의   장비 파일  →  [프로파일]  →  곡선·요약값
    솔버 덱 정의     물성 카드  →  [템플릿]    →  덱 텍스트

### 셋을 그대로 베낀다

「장비 파일 정의」 가 쓸 만한 이유는 셋이고, 그 셋을 같이 옮긴다.

1. **정의가 데이터다** — DB 행 하나(JSONB). 배포 없이 늘어난다.
2. **저장 전에 돌려 본다** — 장비 파일 쪽의 `/api/formats/preview` 가 실제 파일을 받아
   무엇으로 읽히는지 먼저 보여 준다. 덱 쪽은 **기존 카드 하나를 골라 렌더**해서
   덱 텍스트를 보여 준다. 저장하고 나서 틀린 것을 아는 것과 다르다.
3. **부서 소유** — 부서마다 쓰는 솔버가 다르다. 전역(NULL)도 그대로 둔다.

### 정의 모양 (v1 초안)

```json
{
  "match":  { "solver": "abaqus", "extension": "inp" },
  "needs":  [
    { "block": "elastic", "values": ["youngs_modulus", "poisson_ratio"] },
    { "block": "elastic", "values": ["density"], "optional": true },
    { "block": "table",   "rows_min": 2 }
  ],
  "template": "*MATERIAL, NAME={{ name }}\n*ELASTIC\n{{ elastic.youngs_modulus }}, ...",
  "notes":  [
    { "when": "missing:elastic.density",
      "say": "밀도가 카드에 없어 *DENSITY 를 빼고 그 사실을 덱 주석에 적었습니다." }
  ]
}
```

`needs` 는 지금 `Need` 가 하는 일 그대로다 — **화면이 「이 형식은 아직 못 낸다」 를
미리 말할 수 있어야** 한다. 지금도 그 검사가 렌더 전에 돈다.

## 그대로 가져오면 안 되는 것 — **템플릿은 코드가 아니다**

여기가 이 결정에서 가장 위험한 자리다.

장비 파일 정의은 **선언적이다** — 「이 열은 하중」. 그래서 JSON 으로 충분하다.
덱 렌더러는 그렇지 않다. 지금 여섯 벌이 실제로 하는 일을 세어 보면:

- 값이 없으면 **키워드를 통째로 빼고 왜 뺐는지 덱 주석에 적는다**(`*DENSITY`)
- 표를 **정리한다**(`prepare` — 중복 제거·정렬·단조성 검사)
- 솔버마다 **열 순서가 반대다**(Abaqus 는 응력 먼저, OpenRadioss 는 변형률 먼저)
- 단위계를 골라 **환산한다**(`UnitSystem`)

이것을 다 표현하려면 템플릿 언어가 결국 프로그래밍 언어가 된다. **그러면 「배포
없이」 를 얻는 대신 「디버깅할 수 없는 코드」 를 얻는다** — 그 코드는 타입 검사도
시험도 못 받는다.

그래서 **선을 긋는다**:

| 템플릿이 하는 것 | 코드가 하는 것 |
| --- | --- |
| 키워드 이름·차례·자리 | 표 정리(`prepare`) |
| 값을 어디에 꽂나 | 단위 환산 |
| 있으면 넣고 없으면 빼는 **선택 블록** | 물성 계산 |
| 빠졌을 때 적을 말 | 「이 값이 물리적으로 말이 되나」 |

즉 **템플릿은 조판만 한다.** 계산이 필요하면 그것은 새 물성이지 새 솔버가 아니고,
`register_block`·`register_family` 로 간다.

이 선을 못 지키겠으면 **그 솔버는 코드로 짠다.** 파일 정의는 「거의 같은데 키워드만
다른」 솔버들을 위한 것이지 모든 솔버를 위한 것이 아니다.

## 왜 지금인가 — 그리고 안 할 이유

**할 이유**: 사내에 Abaqus·OpenRadioss 말고 다른 솔버가 있으면(LS-DYNA·ANSYS·
Moldflow) 지금은 요청 → 개발 → 배포다. 그 사슬이 한 번이라도 돌면 이 작업이
싸진다.

**안 할 이유가 더 클 수도 있다.** 실제로 필요한 솔버가 둘뿐이면, 이 구조는 쓰는
사람 없는 창구를 하나 더 만드는 것이다 — `register_renderer` 가 지금 그 상태다.

**그래서 착수 조건을 걸었다**: 개발계획 §11 의 열린 항목 「실제 사용하는 솔버 목록과
우선순위」 가 답해지고, **그 목록에 지금 없는 솔버가 둘 이상**일 때 시작한다.
하나면 코드로 짜는 것이 싸다.

→ **충족됐다**(아래). 이 판단은 지나갔고 남은 것은 「어떻게」 뿐이다.

## 착수 조건이 충족됐다 (2026-08-30)

물어보니 그 수를 크게 넘는다:

    Abaqus            있다
    Radioss           있다(OpenRadioss)
    OptiStruct        없다
    ANSYS Mechanical  없다
    LS-DYNA           없다
    …그 밖에도 많다

**셋 이상을 코드로 짜는 것보다 창구를 하나 만드는 것이 싸다.** 이것으로
`register_renderer` 가 「한 번도 안 불린 창구」 라는 반대 근거도 사라진다 — 안 불린
이유가 창구가 좁아서가 아니라 **붙일 솔버가 아직 안 왔기 때문**이었다.

### 그 목록이 요구사항을 하나 더 드러냈다 — **칸 폭**

새로 붙을 솔버들이 쓰는 것이 자유 형식만이 아니다.

    Abaqus        자유 형식, 쉼표로 나눈다
    OpenRadioss   **고정 20칸** — 이미 `_fixed` 가 그 일을 한다
    OptiStruct    Nastran 벌크 데이터 — **고정 8칸**
    LS-DYNA       키워드 카드 — **고정 10칸**

`matcore/export` 의 주석이 그 무게를 이미 적어 두었다: *「고정 20칸. **칸이 어긋나면
다른 필드로 읽힌다**」*. 값이 틀리는 것이 아니라 **다른 값이 되는** 종류의 오류라,
덱을 읽는 솔버는 그것을 오류로 알려 주지 않는다.

그러므로 템플릿 언어는 **칸 폭과 정렬을 표현할 수 있어야 한다.** 아래 「선 긋기」 의
「조판만 한다」 는 그대로지만, **조판 자체가 만만치 않다**는 뜻이다 — 자유 형식만
가정하고 만들면 절반의 솔버에서 다시 코드로 돌아가야 한다.

## 단계

각 단계가 **혼자 쓸모 있어야** 한다 — 중간에 멈춰도 버리는 것이 없게.

### 1. 코드 렌더러를 템플릿으로 다시 표현해 본다 (검증, 배포 없음)

Abaqus 탄성 하나를 위 정의 모양으로 적어 보고, **지금 렌더러와 바이트가 같은
덱이 나오는지** 시험으로 비교한다. 이 단계의 산출물은 「된다/안 된다」 는 답이다.

- 안 되면 여기서 멈춘다. 그때까지 쓴 것은 시험 하나뿐이다.
- 되면 그 시험이 그대로 회귀 시험이 된다.

**답은 「된다」 다** (2026-08-30). `matcore/export/template.py` · `ABAQUS_TEMPLATE` ·
`tests/unit/test_export_template.py`. 밀도 있음/없음·표 정리·온도별 탄성표 넷에서
바이트가 같고, 사람에게 남기는 말과 그 **차례**까지 같다.

표현하는 데 걸린 자리가 하나도 없었던 것은 아니다. **드러난 것 셋**:

    코드가 계속 만드는 것    `header` · `elastic` · `thermal` — 셋 다 검증·분기가 있다.
                            템플릿은 「그 묶음을 여기 꽂아라」 만 적는다.
    표 정리를 먼저 돈다      `prepare` 가 남기는 말이 줄에서 나온 말보다 앞선다.
                            차례가 곧 「무엇을 먼저 알아야 하나」 라서 우연이 아니다.
    형식은 화이트리스트      모르는 이름을 조용히 자유 형식으로 떨어뜨리지 않는다.
                            그러면 고정폭 솔버가 말없이 틀린 덱을 받는다.

시험이 무는지는 일부러 망가뜨려 봤다 — 표의 **열 순서 뒤집기**(응력↔변형률) ·
`*DENSITY` 뒤 **쉼표 빼기** · 유효숫자 **12→11** · 빠짐 조건 뒤집기 · 안내 문구
바꾸기. 다섯 다 물었다. 넷은 솔버가 오류로 알려 주지 않는 종류다.

### 2. 렌더러 레지스트리를 DB 정의로 채운다

**`matcore` 는 DB 를 모른다** — 읽는 것은 `app/modules/fitting` 쪽이고 `matcore`
에는 dict 로 준다(장비 파일 정의과 같은 규칙).

**했다** (2026-08-30). `ExportProfile` 모델 · `app/modules/fitting/renderers.py` ·
`tests/api/test_export_profiles.py`. 부서 정의 행 하나가 목록에 뜨고 덱을 낸다.

#### 기동이 아니라 요청 때 합친다 — 이 초안을 고쳤다

이 자리에 원래 「앱 기동 시점에 `add_renderer` 로 얹는다」 고 적혀 있었다. 안
그렇게 했다. 셋 다 「배포 없이」 라는 목적 자체를 깎는다:

    고치면 바로 먹어야 한다   기동 때 한 번 얹으면 화면에서 고쳐도 재기동 전까지
                            옛 덱이 나간다. 재기동이 남으면 절반만 얻는다.
    워커마다 상태가 갈린다     여럿 띄우면 얹은 시점이 달라, 같은 요청이 어느
                            워커에 닿느냐로 다른 덱이 나온다 — 재현되지 않는다.
    레지스트리는 프로세스 전역   부서마다 정의가 다른데 전역에 얹으면 한 요청이
                            옆 요청의 덱을 바꾼다.

값이 싼 것도 확인했다 — 레지스트리를 부르는 자리가 **둘뿐**이다(`list_formats` ·
`export_card`). 대신 `matcore.export` 의 조회 함수 넷이 `key` 말고 **렌더러 객체도**
받게 했다(`_resolve`). 그래야 만든 것을 전역에 얹지 않고 들고 다닐 수 있다.

#### 정한 것 셋

    코드 렌더러를 못 덮는다   덮게 두면 코드 쪽 검증(키워드 확인·물리적 타당성)을
                            정의 하나가 조용히 우회한다.
    부서 것이 전역을 덮는다    같은 솔버라도 사업부마다 덱 관례가 다르다 — 어느
                            키워드를 쓰는지, 표를 몇 줄로 자르는지.
    깨진 정의는 건너뛴다      하나가 깨져 목록이 안 뜨면, 고치러 들어갈 화면도 그
                            목록 위에 있어서 사람이 손쓸 길이 사라진다.

사보타주로 다섯을 확인했다 — 부서 걸러내기 제거 · 코드 렌더러 보호 제거 · 소프트
삭제 무시 · 부서 우선 뒤집기 · 깨진 정의에서 터지기. 다섯 다 물었다.

### 곡선이 들어가는 물성 — 문법을 화면보다 먼저 넓혔다 (2026-08-30)

*「선형 물성뿐 아니라 나중에 곡선이 들어가는 물성들도 문제없이 되는가」* 를
물었다. **그때는 안 됐다.** 확인한 것이 둘이다:

    2열 점 표만 받았다      `rows` 가 `x`·`y` 를 요구했다. Abaqus 의 Prony 줄은
                          `g, k, τ` 셋이다.
    표를 무조건 정리했다     `prepare` 를 늘 돌렸다. **Prony 는 점이 아니다** —
                          `(g, τ)` 를 τ 로 정렬하거나 중복을 묶으면 **다른 재료가
                          된다.** 그리고 덱은 멀쩡히 돌고 결과도 그럴듯하다.

**화면(4단계)이 나오기 전에 고쳤다.** 문법이 굳은 뒤에 넓히면 이미 저장된 정의를
마이그레이션해야 하는데, 그 정의는 현장에서 만든 것이라 무엇이 들어 있는지 이쪽이
모른다. 넓힌 것 셋:

    표를 있는 그대로 반복    `x`·`y` 를 안 주면 정리하지 않는다. 그 둘이 곧
                          「이것은 점 표다」 라는 스위치다.
    아무 열이나 꽂는다      2열 제약을 없앴다.
    상수 칸               `{"const": "0.0"}`. Prony 의 체적항 `k` 는 DMA 가 재지
                          않아 코드가 지어내지 않고 0 을 적는다.

**상수는 글자로 주면 글자 그대로 나간다.** 코드가 `0.0` 으로 적는데 포맷을 거치면
`0.000000000000E+00` 이 되어 그 자리가 바이트로 달라진다. 덱에는 이런 리터럴이 흔하다.

Abaqus 점탄성의 Prony 표를 템플릿으로 적어 **코드와 바이트가 같은 것을 확인했다.**
사보타주 셋이 물었다 — 곡선 표도 정리하기 · 상수를 포맷에 태우기 · 점 표 정리 끄기.

**여전히 코드로 남는 것.** 점탄성 덱 *전체* 는 아직 템플릿으로 못 적는다. 기준
온도 주석이 `reference - 273.15` 를 **계산**하기 때문이고, 초탄성은 `family` 로
키워드가 갈린다. 그것은 이 결정이 그은 선의 바깥이 맞다 — 계산과 분기는 코드고,
템플릿은 그 묶음을 제자리에 꽂는다. **표 자체가 되는 것이 요점이었고, 그것은 된다.**

### 3. 미리보기 — 저장 전에 덱을 본다

`POST /api/fitting/export-profiles/preview` — 정의 + 카드 id 를 받아 덱 텍스트와
`needs` 판정을 돌려준다. **저장하지 않는다.**

**했다** (2026-08-30). `preview_deck` · `DeckPreviewIn`/`Out` ·
`tests/api/test_fitting.py::Test덱_미리보기`.

덱 쪽에서 이것이 장비 파일 쪽보다 더 필요하다: **틀린 덱은 솔버가 오류로 알려 주지
않는다.** 칸이 어긋나면 다른 필드로 읽히고, 해석은 그대로 돌아 그럴듯한 결과를 낸다.

#### 정한 것 셋

    미리보기와 실제가 같은 덱   `_deck_for_card` 를 뽑아 둘이 같이 쓴다. 다르면
                            사람은 미리보기를 한 번 믿고 두 번 안 믿는다.
    못 냈어도 200            **못 낸 이유를 보여 주는 것이 미리보기의 절반이다.**
                            422 로 던지면 화면은 오류 상자 하나를 띄우고, 사람은
                            정의의 어느 줄이 문제인지 모른 채 돌아간다.
    빈 카드와 틀린 정의를 가른다  `missing` 을 따로 준다. 안 가르면 멀쩡한 정의를
                            고치며 시간을 버린다 — 할 일은 다른 카드를 고르는 것이다.

사보타주 셋이 물었다 — 미리보기만 다른 덱 쓰기 · 못 냈을 때 422 던지기 ·
`missing` 안 채우기.

**덱 조립부를 함수로 뽑는 데서 한 번 미끄러졌다.** `item = _visible_card(...)` 가
파일에 여러 번 나오는데 첫 번째를 잡아 **다른 라우트의 본문을 잘라냈다.** 타입
검사가 잡아 되돌렸다 — 앵커로 코드를 옮길 때는 그 앵커가 파일에서 유일한지 먼저
본다.

### 4. 화면

**했다** (2026-08-30). `ExportProfilesPage` · `ExportProfileEditorPage` ·
`deckLines.ts` · CRUD 라우트 넷.

#### 그룹 이름을 넓혔다 — 「데이터 수집 체계」 → **「데이터 체계」**

미뤄 둔 자리가 이것이었다. 그룹을 하나 더 두는 대신 이름에서 '수집' 을 뺐다:
장비 파일 정의가 「어떻게 읽나」 라면 덱 정의는 「어떻게 쓰나」 이고, **둘 다 데이터를
무엇으로 다루나 라는 한 가지 일이다.** 쓰는 사람도 같다 — 새 솔버를 붙이는 사람은
장비 파일 정의를 만든 그 사람일 때가 많아서, 덱 정의를 장비 파일 정의 **바로 다음**에 뒀다.

#### JSON 이 아니라 줄 폼으로 적는다

정의는 JSON 이지만 JSON 으로 적게 하지 않았다. 이 문법은 자유 형식이 아니라 **네
가지 줄**뿐이라 고르는 편이 적는 편보다 틀릴 자리가 적고, **덱에서 틀린 자리는
솔버가 오류로 알려 주지 않는다.**

폼과 JSON 사이를 옮기는 코드가 하나 생겼다(`deckLines.ts`). 거기가 조용히 틀리는
자리다 — 미리보기도 이 변환을 거친 정의를 보므로 **같이 틀린다.** 그래서 시험을
그 변환에 걸었다:

    빈 칸을 안 보낸다     `when: ""` 은 「늘 그린다」 가 아니라 값 하나를 찾는
                       조건이 되어 그 줄이 통째로 사라진다.
    상수를 값으로 안 바꾼다  Prony 의 체적항은 상수다. 값이 되면 표에 없는 열을 찾다
                       덱이 안 나온다.
    왕복해도 같다        고치러 들어와 저장만 눌러도 정의가 바뀌면, 아무도 안 건드린
                       솔버의 덱이 어느 날 달라져 있고 왜인지는 아무 데도 안 남는다.

**저장할 때도 실제로 만들어 본다**(`_checked`). 안 하면 「저장은 됐는데 내려받을
때 터지는」 정의가 생기고, 그때는 화면에서 고칠 사람이 그 자리에 없다 — 해석을
돌리려던 사람이 500 을 본다. 고칠 때도 검사한다(만들 때만 하면 고치며 깨뜨린다).

**`key`·`label` 은 행의 칸이 정본이다.** 컬럼에도 정의에도 둘 수 있는데, 두 벌로
두면 목록에 뜨는 이름과 덱에 적히는 이름이 어긋나고 어느 쪽이 맞는지 화면에 안
나온다.

#### 빈 폼에서 시작하지 않는다 — **예제 덱을 읽어 초안을 만든다**

폼을 만들어 놓고 보니 *「어떻게 쓰는 건지 모르겠다. 약간 막연하다」* 였다. 맞는
지적이었다: 무슨 줄을 몇 개 쌓아야 하는지, 칸 폭을 얼마로 둬야 하는지 화면 어디에도
없었다.

**장비 파일 정의가 같은 문제를 이미 풀었다**(ADR 0006) — 실제 파일을 올리면 구조는
코드가 읽고 「이 열이 무엇인가」 만 사람이 정한다. 덱 쪽만 그 대칭이 없었다. 그리고
**덱을 붙이려는 사람에게는 대개 그 솔버의 덱 파일이 이미 있다** — 해석을 돌려 본
사람이니까.

`matcore/export/scan.py` · `POST /fitting/export-profiles/scan`.

    읽는다                          못 읽는다 (= 사람이 할 일)
    ──────────────────────────     ──────────────────────────────
    키워드 줄인가 숫자 줄인가          어느 숫자가 탄성계수인가
    연속된 같은 모양 = 표             이 줄이 언제 빠지는가(`when`)
    구분자(쉼표냐 칸이냐)              이 표가 소성인가 Prony 인가
    **칸 폭과 지수 자릿수**

**카드를 함께 주면 이름까지 제안한다.** 덱의 숫자와 카드 값을 맞춰 `7850 →
elastic.density` 를 붙인다 — 그것이 「막연하다」 를 실제로 없애는 자리다. 다만
**맞는 것이 여럿이면 아무것도 제안하지 않는다**: 0 이나 1 은 여러 자리에 나오고,
그때 하나를 고르는 것은 짐작이며 **짐작을 제안으로 내면 사람이 그대로 저장한다.**
제안한 자리는 「짐작입니다」 라고 함께 적는다.

##### 만들면서 잡은 것 넷 — 넷 다 조용히 틀리는 종류였다

    `DP600` 의 600         키워드 줄의 재료 이름에 숫자가 있다. 숫자 유무로 가르면
                          키워드 줄이 값 줄이 된다 — 접두사(`*` `/` `#` `$` `!`)를
                          먼저 본다.
    값 줄 하나가 사라졌다    표가 아닌데도 같은 모양을 묶고 한 줄만 냈다. 없어진 줄은
                          화면 어디에도 안 남는다.
    길이만 나누어떨어짐      `1.0E+00 22.0E+00` 은 16÷2=8 로 떨어지지만 첫 숫자가
                          7번째에서 끝난다. 8칸으로 저장하면 **모든 값이 한 칸씩
                          밀려 다른 필드로 읽힌다** — 끝 위치까지 본다.
    표로 묶는 선은 3줄부터   둘을 표로 보면 값 줄 둘 중 하나가 사라진다. 반대(표를
                          값 줄로 봄)는 화면에 그대로 보여서 사람이 안다.

앞의 셋은 **시험이 먼저 잡았다.** 사보타주도 걸었다 — 키워드 접두사 무시 · 표 최소
2로 · 애매해도 제안 · 칸 폭 20 고정 · 정렬 검사 빼기 · 안 묶은 줄 건너뛰기.

##### 전처리기가 낸 덱 — **HyperMesh 가 흔하다**

*「예제파일에 주석이 있으면 착각하진 않나. HyperMesh 로 인풋덱 출력하면 그런 경우가
종종 있다」* 는 물음에 실제 덱으로 확인했다. **주석 자체는 잘 걸렸다** — HyperMesh 가
쓰는 `$$` · `$HMNAME` · `**HM_ADD_COMMENTS` · `$#` 가 다 접두사 규칙에 걸린다.

**그런데 주석이 아닌 자리에서 두 개가 걸렸다:**

    MAT1 의 1              Nastran 벌크 데이터는 **키워드 이름에 숫자가 있고**
    TABLES1 의 1           `$` 로 시작하지도 않는다. 칸이 하나 늘어난 채로 정의가
                          만들어지고, 그 덱은 **모든 값이 한 칸씩 밀린다.**
    주석이 표를 두 동강      HyperMesh 는 카드마다 이름·색 주석을 넣는다. 같은 모양의
                          줄이 주석으로 갈려 표로 안 묶인다.

첫째는 **글자에 붙은 숫자를 값으로 안 읽는** 것으로 고쳤다(앞뒤 둘 다 본다 —
`1.0D` 처럼 지수가 잘린 표기와 `100mm` 같은 단위도 값이 아니다). 이 검사는 접두사
규칙보다 넓어서 `NAME=DP600_MD` 의 `600` 도 여기서 걸린다.

둘째는 **고치지 않고 말해 준다.** 주석을 건너뛰고 이어 붙이면 그 주석이 사라지는데
덱에 있던 것이라 정의에도 남아야 하고, 무엇보다 **거기가 진짜 경계일 수 있다**(다른
재료의 표가 이어지는 자리). 흩어진 같은 모양이 셋 이상이면 「표로 묶지 않았다」 를
적고, **없으면 적지 않는다** — 없는 문제를 말하면 다음부터 안 읽는다.

##### 일곱 솔버 덱으로 다시 확인했다 — **여섯을 더 잡았다**

Abaqus · HyperMesh Abaqus · Nastran/OptiStruct(고정·자유) · LS-DYNA(카드·곡선) ·
ANSYS APDL · OpenRadioss 를 통째로 먹여 봤다. 주석은 다 걸렸는데 **주석이 아닌
자리에서 여섯이 나왔다.** 여섯 다 「칸이 하나 늘거나 줄어 모든 값이 밀리는」 종류다.

    Nastran 축약 지수     `7.85-9` 는 `7.85e-9` 다. `7.85` 와 `-9` 로 읽었다 —
                        값도 칸 수도 틀렸다. **소수점이 있을 때만** 축약으로 본다
                        (`1-2` 를 지수로 오해하지 않게).
    왼쪽 맞춤을 못 쟀다     맞춤이 두 가지다 — LS-DYNA·Radioss 는 오른쪽,
                        Nastran·OptiStruct 벌크는 왼쪽. 오른쪽만 보면 절반이 막힌다.
    폭을 길이로 나눴다      `MAT1` 이 첫 칸을 차지하면 안 맞는다. **간격으로** 재고,
                        자리마다 폭의 배수인지까지 본다.
    ANSYS 세 물성이 한 표   `MP,EX`·`MP,PRXY`·`MP,DENS` 가 숫자 개수만 같아 묶였다 —
                        표는 줄 하나로 여러 줄을 내므로 **두 물성이 사라졌다.**
                        접두 글자를 줄의 모양에 넣어 갈랐다.
    접두 글자를 담을 데 없음  `MP,EX,` · `MAT1    ` 을 못 적으면 그 솔버는 **아예 정의로
                        못 붙인다.** 템플릿에 `prefix` 를 넣었다.
    값 줄의 상수          Nastran 은 재료 번호가 값과 같은 줄에 온다. 상수가 표에만
                        있어 그 줄을 못 적었다.

**왕복으로 확인했다**: 남의 Nastran 덱을 읽어 정의로 만들고, 그 정의가 낸 덱이
다시 8칸 왼쪽 맞춤으로 읽힌다. 읽기만 되고 그 모양으로 못 내면 초안은 종이일 뿐이다.

사보타주 일곱이 물었다 — 축약 지수 끄기 · 왼쪽 맞춤 무시 · 접두를 모양에서 빼기 ·
접두 안 담기 · 앞 공백을 접두로 · 배수 검사 빼기 · 최소 폭 없애기.

##### 「남는 한계」 로 적었던 둘 — 하나는 이미 됐고 하나는 고쳤다

**연속 카드는 이미 됐다.** `+` 가 접두로 잡혀 세 줄이 표로 묶인다 — 한계라고 적은
것이 확인 없이 쓴 말이었다.

**빈 필드는 진짜 결함이었다.** `MAT1,1,210000.,,0.3,7.85E-9` 의 네 번째는 전단
탄성계수 자리이고 비운 것은 「기본값을 쓰라」 는 뜻인데, 그것을 빼고 세면 **뒤 값이
한 칸씩 당겨져** 푸아송비가 그 자리로, 밀도가 푸아송비 자리로 간다. 해석은 그대로
돌고 솔버는 아무 말도 안 한다.

**쉼표로 가르는 줄은 쉼표가 칸을 정하게** 했다. 빈 칸은 `empty` 로 표시해 초안에서
빈 상수(`{"const": ""}`)가 되고, 그 자리가 덱까지 `,,` 로 살아 나간다. **빈 상수도
저장한다** — 안 보내면 자리가 사라져 같은 어긋남이 다시 생긴다.

덤으로 하나 더 잡혔다: `TABLES1        2` 의 폭을 **16칸으로 쟀다.** 실제로는 8칸
둘이고 앞칸이 키워드다 — 값 하나로는 알 수 없으므로 **앞에 글자가 있으면 폭을
짐작하지 않는다.** 틀린 폭보다 자유 형식이 안전하다(자유 형식은 넘치지 않는다).

### 5. 소프트 삭제·휴지통

**했다** (2026-08-30). 수집 체계 넷과 같은 규칙이다 — 부분 유니크 인덱스
(`deleted_at IS NULL` · `nulls_not_distinct`)까지. 휴지통 종류로 「솔버 덱 정의」 가
늘었다.

**매달린 것을 검사하지 않는다.** 덱 정의에 딸린 데이터가 없다 — 지우면 그 솔버로
못 낼 뿐이고, 이미 나간 덱은 파일이라 그대로다.

## 결과

- **얻는 것**: 키워드만 다른 솔버가 배포 없이 는다. 현장에서 만든다.
- **잃는 것**: 덱을 만드는 길이 둘이 된다. 「왜 이 솔버는 코드고 저건 정의인가」 를
  누군가 반드시 묻는다 — 위의 선 긋기 표가 그 답이고, 답이 흐려지면 이 결정을
  다시 본다.
- **안 하면**: 새 솔버마다 요청 → 개발 → 배포. 솔버가 둘뿐이면 그게 더 싸다.
