# 0036. 나가는 숫자의 기본 단위계는 **mm·N·tonne** — 저장은 그대로 SI

날짜: 2026-09-24
상태: 채택
관련: [ADR 0004](0004-재료-계층과-식별자-정책.md) ·
[ADR 0035](0035-보기는-모두에게-고치기는-사람에게.md)(D3 교환의 두 길) ·
개발계획 「화면 단위를 CAE 단위계로 옮겼다」(v1.88.0) · 「화면 단위가 API 로 새어 나갔다」

## 배경

해석 연동 쪽이 MatNexus 에서 받은 데이터를 보고 짚었다(2026-09-24):

    밀도       2.68e-09  tonne/mm3   ← mm·N·tonne
    탄성계수    7.0e+10   Pa          ← SI
    열전도율    237       W/(m.K)     ← SI

받은 파일은 재료 내보내기(`GET /api/materials/export`)였다. 그 함수의 설명은 「값은 **SI
그대로**다」 인데, 화면 응답(`_material_out`)을 그대로 담아서 **밀도는 화면 표시 단위,
두께는 넣은 단위**였다. 받는 쪽이 「전부 SI」 로 읽으면 밀도가 10¹² 배, 모델이 mm 계라서
SI 를 그대로 넣으면 탄성계수가 10⁶ 배 틀리고 — 둘 다 **오류 없이 그럴듯한 답**을 낸다.

그 전에도 계를 고르는 자리는 있었다. 카드 덱은 `units` 로 SI · mm·N·tonne · 사용자 계를
골랐고(v1.110.0), 화면과 MCP 는 mm·N·tonne 을 기본으로 골라 보냈다(2026-09-05). 그런데 **REST
를 인자 없이 부르면 SI** 였다 — 「스크립트가 전과 다른 것을 받으면 안 된다」 는 판단이었다.
그래서 같은 카드가 화면에서 받으면 mm·N·tonne, 연동이 인자 없이 받으면 SI 였고, 재료·문헌
내보내기에는 고를 자리가 아예 없었다.

## 결정

### D1. 나가는 숫자는 고른 단위계 하나로 — 고르지 않으면 mm·N·tonne

다른 시스템으로 나가는 것 전부가 `units` 를 받고, **안 주면 mm·N·tonne** 이다.

| 자리 | 전 | 지금 |
| --- | --- | --- |
| 카드 덱·중립 JSON `GET /fitting/cards/{id}/export` | 인자 없으면 SI | mm·N·tonne |
| 덱 미리보기·되읽기 검사·카드 묶음(POST 본문 `units`) | SI | mm·N·tonne |
| 부품표 덱(BOM)·문헌 덱 | SI(사용자 계는 못 골랐다) | mm·N·tonne(사용자 계도) |
| 재료 내보내기 `GET /materials/export` | 「SI」 라 적고 밀도·두께만 표시 단위 | `units`, 기본 mm·N·tonne |
| 문헌 내보내기 `GET /catalog/export` | SI(고를 수 없었다) | `units`, 기본 mm·N·tonne |

SI 는 `units=si` 로 고른다. 계를 고르는 자리는 `app/shared/unit_systems` 하나다(`DEFAULT`) —
자리마다 기본을 적어 두면 한 곳만 SI 로 남고, 그 한 곳이 이번 같은 사고가 된다.

**화면도 같은 목록에서 고른다.** 재료·문헌의 「JSON 내보내기」 는 계를 먼저 고르고 받는
메뉴가 됐고(`shared/components/ExportJsonMenu` — 받기 전에 파일 이름으로 계가 보인다), 문헌
덱·부품표 덱은 화면이 적어 둔 SI 기본을 걷고 서버 목록의 기본(`is_default`)을 쓴다. 목록은
`frontend/src/shared/api/unitSystems` 에 둔다 — 재료·문헌 화면이 카드 모듈을 부르지 않게.

화면이 기본을 적어 둔 자리는 **서버 기본이 바뀌는 날 거꾸로 뒤집힌다.** 부품표 덱은 「SI 면
비워 보낸다」 였는데, 비운 것이 이제 mm·N·tonne 이라 SI 를 고른 사람이 오류 없이 mm 덱을 받을
뻔했다. 화면은 고른 키를 그대로 싣는다.

### D2. 파일이 제 계를 말한다

기본이 바뀌었으니 어제 받은 파일과 오늘 받은 파일이 다를 수 있다. 그래서 숫자를 읽기 전에
계가 보이게 한다.

- **파일 머리에 `unit_system`** — 키 · 이름 · 질량/길이/시간 · 응력 기호 · SI 기호 → 이 계의
  기호 표 전부. 덱은 전처럼 머리 주석(Abaqus)이나 `/UNIT`(OpenRadioss)으로 말한다.
- **파일 이름에 계의 키** — `…_mm_n_tonne.json` · `…_si.k`. 두 계가 한 폴더에 섞여도 열지
  않고 가려진다.
- **값마다 단위** — `value` 는 그 계, `value_si`·`density_si` 는 저장된 SI 를 곁에 둔다.
  중립 JSON 은 선언마다 `unit`(이 파일의 단위)을 `si_unit` 곁에 싣는다 — `si_unit: "Pa"` 만
  두면 MPa 숫자를 Pa 로 읽는다.

### D3. 계가 정하는 물리량은 전부 옮기고, 정하지 않는 것은 그대로 두고 **적는다**

계가 정하는 것은 질량·길이·시간 셋이다. **그 셋(과 온도)으로 짜인 SI 단위는 전부 옮긴다** —
카드 블록의 11종(`systems.DECLARED`)에 더해 나가는 파일이 드는 29종(`systems.EXCHANGED`):
선하중 N/mm · 에너지 mJ · 표면에너지 mJ/mm² · 확산율 mm²/s · 파괴인성 MPa·mm^0.5 · 속도 mm/s ·
열유속 mW/mm² · 면밀도 tonne/mm² · 음향 임피던스 N·s/mm³ … 기호는 SI 기호의 m·kg·Pa·J·W 를
mm·tonne·MPa·mJ·mW 로 바꾼 것이고, 음향 임피던스만 `MPa.s/mm` 대신 `N.s/mm3` 로 적는다(사람이
`mPa.s` 로 읽는다 — 점도와 같은 이유).

**전류·물질량·로그·눈금·각은 계가 정하지 않는다** — 저항률(ohm·m)·전도율(S/m)·몰당
에너지(J/mol)·준위 에너지(eV)·dB·경도(HV·Shore)·deg. 지어내 옮기지 않고 받은 값과 단위를
그대로 두되, 파일 머리의 `kept_units` 에 적는다. 모델 파라미터의 항(`term`)은 정의의 단위가
아니라 제 단위(대개 MPa·1/s·K)로 적혀 있어 옮기지 않는다.

처음에는 카드의 11종만 옮기고 나머지를 전부 `kept_units` 로 두었다(같은 날 오전). 문헌
SUS304 하나를 받아 보니 9종이 남았고 그 가운데 넷(J/m² · m/s · m²/s · Pa·s/m)은 역학
물리량이었다 — 해석 연동이 「넣어 달라」 고 했다. 부서가 만든 계도 같은 표로 유도된다 —
기호에는 그 계의 기본 단위만 든다(kg·mm·ms 계의 질량 플럭스는 `tonne/(mm2.s)` 가 아니라
`kg/(mm2.ms)`, 인수는 같아도).

### D4. 저장도 REST 도 SI — 표시는 화면의 일

- **저장** — 처리 결과의 해시 사슬이 저장값에 걸려 있다(v1.88.0). 옮기면 전부 다시 써야 하고
  얻는 것은 「DB 를 열었을 때 익숙한 숫자」 하나다.
- **REST 의 화면용 응답**(`GET /materials` 등)도 SI 다 — 재료·시료의 밀도(kg/m³)·규격
  두께(m), 시편 치수(m), 「값 출처」 패널(`property-sources`)까지, 선언 물성과 같은 계다.
  mm · tonne/mm³ 로 바꿔 보이는 것은 화면이다. 입력은 값과 단위를 함께 받고(화면은 표시 단위를
  적어 보낸다), **단위를 안 적으면 응답과 같은 SI** 로 읽는다 — 읽은 값을 그대로 되보내면 제
  숫자가 돌아와야 해서다. 단위 실수는 울타리가 거절한다: 밀도는 0.5~50,000 kg/m³(카드와 같은
  것), 시편 치수는 1 m 까지(mm 로 적은 폭 12.5 를 단위 없이 보내면 12.5 m 다).
- **MCP 가 주고받는 값**은 SI 다. 사람에게 답할 때만 mm·N·tonne 으로 말한다(안내 GUIDE).

**처음에는 달랐다**(같은 날). 재료·시료의 `density` 는 화면 표시값(tonne/mm3)으로 두고 SI 를
곁의 `density_si` 로 줬다 — 수정 창이 그 값을 되보내는 모양이라 뜻을 바꾸기 겁났다. 그런데
화면이 이미 변환 도구를 갖고 있었고(재료 상세는 표시값을 SI 로 되돌렸다가 다시 표시 단위로
바꾸는 왕복을 하고 있었다), 칸이 둘이면 받는 쪽이 어느 것을 읽을지 다시 고른다. 그래서
`density`·`spec_thickness` 를 SI 로 바꾸고 `density_si` 를 걷었다. 내보내기 파일의 `density_si`
는 남는다 — 거기서 `density` 는 고른 계라 SI 가 곁에 있어야 한다(`value_si` 와 같은 자리).
시편 치수(`thickness`·`width`·`gauge_length` — 넣은 단위를 되돌려 줬다)와 「값 출처」 패널
(`display_unit` — 서버가 표시 단위로 바꿔 줬다)도 같은 날 밤 SI 로 옮겼다. 패널의 칸은 이제
`si_unit` 이다(적합 응답의 「물려받는 값」 과 같은 이름 — 그쪽은 처음부터 SI 였다).

## 대안

- **인자 없는 호출은 SI 로 둔다**(2026-09-05 의 판단) — 옛 스크립트를 지키지만, 이번처럼 새
  연동이 기본을 믿고 받으면 해석이 쓰는 계와 다른 것을 받는다. 파일이 제 계를 말하게 한 뒤라
  기본을 바꿔도 **조용히** 달라지지는 않는다고 판단했다.
- **저장까지 mm·N·tonne** — D4. 이득에 비해 비용(해시 사슬 · 파일 420개)이 크다.
- **화면용 응답에도 `units`** — 화면 수정 창이 표시값을 되보내는 모양이라, 같은 칸이 요청에
  따라 다른 계가 되면 되보낸 값이 어느 계인지 서버가 모른다. 연동은 내보내기를 쓴다.

## 결과

- `app/shared/unit_systems` — `DEFAULT`·`resolve`(비우면 기본, 사용자 계 포함)·`convert`
  (표기를 가려 읽고, SI 단위만 옮기고, 못 옮기면 그대로 두고 말한다)·`describe`.
- 부품표 덱과 문헌 덱이 **사용자 계를 못 고르던 것**도 같이 풀렸다 — 둘 다 붙박이만 찾았다.
- 시험: 인자 없이 받으면 mm·N·tonne 이고 파일 이름에 계가 든다 · `units=si` 는 SI · 모르는
  계는 422(쓸 수 있는 것을 말한다) · 재료 내보내기의 밀도·두께·선언 물성이 한 계 · 문헌의
  불확도도 같은 계 · 못 옮긴 단위가 `kept_units` 에 · 파라미터 항은 그대로.
  SI 숫자를 대조하던 시험 다섯은 **SI 를 대 놓고 고르게** 고쳤다 — 그것 자체가 「이제 SI 는
  골라야 나온다」 를 적는다.
- 기호표(D3): 붙박이 계의 인수(단위표)와 유도한 계의 인수(차원식 `EXPONENTS`)를 새 단위까지
  대조하고, 차원식은 기호를 밑기호로 풀어 다시 센다 — mm·N·tonne 은 시간이 s 라 시간 지수가
  틀려도 숫자가 같게 나와 그 계로는 안 드러난다. 실제 DB 표기(`J/m^2`·`Pa*m^0.5` …)로 옮기는
  시험을 따로 둔다. 사보타주 셋(단위표 인수 · 시간 지수 · tonne 이 든 인수)이 전부 물렸다.
  `mJ` 가 단위표에 들어오면서 `MJ`(메가줄)는 「대소문자로 갈린다」 로 거절된다(`MPa.s` 와 같다).
- 화면 시험: 안 고르면 서버가 기본이라 한 계(목록의 첫째가 아니게 두었다)가 요청과 파일
  이름에 실린다 · 부서가 만든 계도 고른다 · 목록을 못 받았으면 받지 않는다 · 부품표 덱에서
  SI 를 고르면 `si` 가 실린다. 사보타주 둘(옛 「SI 면 비움」 · 기본을 목록의 첫째로)에 각각
  2건 · 6건이 물었다.
- **받는 쪽이 할 일** — 인자 없이 받던 연동은 이제 mm·N·tonne 을 받는다. SI 가 필요하면
  `units=si` 를 붙이고, 어느 쪽이든 파일 머리의 `unit_system` 을 먼저 읽는다.
