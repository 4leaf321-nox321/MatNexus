# 0050. 물성의 정의문은 허브 키가 들고, 조회가 돌려준다

날짜: 2026-10-02
상태: 채택
관련: [ADR 0027](0027-물성-카탈로그를-들인다.md)(문헌 카탈로그) · [ADR 0028](0028-온톨로지는-표를-안-바꾸고-얹는다.md)(온톨로지) ·
[ADR 0046](0046-가이드-씨앗은-사람이-안-고친-절만-따라간다.md) · [ADR 0047](0047-기본-형식-정의판은-배포가-꺼진-채-넣는다.md)(씨앗은 사람이 안
고친 것만 따른다) · [ADR 0035](0035-보기는-모두에게-고치기는-사람에게.md)(검토의 뜻이 있는 일은 자료 관리자)

## 배경

요청(2026-10-02): 「물성 설명칸은 있지만 조회 도구가 이름 · 단위 · 기호만 돌려주고 설명을 주지 않는다.
물성의 정의문을 받을 필요가 있다.」

실측:

- 문헌 물성 정의에 정의문 칸(`catalog_definitions.description`)이 있고 「문헌 물성 추가」 창 · MCP 추가
  도구가 그 칸을 받는다. 그런데 **271종 전부 비어 있었다** — 원본(MaterialTwin)의 정의 271개도 설명이 0개다.
- 조회 쪽은 그 칸을 아예 안 실었다 — 이름 풀기(`/catalog/properties/resolve`, MCP `resolve_property`),
  물성 키 사전, 사내 물성 항목 목록(MCP `list_property_items`), 매핑 화면 모두 이름 · 단위 · 기호뿐이었다.
- 그래서 「항복응력」(페이스트가 흐르기 시작하는 응력, 9건)과 「항복강도」(금속의 0.2 % 내력, 486건)를
  이름과 도메인으로만 가렸다 — `resolve_property` 의 안내가 바로 이 혼동을 경고하는데, 뜻을 읽을 글은 없었다.
- **배포마다 원본 이관이 다시 돈다**(`deploy.ps1` → `import_materialtwin.py --apply`). 정의 행을 원본 값으로
  갱신하므로, 사내에서 정의문을 적어도 원본의 빈 값이 배포마다 지웠을 것이다.

## 결정

1. **정의문은 허브 키(문헌 물성 정의) 한 곳에 둔다.** 사내 물성 항목은 자기 정의문을 따로 갖지 않고, 「같은
   것(`same_as`)」 으로 이은 키의 정의문을 낸다. 항목마다 적으면 같은 물성의 뜻이 두 벌이 되고 갈린다.
   같은 물성 연결이 둘 이상인 항목(경도 — HV · HB 척도마다 다른 키)은 하나로 못 정해 비운다.
2. **조회가 정의문을 돌려준다** — 이름 풀기 후보(`description` · `test_standard`), 물성 키 사전
   (다른 시스템이 받아 가는 파일), 사내 물성 항목 목록(`property_key` · `description`), 매핑 화면. MCP 의
   두 도구는 응답을 그대로 넘기므로 저절로 실리고, 도구 설명과 GUIDE 가 「후보를 이름이 아니라 정의문으로
   고르고, 뜻을 물으면 지어내지 말고 이 글을 옮겨라」 고 말한다.
3. **내용은 씨앗이 채운다** — `seeds/catalog/property-descriptions.json` 에 271종의 정의문(무엇인가 · 어떤
   기준으로 잰 값인가 · 함께 읽어야 할 조건 · 헷갈리는 이웃 물성, 한두 문장). 모델 상수 묶음(Anand · Prony ·
   초탄성 등)은 「항마다 뜻 · 단위가 달라 한 벌로 써야 한다」 고 적는다. 배포의 씨앗 맞추기
   (`refresh_builtins.py`)가 **비었거나 아무도 안 고친 정의문만** 채운다 — 씨앗이 마지막으로 쓴 글의
   지문(`description_seed_digest`, 마이그레이션 `8b3d5f7a9c21`)과 지금 글이 같을 때만 새 씨앗을 따른다
   (ADR 0046 · 0047 과 같은 규칙). 사람이 고친 것은 안 덮고 이름만 로그에 적는다.
4. **원본 이관은 빈 정의문으로 덮지 않는다.** 원본에 정의문이 생기면 그것이 이긴다 — 원본이 정본이다.
5. **고치기는 자료 관리자 · 시스템 관리자**(`PATCH /catalog/properties/{key}`, `require_steward`). 허브 키의
   뜻은 사내 항목 · 다른 시스템 · AI 가 함께 읽으므로 「검토의 뜻이 있는 일」 이다. 고치면 감사에 남는다
   (`catalog_property.described`). 잇기 · 폐기(시스템 관리자)보다 넓은 까닭: 정의문은 값 검색을 바꾸지 않는다.
6. **AI 에게 고치는 도구는 두지 않는다.** 정의문은 사람이 읽고 책임지는 뜻이다. 필요하면 연다.

## 대안

- **사내 물성 항목에 정의문 칸을 따로 둔다.** 항목과 허브 키가 같은 물성을 두 글로 말하게 된다 — 한쪽만
  고쳐지는 날 화면과 AI 가 다른 뜻을 읽는다. 기각. 허브 키에 안 이어진 사내 전용 항목은 「문헌 물성 추가」 로
  키를 만들어 잇는 길(ADR 0045)이 이미 있다.
- **정의문을 비워 두고 사람이 채우게 한다.** 271종을 누가 언제 채울지 정해지지 않으면 조회는 계속 빈 칸을
  돌려준다. 씨앗으로 채우고 사람이 고치는 쪽이 낫다. 기각.
- **정의문을 화면에서만 보이고 도구에는 안 싣는다.** 요청이 바로 도구였다. 응답이 커지는 것은 후보당 한두
  문장이라 감당된다. 기각.

## 결과

- 문헌 물성 271종에 정의문이 생겼고(개발 DB 에 씨앗 맞추기로 채움), 이름 풀기 · 사전 · 사내 항목 · 매핑
  화면 · MCP 두 도구가 그것을 돌려준다.
- 화면: 「온톨로지 편집 → 사내 물성 항목 → 물성 매핑」 표의 문헌 물성마다 정의문(없으면 「정의문 없음」)과
  자료 관리자용 연필 단추. 선언 물성 편집 창이 고른 항목의 정의문을 보이고, 항목 고르기 목록은 마우스를
  올리면 보인다.
- 마이그레이션 `8b3d5f7a9c21`(칸 하나). 배포는 마이그레이션 → 씨앗 맞추기 → 카탈로그 이관 → 씨앗 맞추기
  순이라, 갓 설치한 서버도 두 번째 씨앗 맞추기에서 정의문을 받는다.
- 시험: `tests/api/test_property_descriptions.py`(씨앗 · 사람이 고친 것 보존 · 이관 · 조회 넷 · 고치기 ·
  권한), `tests/architecture/test_catalog_seed.py`(정의문 씨앗이 동봉 원본의 물성을 빠짐없이 덮는다 — 원본에
  물성이 늘면 정의문도 쓰라고 멈춘다), 화면 시험(매핑 표 · 고치기 창 · 선언 물성 창).
- **점검에서 잡은 것**: 이름이 정확히 안 맞아 **뜻으로 찾은 후보**(`matched_by: meaning`)는 다른 길에서 만들어져
  정의문을 빠뜨렸다 — AI 세션이 「유전손실계수(Df)」 를 「정의문이 아직 없다」 고 답해 드러났다. 고치고 시험으로
  묶었다. 의미 색인은 정의문까지 한 조각으로 심으므로(`semantic._property_chunks`), 배포 뒤 주기 색인
  (`search.reindex`)이 돌면 뜻 찾기도 정의문으로 걸린다.
- 사보타주 다섯(이관이 빈 정의문으로 덮음 · 씨앗이 사람 글을 덮음 · 고치기 권한 · 같은 것 아닌 연결의 정의문 ·
  뜻 경로의 정의문 누락)을 시험이 전부 물었다. MCP 프로브 101건 중 100(남은 1은 자료에 따른 거절), AI 세션은
  「항복응력 / 항복강도」 를 정의문을 인용해 갈랐다.
- **열린 것**: `local.*`(사내에서 만든 키)의 정의문은 만든 사람이 적는다 — 씨앗에 없다. 정의문의 영문판.

## 덧붙임 (2026-10-04) — 결정 4 다듬기: 원본 글은 사람이 안 고친 동안만 이긴다

결정 4(「원본에 정의문이 생기면 그것이 이긴다」)는 고치기 경로의 약속(「고친 정의문은 배포가 안
덮는다」)과 부딪친다. 원본에 정의문이 생기는 순간 이관이 배포마다 원본 글로 덮어, **자료 관리자가
고친 글이 배포마다 되돌아갔을** 것이다. 지금 원본의 정의문은 271종 전부 비어 있어 안 터졌을 뿐이다.

- 원본 글을 **따로 든다**(`catalog_definitions.source_description`, 이관이 매번 다시 적는다).
- 이관은 정의문 칸이 비었거나 **기계가 마지막으로 쓴 글 그대로**(씨앗이든 원본이든 — 지문이 같다)일
  때만 원본 글로 바꾼다. 사람이 고친 글은 안 덮는다.
- 원본 글이 있는 키는 **씨앗이 안 채운다** — 원본이 정본이다. 안 그러면 배포마다 이관(원본 글)과
  씨앗 맞추기(사내 글)가 번갈아 쓴다.

시험: `tests/api/test_property_descriptions.py::Test원본에_정의문이_생기면`, 사보타주 둘(이관이 사람
글을 덮음 · 씨앗이 원본 글을 덮음)을 시험이 물었다.
