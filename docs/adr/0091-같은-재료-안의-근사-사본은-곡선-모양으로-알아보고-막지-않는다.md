# 0091. 같은 재료 안의 근사 사본은 곡선 모양으로 알아보고 막지 않는다

날짜: 2026-11-17
상태: 채택
관련: [ADR 0077](0077-같은-측정은-SI-값-지문으로-알아보고-막지-않는다.md)(값 지문) ·
[ADR 0076](0076-확인할-경고는-결과와-함께-남고-채택에서-확인을-받는다.md)(점검이 채택 · 카드로 간다)

## 배경

ADR 0077 의 값 지문은 곡선의 SI 값을 유효숫자 10자리로 해시해 **정확히 같은 값**만 알아본다. 줄끝 ·
머리말 · 형식 · 단위 표기만 다른 사본은 잡지만, VOC 54 에서 남긴 셋은 지문이 달라 통계에 두 번 들어갔다.

- 자릿수를 줄여 저장한 사본(엑셀로 열었다 저장)
- 점을 솎은 사본(장비가 몇 점에 하나만 내보냄)
- 단위를 잘못 적어 한 열이 일정한 배수로 어긋난 사본(kN 을 N 으로 — SI 로 바꿔도 1000배)

비슷하지만 따로 잰 시편까지 사본으로 짚으면 경고가 늘 떠서 아무도 안 읽게 된다. 그래서 브리핑에서 「같은
재료 안에서만 견주고 기준은 개발 DB 곡선으로 오경보를 세어 본 뒤 정한다」 로 했고 사용자가 골랐다.

## 결정

1. **곡선마다 작은 모양을 둔다**(`curves.shape`, 마이그레이션 `c9e3a7d51f42`, `matcore.curves.shape`). 지문과
   같은 채널(시험 종류가 정의한 것)에서, 이름순으로 처음 「늘기만 하는」 열(인장은 변위, DMA 변형률 스윕은 진동
   변형률)을 축으로 그 [최소, 최대] 를 고르게 나눈 64 자리의 다른 열 값을 둔다. 축 위의 자리로 재므로 점을
   솎아도 모양이 같다. 그런 열이 없으면 행 차례(0~1)로 잰다. 곡선 하나에 대개 1~2 KB(개발 DB 최대 5.6 KB).
2. **견주기**(`near_copy` · `copy_gap`): 축 · 채널 목록이 같아야 하고, 축 범위 비와 채널마다 크기의 비는 단위
   상수(1 · 10의 거듭제곱 · 9.80665 · 25.4 · 6894.757 · 4.448222 · 60 · 3600) 중 가장 가까운 것에서 5 % 안이어야
   한다. 겹친 축 구간이 양쪽 다 90 % 넘어야 한다(잘린 사본은 이 판정의 몫이 아니다). 차이는 채널 폭 대비
   차이의 95 번째 자리 중 가장 큰 값 — **0.4 % 아래면 거의 같다**(잠정값).
3. **읽을 때 같은 재료 · 같은 시험 종류의 다른 시험과만 견준다**(`tests.services._near_copies`). 다른 재료의
   비슷한 곡선은 정상이다. 지문이 같은 곡선 · 같은 원본 파일은 앞의 점검이 말하므로 뺀다. 최근 2000 곡선까지.
   점검 `near_duplicate_curve` 로 남고 다른 점검처럼 채택 확인 · 일괄 「바로 채택」 미룸 · 카드 근거로 간다.
   **막지 않는다.** 통계의 「같은 지문은 하나로」 에도 넣지 않는다 — 근사는 판정이라 사람이 본다.
4. 칸에 두는 까닭: 재료 하나에 시험이 수백 건이면 업로드마다 그만큼 곡선 파일을 열게 된다(파일 하나 3 ms).
   모양끼리 견주면 쌍 하나에 0.3 ms 안팎이다.
5. 옛 곡선은 `backfill_curve_fingerprints.py` 가 지문과 함께 채운다(배포의 채우기 단계). 끝 줄에 같은 재료 안
   거의 같은 곡선 쌍 수를 센다 — 옛 시험의 점검은 다시 읽어야 선다.

## 기준값 — 개발 DB 실측(2026-11-17, 측정 곡선 197개)

- 같은 재료 · 종류의 다른 시험 곡선 쌍 524개(같은 지문 316쌍 제외) 중 견줄 수 있던 236쌍: 가장 가까운 쌍이
  0.57 %(예제 파일을 늘려 만든 데모), 따로 잰 시편은 1.4 % 넘게 달랐다. 0.4 % 아래는 **0쌍**.
- 합성 사본(점 200개 넘는 원본 44개): 유효숫자 4자리 44/44(최악 0.28 %) · 10점에 하나(첫 점 빠짐) 44/44
  (최악 0.33 %) · 한 열 1000배 + 5점에 하나 44/44 · 유효숫자 3자리는 26/44 — 3자리는 0.1 % 해상도라 따로 잰
  시편과 가르기 어렵다.
- 먼저 해 본 두 안: 행 차례로 64 점(솎으면 끝이 어긋나 10/14 만 잡힘), 최소 · 최대 범위로 후보 거르기(솎으면
  첫 · 끝 점이 빠져 범위가 2~3 % 달라졌다).

## 대안

- **지문을 거칠게(유효숫자 4자리)** — 자릿수 사본은 잡지만 솎은 · 배수 사본은 못 잡고, 반올림 경계에 걸린 값
  하나로 같은 사본이 갈린다.
- **업로드마다 같은 재료의 곡선 파일을 읽어 점끼리 견준다** — 가장 정확하지만 재료 하나에 시험이 많으면
  업로드가 느려진다.
- **다른 재료까지 견준다** — 같은 공정의 비슷한 재료에서 오경보가 늘고, 재료를 잘못 붙인 사본은 다른 점검
  (탄성률 범위 · 재료에 적어 둔 값)이 더 잘 잡는다.
- **막는다 · 통계에서 뺀다** — 반복 측정이 정상인 자리라 ADR 0077 과 같이 막지 않는다.
