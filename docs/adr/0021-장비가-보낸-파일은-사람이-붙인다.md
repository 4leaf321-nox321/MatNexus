# ADR 0021 — 장비가 보낸 파일은 서버가 읽고, 시편은 사람이 붙인다

- 상태: 채택 (2026-08-28)
- 관련: ADR 0002(PAT), ADR 0005(형식 프로파일), ADR 0017(옛 데이터는 프로파일로 읽는다)
- 코드: `app/modules/pipelines/`, `app/shared/ingest.py`, 마이그레이션 `a7c2e9d41b58`
- 계약: MatPylon 저장소의 `docs/api/matpylon-openapi.yaml`

## 배경

장비 PC 에 수집 에이전트(MatPylon)를 두고, 장비가 떨어뜨린 파일을 사람이 옮기지
않아도 MatNexus 에 들어오게 한다. 그때 세 가지를 정해야 했다.

    누가 읽나           에이전트가 파싱해서 곡선을 보내나, 서버가 원본을 받아 읽나
    시편은 누가 정하나   에이전트가 파일 이름으로 시편을 만드나, 서버가 찾나
    두 번 오면          에이전트 장부를 믿나, 서버 장부를 믿나

## 결정

**파싱은 서버가 한다.** 에이전트는 원본만 보낸다. 형식 프로파일(ADR 0005)이 서버에
있고, 곡선을 API 로 직접 꽂지 않는다(ADR 0017)는 결정을 그대로 따른 것이다.
에이전트가 읽으면 장비마다 에이전트를 다시 배포해야 하고, 서버와 에이전트가
**같은 파일을 다르게 읽는** 날이 온다.

**시편을 만들지 않는다.** 에이전트는 파일 이름에서 뽑은 **힌트**만 보낸다. 서버가
프로파일 `identity` 와 힌트로 후보를 좁히고, 정확히 하나면 시험을 만들고, 0 또는
2 이상이면 **사람이 붙인다**. 오타 하나로 유령 시편이 생기는 병을 피한다 —
이관에서 같은 이유로 「지어내지 않는다」 를 정했었다.

후보 조회는 **처음엔 좁게.** 재료 코드가 없으면 후보를 만들지 않는다. 시편
이름만으로 전 부서를 뒤지면 엉뚱한 재료에 붙는다 — 이름은 흔하고(`MD_01`),
재료가 다르면 그건 다른 시편이다. 파일 안의 값(identity)과 이름의 값(힌트)이 둘
다 있으면 **파일이 이긴다** — 파일은 장비가 적은 증거고 이름은 사람이 붙인
이름표다.

**서버 원장이 정본이다.** 같은 sha256 이 이미 있으면(시험이든 수집함이든) 409 로
기존 id 를 돌려주고, 에이전트는 그것을 「보냄」 으로 닫는다. 에이전트가 죽었다
살아나 같은 파일을 다시 보내도 두 번 등록되지 않는다.

**원본은 한 곳에만.** `inbox/…` 에 떨어졌다가 시험이 되면 `test-runs/…` 로
**옮긴다**(복사 아님). 두 벌이면 정리 잡이 어느 것을 지워야 하는지 모른다.

**시험이 되는 길은 하나다.** 수집함에서 시험을 만들 때 직접 곡선을 저장하지 않고,
원본을 옮긴 뒤 화면 업로드와 같은 파싱 워커(`tests.parse_upload`)에 넘긴다. 곡선을
만드는 길이 둘이면 한쪽만 고쳐지는 날이 온다.

## 어디에 두나

`app/modules/pipelines/` — 개발계획 §구조에 예약돼 있던 이름이다. 시험을 만드는
자리가 둘이 됐으므로(화면 업로드·장비 커넥터) 둘이 같아야 하는 것 — 종류 감지 ·
회차 받기 · 이름 짓기 · 파싱 큐 넣기 — 을 **`shared/ingest.py`** 로 올렸다.
모듈끼리 직접 부르지 않는다는 규칙 때문이기도 하지만, 진짜 이유는 사고다: 회차
충돌 재시도(`contention`)를 한쪽만 갖고 있으면 다른 쪽은 같은 순간에 두 파일이
오면 500 을 낸다. 장비는 배치로 보내므로 **그쪽이 더 자주 부딪힌다.**

`tests` 의 기존 업로드 경로는 아직 `ingest` 를 안 쓴다. 돌아가는 것을 옮기지
않는다 — 다른 세션이 그 파일을 고치고 있는 동안은 더욱. **구조 정리** 항목으로
남긴다.

화면은 `/settings/connectors` — **부서 설정**이다. 장비를 붙이는 것은 사업부의
일이고, 시편을 못 정한 파일을 붙이는 것도 부서 관리자가 한다(재료·프로파일을
만드는 역할과 같다, ADR 0006).

## 대안

- **에이전트가 파싱해 곡선을 보낸다.** 서버가 가벼워진다. 그러나 형식 프로파일을
  에이전트에도 배포해야 하고, ADR 0017 을 뒤집는다. 기각.
- **힌트로 시편을 자동 생성한다.** 사람 손이 안 간다. 그러나 파일 이름의 오타가
  시편이 된다. 이관에서 「지어내지 않는다」 를 정한 것과 같은 이유로 기각.
- **재료 코드 없이도 시편 이름으로 찾는다.** 더 자주 자동 등록된다. 그러나 엉뚱한
  재료에 붙으면 통계가 그 시편의 것으로 **조용히** 센다. 처음엔 좁게 — 실데이터에서
  못 찾는 비율을 보고 넓힌다.

## 결과

- 표 둘(`pipeline_connectors`·`pipeline_inbox_items`), 작업 종류 하나
  (`pipelines.parse_inbox`), 알림 종류 하나(`pipelines.needs_specimen` — 부서
  관리자에게).
- 계약과 다른 것 둘. MatPylon 이 부르지 않는 관리 화면용 엔드포인트라 에이전트에는
  영향이 없다.
  - `POST /inbox/{id}/assign` 은 `TestRunOut` 이 아니라 **`InboxItemDetail`**
    (등록됨 상태, `test_run_id`·`test_run_name` 포함)을 돌려준다. `tests.schemas` 를
    다른 모듈이 import 할 수 없다.
  - `GET /inbox` 의 쪽 넘김은 이 저장소 규약대로 **`limit`·`offset`** 이다
    (`page`·`size` 아님).
- 에이전트가 붙는 지점: `POST /pipelines/connectors` → `POST /pipelines/inbox` →
  파일이 `filestore/inbox/…` 에 떨어지면 절반이다. 워커가 켜져 있어야 그다음이
  돈다.
