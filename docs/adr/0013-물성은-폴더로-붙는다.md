# ADR 0013 — 물성은 폴더로 붙는다

- 상태: 채택 (2026-08-23)
- 관련: D7(정의는 데이터, 계산은 플러그인), ADR 0012(물성 카드는 블록의 모음이다),
  개발계획 §6 Phase 5
- 코드: `matcore/extensions.py`, `matcore/export/__init__.py`(`Deck`·`Need`·
  `register_renderer`·`requires_labels`), `backend/extensions/README.md`,
  `app/main.py`(기동 시 읽기), `app/config.py`(`extensions_dir`)

## 배경

ADR 0012 로 저장은 마이그레이션 0 이 됐다. 고무 초탄성으로 재 보니 **한 자리가
남아 있었다.**

```
matcore/export/__init__.py       +100줄   ← 물성마다 커진다
matcore/cards/__init__.py          +1줄   ← 읽을 파일 이름을 적는다
matcore/fitting/__init__.py        +1줄   ← 같은 이유
```

### 카드 양식이 물성마다 커졌다

`export.Card` 는 **정해진 칸**이었다.

```python
class Card:
    youngs_modulus · poisson_ratio · density · points   # 금속
    prony · prony_reference_temperature                 # 점탄성 때 뚫은 칸
    hyperelastic_family · hyperelastic_parameters       # 초탄성 때 뚫은 칸
```

솔버가 무엇을 요구하는지도 그 칸 이름으로 적혀 있었다(`requires=("prony",)`).
그러니 새 물성은 **반드시 이 파일을 고쳐야** 했다 — 저장·API·화면이 전부 데이터가
된 뒤에도 여기만 코드로 남았다.

### 파일을 만들어도 "읽어라" 라고 적어 줘야 했다

```python
from matcore.cards import hyperelastic, mechanical, viscoelastic
```

두 줄이지만 성격이 나쁘다. 여러 사람이 각자 물성을 붙이면 **같은 줄을 서로 고치게**
되고, 확장을 따로 배포할 길이 없다.

## 결정

### ① 렌더러가 블록을 먹는다

`Card` 를 `Deck` 으로 바꿨다. 정해진 칸이 없고 **카드가 가진 블록을 그대로** 든다.
무엇이 필요한지는 솔버가 **블록 이름으로** 선언한다.

```python
@register_renderer(
    key="abaqus_hyperelastic",
    needs=(
        Need("hyperelastic", rows_min=1),
        Need("elastic", values=("density",), optional=True),
    ),
)
def render_abaqus_hyperelastic(deck: Deck) -> Rendered: ...
```

솔버 목록도 딕셔너리 리터럴에서 등록제로 바뀌었다. **확장 폴더에서도 솔버를
붙일 수 있다** — 전에는 이 파일 안에서만 가능했다.

### ② 폴더를 훑는다

`backend/extensions/<이름>/__init__.py` 가 등록 함수를 부르면 끝이다. 기동할 때
읽고, **하나가 터져도 나머지는 산다** — 실패한 것은 로그에 남고 그 물성만 목록에서
빠진다. 남의 확장 때문에 내 물성을 못 쓰면 안 되고, 그 사실이 "서버가 안 켜진다"
로만 보이면 더 나쁘다.

## 대안

- **`pip install` + entry_points** — 파이썬의 표준 확장 방식이다. **폐쇄망에서
  값이 안 나온다** — 반입물이 `deploy_package.zip` 하나이고, 확장마다 wheel 을
  만들어 번들에 넣는 절차가 는다. 폴더는 `Copy-Item -Recurse .\backend` 에
  저절로 따라간다.
- **65 의 OCI 샌드박스** — 65 는 `plugins/execution.py` 로 외부 패키지를 격리해
  돌린다(서명·digest·타임아웃). **다른 문제를 푼다** — 남이 만든 코드를 안전하게
  실행하는 일이다. 사내 개발자가 짜는 확장이라면 in-process + 코드 리뷰로 충분하고,
  샌드박스는 그 값의 열 배가 든다. 외부 제공자가 생기면 그때.
- **화면에서 수식을 입력받는다(노코드)** — 초탄성 4종·경화식 3종이 전부 수식 한
  줄이라 기술적으로는 된다. 미룬 이유는 **안전장치**다: 부호 하나를 잘못 쳐도
  숫자는 나오고 덱도 만들어진다. 단위 선언이 틀리면 100만 배가 조용히 지나간다.
  검산·단위검사·미리보기를 갖춰야 열 수 있고, **그 모양은 폴더로 물성을 두어 개
  더 붙여 봐야 드러난다.** 지금 만들면 짐작으로 만드는 것이다.

  다만 이 길은 **①이 있어야 열린다** — 화면에서 만든 물성도 결국 솔버까지 가야
  하는데, 그 길이 ①이다.

## 결과

**새 물성이 폴더 하나로 붙는다.** 중심 코드 0줄, 마이그레이션 0번, 화면 0줄.

| | 줄 |
|---|---|
| `matcore/export` 재작성(`Deck`·`Need`·등록제) | +405 / −239 |
| `matcore/extensions.py` | 116 (새로) |
| `matcore/cards` 정리(`to_card` 3개 제거) | +15 / −114 |
| `app`(기동 시 읽기·설정) | +19 |
| `extensions/README.md` | 81 (새로) |
| (시험) | +229 / −155 |

**블록이 더는 "덱의 어느 칸에 실리는지" 를 모른다.** `to_card` 가 사라지면서 물성
파일이 114줄 짧아졌다. 담는 자리와 싣는 자리가 나뉜 것이 맞다 — 블록은 자기 값의
이름과 뜻만 알면 된다.

**"덱에 실림" 표시가 실제 사용에서 나온다.** 전에는 블록이 스스로 선언했는데
(`to_card is not None`) **실제로 쓰이는지와 어긋날 수 있었다.** 지금은 등록된
솔버들이 요구하는 것에서 계산한다(`blocks_in_decks`).

**중립 JSON 이 스스로를 설명한다.** 정해진 칸을 손으로 적던 것을, 블록을 그대로
내되 **이름·단위 선언을 같이 실어** 보낸다(`matnexus.property-card/2`). 받는 사람이
`200000000000` 만 보고 Pa 인지 MPa 인지 몰라 헤맬 일이 없다.

### 고치다 잡은 것

**형식 목록이 "어느 값이" 필요한지 안 말하게 됐었다.** 블록 단위로 바꾸면서
`["탄성", "소성 표"]` 로 뭉뚱그려졌다 — 사람이 찾는 것은 *"이 카드에 뭐가 빠졌나"*
이지 *"어느 블록이냐"* 가 아니다. 값 이름으로 되돌렸다.

### 남은 것

- **`fitting`·`processing`·`parsers` 의 등록 창구가 아직 따로다.** 화면도
  `/families`·`/blocks`·`/formats`·`/processing/plugins` 를 따로 묻는다. 합치면
  `GET /extensions` 하나가 되는데, 급하지 않다
- **차원 검사가 없다.** 밀도 자리에 온도를 넣어도 지금은 아무도 모른다. 확장을
  쓰는 사람이 늘면 그때 값이 커진다
- **조회 가능성.** 블록이 JSONB 라 *"이 재료군의 Voce b 분포"* 같은 질문이 번거롭다.
  65 는 물성마다 테이블이 있어 SQL 로 답한다 — 우리가 치른 대가이고, 선언에서
  값 목록표를 자동으로 펼치는 것으로 갚을 수 있다
