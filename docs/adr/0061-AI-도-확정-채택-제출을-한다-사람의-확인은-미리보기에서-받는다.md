# 0061. AI 도 확정 · 채택 · 제출을 한다 — 사람의 확인은 미리보기에서 받는다

날짜: 2026-10-14
상태: 채택
관련: [ADR 0007](0007-원본과-처리결과-저장-구조.md)(명시적 채택) ·
[ADR 0024](0024-워크벤치는-가로지르는-일에만-둔다.md)(워크벤치는 대신 눌러 주지 않는다) ·
[ADR 0032](0032-새-기준정보-값은-부서-관리자가-세운다.md)(MCP 는 새 낱말을 안 만든다) ·

## 배경

MCP 는 일곱 가지를 일부러 열지 않았다 — **물성 카드 확정, 처리 결과 채택, 측정 의뢰 제출과
상태 이동, 시험 파일 올리기, 기준정보 새 값, 시험 종류 저장, 해석용 정의 켜고 끄기.** 「되돌리기
비싸거나 다른 사람 · 다른 시스템이 그 결과를 믿는 일은 사람이 화면에서 한다」 가 이유였다.

그 결과 AI 와 일하는 흐름이 그 일곱 자리에서 매번 끊겼다. AI 가 미리보기를 보이고, 사람이
화면으로 가서 같은 것을 다시 찾아 누르고, 대화로 돌아온다 — 확인 자체는 대화에서 이미 끝난
뒤였다. 사용자 결정(2026-10-14): **일곱 가지 모두 AI 가 할 수 있게 한다.**

## 결정

1. **일곱 가지를 MCP 도구 10개로 낸다.**

       확정 · 사용 중지 · 되살림      set_card_status
       채택 · 채택 거두기 · 되돌리기  adopt_results
       의뢰 내기 · 상태 이동          create_commission(submit=True) · change_commission_status
       의뢰 담당 · 시험 연결          assign_commission · link_commission_run
       시험 파일 올리기              upload_test_run
       기준정보 새 값 · 별칭          create_vocabulary_term · add_vocabulary_alias
       시험 종류 저장                save_test_type
       해석용 정의 켜고 끄기          set_export_profile_active

2. **사람의 확인은 화면 대신 미리보기에서 받는다.** 전부 `dry_run=True` 가 기본이고, 미리보기가
   무엇이 바뀌는지(상태 전 → 후 · 카드의 경고 · 비슷한 기준정보 값 · 갈 수 있는 의뢰 상태 · 채택
   전 → 후의 값)를 준다. 도구 설명과 안내서가 「사람에게 보이고 「그대로」 를 들은 뒤에」 를 적는다.
   **서버가 강제하는 것은 아니다** — 대화의 규약이다(아래 결과).
3. **권한 판정은 그대로 서버에 둔다.** 토큰이 곧 그 사람이다(ADR 0032 D4). 확정 · 사용 중지 ·
   되살림은 자료 관리자, 통제 축의 새 기준정보 값은 자료 관리자, 별칭은 시스템 관리자, 의뢰 상태는
   낸 쪽 · 받는 쪽의 이동 규칙, 채택은 고칠 권한(ADR 0035). AI 에게만 따로 넓히거나 좁히지 않는다.
4. **전부 감사에 「AI 경유」 로 남긴다.** 확정 · 시험 종류 · 정의 켜고 끄기 · 기준정보 새 값은 이미
   남기던 길이고, 여섯을 새로 남긴다 — 채택(`results.adopted_by_client`) · 시험 파일
   (`test_run.uploaded_by_client`) · 의뢰 상태 · 담당 · 시험 연결 · 기준정보 별칭. 화면에서 한
   것은 전처럼 안 남는다(`record_by_client`).
5. **지우는 일은 열지 않는다** — 카드 · 결과 · 시험 · 재료 삭제, 기준정보 병합. 되돌릴 길이 없다.
   수집함 승인 · 선언 값 승인 · 계산식 저장도 그대로 사람 몫이다(이번 결정의 범위 밖).
6. **등록 도구는 여전히 새 낱말을 지나가며 세우지 않는다**(`term_gate`). 새 값은
   `create_vocabulary_term` 으로 **따로, 일부러** 세운다 — 비슷한 값을 사람에게 보인 뒤에.
   그럴듯한 이름을 짓는 것이 AI 가 가장 잘하는 일이라는 ADR 0032 의 우려는 그대로다.

## 대안

- **지금처럼 화면에서** — 흐름이 끊긴다는 사용자 판단으로 기각.
- **서버에 「AI 는 확정 금지」 같은 정책** — ADR 0032 D4(사람이 아닌 경로를 따로 막지 않는다)와
  어긋나고, 같은 토큰을 든 스크립트는 이미 그 API 를 부를 수 있다.
- **확인을 서버가 강제(두 단계 확인 토큰 등)** — 대화 밖의 장치가 하나 더 필요하다. 미리보기
  기본값과 감사로 둔다.

## 결과

- 도구 98 → 108개, 도구 설명 예산 52,000 → 56,500자(`test_mcp_tools.py` 에 이유를 적었다).
- **AI 가 확인 없이 `dry_run=False` 를 부르는 것을 서버는 못 막는다.** 감사의 「AI 경유」 와 사용
  현황으로 사후에 센다. 되돌리는 길을 같은 도구에 둔다 — 확정은 `deprecate` → `restore`(초안으로),
  채택은 `previous_adopted_id` 를 다시 보내기, 의뢰는 「작성 중으로 되돌림」.
- **사후에 세던 것을 그 자리에서 알린다(2026-10-15).** 카드 확정 · 사용 중지 · 되살림과 채택이
  `X-Client` 를 달고 오면 자료 관리자(없으면 시스템 관리자)에게 알림(`ai.confirmed`)이 간다 — 토큰
  주인에게도. 막지는 못해도 바로 안다. 화면에서 한 것은 안 간다(`shared/steward_notice`).
- 시험 파일은 대화로 나르므로 10MB 상한이다 — 큰 파일은 장비의 수집 에이전트(수집함)로 간다.
- HWAX 포털 게이트웨이로 붙은 사람(ADR 0056)은 읽기 전용 토큰이라 이 도구들도 서버가 거절한다.
- 의뢰 이력 · 백엔드 감사 여섯 자리를 시험이 문다(`test_audit_client.py` 「사람만 하던 일을 AI
  에게」, 채택 감사는 일부러 망가뜨려 시험이 무는 것을 확인했다).
