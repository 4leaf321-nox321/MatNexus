# 0073. 문헌 상세의 출처는 고를 때 한 번만, 이름이 정확하면 뜻 검색을 안 한다

날짜: 2026-10-26
상태: 채택
관련: [0072](0072-문헌-재료-상세는-벌의-점을-싣지-않는다.md)

## 배경

ADR 0072 뒤에도 남은 둘.

- **재료 상세의 출처 되풀이.** Ti-6Al-4V (L-PBF) 상세 2.1 MB 중 490 KB 가 출처였다 — 출처는 3종인데 값 639 ·
  벌 555 마다 통째로 실었다. 벌 메모(253 KB)는 벌마다 원 논문 이름이라(345종) 되풀이가 아니었다.
- **값 검색의 이름 풀이.** 값 질의는 30 ms 인데 요청마다 0.4~0.6 초가 들었다 — 물성 이름을 풀며 글자로 찾은
  후보가 다섯보다 적으면 늘 임베딩(뜻 검색)을 불렀다. AI 는 대개 이미 푼 키를 그대로 넘긴다.

## 결정

1. **상세는 `source_once=true` 일 때만 출처를 한 번 싣는다.** 맨 위 `sources` 에 한 번씩, 값 · 벌에는
   `source_id` 만 두고 `source` 를 비운다. **안 주면 지금 모양 그대로**다. 화면은 받자마자 다시 채워
   (`catalogApi.material` → `withSources`) 나머지 코드는 `source` 를 그대로 읽는다.
2. **글자가 통째로 맞으면(키 · 이름 · 별칭 · 기호) 뜻 검색을 부르지 않는다**(`property_names.EXACT_MATCHES`).
   부분으로만 걸렸거나 못 찾았을 때는 전처럼 뜻 후보를 아래에 붙인다.

## 대안

- **상세 모양을 그냥 바꾸기**: 가장 단순하지만 상세를 직접 읽는 바깥(수집기의 반입 확인 스크립트 · MCP)이
  `source` 가 빈 것을 「출처 없음」 으로 읽는다 — 조용히 틀린다. 고를 때만으로 두었다.
- **출처 칸을 줄이기**(제목만): 귀속 문구 · 라이선스가 값 옆에서 사라진다(ADR 0068 의 조건).
- **정확히 맞아도 뜻 후보를 붙이되 임베딩을 미리 계산**: 질문 글은 미리 알 수 없다.

## 결과

개발 DB, 같은 실행 안의 비교(그때 PC 가 다른 일로 바빠 절대값은 평소의 두 배쯤이다):

| 무엇 | 전 | 후 |
| --- | ---: | ---: |
| 상세 Ti-6Al-4V (L-PBF) — 화면이 쓰는 모양 | 868 ms · 2,125 KB | 576 ms · 1,661 KB |
| 값 검색 키 `mechanical.fatigue_strength` | 420~560 ms | 69 ms |
| 값 검색 이름 「피로한도」 · 「인장강도」(별칭) | 420~560 ms | 65 · 87 ms |

- 정확히 맞은 이름에는 「이것 아닐까」 뜻 후보가 더는 안 붙는다. 그 후보는 점수가 낮아 아래에 서던 것이고,
  고르는 데 쓰인 적이 없다(되묻기 `ambiguous` 는 글자 후보로 가른다).
- MCP 는 지금 모양을 그대로 받는다. 대신 AI 검증(2026-10-26)에서 SAC305 의 `get_catalog_material` 이 69 KB 로
  클라이언트가 파일로 빼는 것을 보고, 조건의 관리 표지를 빼고 계수 묶음 항은 키를 콕 집을 때만 싣게 했다(35 KB).
  관리 표지 판정은 백엔드와 같은 규칙이고 시험이 대 본다(`test_mcp_catalog_rows.py`).

## 후속 (2026-10-26) — 벌 머리는 셈에 쓰는 칸만, 머리 전부는 쪽으로

출처를 한 번만 실은 뒤에도 Ti-6Al-4V (L-PBF) 상세의 절반(872 KB)이 벌 머리 555개였고, 그 절반이 메모(258 KB) ·
공통 조건(152 KB)이었다. 그 칸을 쓰는 것은 「곡선 · 표」 탭의 카드뿐이고, 그 탭은 이미 20벌씩만 세운다.

- **`series_brief=true` 면 상세는 벌마다 셈에 쓰는 칸만 싣는다**(`series_brief`) — 종류 · 축과 범위 · 열(점 수 ·
  값 범위) · 점 수 · 방법 · 등급 · 출처. 물성 요약 · 출처 · 등급 셈은 그대로 화면이 한다(셈을 서버로 옮기면 같은
  규칙이 두 곳에 산다). 안 주면 지금 모양 그대로다 — 수집기 확인 스크립트 · MCP 가 깨지지 않게.
- **머리 전부는 `GET /catalog/materials/{id}/series?kind=points|parameter_set` 로 쪽마다**(기본 20, 상한 100, 상세와
  같은 차례). 「곡선 · 표」 탭은 첫 쪽을 받고 「더 보기」 가 다음 쪽을 부른다. 「계수 묶음」 탭은 한 쪽에 받는다.
- 버린 것: 요약 집계까지 서버가 내고 상세에 벌을 아예 안 싣기 — 194 KB 를 더 줄이지만 요약 · 출처 · 등급 셈의 규칙이
  화면과 서버 두 벌이 된다.

개발 DB 같은 실행 안: 상세(화면 모양) 1,661 → 1,072 KB, 316 → 232 ms. 쪽 하나(20벌) 38 KB · 11 ms. 남은 1 MB 는
값 639개(메모 271 KB · 갈리는 조건 80 KB 포함)다.
