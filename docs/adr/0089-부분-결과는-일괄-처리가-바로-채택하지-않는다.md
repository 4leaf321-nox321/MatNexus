# 0089. 부분 결과는 일괄 처리가 바로 채택하지 않는다 — 처음 처리하는 시험도 검토대에서 한 번 본다

날짜: 2026-11-17
상태: 채택
관련: [ADR 0065](0065-처리-단계가-실패해도-나온-값은-부분-결과로-저장한다.md)(결정 4 를 고친다) ·
[ADR 0076](0076-확인할-경고는-결과와-함께-남고-채택에서-확인을-받는다.md)(경고가 있으면 일괄 채택을 미룬다) ·
[ADR 0058](0058-워크벤치는-업무-단위다-업무가-전용-화면을-가진다.md)(채택 검토대)

## 배경

VOC 58 은 잘못 자른 곡선의 4.75 MPa 가 실패 표시 없이 인장강도로 채택된 일이었다. 원인(봉우리 자르기가
탄성 구간 잡음에 걸린 것)은 v1.312.0 에서 고쳤고, 그런 자르기는 이제 실패로 남는다. 브리핑의 둘째 안
「부분 결과는 일괄 채택하지 않음」 은 그때 하지 않았다 — ADR 0065 결정 4 가 「처음 처리하는 시험은 잃을
것이 없으니 부분 결과도 채택한다(인장강도라도 물성으로 선다)」 를 정해 두었기 때문이다.

남은 틈은 이것이다(코드로 확인, 2026-11-16). 경고가 있는 결과는 일괄 「바로 채택」 이 미루는데
(ADR 0076), 실패한 단계는 경고로 세지 않는다. 그래서 처음 처리하는 시험은 단계가 실패해도 나머지 값이
**사람이 한 번도 안 본 채** 물성이 됐다. 단계가 실패했다는 것은 그 곡선에 무언가 있다는 신호인데 — 4.75 MPa
가 그런 곡선이었다 — 일괄 처리는 사람이 줄마다 볼 수 없다.

## 결정

1. **일괄 처리의 「바로 채택」 은 실패한 단계가 있는 결과를 채택하지 않는다.** 처음 처리하는 시험도
   그렇다. 결과는 그대로 저장되고 줄에 까닭(「실패한 단계가 N개 있는 부분 결과라 미뤘습니다 — 단계: 이유」)
   이 붙는다. 미리보기(`dry_run`)도 같은 말을 먼저 한다.
2. **사람이 한 번 고르면 선다.** 한 건 채택 · 채택 검토대는 부분 결과라는 것만으로 막지 않는다 — 10월
   보고의 요청(인장강도라도 물성으로)은 그대로 지킨다. 검토대의 확인 창은 「실패한 단계가 있는 부분 결과
   N건」 과 빠진 단계를 센다.
3. 지금 채택된 값을 잃게 하는 부분 결과는 전처럼 그 까닭(「채택은 그대로 두었습니다」)이 먼저 나간다.
4. MCP 일괄 도구도 같은 서버 판정을 지나고, 부분 결과 건수와 「채택은 미뤘습니다」 를 `note` 에 싣는다.

## 대안

- **그대로 둔다** — 잘못 자른 곡선 같은 다른 실패가 또 생기면 같은 길로 물성이 된다.
- **부분 결과는 늘 채택하지 않는다** — 사람이 보고 고른 것도 막아 10월 요청(인장강도라도)을 버린다.
- **실패를 경고로 옮긴다**(`processing_results.warnings` 에 함께 저장) — 한 건 채택에도 확인을 받게 되고 카드
  근거에도 실리지만, 같은 사실이 두 칸에 두 번 저장된다. 사람이 고르는 길은 이미 「부분 결과」 를 말하므로
  일괄 경로 하나만 고쳤다.

## 결과

- 코드: `app/modules/processing/routes.py`(`_partial_problem`, 일괄 처리의 저장 · 미리보기), 화면
  `AdoptionBoard`(확인 창), MCP `run_batch_processing` 의 `note`, 사용 안내 「부분 결과와 채택」.
- 시험: API(처음 처리하는 시험의 부분 결과가 미뤄지고 한 건 채택은 되는 것 · 실패 없는 결과는 전처럼 바로
  채택) · 화면(확인 창의 부분 결과 건수). 사보타주: 미루는 판정을 빼면 API 시험이 문다.
- 이미 채택된 부분 결과는 그대로다 — 이 결정은 앞으로의 일괄 채택에만 걸린다.
