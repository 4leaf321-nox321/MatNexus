# 0035. 보기는 **모두에게**, 고치기는 **사람에게** — 부서가 권한을 정하지 않는다

## 배경

### 권한이 자료 종류마다 달랐다

같은 사람이 같은 재료를 보는데 판정이 다섯 갈래였다.

| 판정 | 어디에 |
| --- | --- |
| 볼 수 있으면 고친다 | 시료·시편·시험, 처리 결과 채택, 초안 카드 |
| 부서 멤버 | 재료 수정·삭제, 묶음, 워크벤치, 커넥터 수신함 |
| 부서 관리자 | 장비 파일 정의·시험 종류·레시피·해석용 물성 정의, 카드 확정, 처리 결과 삭제, 문헌 연결, 장비 |
| 등록자 + 시스템 관리자 | 문헌 직접 입력, VOC |
| 시스템 관리자 | 전역 항목, 기준정보 관리, 휴지통 |

보는 범위도 갈렸다 — 재료 계층은 「모든 부서(가린 부서만 빼고)」, 정의는 「전역 + 내
부서」, 의뢰는 「두 부서」. 그래서 같은 재료에서 필드는 고쳐지는데 문헌 연결은
막히고(카탈로그의 「재료 만들고 연결」 화면에 그 실패만 받는 코드가 따로 있었다),
자기가 만든 처리 결과를 자기가 못 지웠다.

### 잠긴 이유를 사람이 알 수 없었다

소속(대표 부서)은 가입 승인 때 정해지고 화면에서 고르지 않는다. 막히면 「권한이
없습니다」 만 나오고 누구에게 물어야 하는지는 안 나왔다. 부서가 가림(`restricted`)을
켰는지는 막힌 쪽에서 보이지 않아 「없다」 와 「가려졌다」 가 같은 모양이었다.

### 다른 시스템이 「전역 정의가 없다」 로 막혔다 (2026-09-24)

CompCore 가 물성을 받아 가다 멈췄다. 원인이 둘이다.

1. **`is_global` 을 공식 여부로 읽었다.** 전역 재료는 0건이다 — ADR 0004 가 승격을
   「필요해질 때 만든다」 로 미뤘다. 모든 계정이 모든 재료를 보는데 응답은 전부
   `is_global: false` 였다.
2. **자료는 보이는데 정의는 안 보였다.** 시험은 전원이 보는데 그 시험을 해석할 시험
   종류·장비 파일 정의·레시피는 「전역 + 내 부서」 만 보였다.

## 결정

### D1. 보기는 전원이다 — 자료와 정의 모두

로그인한 사람은 **살아 있는 것 전부**를 본다. 자료(재료·시료·시편·시험·처리 결과·
카드·파라미터 벌)와 정의(시험 종류·장비 파일 정의·레시피·해석용 물성 정의) 둘 다다.
문헌은 원래 전원이 봤다.

- `restricted` 를 걷는다. 켜져 있던 부서는 지우기 전에 감사 기록
  (`workspace.restriction_removed`)으로 남긴다 — 다시 가려야 할 자료가 있는지 그
  목록으로 본다.
- **자동으로 고를 때는 좁힌다.** 장비 파일 자동 추정과 시험 읽기는 내 부서 것과
  전역만 대 본다(`formats.auto_profiles` · `services._pick_reader`). 남의 부서 지문이
  내 파일을 먼저 가로채면 사람은 왜 그 종류가 골라졌는지 모른다. 남의 부서 것은
  사람이 골라서 쓴다(「이 형식으로 다시 읽기」).
- 예외는 **자료가 아닌 것**뿐이다 — 측정 의뢰(두 부서, 작성 중은 낸 사람), 장비
  커넥터·수신함(부서), 워크벤치 작업(부서 안에서 이어 한다, ADR 0025), 감사 기록.
  앞의 셋은 「보기」 와 「고치기」 가 같은 함수에 묶여 있어서, 보기만 먼저 열면
  고치기가 딸려 열린다 — 2단계에서 둘을 떼면서 다시 본다.
  **(3단계) 셋을 뗀 뒤 보기도 열었다.** 남은 예외는 작성 중인 의뢰(낸 사람)와 감사
  기록(부서 관리자는 제 부서 것)뿐이다.

### D2. 정의의 key 는 전사에서 하나다 — 비우면 서버가 짓는다

장비 파일 정의(`fmt_`), 레시피(`rcp_`), 해석용 물성 정의(`deck_`) 뒤에 16진 8자리.

- **왜 하나인가** — 부서 안에서만 하나였을 때는 「남의 부서 것은 안 보인다」 가
  구별을 대신했다. 보기를 열자 같은 key 가 둘 보이고 `/formats/{key}` 같은 조회가
  그중 **아무거나** 집는다.
- **왜 서버가 짓나** — 사람에게 받으면 전사 유일이 곧 「옆 부서가 먼저 쓴 이름은 못
  쓴다」 가 된다. 사람이 읽는 것은 이름(label)이다. 화면은 key 를 묻지 않는다.
- **API 는 key 를 받는다** — 파일로 옮겨 오는 정의(개발 → 운영)는 같은 key 여야 두 번
  들여올 때 409 로 막힌다. 새로 지으면 같은 것이 조용히 둘 생긴다.
- **이미 겹친 것** — 전역이 key 를 지키고, 부서끼리는 먼저 만든 쪽이 지킨다. 나머지는
  `<원래 key>_<8자리>` 가 되고 감사 기록(`definition.key_renamed`)에 전후가 남는다.
  key 는 주소라 북마크·배치 설정에 적혀 있을 수 있다.
- **따라 사라진 것** — 「같은 key 의 부서 것이 전역을 덮는다」(해석용 물성 정의).
  같은 「abaqus」 를 눌러도 누구냐에 따라 다른 덱이 나오던 규칙이다. 사업부의 덱
  관례는 이제 **다른 형식**으로 나란히 뜬다. 부서 합치기의 이름 충돌 검사에서 정의
  셋이 빠졌고, 휴지통 되살리기는 전사 key 로 자리를 본다.

### D3. 다른 시스템과의 교환은 두 길이다

| 무엇 | 길 | 조건 |
| --- | --- | --- |
| 시험에서 나온 물성 | 확정 카드 — `GET /api/fitting/cards?status=published` · `…/{id}/export` | 초안은 안 넘긴다 |
| 문헌 물성 | `GET /api/catalog/export` — 사내 재료와 **연결 안 된 것도 전부** | `quality_tier` 를 함께 |

두 길 모두 `units` 로 단위계를 받고, 안 주면 mm·N·tonne 이다 —
[ADR 0036](0036-나가는-숫자의-기본-단위계는-mm-N-tonne.md).

부서·전역은 공식 여부가 아니다 — 등록한 부서를 적은 칸이다. MCP 응답에서
`is_global` 을 뺐고 안내(`get_guide("exchange")`)에 두 길을 적었다.

### D4. 고치기는 사람 기준이다 (2단계)

판정 하나: **시스템 관리자 · 자료 관리자 · 그 자료의 등록자 · 그 자료에 편집을 받은
부서의 멤버.**

- **자료 관리자** — 사람에게 붙는 전사 역할이다. `is_system_admin` 과 같은 모양이고
  계정·서버 권한은 없다. 카드 확정도 이 역할이 한다(D12 의 「부서 관리자가 확정」 을
  사람 역할로 옮긴다).
- **층마다 제 등록자다.** 시료·시편·시험은 재료의 권한에 딸려 가지 않는다 — 딸려 가면
  SECC 를 처음 올린 사람만 그 아래를 고친다. 남의 재료 밑에 시료를 붙이는 것은
  누구나 하고, 붙인 사람이 그 시료의 등록자다.
- **부서에 편집을 줄 수 있다** — 자료마다 부서 하나, 선택. 소속이 권한을 **몰래** 정하던
  것을 등록자가 **보이게** 주는 것으로 바꾼다.
- **업무 흐름은 권한이 아니라 역할이다** — 의뢰 상태(낸 쪽 / 받는 쪽), 수신함(커넥터의
  부서)은 그대로 둔다. 「고치기」 가 아니라 「일을 넘기기」 다.
- **계층** — 남의 자식이 있으면 부모 삭제·통째 지우기를 막고, 누구의 무엇 때문인지
  말한다. 부모를 고쳐 자식 이름이 바뀌는 것은 허용한다(이름은 값에서 계산된다, ADR
  0004).
- **보이게 한다** — 응답에 `can_edit` 과 못 고치는 이유, 403 에 등록자·자료 관리자
  이름. 판정은 `shared/permissions` 의 함수 하나로 모으고 `tests/architecture` 가 모든
  쓰기 엔드포인트가 그것을 거치는지 본다.

### D5. 부서는 일을 나누는 표로 남는다 (3단계)

부서 관리자는 멤버 관리·의뢰·수신함만 한다. 정의의 `owner_workspace_id`(전역 / 부서)가
정하던 고칠 권한은 D4 로 옮기고, 「전역」 이라는 말은 화면과 응답에서 걷는다.

## 대안

- **부서 기준 한 줄**(「그 자료의 부서 사람이 고친다」) — 팀 공동 편집은 살지만
  「소속 때문에 잠겼다」 는 문제 자체가 남는다. 보이게 할 수는 있어도 없앨 수는 없다.
  문제의 뿌리가 소속을 권한에 쓰는 것이었다.
- **등록자만**(부서 부여 없이) — 가장 단순하지만 팀원이 서로의 오타를 못 고치고, 퇴사·
  휴가자의 자료가 전부 관리자에게 몰린다. 부서 부여가 그 틈을 **보이게** 메운다.
- **key 는 부서 범위로 두고 조회를 id 로** — 주소가 전부 바뀐다(화면 경로·배치 설정·
  MCP 인자). key 를 전사에서 하나로 두는 쪽이 옮길 것이 적다.
- **`restricted` 유지** — 전략과제처럼 가려야 하는 자료를 위한 손잡이였다. 그런데 켜졌는지
  막힌 사람이 모른다. 다시 필요해지면 부서가 아니라 **자료 하나에** 보이는 표시(「비공개 —
  열람: 누구」)로 연다.

## 지나가 보고 알게 된 것

- **규칙이 한 곳이라는 말이 이미 한 번 어긋나 있었다.** `shared/graph.visible_ids` 가
  레시피의 「전역 + 내 부서」 를 제 손으로 적어 두고 있었다. D4 의 `tests/architecture`
  검사가 필요한 이유가 이것이다.
- **보기와 고치기가 같은 함수로 묶인 자리가 있다.** 시료·시편·시험의 수정·삭제는 「볼 수
  있으면 고친다」 였다. 보기를 열자 고치기도 함께 열렸다 — 열린 부서에서는 전부터
  그랬고, 1단계로 가려 두던 부서까지 넓어졌다. **2단계가 닫는다.**

## 2단계에서 정한 것 (2026-09-24)

1. **있던 자료는 그때의 소속 부서에 편집을 준다** — 재료는 `owner_workspace_id`, 시료·
   시편·시험·묶음은 `workspace_id`, 카드는 그 재료의 소속. 개편하는 날 팀이 제 자료를
   못 고치게 되면 안 된다. 등록자가 언제든 걷거나 바꾼다.
2. **새 자료는 등록자만 고친다.** 부서는 필요할 때 등록자가 준다(「권한」).
3. **채택과 시편 치수 입력은 고치는 일이다** — 채택은 시험을, 치수는 시편을 고친다.
   올린 사람과 해석하는 사람이 다르면 그 부서에 편집을 준다. 처리 결과를 **만드는**
   것은 누구나 하고, 만든 사람은 제 결과를 지운다(전에는 부서 관리자만 지웠다).
4. **커넥터는 등록할 때 고른 부서에 편집을 준다.** 커넥터로 들어온 시험의 편집 부서가
   그 커넥터의 부서다. 스스로 붙인 시험은 등록자가 없으므로(`actor=None`), 이것이 없으면
   자료 관리자만 고칠 수 있다.
5. **등록자 넘기기를 만든다** — `/api/ownership/{kind}/{id}`. 등록자와 편집 부서를 한
   창에서 보고 바꾸며, 아래에 딸린 것까지 넘길 수 있다(남이 붙인 것은 건너뛰고 이름을
   말한다). 넘기는 사람은 등록자와 관리자뿐이다. 넘긴 일은 행마다 감사에 남는다
   (`ownership.changed`) — 넘긴 뒤 「등록자」 칸은 새 사람이라, 처음 올린 사람은 그
   기록에만 남는다.

- 계층: 남이 붙인 것이 있으면 재료 통째로 지우기를 막고 「시험 5건(김철수)」 처럼 말한다.
  남의 재료 밑에 시료를 붙이는 것은 누구나 한다(일괄 등록도).
- 카드 확정·내리기·되살리기는 자료 관리자. 초안 고치기·지우기는 사람 기준.
- 문헌 직접 입력·물성 별칭 지우기는 넣은 사람과 관리자(별칭은 전에 누구나 지울 수 있었다).
- `tests/architecture/test_edit_rule_routes.py` — 자료 모듈의 쓰기 라우트는 판정을 부르거나
  사유를 적어야 한다. AGENTS.md 「구조」 에 규칙으로 올렸다.
- 화면: 자료 머리에 「등록자 · 편집 부서」 한 줄과 「권한」 창, 못 고치는 단추는 미리 막고
  까닭을 단다. 계정 관리에 「자료 관리자 지정」.

## 3단계에서 정한 것 (2026-09-24)

1. **정의와 장비도 D4 다.** 시험 종류·장비 파일 정의·레시피·해석용 물성 정의, 그리고 보유
   장비 — **누구나 만들고** 등록자 · 편집을 받은 부서 · 자료 관리자가 고친다. 만들기를 부서
   관리자에게 남기지 않은 이유: D5 로 그 자리가 권한을 갖지 않게 됐고, 자료 관리자에게
   몰면 ADR 0006 이 버린 「요청하고 기다리기」 가 돌아온다. 위험은 사람이 아니라 **검사**가
   막는다 — 채널 이름의 뜻(0006), 자동 추정의 범위(아래 2).
2. **「전역」 을 걷되 「부서 없이」 는 남긴다.** 정의의 `owner_workspace_id` 는 이제 **등록한
   부서**다(권한이 아니다). 남은 뜻은 하나 — 장비 파일 **자동 추정**은 올린 사람 부서의 것과
   부서 없는 것만 대 본다(1단계). 그래서 부서 없이 올리는 것만 자료 관리자가 한다. API 는
   「안 보낸 것」(= 내 소속)과 「비워 보낸 것」(= 부서 없이)을 가른다(AGENTS.md).
3. **있던 정의·장비는 그 부서에 편집을 준다** — 2단계 1번과 같은 판단. 정의는 등록 부서,
   장비는 그 장비를 든 조직. 전에는 그 부서의 **관리자**만 고쳤으니 부서 사람 모두로 넓어진
   것이다 — 자리가 권한을 갖지 않으니 부서에 준 것은 부서 사람의 것이다.
4. **검토의 뜻이 있는 일은 자료 관리자다** — 카드 확정(2단계)에 더해 **새 기준정보 값**
   (ADR 0032 D2 대체)과 **핸드북 승인**(ADR 0022). 0032 가 걱정한 「한 사람에게 몰리면 일단
   승인이 된다」 는 자료 관리자를 사업부마다 여럿 두는 것으로 푼다.
5. **보기와 고치기를 뗐다.** 의뢰는 낸 것을 전원이 보고(작성 중은 낸 사람), 움직이고 **말을
   보태는** 것은 낸 쪽·받는 쪽이다 — 제3부서의 말이 두 부서의 약속에 끼지 않게. 커넥터와
   수신함은 전원이 보고 그 커넥터 부서의 관리자가 다룬다(줄마다 `can_manage` ·
   `can_handle`). 워크벤치 작업은 전원이 열고 그 부서 사람 · 시작한 사람 · 자료 관리자가
   민다. **목록의 기본은 셋 다 「우리 부서」** 다 — 할 일을 보는 자리에 남의 것이 섞이지
   않게, 「모든 부서」 로 넓힌다.
6. **부서 관리자는 멤버 · 커넥터와 수신함 · 의뢰 알림만** 한다(D5). 부서의 변경 이력을
   보는 것은 남겼다 — 읽기이고, 멤버를 관리하는 사람이 제 부서에서 무엇이 바뀌었는지 본다.
7. **휴지통은 지울 수 있는 사람이 되살린다** — 되살아날 것 **전부**를 고칠 수 있어야 한다.
   재료 하나를 되살리면 그 아래 남이 붙인 시료까지 살아나므로, 지우기가 남의 것이 딸린
   재료를 막는 것과 같은 규칙이다. 목록은 **내가 되살릴 수 있는 것만**, 영구 삭제는 그대로
   시스템 관리자다.
8. **상단의 부서 선택기를 걷었다.** 그것이 정하던 것은 `/w/<부서>/…` 주소뿐이었고, 그 화면들
   (홈·워크벤치)은 부서를 골라도 같은 것을 보였다. 남아 있으면 사람은 그것이 권한을 바꾸는
   줄 안다. 부서로 좁힌 시험 목록은 `?workspace=` 거르기, 부서 멤버는 화면 안에서 고르고,
   옛 주소는 새 주소로 넘어간다. 내 소속·역할은 계정 메뉴에 적는다.

## 결과 (3단계, 2026-09-24)

- 마이그레이션 `e3206237002a` — 정의 넷과 장비에 `edit_workspace_id`, 시험 종류에
  `created_by_id`, 장비에 `registered_by_id`, 위 3의 백필. 시험 종류와 장비는 **등록자가
  비어 있다**(누가 만들었는지 적지 않았고 감사에도 없다) — 편집 부서와 자료 관리자가 고친다.
- 판정: `permissions.Owned` 에 정의 넷·장비·워크벤치 작업. 등록자·편집 부서 칸 이름이
  표마다 갈린 것은 `_REGISTRANT`·`_EDIT_SPACE` 한 곳이 흡수한다(작업은 제 부서가 곧 편집
  부서다). `require_owner_edit`·`resolve_owner_workspace` 를 걷고 `registering_workspace`
  를 뒀다. 휴지통 목록은 `editable_clause`(`Editor.allows` 와 같은 뜻의 SQL)로 거른다.

  편집 부서가 작업의 부서 자체다.
- 응답에서 `is_global` 을 걷었다(재료·카드·정의 넷, 재료 내보내기, 데이터 내보내기의

  재료는 만들 길이 없다. 카드 거르기의 「(전역)」 은 「(부서 없음)」 이다(`owner=none`, 옛
  북마크를 위해 `global` 도 받는다).
- **지나가다 고친 것** — 홈의 「수신함 대기」 가 서브쿼리를 곱하는 SQL

  이라, 커넥터가 하나라도 보이면 **모든 커넥터**(지운 것까지)의 대기 건을 셌다. 화면이
  부서를 안 보내서 부서 관리자가 해석용 물성 정의를 만들면 「전역」 으로 읽혀 403 이 나던
  것(레시피를 MCP 로 저장할 때도 같았다)도 「안 보내면 내 소속」 으로 풀렸다.
- `tests/architecture/test_edit_rule_routes.py` 가 장비 파일 정의(`formats.py` — 2단계

## 남은 것

- ~~**감사 화면의 범위** — 부서 관리자는 제 부서 것만, 등록자는 제 자료의 이력을 따로 볼
  길이 없다. 보기가 전원으로 바뀐 뒤 「내 자료에 무슨 일이 있었나」 를 등록자가 물을
  자리가 필요해질 수 있다.~~ — **닫았다(2026-09-25).** 들여다보니 볼 자리만 없던 것이
  아니라 **남길 것도 없었다** — 남이 칸을 고친 일은 감사에 안 남았다(값 수정은 원래 감사
  대상이 아니다). 그래서 셋을 했다.
  - **판정 자리가 남긴다.** `require_edit` 가 허락한 사람이 등록자가 아니면 「남의 자료 고침」
    (`data.edited_by_other`)을 **근거와 함께**(자료 관리자 · 시스템 관리자 · 편집을 받은
    부서(이름)) 남긴다. 고치는 길이 전부 거기를 지나서 새 쓰기 길이 생겨도 빠지지 않는다.
    남의 것을 고친 것은 권한이 실린 일이라 감사의 원래 규칙 안이다.
  - **일괄 경로는 바꾼 줄에서만 적는다**(`permissions.note_edit`). 처음에는 일괄 경로도 판정하는
    순간 적었는데(`admits`), 판정 뒤에 「이미 같은 값」 · 「시료가 남아 있다」 로 건너뛴 줄에도
    「고쳤다」 가 남았다 — 같은 날 점검에서 잡아 걷었다. 시편·시험 일괄 수정은 값이 바뀐 줄에서,
    시험·재료 일괄 삭제는 실제로 지우는 자리에서 적고, 재료 일괄 삭제는 판정을 `note=False` 로
    부른다. 처리 배치는 시험마다 커밋해서(하나가 실패해도 나머지는 남게) 채택된 시험을 모아
    **끝의 한 트랜잭션에서** 적는다 — 돌면서 적으면 시험 수만큼 줄이 생겼다.
  - **한 요청의 같은 일은 한 줄이다** — 일괄 300건이 300줄이면 표를 못 쓴다. 요청마다 메모장
    (`request_context.get_scratch`)에 `(등록자, 표, 근거)` 별로 모아 건수와 이름 스무 개를
    싣는다. **커밋된 쓰기에만 남는다**: 기록이 그 변경과 한 트랜잭션이라 삭제 계획 같은
    미리보기가 판정을 불러도 아무것도 안 남는다. 등록자가 없는 자료와 워크벤치 작업(부서
    안에서 함께 미는 표)은 안 남긴다.
  - **기록마다 「누구의 자료였나」**(`audit_entries.subject_id`). 안 주면 대상의 지금
    등록자로 채운다 — 삭제·확정·내림도 이제 등록자에게 보인다. 넘기기만 따로 준다(넘기기
    전의 등록자, 제 것을 제가 넘겼으면 받은 사람). 마이그레이션이 있던 기록도 채웠다(넘기기
    제외 — 지금 표에는 새 사람이 적혀 있다).
  - **`GET /audit/mine` · 「내 자료 변경 이력」(내 활동).** 누구나 부르되 제 자료의 기록만.
    내가 손으로 한 일은 빼고, 내 이름으로 AI 가 한 일은 남긴다.
